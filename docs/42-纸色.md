# 纸色

2026-08-20。

设置里一个开关，一档，没有深浅可调。开了之后整个界面的底色从纯白变成很浅的米色——阅读页、聊天窗口、侧栏、书架、设置，全部。只调阅读页会更糟：一半米色一半纯白，两半的亮度差比全白更累眼。

开关存 localStorage，不进 settings.json 也不进 device.json。localStorage 是同步的，`main.tsx` 里 mount 之前就能应用；device.json 异步读，晚一帧就意味着每次启动闪一下白屏。这也是 `ui/components/base/topic-nav.ts` 里那条本机视图偏好的存法。

开着时 `document.documentElement` 上挂 `data-tint="paper"`。界面那半靠 `styles.css` 里 `[data-tint="paper"]` 覆盖颜色 token（紫色系和文字色不动，只暖背景、边框和那几层灰）；阅读页那半靠一层 `mix-blend-mode: multiply` 的 `var(--page-wash)`，盖在 sheet 和 raster 上——白纸乘成米色，黑字乘出来还是黑，对比度不掉，图只是微微偏暖。

那层 wash 不能盖到选区、标注和引文高亮：它们的黄和紫是按白纸挑的，被乘一道就浑了。DOM 里它插在 raster 之后、这三层之前。

不用 `filter: sepia()`：滤镜作用在整页 raster 上，滚动时每帧重算，iPad 上 2x DPI 加 tiling 会掉帧；multiply 只是合成。

不做夜间/反色。全应用没有深色主题（`styles.css` 只有一套 `:root`，聊天里还有写死的紫色 hex），真做就是 token 铺一遍加每个界面过一遍视觉的工程。而且 PDF 反色对图基本是灾难，一本理工书里的图全变负片，Chrome 的 PDF 深色模式就是这个毛病。

页与页之间那圈灰色桌面这一版不动。
