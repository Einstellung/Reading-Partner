## 买不到也抄不到

Letta/MemGPT、Zep、Mem0、LangMem、MemOS、HMS 全都是 Python，或者要一个服务端。LangMem 实际上已经废弃（和 langgraph 1.0 不兼容）。HMS 是 Python + FastAPI + Postgres/pgvector 或 Oracle 加后台 worker，它的 TypeScript SDK 是 OpenAPI 生成的客户端，不是引擎。产品层没有一个能在没有后端的 webview 里跑，`docs/02` 得出同一结论之后这件事没有变。这是这个品类的形状，不是我们漏看了什么。

## 也信不了任何人的数字

一份独立审计发现 LoCoMo 的 1540 条标准答案里有 99 条是错的（6.4%），理论上限只有 93.57%；它的 LLM 裁判会接受 62.81% 的"含糊但沾边"的错答案；一次第三方复现打出 38.38%，而厂商自称 92.32%。LoCoMo 的对话只有 16k–26k token，把全部内容塞进上下文的朴素基线就能到约 73%，高于 Mem0 的约 68%。HMS 报 93.5%，几乎就是审计出来的天花板，而它的公开仓库里没有任何评测代码：标题为 "Add LoComo benchmark support" 的那个 commit 往 `.gitignore` 加了两行，全仓 grep "locomo" 没有结果，也没有 CI 目录。这个数字从公开代码无法证伪。

## 2026 年的评测换了口径

微软的 STATE-Bench（2026-05-19）量的是 agent 有记忆之后是不是做得更好——任务成功率、重复运行的稳定性、轮数和 token 成本——而不是召回准确率；作者写明大多数记忆评测是检索测试，不能告诉你 agent 表现更好。LongMemEval-V2（2026-05-12）同样。对我们的推论是：该问的是陪读的回答有没有变好、读者有没有不用再重复解释自己。

## 图这条关掉

Mem0 自己的图版本比非图版本高约 2%。BEAM（ICLR 2026）把对话堆到 1000 万 token，它的结构化记忆框架比纯长上下文高 3.5%–12.69%。1000 万 token 上整套结构化记忆机器只买到个位数到十几个点，而我们的规模是每个主题几十次会话、几百条标注。单用户、单主题、几百条记录这个量级没有任何研究。`docs/16` 是按产品理由关掉图的，现在证据同意。

## 检索要先证明自己

大约 26k token 以下，全放进上下文胜过记忆机器——朴素基线赢 Mem0 就是这么来的。这里一个主题的历史很可能在这条线以下。所以召回层要先证明自己赢过"全都放进去"，才配存在。

## 注入越多不等于越好

Chroma 跨 18 个模型的研究：输入变长会让表现下降，连很简单的任务也是；单个干扰项的影响随长度放大；打乱顺序的语料可以胜过连贯的语料。另有实验：把信息分散在多轮里给而不是一次给全，平均掉约 39%。两条都反对把记忆一条一条在对话里喂进去。

## 写入端的安全

记忆是 prompt injection 唯一的持久落点。两个已公开的案例：在 macOS 上写进 ChatGPT 记忆的跨会话持续外泄；以及一个形状和我们一样的 Gemini 案例——一份恶意 PDF 埋下触发条件，用户之后说一句"好"，模型就写下一条捏造的事实，绕开了"不要对不可信数据用敏感工具"的规则。我们的蒸馏读 PDF 正文和抓回来的文章正文，这些输入都不可信，写入路径需要一条不依赖模型判断的约束。

## 偏好会随对话衰减

PrefEval（ICLR 2025）测出大多数模型在约十轮（约 3000 token）之后遵循用户偏好的准确率掉到 10% 以下，提示词和 RAG 都挡不住。分诊每次运行都重新注入 profile，架构上是对的。长的阅读对话才是开头说的那条偏好死掉的地方。

## 控件要被读成指令

Mozilla 的 YouTube 审计（22722 名用户，567880195 条推荐）量了每个控件压掉坏推荐的比例："不要推荐这个频道"约 43%，"从观看历史中移除"约 29%，点踩约 12%，不感兴趣约 11%。Mozilla 的解读是：有效的控件被理解成具体指令，无效的被理解成偏好表达。我们的划掉写进 `info-feedback.jsonl`（`src/memory/profile/feedback.ts`），在分诊提示词里以 "RECENT REACTIONS (oldest first; learn the reader's taste from these)" 的形式给模型当证据权衡——11% 那个形状。

## 开放学习者模型：两份信念都留着，推断必须可谈判

可协商的开放学习者模型（Mr Collins 1995、CALMsystem 2008）同时展示系统的推断和用户的自评，给双方对称的动作——陈述信念、出示证据、质疑、要求解释、同意、折中——要求证据是具体的，并允许谈不拢时"先过"，两份信念都留着。实测：协商组的自评准确度提升显著高于只看不谈的对照组。

唯一一个经常推断一个人的能力、并且认真想过这件事的领域就是开放学习者模型，它的答案是这类模型必须给学习者看见、必须可协商，绝不能沉默。记成规则：关于口味的推断可以沉默形成、按需展示；任何读起来像是对读者能力或品性的判断，要么不存，要么只以他看过并且能反驳的形式存在。欧盟 AI 法案第 5 条是唯一一处法律直接禁止某种推断而不是只要求披露的地方，它管的是情绪、生物特征和社会评分，不管口味。

## 采信该由累积触发

Generative Agents 在写入时让模型给一个 1–10 的重要性分，检索分是新近度加重要性加相关度，而反思——形成关于这个人的更高层信念——只在最近的重要性之和越过阈值时触发，大约一天两三次；产出的洞察带着回指来源记忆的引用。这是区分一句随口的话和一个反复出现的模式的可用模板。

## 矛盾不该删除

Mem0 把矛盾处理成 DELETE，旧信念被销毁。我们的蒸馏提示词要求改写成演变、两个状态都留着（`src/memory/observations/distill.ts`）：

> On contradiction with an existing observation (e.g. the reader was stuck and now gets it), never silently drop the old state: rewrite that observation as an evolution — "was stuck on X, resolved on \<date>" — so both states stay visible.

我们这条更强，不许退回去。

## 时间有效性：两种形状

Zep/Graphiti 给每条事实 `valid_at` 和 `invalid_at`，和入库时间分开，失效是置位而不是删除，整套长在图里。HMS 把区间放在原始事实上——`occurred_start`、`occurred_end`、`mentioned_at`，和行时间分开——在抽取阶段就分类，事件必须带发生日期、持续的状态或偏好必须不带，"几个月前"解析成模糊区间而不是编一个具体时间点，并且从不把原始事实标成假：矛盾在上一层处理，派生信念的文本原地改写，旧文本推进一个 history 字段。

对一个文件存储、信念是策展出来的、带证据锚点的系统，HMS 那个形状更便宜；而且正是抽取阶段的分类让两个时钟可用。

## HMS 里值得重新实现的做法

都是 MIT 许可的设计，代码用不了：

- 任何模型调用之前先做确定性的相对日期解析，一张正则时段表加一个日期库产出显式区间——这才是那边实际在跑的东西，他们的 LLM 版本处于禁用且不可达的状态。
- 有界的乘法打分：相关度是底，新近度、时间接近度、证据强度是封顶的微调，约 ±10%、±10%、±5%。
- 约束响应 schema 而不是只约束提示词：每次调用推导一个 schema，其 creates 数组有最大长度，模型在结构上就超不出预算；deletes 在 creates 之前执行，腾出的名额可以再用。
- 把模型引用的 id 和本次运行里工具实际返回的 id 求交集，丢掉捏造的出处。
- 三层每层带一个新鲜度标志，附一条"过期就下钻到原始事实"的指令，一个 boolean 换一次验证。
- 删掉一个来源就删掉它的派生，并把同级重置以便重新派生。
- 一条明令：整合器不许做算术和推理，计数只在用户重新陈述时才变。

宣传文章声称的机制在那个仓库里不存在：带六个检索键的计划式召回、检索自检，以及 handoff / rollback / verify 三个动词。它自己的 README 也没有声称这些。

## 没有人解决的

遗忘：2026 年一份综述把"学会遗忘"列为开放问题，工程侧列出写入路径过滤、矛盾处理、延迟、隐私治理。单用户评测：没有成熟方法，最接近的是 n-of-1 交替条件设计，没人把它用在 AI 助手上，而且读者知道自己在被测本身就是混淆。"值不值得你注意"没有经过验证的度量。一等公民的否定断言——"我对 X 不感兴趣"作为有作用域、持久、可撤销的对象——在找到的任何产品和论文里都不存在。没有任何东西能区分一个死掉的兴趣和一个休眠的兴趣。还有一个没人处理的情况：一条信念写下时是真的，之后悄悄不再为真，而且没法纠正，因为系统不再呈现那个类别，于是反证永远不会到来。

## 我们已经领先的两条

蒸馏提示词里跨标注找模式的那条（`src/memory/observations/distill.ts`）：

> Judge whether they show a PATTERN worth recording (what the reader keeps marking, which themes or pages they lingered on). If so, write ONE aggregated observation ... anchored to those annotation ids — never one observation per mark.

调研者读完整个文献之后的判断是：在区分一次性和模式这件事上，这是任何地方能找到的最强表述。

`PROFILE_SKELETON_GUIDANCE`（`src/memory/profile/profile.ts`）里不许沉默丢掉过期条目的那条，比找到的任何已发表实践都严：

> Do not silently drop a stale Now entry: when one looks out of date, ask the user in chat whether it still holds before changing it.

重做不能把这两条弄丢。

## 我们的缺口

按 2026-07-31 的代码查证。

- 没有累积阈值。蒸馏每次挂断跑一次（`src/memory/live/live.ts`，另有历史裁剪的兜底），一句随口的话可以变成一条记忆，和一个反复出现的模式地位相同。`src/memory/` 里没有任何重要性或阈值的概念。
- 没有时间有效性。条目带 `created` 和 `updated`（`src/memory/observations/types.ts`），那是我们写下的时间；一个卡点的解决作为散文活在 body 里，不是字段。所以没法只加载当前有效的信念，也答不出读者三月份相信什么。
- 没有 rollback。蒸馏静默写入，一次 pass 之前没有记忆的快照。
- 没有 verify。证据锚点有（`anchors`），但没有任何东西回头检查锚点还解析得开、或者信念还能从它推出来。Observation Adapter（当时叫 Memory Adapter）的五个方法（retain/recall/listObservations/correct/rebuild）里没有这一项。
- 写入路径是单向的。`update_profile` 只挂在 info 一侧（`src/info/companion/companion-tools.ts`），阅读对话——一个人怎么读，恰恰是在那里才看得见——提不了画像修改，它挂的只有本主题的 memory 工具。
- 确认卡是单向的。`update_profile` 交一份完整的新画像，用户只能 Apply 或不 Apply，没有反驳、出证据、折中这些动作；画像是一份文档，最后写的人覆盖前面的。
- 画像会被稀释。提示词要求 profile 压在约 1500 字符以内，`info-feedback.jsonl` 则无界增长，分诊提示词同时吃这两样。注入的反馈是最近 30 条（`FEEDBACK_TAIL`）而不是整个日志，所以稀释的上限是这 30 条的字数。
