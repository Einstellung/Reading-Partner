# 291 工具一起跑就把这一轮写过的字擦掉

## 现象

文字聊天里模型输出一段话，然后调工具：那段话原地消失，空白几秒（只剩工具状态行），第二轮从零开始重新输出。落盘的消息只有最后一轮的文字。语音路径不受影响。

## 原因

`call-state.ts` 的 `tool-start` 把行的 `text` 清空（info 聊天在 `use-info-call.ts` 里做同一件事），理由是"轮间的话是过场，只显示最终答案"；工具成功后状态行又被 `resolveToolStatus` splice 掉，行里就什么都不剩。`runAgentLoop` 的 `onDone` 只交答出来的那一轮的文字，前面几轮永久丢失。

以前每轮挂工具是偶发，清空基本看不见。soul 那次改动（d7f90559）之后每轮都挂工具，它成了默认体验。

## 解法

一轮的文字不再是过场，是回复的一部分。`appendRoundBreak` / `joinRoundTexts`（`src/ai/turn-rows.ts`）是唯一的拼法：`tool-start` 把已有文字后面留一个空行（同一轮的第二个工具不再多留），循环在 `onDone` 的第三个参数 `turnText` 里交各轮拼接后的全文。两边共用这两个函数，否则落地那一刻屏幕上的回复会重画一次。

`onDone` 的第一个参数仍是答出来的那一轮，产出物走这条路（笔记、蒸馏、马前卒的结果不能带上"我先看看第 4 页"）。工具结果不进任何一条。

工具状态行画在文字下面（`messageToParts` 的顺序和 `chat.tsx` 的行都改了），不是上面：读者读到哪里，字就停在哪里。
