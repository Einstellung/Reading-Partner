# iOS 冻住 app 一分钟，流式连接没死，回前台一次把整段回答吐完

## 现象

iPad 真机（iPad15,7 / iOS 26.7.1），`.dev` 包，Haiku 5.5 的阅读回合。Thinking 刚开始就把 app 压到后台（从 Mac 上 `dvt launch` 设置），30 秒和 60 秒后再切回来：离开期间 JS 定时器一个都没跑，turn-log 的 `round` 结束时间和回前台的 `visibilitychange` 在同一秒，3600 到 3800 个输出 token 在回来后一秒内全部画出，回合 `done`，没有停摆、没有重问，线程文件里答案完整、不重复。

另一次回答短（不到 2000 token），离开 6 秒内就在后台写完了：进后台后进程还会跑几秒才冻。

## 原因

冻住的是 app 进程，不是 TCP 连接。供应商那边照常生成，数据堆在系统的 socket 缓冲里（满了靠流控让对端等），一分钟内连接没被任何一方关掉。解冻后读到的是完整的流。坑 390 那种「连接静默死掉」是更长的离开或网络切换才有的，不是每次切后台都会发生。

停摆看门狗没动作也是对的：进后台后那几秒宽限里还有 thinking delta 到达，`lastBeat > awaySince`，`back()` 认为连接活过了这次离开，交给 90 秒的普通窗口；回来时距最后一个字节约 61 秒，不到 90 秒。

## 解法

不用改。验证切后台时要知道：

- 要在 Thinking 阶段或正文刚开始就切，Haiku 出正文很快，晚一两秒切，回合就在后台宽限里写完了，测不到冻结。
- 离开超过 90 秒时，解冻后第一个 tick 可能先于缓冲里的字节被处理，看门狗会掐掉一条其实活着的流再重问一次。这次没量（真模型次数用完），量的时候看 turn-log 有没有 `aborted` 紧跟一个新 `start`。
- 从 Mac 把 app 叫回前台要 `dvt launch --no-kill-existing <bundle id>`，默认是先杀再起；判据是返回的 PID 不变、页面里挂的 `window.__tl` 还在。
