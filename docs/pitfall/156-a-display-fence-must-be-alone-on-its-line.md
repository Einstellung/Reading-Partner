# `$$` 不单独占一行，整段回复就变成一堵红色的 LaTeX

## 现象

AI 回复里的多行公式连同后面的正文一起渲染成红色原文（红色是 rehype-katex 的 errorColor）：

```
$$S=\begin{bmatrix}
0.9995&0.9544
\end{bmatrix}$$

现在把 x₃ 和 x₄ 对调。
```

单行的 `$$x=1$$` 是好的。翻了本机全部会话：写过 `$$` 的回复几十条，绝大多数是单行成对的，多行公式每一处都是上面这个坏形状，写成规范形式（`$$` 独占一行）的一处也没有——而提示词里已经写着块公式用 `$$...$$`。

## 原因

remark-math 的 flow 规则。开头那行 `$$` 后面还有东西，那些东西变成节点的 `meta` 被静默丢掉；收尾必须是只有 `$$` 的一行，`\end{bmatrix}$$` 不算收尾，`$$ 然后。` 也不算。没收上的块一路吃到文本结尾，于是公式和后面的正文一起进了同一个 math 节点，KaTeX 解析不了就整块涂红。

`$$x=1$$` 写在一行反倒对：`meta` 里会出现 `$`，flow 构造失败，退回 inline math。

只有起在行首的 `$$` 才走 flow 规则（前面允许引用符号、一个列表标记，再最多三列空白；第四列就成了缩进代码块）。数的是列不是字符：一个 tab 跳到下一个 4 的倍数。写在行中间的 `$$` 是 inline math，跨几行都正常。

## 解法

在交给 react-markdown 之前把围栏搬到自己的行上：`src/ui/components/markdown/mathFences.ts` 的 `canonicalizeMathFences`，装在 `MarkdownRenderer.tsx` 里 `linkifyCitations` 前面。

它逐行走，只认上面那个坏形状：`$$` 起在行首、后面还跟着东西、而且跟着的东西里一个 `$` 都没有。micromark 的 meta 见到第一个 `$` 就拒绝 flow（`math-flow.js` 的 `if (code === 36) return nok(code)`），不看那个 `$` 连成多长——所以 `$$ 表示块公式，$ 表示行内公式。` 是一句普通的话，不是坏开头，动它就等于把它涂红。坏的开头行切成「`$$`」和「剩下的」，块里第一个前面有内容的收尾行切成「前面的」「`$$`」「后面的」。

它写出的字节只有三种：这两处切口，切口插进的新行带的容器前缀，和下面那个转义。别的行原样返回——行中间的 `$$`、单行成对、围栏代码、缩进代码不用特判，形状本身把它们排除了。正文里的钱数只有不在行首时才自动排除：`$$100 元。` 独占一行的话 remark 本来就当块公式开头读，这一步跟着它读。

行首要看清容器，不然会在不是容器的地方下刀：

- 列表标记后面最多四列空白，第五列把内容推进列表项里的缩进代码块。`1.` 加两个空格再加一个 tab 是八列，那行整个在缩进代码块里，按字符数只有三个空白就会读成行首，把 `&#36;&#36;` 写到读者眼前。
- `2.` 这类序号打断不了段落（CommonMark 只放行 `1.`/`1)`），所以 `公式如下：` 换行接 `2. $$x=` 是一整段，里面是能正常渲染的行内公式，当列表项切就成了字面文本加一个空块。空行之后、或者列表已经开着的时候，`2.` 才是标记。
- 行首是 `<` 的开一个原始 HTML 块，块里不动手：没装 rehype-raw，那里的内容原样送到读者眼前，切口和转义都看得见。各种块的结束位置不一样：`<pre>`/`<script>`/`<style>`/`<textarea>` 到闭合标签，`<!--` 到 `-->`，`<?` 到 `?>`，`<!X` 到 `>`，`<![CDATA[` 到 `]]>`，剩下那两类标签形状的才到空行。把注释当成到空行结束，`<!-- c -->` 下面那道红墙就不修了。
- 反引号围栏的 info string 里不能有反引号（`~~~` 没这条），所以 ```` ```a`b ```` 是一段普通文字。当围栏读，它会开一个由后面某行的 ``` 来关的块，中间那几行就落在真正的围栏里被切。
- CRLF、LF、单独一个 CR 都是 CommonMark 的换行。每行插新行用它自己的那个终止符，不按整篇挑一个，末行的终止符也留着。

插进去的行要带上引用和列表前缀，否则块会从列表项里掉出来。块在开它的那个容器（引用层数、列表缩进）结束时结束：容器读短了最多是不动手，读长了才会切错，所以上面几条都往「不是容器」那边偏。前缀只认「引用符号在列表标记之前」这一种嵌套，`- > $$S=…` 修不了——漏修可以，切错不行。

转义只有一种情形：被切开的开头行直到文末都没等到收尾（流式写到一半），那个 `$$` 换成 `&#36;&#36;`，不然半截公式的红墙会一直立到公式写完。不能用 `\$\$`：mathText 不认收尾 `$` 前面的反斜杠，`\$\$` 还是两个定界符，同一段里早一点的一个 `$`（`每股 $200`）会跟它配上，把中间的正文圈进行内公式涂红。字符引用在行内解析之后才还原，它的 `$` 永远当不成定界符，读者看到的还是 `$$`。转义是自消的：每次渲染都从模型的原文重算，收尾一到就没了。本来就规范的 `$$`（独占一行）即使还没收尾也不碰——那是能正常渲染的块，转义了反而把它变成字面文本。

实测的保证不是「一个字节都不改」，是「改前能正常渲染的一个字节都不改」：本机 521 条存量消息里只有 2 条被改，就是上面那个坏形状，两条都从红墙变成正常公式。另外拿五万条容器密集的随机输入扫（种子发生器用 mulberry32，别用 `seed * 1103515245`，那个乘法溢出 2^53 之后两万次抽样只落在 1812 个串上），改前树里没有带 meta 的 math 节点、改后字节却变了的有 87 条：81 条是规范开头加一行「内容 + 收尾」，改前红墙改后正常；5 条改前本来就有一个 KaTeX 认不了的 math 节点；剩 1 条改前改后渲染完全一样，只是多了一次转义。

## 还修不了的

三处都要真的按 CommonMark 匹配容器，靠行首正则做不到，而且都要模型不会写的 markdown——521 条存量回复里一条都没有：

- 围栏跟踪不看容器，会拿别的容器里的 ``` 关掉一道围栏，于是在 remark 还开着的块里下刀：`"> ```\n> a\n```\n$$x=\n1$$"`。
- `holds()` 不看收尾行在哪个容器里，remark 读成另一个列表项里缩进代码的行也可能被当成收尾：`">\t1) $$a|b|\n >    *     $$每股 $200"` 这类形状。
- 缩进代码块之后 micromark 不让 `1.` 以外的序号开列表（空行也关不掉它），这一步的段落模型不知道，于是 `"    x\n\n2) $$a"` 里的 `$$` 被当成行首转义掉——渲染结果一样，只是字节动了。

守着的单测是同目录的 `mathFences.test.ts` 和 `Markdown.math.test.tsx`。
