# 652 神经 VAD 的帧按它落进的 tap buffer 取电平，短词的尾巴被回声门挡掉

## 现象

iPad 静默语音测试的 `barge-in`（2026-10-17 两次神经、两次能量）：「等一下」（约 0.35 s）在神经 VAD 下两次都是 duck 之后 resume，没有 stop；能量 VAD 两次都在 clip 开始后约 510 ms 停下。

## 原因

播放期间，神经路径要求一帧同时过 Silero 的概率线和 -35 dBFS 这条回声门。电平取的是这一帧最后一个样本所在的那个 100 ms tap buffer 的 RMS。

「等一下」的语音在 540 ms 结束。最后三个高概率帧（524、556、588 ms，p 为 0.95、0.89、0.61）都落在 500–600 ms 那个 buffer 里，这个 buffer 大半是静音，RMS 只有 -38 dB，三帧全被挡掉。最后一个算数的帧在 492 ms，离 duck 的 204 ms 是 288 ms，够不着 300 ms 的确认窗。能量路径的 duck 和 stop 都打在 buffer 的结束时刻（200 和 500），正好 300 ms。日志里神经路径的 duck 在 304 ms，因为事件是在帧所在的 buffer 送到时才发出的，帧本身的时刻还是 204。

「嗯」在测试台上两种 VAD 都没 duck 过。剧本让它在长回复开始播放后 1.5 s 出声，从时间线看落在 2 s 的免疫窗里，所以没有 duck 不是靠区分出来的。不在免疫窗里时，能量路径靠时长区分：「嗯」有三个响的 buffer（200–400 ms），「等一下」有四个（200–500 ms），中间只差一个 buffer。

## 解法

帧的电平改成截止到这一帧末尾的 100 ms（16 kHz 下 1600 个样本）的 RMS。TS 侧是 `trailingLevelDb`，Swift 在 `NeuralFront` 的环形缓冲上算同一个数。门限还是 -35，窗长还是 100 ms，只是窗口和帧对齐了。

Silero v6（ONNX，权重和 CoreML 版相同）按测试台的喂法跑 clip，逐帧数据写进了 `turn-detect.test.ts`。「等一下」算数的帧延到 588 ms，在 524 ms stop。「嗯」到 428 ms，离 duck 224 ms，resume。两边离 300 ms 的确认窗都还有七八十毫秒的余量。
