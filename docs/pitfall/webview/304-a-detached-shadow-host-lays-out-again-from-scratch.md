# 304 从文档里摘下来的 shadow host，再挂回去要整棵重排

## 现象

v0.18.1 在 iPad 上滚公式多的 EPUB 卡得肉眼可见，v0.18.0 不卡；同一版翻没有公式的书完全不卡。

模拟器里量（iPad Pro 11-inch M5 / iOS 26.5，一步一页共 20 步，记 rAF 间隔）：

| 书 | v0.18.0 平均帧 | v0.18.1 平均帧 |
|---|---|---|
| Cordis 双语（3907 个 `<math>`，40497 个元素） | 217ms | 876ms |
| 纯文字（0 个 `<math>`，141 个元素） | 17.4ms | 17.5ms |

差别来自 0.18.1 的 sanitizer 开始保留 MathML：同一个 EPUB 文件，解析出来的树从 2344 个元素变成 40497 个。但 MathML 只是把代价放大了，代价本身 0.18.0 就在。

## 原因

页卡片是一个 shadow host，里面挂着整篇 spine 文档的克隆，按多栏排版，靠 transform 平移到某一栏（docs/64）。滚动时 `syncMounted` 把离开窗口的卡片 `el.remove()`，把进入窗口的卡片 `slot.el.append()`。

把 shadow host 从文档里摘下来，它底下整棵渲染树就没了；挂回去是整篇文档重新排一遍多栏。在 Cordis 那本书上实测：

| 一步里做的事 | 耗时 |
|---|---|
| 摘下来再挂回去 | 830-870ms |
| 已挂载卡片上跑完整个 `show()` | 0.1ms |
| CFI 解析 + 读 range 的 client rects | 0.1-1.8ms |
| 把 columns 的 transform 换一栏再读盒子 | 0.1ms |

卡片池当时也在帮倒忙：卡片一离开窗口就 `clear()` 清空 shadow root，所以下一页连克隆都要重做。但那不是大头——只留住克隆、照样摘挂，平均帧 876ms 只降到 851ms。

## 解法

卡片不再是 slot 的子节点，而是直接挂在 strip 上，按页号算绝对坐标摆位；离开窗口的卡片只 `visibility: hidden`，永远不从文档里摘出去（`visibility` 保留排版，`display:none` 和 `remove()` 一样会扔掉渲染树）。卡片池按 spine 下标发卡片，让同一篇文档的下一页拿回已经排好的那张。

Cordis 那本书的平均帧从 876ms 回到 17ms，长帧（>50ms）从 20 步里的 19 次变成 0 次。

剩下的一次性代价没有动：这本书的一张卡片第一次挂载要 1.4 秒，开书和跨 spine 文档时还会撞到。真正治它要让卡片只克隆本页那几个块，不是整篇。
