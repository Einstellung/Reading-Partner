# 解析出来的树原样写回去，再解析一遍不一定还是那棵树

## 现象

`src/info/extract/sanitize.ts` 解析正文、按白名单走树、把留下的节点重新写出来。清洗在存的时候跑一遍，之后每次读又跑一遍，所以要求 `sanitize(sanitize(x))` 和 `sanitize(x)` 逐字节相等（坑 126）。安全没问题，逐字节不相等的有五类，都不是攻击，都是同一条正文在第 N 次读和第 N+1 次读渲染不一样：

```
<pre>\n\ncode</pre>          每读一次少一个换行，代码块的首行空行一次掉一行
<p>a&#13;b</p>               CR 下一趟变成 LF
<p>x<button><p>y</p></button></p>    第二趟拆成两个并列的 <p>
<h1>a<em-x><h1>b</h1></em-x></h1>    第二趟拆成两个并列的 <h1>
<ul><li>a<table><li>b</li></table></li></ul>   第二趟拆成两个并列的 <li>
```

## 原因

五类是三件事。

**`<pre>` 后面的换行**。树构建器规定 `<pre>`/`<listing>`/`<textarea>` 起始标签后紧跟的那个 LF 直接丢掉。所以 `<pre>\n\ncode` 解析出来的文本节点只有一个 `\n`；原样写回去就成了 `<pre>\ncode`，下一趟再丢一个。

**`&#13;`**。输入流预处理把源码里的字面 CR 换成 LF，但字符引用是预处理之后才解码的，所以 `&#13;` 真能在文本节点里留下一个 CR。把它当普通字符写回去就是一个字面 CR，下一趟被预处理换成 LF。

**起始标签会关掉已经开着的元素**。`<li>` 关掉上一个 `<li>`，第二个 `<h2>` 关掉第一个，块级元素关掉开着的 `<p>`，`<rt>`/`<rp>` 通过 implied end tags 关掉列表项和段落。树里确实能出现「一个 `<li>` 套在另一个 `<li>` 里」这种位置，但写出来之后下一趟解析不认，要拆成并列。三条进去的路，只有第一条是把某个元素拆掉造成的：

- `button`、`marquee` 这些 scope boundary 挡住了关闭规则，把它们 unwrap（去标签留孩子）就把挡板抽走了；
- `h1`-`h6` 的规则只看 current node，所以**任何**元素都是挡板，包括没人认识的自定义元素，unwrap 它一样抽走挡板；
- foster parenting 根本不需要 unwrap：`<table>` 里出现的 `<li>` 被搬到 `<table>` 前面，正好落在外层 `<li>` 里面。

## 解法

前两件事在写出去的时候补偿：`<pre>` 的内容以 LF 开头就多写一个 LF（下一趟正好吃掉，这也是 `innerHTML` 序列化算法自己的规则），文本里的 CR 写成 `&#13;`。判断「以 LF 开头」要看**实际写出去的第一个字符**，不能看元素的第一个子节点——`<pre><!--c-->\ncode` 里注释挡住了树构建器吃换行，而注释在写出去的时候已经没了。

第三件事不补偿，也不去建模树构建器那十几条关闭规则——用解析器就是为了不重写解析器。改成：走树的时候维护一份「输出侧已经打开的元素」栈，写一个起始标签之前查它会不会关掉栈里的东西；会，就说这趟结果不作数，把它再喂给解析器一遍，直到解析器不再改动它（上限 5 趟）。这张关系表宁可多列也不能漏，漏了就漏掉性质，多列只多花一次解析。90000 条随机嵌套里 99.95% 一趟就定，剩下的两趟，没有需要第三趟的。

`button` 和 `marquee` 顺手改成连内容一起丢：`button` 是表单控件，和 `input`/`select`/`textarea` 一组；`marquee` 和已经在丢的 `applet`/`object` 是同一族 scope boundary。这是为了输出干净，不是为了稳定性——稳定性由上面那条兜底。

清洗器之后还有别的步骤时，那一步也要算进来。`reading/saved-articles.ts` 在清洗之后跑 `stripDataImages` 删内联图，`<pre><img src="data:...">\ncode</pre>` 里那个 `<img>` 正挡在起始标签和换行中间，删掉它就留下一个下一趟会被吃掉的换行；所以它删到东西的时候要把结果再过一遍清洗器。

测试的判据必须是逐字节相等，而且 fuzz 要**嵌套**：原来那个 fuzzer 把标签平铺着拼，跑两千轮一条都发现不了——只在回程散架的形状得先有个「里面」。上面五类里有四类是嵌套 fuzzer 发现的，不是想出来的。
