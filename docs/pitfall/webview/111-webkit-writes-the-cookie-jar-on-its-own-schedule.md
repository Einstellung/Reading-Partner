# 删了 cookie 内存里干净了，盘上还留着，下次启动人又是登录状态

## 现象

退出登录调完 `delete_cookies_for_domain`，命令返回成功，当前进程里那个站确实没 cookie 了。但 `<profile>/cookies` 文件里还留着 13 行该站的记录。下次启动 app，WebKit 从文件读回来——用户又是登录状态，退出等于没退。

实测：删之前 48 行，删之后文件 13 行。

## 原因

`delete_cookies_for_domain` 是个 void 调用，没有完成回调，删除动作发给 network process 之后就返回了。而持久化是 WebKit 自己安排的：什么时候把内存里的 jar 落盘不归调用方管，也没有 flush API。命令返回、窗口销毁、进程退出，都可能赶在那次写之前。

对一个只靠 cookie 表达登录态的功能来说，"内存删了"不算删了。

## 解法

两步：

1. **先确认删除已经落到 network process**。删除本身没有完成信号，但同一个 cookie manager 的读有：`webkit_cookie_manager_get_cookies()` 是异步的，同一个进程按顺序处理，它的回调返回就说明前面的删除都处理完了。拿这次读当 barrier。
2. **然后自己重写 jar 文件**。按域名过滤掉该站的行，写临时文件再 rename。第 1 步保证了内存是干净的，所以 WebKit 之后无论什么时候再落盘，写出来的都和我们写的一致，不会把删掉的行带回来。

实测这两步之后 48 行 → 0 行。过滤是纯函数（`jar_without()`），注释行和别的站点的行原样保留，单测盯着"退出一个站不能顺手删掉另一个站的会话"。
