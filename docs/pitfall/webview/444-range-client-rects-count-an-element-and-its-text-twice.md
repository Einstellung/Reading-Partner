# Range 的 client rects 把整个包进去的元素和它的文字各算一遍

## 现象

手机 EPUB 流式阅读器里跳到 AI 引的一段，引文里有个斜体词（`<em>me</em>`），那个词上的紫色底比周围深一层：实测取色 (174,163,194) 对 (205,196,205)。高亮和下划线也一样。

## 原因

`Range.getClientRects()` 按规范对范围完整包住的元素返回元素自己的边框盒，再对其中的文本节点返回文字的盒。`<em>` 的盒和 "me" 的盒几乎重合，半透明的底按 rect 一个一个画，重合处就叠了两层。所有从 range 取 rect 的地方都是这样：流式视图的 `rectsIn`、iPad 分页视图的 `card.rectsOf`，引文底和标注共用这条路。

## 解法

`mark-draw.ts` 的 `drawQuote` 和 `drawStroke` 先过 `mark-geometry.ts` 的 `lineBands`：同一行（竖向重叠至少较矮那个的一半）上重叠或相接的 rect 并成一条，每处只画一次。行间盒子因行高紧而略有重叠的，仍算两行；同一行上真有空隙的，仍是两段。命中测试用的 rect 不用改，重复的 rect 不影响「按没按到」。
