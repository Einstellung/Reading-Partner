# TTS 句尾那半秒不是静音，是底噪，按静音去裁会一点都裁不掉

## 现象

小米 `mimo-v2.5-tts` 每句前面 117 ms、后面 451 ms 没有人声（docs/33 实测）。按句接力时这段是每句之间凭空多出的空白，要裁掉。

按"静音 = 采样点接近零"写裁剪器，阈值取 -60 dBFS，跑真实语料：句首平均裁掉 18 ms，句尾平均裁掉 39 ms。那 451 ms 一动没动。

## 原因

那段区间根本不是数字静音，是 -45 到 -65 dBFS 的底噪，逐句不同。16 句语料、10 ms 窗、逐窗峰值：句首前三个窗最响的一句到 -46.4 dBFS，最安静的到 -84 dBFS；句尾的噪声区同样在 -50 到 -63 之间，个别句子末尾才落到 -84 以下的真静音。

各阈值下平均裁掉多少（同一批 16 句）：

| 阈值 dBFS | 句首均值 ms | 句尾均值 ms |
|---|---|---|
| -60 | 18 | 39 |
| -55 | 59 | 153 |
| -50 | 81 | 326 |
| -45 | 99 | 415 |
| -40 | 109 | 431 |

docs/33 里那个 451 ms 是按 -40 一档的口径量的。要真把它拿掉，阈值必须压到 -45 上下，也就是必须高于底噪，而不是接近零。

## 另一半：尾部护栏不是保险，是必需

阈值定在 -45 之后再验有没有削掉语音：16 句（专门挑了 s-／k- 开头和擦音结尾的）分别裁和不裁，同一个 ASR（SenseVoiceSmall）回读，逐句一字不差。

但护栏归零就不行了。句尾护栏设 0（裁到最后一个超阈值窗为止），「是。」回读成 `Shi.`——整句只有一个音节，全是擦音，尾巴的无声段能量本来就在阈值以下，切掉之后 ASR 认不出中文。句首护栏归零则一句没变。阈值 -35 加双护栏归零时还多毁一处：「峰值扭矩」变成「峰值扭曲」。

所以这一层有三个数，缺一不可：阈值 -45 dBFS、句首护栏 40 ms、句尾护栏 60 ms。

## 解法

`plugins/voice/src/tts/trim.rs`：10 ms 窗逐窗取峰值，超过 -45 dBFS 算有声；句首从第一个有声窗往前留 40 ms，句尾从最后一个有声窗往后留 60 ms。整句一个有声窗都没有时两端都不裁——量不出来就别删。

复测方法在 `docs/assets/tts-probe/`，回读脚本用同一个 ASR 对照裁前裁后，不要靠听。
