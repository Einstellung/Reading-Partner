# 守卫测试里扫源码的正则，否定字符类会跨行

## 现象

给 palace 加「哪种数据存了 topicId 却没登记」的守卫测试，按 `tests/layering.test.ts` 的路子扫 `src/` 下每个文件，只认接口字段这一种写法：

```ts
const DECLARES = /^[ \t]*topicId\??: [^;]*;$/m;
```

先用 `grep -rlE "^[[:space:]]*topicId\??: [^;]*;$"` 列出 22 个文件，照着写进表里。测试跑起来多出 13 个文件，里面一个字段声明都没有，只有 `topicId: null,` 这类实参和形参。

## 原因

JS 的 `.` 不匹配换行，否定字符类匹配。`[^;]` 里没排除 `\n`，于是 `[^;]*` 从形参那行的 `topicId: ` 一路吃过换行，直到后面某一行以 `;` 收尾，`/m` 的 `$` 在那行末尾满足，整段算一次命中。grep 是按行喂的，同一个模式在 grep 下不可能跨行，两边于是给出不同的答案。

## 解法

否定字符类里显式排掉换行：

```ts
const DECLARES = /^[ \t]*topicId\??: [^;\n]*;$/m;
```

判据是同一模式下 grep 的文件数和测试列出来的文件数对得上；对不上先怀疑跨行，不要先怀疑表写漏了。
