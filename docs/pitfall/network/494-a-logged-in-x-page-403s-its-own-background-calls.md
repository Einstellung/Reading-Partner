# 登录态读 X 永久链接页，页面自己的后台请求大量 403，内容却完整

## 现象

用带登录 cookie 的 WebKit 逐条读永久链接页，8 次里有 6 次，页面发出的 `x.com/i/api/graphql/.../UsersByRestIds` 和 `x.com/i/api/1.1/graphql/app_context.json?keepalive=true` 回 403（每次一到两遍）。同一时刻页面照常渲染，推文正文、Article 正文、回复都在，没有挑战页，没有登出，标题栏带通知数说明登录有效。不登录读同样的 8 个链接，一个 403 也没有。

## 原因

未查证。这两个是页面的通知数和上下文刷新，不是取正文的请求；Playwright 的 WebKit 不是真浏览器，大概率是 X 对这类后台调用的风控。没有出现 429。

## 解法

限流和风控的判据不能写成"x.com 的任何请求回 403/429"，否则每次都会误停。只认三种：状态页本身（`TweetDetail` 一类取内容的请求）回 429；最终落地的 URL 不再是 `/status/` 页（跳去登录、`/account/access`、挑战流程）；页面正文里出现限流、锁定、验证的提示。后台请求的 403 只记日志，不拦。

*实测：2026-10-08*
