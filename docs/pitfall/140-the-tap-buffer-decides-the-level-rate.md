# 电平事件的频率是 tap 的 bufferSize 定的，不是你的节流定的

## 现象

电平事件按 15Hz 节流（`now - lastLevelAt >= 1.0/15`），真机上量出来是 9.6-10.0Hz，
十二轮按住说话都是这个数，一次都没到过 15。

## 原因

节流只能减速不能加速。事件是在 tap 回调里发的，而 tap 回调的节奏是
`installTap(onBus:bufferSize:format:)` 的 `bufferSize` 除以硬件采样率：

```
4096 frames / 48000 Hz = 85.3ms  ->  最多 11.7Hz
```

66.7ms 的节流阈值比 85.3ms 的到达间隔还短，所以它一次都没生效，实际频率完全由缓冲区
大小决定。想真到 15Hz 得把 bufferSize 降到 3200 以下，那是更多的回调、更多的转换、
更多的 IPC。

## 解法

10Hz 落在电平条想要的区间里（CSS 是 `duration-75`，低于 ~13Hz 显得一格一格，高于
~30Hz 每条事件都是十三个 span 的整棵重渲染），所以缓冲区保持 4096，节流留着当上限，
注释写清楚真正定频率的是谁。

要改频率就去改 `bufferSize`，别去调节流的数。
