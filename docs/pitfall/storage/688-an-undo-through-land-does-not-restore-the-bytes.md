# 经 land 撤销回去的文件，字节不回到原样

现象：edit_data 连写两次（A→B→C），undo_edit 撤第一次成功（回到 B），再撤第二次被拒，说「数据在那次写入之后变了」。中间没有任何别的改动。

原因：版本记录存的是写入后文本的 hash，撤销要求当前文件的 hash 等于目标记录的改后 hash。没有 `restore` 的 entry 撤销时把旧文本 parse 后走 `land`，`land` 会重算程序算的字段、重盖时间戳（`updatedAt`、`revision` 之类），落盘的文本和当初 B 的文本内容相同、字节不同，hash 对不上。

解法：撤销不再拿当前文件比目标记录一条，而是看从目标记录到最近一条记录是否首尾相接：每条记录改前文本的 hash 等于前一条的改后 hash，当前文件的 hash 等于最近一条的改后 hash（`housekeeper/write/engine.ts` `undoLatest`）。撤销记录自己的改前、改后都是它落盘时读到的，所以链能接上；中间有同步或别的回合改过，链在那里断开，照旧拒绝。
