# `</head>` 和 `<body>` 之间的换行把整篇的锚点推后一格

## 现象

合成 EPUB 里 `<body>` 第一个孩子就是 `<span epub:type="pagebreak" id="pg1">`，page-list 指着它。分页表却在它前面多出一个没有页码的块：代码认为第一个印刷页锚点不在文档开头，于是补了一块"前言"。

## 原因

XHTML 用 XML 解析器解，`<head>...</head>\n<body>` 之间那个换行是 `<html>` 的一个文本子节点，原样保留（HTML 解析器会把它挪进 body，XML 不会）。正文抽取按文档顺序累加字符，这个换行先被计入，于是 body 的起点偏移是 1 不是 0，`pg1` 也是 1。整篇文档的每个锚点都跟着推后一格。

`&#13;` 那类问题是内容，这个是版式：书里到处是这种排版换行，`<p>` 之间、`<div>` 之间都有。

## 解法

正文抽取里维护一个"当前在块边界上"的标志，处在边界上时纯空白文本节点整个跳过（`src/reading/epub/text.ts` 的 `pushText`）。块内的空格照旧保留——`<em>a</em> <em>b</em>` 中间那个空格是词间距，不是版式。
