# 按位置 key 的行让按节点配对的 FLIP 失效

## 现象

手机课堂里长按删掉一条 aside，下面该滑上来的那条消息不动，别的节点反而往错的方向挪一小下（-72px、-14px）；删最后一条 aside 时一次动画都不播，内容直接跳。书架和 Saved 列表同一套滑动是好的。

## 原因

`slide-into-place.ts` 删之前记下后面那些 DOM 节点的位置，删之后按同一个节点对比前后位置。课堂的消息列表按下标做 key（`chat/MessageList.tsx` 的 `key={i}`，有意为之），删掉中间一条消息后 React 把每个后续节点复用给下一条内容、删掉最后一个节点，节点身份不再代表同一段内容。另外课堂读到最新一轮时滚动容器停在底部，删掉一行后 scrollTop 被夹紧，真正移动的是被删项上面的行（往下挪），下面的行不动；只量后面的节点永远量不到这一侧。

## 解法

不持有节点引用，按顺序重新找：删之前对每一层容器记下被删项前面有几个（`lead`）、后面有几个（`trail`），删之后在同一个容器里取前 `lead` 个和后 `trail` 个子元素，第 k 个和删之前的第 k 个配对（`movingGroups` / `movingSlots`）。被删的东西都在两侧之间，所以不管 React 保留还是复用节点都对得上；已经离开文档的容器按空位处理，没动的元素不播动画。
