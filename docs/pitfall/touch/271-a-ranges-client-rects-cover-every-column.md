# 一个 Range 的 client rects 跨了整章的所有列，按纸的边框裁不掉它们

## 现象

在页卡片上画标注：把 CFI 解成 Range，`getClientRects()` 换成页坐标画矩形。有些标注画出来是一条横穿页面空白处的黄条，有些干脆画在纸的页边距里；探针里量到的第一个矩形是 `left: -10560, top: -915`。

## 原因

卡片里那份 spine 文档是**整章**排进 multi-column 的，一页只是其中一列（`.rp-columns` 用 `translateX(-k×480)` 把第 k 列挪到版心里，`.rp-clip` 把别的列裁掉）。`getClientRects()` 报的是布局里的真实位置，不管有没有被 `overflow: hidden` 裁掉：第 k 列以外的内容照样有矩形，只是坐标在纸的左边很远（前面的列）或右边很远（后面的列）。一个段落跨十几列，它的矩形就散布在一万像素宽的范围里。

按纸的边框裁不干净。纸宽 576、版心从 48 开始宽 480，所以下一列的内容出现在页坐标 528–1008：`left <= 576` 这个判据会把下一列开头的 48 像素放进来，画在纸的右页边距上。

## 解法

裁到**版心**，不是裁到纸：`clipRect(r, BODY_BOX)`，`BODY_BOX` 是 `[48, 56, 528, 808]`（`mark-geometry.ts`）。落在版心外的矩形整块丢掉，横跨边界的切掉外面那半。墨迹是例外，它本来就画在纸的坐标系里，裁到整张纸（`PAGE_BOX`）。

同一件事的另一面：标注命中测试也只认版心里的矩形，所以画上去的和点得到的是同一批。
