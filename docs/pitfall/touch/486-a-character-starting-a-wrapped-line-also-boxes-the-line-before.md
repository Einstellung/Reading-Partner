# 486 折行后行首字符的 Range 还带着上一行行尾的空矩形

## 现象

EPUB 翻页模式，一段从上一栏接过来的引文，在这一栏顶行从左边距（引文的内边距里）起笔划线：标注的第一个字是上一栏最后一个字（「具使用结合…」），页号记成上一页，这一页上看不到。只修起点判断、不修测量时，起点又偏到行首第二个字。

## 原因

iOS WKWebView 上，折行后行首那个字符的一字符 Range，`getClientRects()` 给两个矩形：上一行行尾一个宽 0 的，加上字符自己的。实测「及」：`[27,1077,w0]`、`[66,151,w16]`，`getBoundingClientRect()` 是两者的并集（left 27、跨两栏的高度）。`caret.ts` 用并集当这个边界的位置，行首边界被算到上一行、左边小于落笔点。

另外 `nearestOffset` 原本在「落笔点在本行第一个字左边」时返回上一行的最后一个边界，也会把上一行的末字带进来。

## 解法

`caretRect` 取一字符 Range 里最后一个有宽度的矩形（`glyphBox`），不用 `getBoundingClientRect()`。`nearestOffset` 在 `here` 属于更早的行、`next` 在落笔点那一行时返回 `low + 1`。
