# 280 打包字体也没让分页跨引擎一致

## 现象

《具身智能》同一份文件、同一份几何（576×864、版心 480×752、Noto Serif 16px/1.55）：

| 引擎 | 页数 |
|---|---|
| Linux WebKitGTK（xvfb） | 75 |
| iOS 26.5 WKWebView（iPad Pro 11-inch M5 模拟器） | 77 |

同一台设备上重开是稳的（77 一直是 77），差异只出现在跨引擎。

## 原因

坑 268 改写 `font-family` 解决的是「有没有装 Georgia」那一类差异，不解决两个 WebKit 分支在断行、断字、行盒取整上的实现差异。multicol 的列数是这些差异一路累积出来的结果，2.7% 的偏差就够多出两页。

## 解法

没有解法，只有两条约束：`pagination-<bookId>.json` 是按设备算的，同步过来的表要么整份用要么整份重算（卡片按起点 CFI 在自己的排版里定列，所以整份用也不会错行）；`[p.N]` 芯片和印刷页码在不同设备上指的不是同一页，别把「页码」当跨设备的稳定标识。
