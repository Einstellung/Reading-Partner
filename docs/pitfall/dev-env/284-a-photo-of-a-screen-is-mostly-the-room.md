# 284 屏幕照片里八成是屋子，判不了渲染

## 现象

用户拍 iPad 照片报 EPUB 页「整页正文非常浅，像蒙了一层」，灰底 sidebar 里的字几乎看不见，而页面底部最后一段反而比上面的深。同一本书、同一页、同一份代码（`page-wash.ts`/`page-mount.ts` 自 v0.16.2 起一行没动）在 iPad 模拟器上复现不出来：黑字 `#000000`，纸面 `#f6efdc`，和 PDF 页逐像素相同。

## 原因

照片记录的光大部分是屋里反射到玻璃上的。真实颜色已知（纸 `#f6efdc`、字 `#000000`），按 `obs = a·L + R` 在线性光里解，页面顶部/中部/底部三处的反射项 R 分别占该处纸面亮度的 83% / 80% / 78%——屏幕自己的光只剩两成。反射是加性的，对比度被整体压平，于是「蒙了一层」。

各处照度还不匀：同为 `#f6f1e4` 一档的顶栏在照片里读 114，纸面读 122–177。亮的地方压得最狠看着最蒙，暗的地方看着深，同一页里就排出了一个假的深浅次序——「底部那段更深」是照度差，不是渲染差。

## 解法

判渲染问题只认设备自己的截图（iOS 电源 + 音量上）或模拟器的 `scripts/ios-sim.sh shot`。照片只说明用户看着不对，不能用来定位是哪一层。

非要从一张照片里榨证据，就在同一张图里找两块真实颜色相同的面（顶栏和纸面都在 244 那一档）比读数：差得多就说明照片自身照度不匀，这张图上关于颜色和对比度的结论一律作废。
