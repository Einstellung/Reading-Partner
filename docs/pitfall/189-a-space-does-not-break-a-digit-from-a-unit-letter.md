# 阿拉伯数字后面的单位字母，加空格也拆不开

## 现象

小米 `mimo-v2.5-tts` 把 Intel 的工艺节点名 `18A` 念成「十八安培」。直觉的修法是在中间垫一个空格：`18 A`。实测两次取样照旧念「十八安培」，一次都没躲开。换 `茉莉` 音色更远，念成「十纳米」。

## 原因

TTS 前端的单位识别按 token 走，不按字符间距走：数字 token 后面跟一个单位字母 token 就是量纲，中间有没有空白无关。只要送进去的还是阿拉伯数字，`A` 就是安培。

## 解法

把数字先换成中文数字，`十八 A`。数字不再是数字 token，单位规则就不触发了。两个音色、Qwen 和 SenseVoice 双 ASR 交叉，全部回读成 `18A`，没有一次出现安培。

`normalizeForSpeech` 里不用为此专门加规则：第 17 步本来就把所有数字读成中文，这条只是要求它排在字母数字拆分之后——现在的顺序已经是这样，`tests/info/speech-normalize.test.ts` 里钉了一条测试防止顺序被改回去。

## 对照

同一批实测里，`620N·m`（数字紧跟单位）念成「620 N 米」，`4.8TB/s` 反而念对成「四点八太字节每秒」。所以这不是「凡是数字贴单位都出错」，是逐个单位的查表行为，只能一个个试出来。
