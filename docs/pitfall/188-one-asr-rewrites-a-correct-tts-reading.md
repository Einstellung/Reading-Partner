# 单个 ASR 会把 TTS 念对的词改成更常见的词

## 现象

用 ASR 回读判读小米 TTS 的读音，`风险试产` 在 SenseVoiceSmall 那里稳定写成 `风险市场` / `风险试场`——两个音色、四次取样无一例外。按「能复现就算真读错」的判据，这条差点被记成一条确定性读音错，并为它往词表里加一行。

同一批 wav 换 Qwen3-ASR-1.7B 回读，四条全是 `风险试产`。TTS 从头到尾念的是对的。

## 原因

ASR 的语言模型比声学证据强势。`进入风险市场` 是高频搭配，`进入风险试产` 是半导体行话，`产`(chǎn) 和 `场`(chǎng) 只差一个鼻音韵尾，语言模型直接把它改了过来。同一个词换个上下文（`进入试产阶段`）SenseVoice 就写对，因为那里 `试产` 才是高频的那一边。

复现次数解决不了这个：同一个 ASR 在同一个上下文里每次都朝同一个方向改，看起来正是「确定性读音错」。

## 解法

判读 TTS 读音要两个来源不同的 ASR 交叉，可疑处以两边一致为准，只有一边报错就当没有证据。SiliconFlow 上现成的两个：`FunAudioLLM/SenseVoiceSmall`（免费）和 `Qwen/Qwen3-ASR-1.7B`。

两边的偏向不一样，用法也不一样：SenseVoice 几乎不做逆规范化，把听到的字面写出来（`GPT杠5`、`苏复27`、`主打1000`），适合抓「念出了不该念的字」；Qwen3-ASR 做逆规范化，会把 `苏 负 二十七` 写回 `苏-27`、把 `十八 A` 写成 `18A` 或 `十八埃`，这类地方它的输出问不出念的是什么。所以 SenseVoice 抓「多念了字」，Qwen 抓「改没改字」，谁也不能单独定案。
