# iPad 上选中文字，系统的 Copy 条压在选区下面而不是上面

## 现象

聊天里长按 AI 回复选中一个词，页面自己浮出来的「Ask about this」按钮整个被系统的 `Copy | Look Up | Translate | Search Web | Share…` 条盖住，点它点到的是 Translate，网页连 `pointerdown` 都收不到。

模拟器实测（iPad Pro 11-inch，iOS 26.5，834×1210，安全区 top 32 / bottom 20）：

| 选区 | 系统条 | 原来的按钮 | 重叠 |
|---|---|---|---|
| 563–583 | 598–642（下方） | 591–635 | 横向全宽，纵向 37px |
| 43–63 | 78–122（下方） | 71–115 | 同上 |
| 903–923 | 844–888（上方） | 931–975 | 无 |
| 1083–1103 | 1024–1068（上方） | 1111–1155 | 无 |

按钮只剩顶上 7px 露在外面：点 (214, 594) 能进网页并开侧聊，点按钮正中 (214, 613) 网页的事件序列是空的。

## 原因

「系统条占的是选区上方」这条前提是错的。它占哪边随选区在屏幕上的高度翻转：选区中心在安全区竖向中点（这台机器上是 32 + (1210-32-20)/2 = 611）以上时条在下方，以下时在上方。实测翻转边界落在选区中心 608 和 613 之间。

两种位置下条和选区的间距都是 15px，条自身高 44px，横向以选区中心对齐并夹进屏幕（选区在左边时左缘停在 x=20）。所以它在选中那一侧吃掉的是「离选区 15 到 59」这条 44px 高的带子。

页面无法知道这次翻到了哪边：这条是 UIKit 的视图，浮在 WKWebView 之上，DOM 里没有它，`elementFromPoint` 看不见它，落在它身上的触摸在 webview 收到之前就被拿走。只有辅助功能树能给出它的 frame（`scripts/ios-sim.sh native`）。

## 解法

不去猜它翻到哪边，两边都让。控件放在选区下方，但先空出那条 59px 的带子，再留 8px：`src/ui/components/chat/aside-control.ts` 的 `asideControlAnchor` 把 y 定在 `选区底 + (15 + 44) + 8`。系统条在下方时两者上下并排各自可点，在上方时代价只是选区和控件之间多一段空白。

带子的两个数是量出来的，写成常量并配 `tests/ui/components/aside-control.test.ts`，换机型或换系统版本要重新量（跑法见坑 118 结尾）。

复测（同一台，同样四个高度）：控件落在 650–694 / 130–174 / 990–1034 / 1138–1182，四次都和系统条无交集；点控件正中拿到 `pointerdown → pointerup → click`，侧聊开出来，选区塌缩后控件跟着消失。

顺带两条同一次测出来的事实：拖选区把手时控件跟着新选区重新居中，不会掉；选区塌缩时系统条和控件一起消失。

## 范围

iPad Pro 11-inch (M5) 模拟器，iOS 26.5，Xcode 26.6，macOS 26.5。这个坑属于坑 118 里「模拟器能验」的那半——一根手指、无笔、不看接触面积。真机上要复核的只有系统条本身的尺寸，它跟着系统字号走。
