# 210 夜间批处理挂在多入口的 tick 上，一次启动跑了四遍

## 现象

0.12 真机，一次启动 35 秒内 `dream-run` 事件出现四次：写 10、写 9、写 0、写 0。十条结论落盘两组，一组中文一组英文，内容一一对应。

## 原因

`runDreamIfDue` 的日闸只看状态文件，而状态文件是在一趟跑完之后才写的。`checkDailyRound` 有三个入口（启动、回前台、五分钟定时器），启动那几秒里三个都会打进来，加上定时器一共四次；四次都在第一次落盘之前读到"今天没跑过"，四次都放行。异步函数里"读状态 → 干活 → 写状态"没有进程内的在飞标记，就等于没有闸。

## 解法

两道闸，都在 memory 侧，`src/memory/dream/gate.ts`：

- 进程内在飞标记，`enter()` 在任何 await 之前置位。第二个调用直接返回 false，不排队——排队只是把四次跑推迟成四次跑。
- 进程内当日标记，一趟跑完（merged / no-change / failed 都算）就点亮，状态文件写失败也照样点亮。

多入口的 tick 是常态，把闸放在被调用的那一侧，不要指望调用点去协调。
