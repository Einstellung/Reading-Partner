# 686 只读代码沙盒

soul 和它坐的每张桌子多一个工具 `run_code`：模型写一段 JavaScript，程序在沙盒里调这一回合的读工具、拿回数据、算出结果。合计、计数、筛选、跨几次查询对比这类数，由程序算，模型只写代码（「事实不经模型转手」）。写操作照旧走草稿加确认那几道闸，沙盒里够不着。

## 沙盒里有什么

- `tools.<名字>(args)`：这一回合手上 `effect: "read"` 的工具，参数和直接调用时一样，先按工具自己的 schema 校验，返回的是模型直接调用时会拿到的那段文字（是 JSON 就 `JSON.parse`），图片不带。
- `text()` / `console.log()` 打印，`return` 交回一个值，`ALL_TOOLS` 列出能调的工具和它们的 TypeScript 签名。
- 没有写工具、没有 `run_code` 自己、没有要在 durable 上跑子对话的读工具（研究子代理那种）；没有网络、文件、定时器、`WebAssembly`。点一个不存在的工具，报错里会列出能调的名字。

只有打印和返回的内容回到模型，中间结果不进上下文。回给模型的文字上限 12,000 字符，超了截断并注明总长。一段程序最多调 50 次工具，整段（含工具耗时）60 秒，纯计算另受 QuickJS 中断预算 100,000 次轮询（M 系列笔记本上约 2 秒的死循环），内存 64 MiB。

出错时工具抛错，模型收到的错误结果里有类别（script / timeout / sandbox）、错误名和消息、出错的行号（`codemode.js:<行>`），以及出错前已经打印的内容，改了再跑。每次 `run_code` 调用占回合的一轮，轮数上限照旧管着，不另设次数上限。

## 怎么跑

库是 `@earendil-works/pi-codemode`（MIT），引擎是它依赖的 `quickjs-wasi` 编出来的 `quickjs.wasm`（约 640 KB）。代码在 `src/legion/codemode/`，capability 层，只读 `legion/durable` 的工具契约。

- wasm 和 pdfium 一样自托管：`bun run wasm` 把它从 `node_modules/quickjs-wasi/` 拷到 `public/quickjs/`（不进 git），webview 从 `/quickjs/quickjs.wasm` 取，每个进程编译一次。CI 各打包流程本来就跑 `bun run wasm`。
- 每段程序开一个专用 Web Worker，Worker 里只有 QuickJS 虚拟机（库的 `serveCodemodeRemote`），工具留在页面这边跑（`RemoteCodemodeSandbox`），两边用 postMessage 来回。结果一定下来就 terminate 这个 Worker，所以超时后还在空转的程序也会被掐掉。界面线程不会被算重的程序卡住。
- 没有 Worker 的环境退回在调用线程上跑（`InlineCodemodeSandbox`），这时只有中断预算能停住纯计算，期间调用线程是堵着的。bun 测试里有 Worker，走的也是 Worker 路径。

## 挂在哪

- 普通 soul 回合：`soul/turn.ts` 的 `assembleTurn` 在工具清单定稿后，在末尾加 `run_code`，它能调的是这张桌子上所有来源（soul 自己、角色、surface、各桌面条目）的读工具。会被计价进预算。
- 子代理和 agent worker：`legion/subagent/run.ts` 的 `runSubagent` 给每个跑起来的子代理加 `run_code`，建在已经计数的工具之上，所以程序里查到的东西和直接调用一样算进证据和进度；程序什么都没查到不算证据。语音通话的 `think` 走的就是这条路，它拿到的是送回那张桌子的读工具加 `run_code`。回合内的子对话（`subagentTool`）也一样。
- durable 运行时按名字从进程级目录注册工具、把目录里的描述发给模型，所以 `run_code` 的描述是一段固定文字，不随桌子变，也不重复列各个读工具的声明（模型的工具列表里已经有它们的 schema，沙盒里 `ALL_TOOLS` 再给一遍签名）。描述固定也让缓存前缀不动。目录里登记了一个 `buildCodemodeTool([])`。

模型从工具描述本身知道怎么用，没有往任何 prompt 里加句子。

## 已知限制

- 进程重启后恢复中的回合：各 place 的 desk resolver 那时重新开桌，开出来的工具里没有 `run_code`，恢复期间对它的调用会报「不可用」；下一个正常组装的回合恢复正常。
- 在 Tauri 自定义 scheme 下起模块 Worker、iOS WKWebView 里跑，没有实测；实测过的是 Vite 打出来的 Worker 在 WebKitGTK（xvfb、HTTP 本地服务）里能跑通（`scripts/codemode-probe/run.sh`）。
- 主 checkout 要先跑一次 `bun run wasm` 才有 `public/quickjs/quickjs.wasm`，否则 `run_code` 每次都返回引擎加载失败。
