# 688 有声阅读

2026-11-14 定。上游：[136](../companion/136-混合语音架构.md) 是语音的两层和念原文的那条路，[64](./64-epub纸页.md) 是 iPad 纸页，[79](./79-手机EPUB翻页.md) 是手机翻页，[82](./82-手机阅读外壳.md) 是手机外壳，[89](../companion/89-安卓语音.md) 是安卓的 `:voice` 进程，[33](../info/33-语音简报.md) 是后台与锁屏的调研。

## 范围

只做 EPUB，只做 iOS（iPad、iPhone）和安卓。PDF 和桌面都不做。功能放在 Experiments 里，默认关（见末节）。

## 入口

用户对 Lumen 说「给我读书」「停一下」「下一章」「读快点」，Lumen 调 `read_aloud`。门口打字对话和语音通话都挂它：门口在 `ui/components/companion/door-tools.ts` 的 `doorTools()` 里加一项，语音前台在 `soul/voice/front/tools.ts` 的 `buildFrontTools()` 里加第五个工具（136「前台只有四个工具」随之改成五个）。只有 Experiments 里打开了、且 `hasNativeSpeech()` 为真时才挂。

```ts
read_aloud({
  action: "start" | "pause" | "resume" | "stop" | "next_chapter" | "previous_chapter" | "rate",
  book?: string,   // 只给 start：书名，用户点名了才填
  rate?: number,   // 只给 rate：0.8 / 1.0 / 1.2 / 1.5
})
```

`effect: "write"`、`gate: "instruction"`，和 `cancel` 一样：动作都可撤，触发它的就是用户的明确指令。返回只有一句状态，例如 `Reading "Being You", chapter 3, from sentence 12.`、`Paused at chapter 3, sentence 40.`、`The on-device voice is not downloaded yet: download it in Settings → Optional → Voice output.`（这句取 `plugins/voice/src/tts/kokoro.rs` 的 `NOT_DOWNLOADED`，安卓是 Voice call 那句）。

`start` 选书：给了 `book` 就在书库里按书名找，找不到或不止一本就返回一句说明让 Lumen 去问；没给就取屏幕上开着的书，没开着就取 `readAt` 最新的那本 EPUB。选中的是 PDF 就返回「只能读 EPUB」。从阅读位置（`getViewState(bookId)` 的 `cfi`）所在的那句开始。阅读器没开着时先把书打开到这个位置再读；读起来之后离开阅读器、回书架、锁屏都不停。

通话里调 `start` 或 `resume`：程序先挂断通话，再开读。

## 成本

书的正文不经过模型。取段落、切句、合成、播放全在本机，读书期间没有模型调用。模型只在用户对 Lumen 说话时被调，看到的是一行状态，不是正文。

## Lumen 怎么知道读到哪

有朗读会话（播放中或暂停）时，每回合带一行状态，没有会话就不带：

```
Reading aloud: "Being You", chapter 3 "The Real Problem", sentence 128 of 412, page 57, 00:42:10 played, paused.
```

门口打字对话里，这一行和 `issueDoorTurn` 的 note 一样挂在读者最后一句上（`use-door-chat.ts` 里 `doorTurnNote(...) + issue.note` 那串，经 `noteOnLastLine`），不进 system prompt，前缀缓存不受影响。语音前台里，它是 `FrontContext.place` 的一部分（`soul/voice/front/contract.ts`）。

用户问到要引原文（「刚才那句怎么说的」），用现成的 `read_pages`（`reading/context.ts` 的 `buildReadingTools`）读状态行里那一页。有会话时门口挂上它，`currentFulltext` 是朗读那本书的 `Fulltext`；通话里的 `think`（`reading/turn/door-think.ts`）同样挂上。

## 朗读稿：取段落和切句

新目录 `src/reading/aloud/`（领域层，登记进 `tests/layering.test.ts` 的 LAYER）。朗读稿从 `EpubBook.docs[]`（`reading/epub/file/parse.ts`）逐个 spine 文档生成，用的是摄入树和它的 `DocumentText`（`file/text.ts`），和分页表、标注是同一套偏移，CFI 天然互认。

按块元素走，逐块决定念不念：

- 念：正文段落、列表项、引文块，章节标题（h1–h6）照念。
- 跳过：脚注和尾注（`epub:type` 为 `footnote`/`endnote`/`rearnote`，`role` 为 `doc-footnote`/`doc-endnote`，判法复用 `file/nav.ts` 的 `hasEpubType`），正文里的注释标号（`noteref` 那个 `<a>`/`<sup>` 的字），图（`figure`、`img`、`svg`，连同 `figcaption`），代码块（`pre`）。
- 非线性的 spine 文档（`package.ts` 的 `linear: false`）照念。

每块的原文经 `soul/voice/speech/split.ts` 的 `createSourcedSplitter()` 切句：它吐出的每句带规范化后的 `text`、`chars` 和原文里的 `source` 跨度。跨度加上块在 `DocumentText` 里的起点，就是这句在 spine 文本里的字符偏移；经 `runs` 落到文本节点，`rangeToCfi`（`file/cfi.ts`）出这句的 range CFI。

一句的形状：

```ts
interface AloudSentence {
  spine: number;
  start: number; end: number;   // spine 抽取文本里的偏移
  cfi: string;                  // range CFI，高亮和写位置都用它
  text: string;                 // 规范化后，交给 TTS
  chars: number;
}
```

规范化按书的语言走（`EpubPackage.language`）。`normalizeForSpeech` 是给中文嗓子写的，数字、日期、单位一律改成汉字（见「当前限制」）；英文书要一份不往句子里塞汉字的规范化，放在 `soul/voice/speech/` 旁边，中文书照用现在这份。

章取 `reading/epub/fulltext.ts` 的 `outlineFor()` 的顶层条目；书没有目录就按 spine 文档算章。章标题从同一处取，进状态行和锁屏。

## 两级队列

文本队列和合成队列分开。

文本队列放在原生侧：开读时把从当前句到下一个 spine 文档末尾的句子一次交过去，不少于 2 万字，播到剩不到一半时 webview 再补。整章交过去，是因为锁屏后 webview 的 JS 可能被挂起（待实测），原生侧手里有字才能接着念。

合成队列不用另写：`plugins/voice/src/tts/relay.rs` 按「播放头前面排着多少毫秒音频」放行合成，`prefetch_ms` 6000，Kokoro 的 `max_in_flight` 是 1。交过去的句子在 relay 的待办里排着，真正合成的只有当前句和后面约 6 秒。暂停、跳句、跳章、调速时，已合成没播的音频丢掉，从目标句重新合成。

## 原生朗读会话

`plugins/voice/src/session.rs` 的 `SpeechSession` 一次只持有一轮，且一轮是「模型流出来、一句一句推」的形状。朗读另起一个会话 `plugins/voice/src/aloud.rs`，持有句子表、当前句序号和倍速，底下照用 `SpeechRelay` 和同一个 `Player`。两个会话共用一个播放器，同一时刻只有一个在出声。

命令（登记进 `plugins/voice/build.rs` 的 `COMMANDS` 和 `permissions/default.toml`，TS 侧常量放 `src/reading/aloud/`，照 `ai/voice/kokoro.ts` 的 `KOKORO_COMMANDS` 配一个对 build.rs 的测试）：

| 命令 | |
|---|---|
| `aloud_load { book, sentences, from }` | 换书或补文本队列 |
| `aloud_play { index }` | 从第 index 句开始 |
| `aloud_pause` | 停播放器、丢掉没播的音频，记住当前句 |
| `aloud_resume` | 从记住的那句重新合成 |
| `aloud_rate { rate }` | 改倍速，从当前句重新合成 |
| `aloud_stop` | 清掉会话 |
| `aloud_state` | 当前句、状态、累计时长，webview 回前台时对账用 |

事件 `("voice", "aloud")`：`sentence { index, startsInMs }` 在每句开播前发（和 `envelope` 一样带延迟，不带时间戳），`state { playing, reason }` 在开始、暂停、播完、被中断时发，`need-text { remaining }` 在文本队列过半时发。

## 跟读高亮和自动翻页

句级高亮，没有逐字。收到 `sentence` 事件后等 `startsInMs`，把这句的 range CFI 画出来。

画在 overlay 的新子层 `.rp-aloud` 里，和 `.rp-marks`、`.rp-quote` 各清各的（坑 272）。手机在 `FlowReaderView`（`reading/epub/flow/flow-contract.ts`）上加 `showAloud(cfi: string | null)`，滚动和翻页两种视图（`flow-view.ts`、`paged-view.ts`）各实现；iPad 在 `EpubReaderController`（`reading/epub/paged/reader-view.ts`）上加同名方法。画法照引文：按整个 range 的矩形画，跨屏跨页两边都画；iPad 版心里看不见时按 `showColumnOf` 挪列（64）。

自动翻页：这句的起点不在当前屏（翻页）或不在视口里（滚动）时调 `goToCfi(起点)`，翻页模式的锚点随之更新（79「锚点」）。用户手动翻页或滚动后停止跟随，朗读照常；朗读条上出「回到朗读处」，点了回到当前句并恢复跟随。

## 点句子从那里开始

有朗读会话时（播放或暂停），点正文中间区（不在左右各 28% 的翻页区）落在字上，从这句开始读：`caret.ts` 的 `caretAtPoint` 取 CFI，在句子表里找包含它的句，`aloud_play`。点在空白处照旧开关工具栏。判定顺序照 79：点标注、点链接在前，点句起读在翻页区之后。iPad 纸页在 `EpubReaderPane.tsx` 的点击区里做同一件事。

## 阅读位置与同步

播放位置就是阅读位置，不另开文件。每个 `sentence` 事件调 `keepReadingPosition(bookId, state)`（`reading/reading-position.ts`），`state` 以 `lastReadingPosition(bookId)` 为底，`cfi` 换成这句起点，`pageIndex` 由 `reader-logic.ts` 的 `pageIndexOfCfi` 算，`readAt` 照常盖上。写盘走它自带的半秒防抖，进 `reading-state.json`，随账号同步，和翻页写的是同一条路。

停止跟随期间只写朗读位置，视图报的位置不写；停止朗读后恢复正常。锁屏期间 JS 若被挂起，回前台时用 `aloud_state` 对账再写一次。

## 倍速

四档：0.8、1.0、1.2、1.5。存 `device.json`（`readAloudRate`），不同步。

倍速用 Kokoro 自己的 `speed` 输入，不在播放器里变速。现在 `SpeechRequest`（`tts/backend.rs`）不带速度，`KokoroBackend` 按 `speed_for(script, phonemes)` 自定：中文按 `zh_speed` 随音素长度在 0.88 到 1.1 之间，英文 1.0。加一个 `rate` 字段，和 `speed_for` 相乘。改倍速从当前句重新合成。

## 后台与锁屏

iOS：

- `src-tauri/Info.ios.plist` 加 `UIBackgroundModes = [audio]`（33 里留着没加的那一项）。
- 现在的播放器挂在通话开起来的引擎上（`plugins/voice/ios/Sources/AudioFront.swift` 的 `configureSessionLocked`：`.playAndRecord` + `.voiceChat`，开麦）。朗读加一条只放音的打开路径：`.playback` + `.spokenAudio`，不读 input node，参照同文件的 `openHarnessLocked`，输出接到硬件。
- 锁屏 Now Playing：`MPNowPlayingInfoCenter` 写书名、章标题、已播时长和倍速；`MPRemoteCommandCenter` 接播放、暂停、下一章、上一章，由原生会话直接执行，不等 webview。
- 系统中断（来电、Siri、闹钟）暂停；中断结束带 `shouldResume` 就继续。

安卓：

- `:voice` 进程现在的前台服务只有 `foregroundServiceType="microphone"`（`plugins/voice/android/src/main/AndroidManifest.xml`）。朗读用 `mediaPlayback` 类型的前台服务，不申请麦克风。
- 锁屏和通知栏控制用 `MediaSession`，四个动作同 iOS。
- 文件随「Voice call」那份下载走，过不了 `voice_capability` 内存门槛的机器没有朗读（89）。

## 和语音通话互斥

通话一开始，朗读暂停。原生侧兜底：`start_conversation` 进来时 `aloud.rs` 先暂停自己，再让通话打开引擎。挂断后不自动继续；用户在通话里说「接着读」，前台调 `read_aloud(resume)`，程序挂断后继续。

## 界面

阅读器外壳上一条朗读条：暂停/继续、倍速、停止，停止跟随时多一个「回到朗读处」。手机挂在 82 的外壳上，iPad 挂在 EPUB 阅读器顶栏。形态先出原型给用户看，点头再写。

## 引擎与当前限制

端上 Kokoro，iOS 和安卓同一个 Rust 引擎：iOS 在 app 进程里跑（`KokoroVoice::on_disk`），安卓在 `:voice` 进程里跑（`KokoroVoice::remote`，经 `engine_link`）。模型是 `onnx-community/Kokoro-82M-v1.1-zh-ONNX` 的 fp32（`model.onnx`，339 MB），fp16 在 iOS 上出 NaN（坑 655）。A16 iPad 上 4 线程 RTF 0.45。

读代码得出的限制：

- 只有两个声音，都是常量：`zf_001` 念中文，`af_maple` 念英文（`tts/kokoro.rs` 的 `VOICE`、`EN_VOICE`），下载包里也只有这两个（`kokoro-onnx/src/manifest.rs` 的 `VOICES`）。不能选声音。
- 每句按文字选前端（`script_of`）：含任何汉字走中文前端和 `zf_001`；不含汉字、含 ASCII 字母或数字走英文前端和 `af_maple`；其余（纯假名、韩文、西里尔、希腊文）落到中文前端，读不了的丢掉，整句无声。实际只能念中文和英文。
- 中文书：汉字句全由 `zf_001` 念，句中夹的英文词由中文前端交给英文 G2P，仍是 `zf_001` 的嗓音；书里整句英文（英文引文、参考文献）换成 `af_maple`，同一段里会换嗓。
- 英文书：`normalizeForSpeech` 把数字、日期、百分号、单位改成汉字，英文句子里一出现数字就含了汉字，整句被判成中文、由 `zf_001` 用中文前端念。所以英文书必须换上按语言走的规范化（见「朗读稿」）才能用。
- 桌面没有声音：`kokoro` feature 只在 iOS 打开，安卓走 `:voice` 的链接。

## Experiments

设置里新增一页 Experiments，放没完善的功能。上架版默认只露出阅读，别的功能以后逐个挪进来；有声阅读是第一个条目。

登记表 `src/platform/experiments/registry.ts`（平台层，新目录登记进 LAYER）：

```ts
interface Experiment {
  id: string;                          // "read-aloud"
  name: string;                        // i18n 键，settings.experiments.readAloud.name
  summary: string;                     // i18n 键，一句话说明
```

设置页：`ui/components/SettingsView.tsx` 的 `TABS` 加第五个 `experiments`，新面板 `settings/ExperimentsPanel.tsx`，按当前平台过滤登记表，每条一个 `Switch` 加一行说明，卡片样式照 `OptionalPanel.tsx` 里 Meals 那张。这台机器上一条都没有就不出这个页签。`SettingsBody` 两种形态（设置页和手机的 `SettingsDialog`）共用这一份。

功能侧只认 `experimentOn(id)`：有声阅读在挂 `read_aloud`、带状态行、出朗读条之前都查它。开着的实验被关掉时，正在进行的会话停掉。

## 待实测

- 锁屏后 WKWebView 的 JS 还跑不跑、跑多久：决定 `sentence` 事件能不能实时写位置，还是只能回前台对账。
- 后台内存：339 MB 的模型在 app 进程里，33 记的 DTS 指导值是后台常驻 100 MB 以下。锁屏连读一小时会不会被系统杀，iPhone 和 iPad 各量一次。
- 连读一小时的发热和耗电，iPhone 上的 RTF（只量过 A16 iPad）。
- 0.8 和 1.5 两档在中文和英文上听着清不清楚。
- 中文前端在长篇正文上的多音字和断词质量；中英混排的书里换嗓听着能不能接受。
- 英文前端（misaki）自己会不会念数字、日期，决定英文规范化要做多少。
- 高亮和声音对不对得上：`startsInMs` 已减掉输出延迟（`conversation.ts` 的 `SpeechEnvelope`），在只放音的引擎上要重新确认。
- iOS 只放音的引擎和通话引擎来回切（朗读暂停、开通话、挂断、继续）会不会撞上坑 162 那类路由问题。
- 安卓 `mediaPlayback` 前台服务和 `:voice` 现有的 `microphone` 服务能不能共存于一个进程，通话开始时怎么切。

## 实现切片

每片独立合并、各自有测试。

1. Experiments 机制。登记表、`device.json` 字段、`experimentOn`/`setExperiment`、ExperimentsPanel 和第五个页签，第一条登记 read-aloud（开关先不接任何功能）。按平台过滤写在登记表的 `.ts` 里。单测：登记表 id 唯一、i18n 键都有文案、按平台过滤、设备存储读写和未知 id 保留。Linux 上验，不开窗口用 xvfb。
2. 朗读稿。`src/reading/aloud/script.ts`：spine 文档到句子表（跳过规则、range CFI、章）和按语言走的规范化。纯 `.ts`，用 `tests/reading/epub/fixture.ts` 的书测：脚注和图被跳过、章标题在、每句 CFI 解回来的字和原文相同、英文句子规范化后不含汉字。
3. 原生朗读会话。`aloud.rs`、七个命令、`aloud` 事件、`SpeechRequest.rate`。Linux 上用替身后端和 `VirtualPlayer` 测：暂停后从同一句续、调速从当前句重来、`need-text` 在过半时发、`start_conversation` 进来先暂停。
4. iOS 放音路径。`AudioFront.swift` 的只放音打开、`UIBackgroundModes`、Now Playing、远程命令、中断处理。CI 编 Swift（`ios-simulator-smoke.yml`），真机验：锁屏连读、锁屏上暂停继续和跳章、来电中断。
5. 安卓放音路径。`mediaPlayback` 前台服务、`MediaSession`、不开麦的播放。真机验，项目同 4。
