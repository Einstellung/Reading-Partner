# 删除一本书

> 2026-09-05 定案。同步引擎的删除模型在 [13](./13-账户同步.md)，文件级删除过不了同步的实测在坑 [208](./pitfall/208-file-deletion-does-not-survive-sync.md)，两个记忆仓在 [48](./48-记忆：观察与statement.md)。

---

## 删什么留什么

划分标准是数据关于书还是关于人。

关于书的随书删：PDF 本体和 library 条目、阅读位置、批注、聊天线程、章节备课材料 `prep-<bookId>/`、全文和图表缓存、复述与排练。

关于人的留下：statement 一律不动。

观察介于两者之间。按 bookId 挑出这本书的观察写观察墓碑，被任何 statement 的 `evidence` 或 `contradictedBy` 引用的观察跳过不删——它们是 statement 的证据链，dream 靠它核对和 supersede。留下来的那些观察的消息锚点会悬空，接受：锚点只是"点回去"，dream 和检索用的是正文和日期。

topic 不等于书。一个 topic 装几本书，一本书可以在多个 topic 里，观察按 topic 存目录、每条带 bookId。所以"删一本书"对观察是在目录里按 bookId 挑，不是删目录。

## 载体

`deleted-books.jsonl`，AppData 根目录，在同步范围内，一行 `{"bookId":"<内容 hash>","at":"YYYY-MM-DD"}`，走 `records` 策略的 lines 形状取并集。

按书不按路径：身份是内容 hash，两台设备删同一本写出同样的字节；派生路径全部由 bookId 算得出来；语义是"这本书没了"而不是"这个路径没了"。

## 引擎

reconcile 之前读一次墓碑，把 bookId 展开成 `annotations-`、`threads-`、`prep-<hash>/` 这些路径。命中的路径不下载、不上传、不合并，删远端也删本地。本地删之前记进 `sync-trash.jsonl`（只在本机，留 30 天）。

Drive 上的 PDF blob 也删。留着的话，退出登录再登录、snapshot 清空的设备会把整本书拉回来。

purge 队列只删远端，管不了别的设备的本地副本。所以载体必须是一条会同步的记录，每台设备各自执行一次。

## 领域侧顺序

`deleteBook(bookId)`：

1. 写墓碑。
2. 删 `library.json` 和 `reading-state.json` 里的条目。
3. 从每个 topic 的 `files` 里摘掉引用。
4. 观察按 bookId 写观察墓碑，跳过被 statement 引用的。
5. 复述、排练、讲稿走各自 store 的删除，并接 `requestRemotePurge`。
6. 删本地派生文件和 `library/<hash>.pdf`。

前三步是记录级删除，本来就传播；墓碑管的是文件级那几类和幂等。

顺带修：复述、排练、讲稿的删除今天删的是同步范围内的文件，却没接 `requestRemotePurge`，删了会回来。接上。

## 冲突与老客户端

离线一周的设备回来把批注以更高 rev 推上去，别的设备这一趟判 dead 再 purge 一次，它自己同一趟拉到墓碑也删本地，一个来回收敛。那一周的编辑没了，这就是删除的含义，`sync-trash.jsonl` 是唯一的回头路。

老版本客户端不认识这个文件，会继续持有并推回被删的书，直到升级。观察墓碑当初也一样，接受。

## 不做的

- 墓碑压缩和过期。和观察墓碑一样只增不减，一行约 60 字节，条数被删过的书的数量限住。真要做，判据是"比最老那台设备的 lastSyncAt 还老"，需要各设备的心跳文件，今天没有。
- 删 topic。今天 `deleteTopic` 只删 `topics.json` 一行；statement 定日期是遍历 topic 找观察的，topic 记录一删那批观察就不可见，根因是观察按 topic 分目录。顺序是：删书 → 观察目录摊平成属性 → 删 topic 变成"删里面每本书加一条删记录"。
- 给读者一个"连这本书留下的印象一起删"的选项，把只以这本书为证据的 statement 一并标掉。statement 是关于人的，默认不做；将来要做也是显式的第二档。
