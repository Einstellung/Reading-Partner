# 引文展示

2026-08-20。

语法不变：`[p.N]` 指路，`[p.N "书上原话"]` 带引文，`src/reading/prep/anchors.ts` 零改动。变的是显示。

带引文的引用自成一段时，整段渲染成引文块——书上原话直接显示，出处标记跟在后面，整块可点，点击跳页并高亮那句。不带引文的还是行内小 chip。判据是有没有引文，不是 lesson 还是 mark 模式；模式差别只体现在提示词里引多引少。

夹在句子中间的带引文引用退化成行内 chip，不劈开句子。提示词那边要求引文自成一段，并写明夹在句子里的代价是原文显示不出来。

渲染前对全文校验（`quote-locate.ts` 的 `locateQuote`）：这一页找不到这句话就退回行内 chip。显示成"书里的原话"而书里没有这句，比高亮静悄悄失败糟得多。取不到页文本（提取还没跑完、页码越界）按放行处理，和 `KnownSlugs` 为 null 时按形状放行是同一个判断。论文引用没有全文可查，不校验。

`[fig:N]` 不动，它早就是这个做法：模型行内写，渲染成自己一行的图卡。

改的理由：原来 quote 从可见文字里剥掉，只当跳页后高亮的载荷，注释里的理由是"和上文重复，不该读两遍"。那条理由的前提是读者读过书、chip 只是回原处的按钮。lesson 前提改成读者一页没读（[09](./09-学习机模式.md)）之后前提没了，引文成了读者唯一能看到的书。实际回复里一句话出现两个一模一样的 `p.72`，读者连它们指的是不是同一句都分不出来。
