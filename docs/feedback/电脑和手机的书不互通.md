# 电脑和手机的书不互通

> 2026-09-29 收到。桌面 0.22.x，手机是 Android（截图状态栏），同一个 Google 账户同步。

## 用户看到的

- 桌面更新完，书架上少了几本书。
- 手机书架上桌面导入的书是灰卡（只有首字，没有封面），用户说看不了。
- 手机上重新导入同一本 EPUB 后，原主题里桌面导入的那本也有了封面，但删不掉。
- 手机导入的书在桌面上是灰卡，书名显示 `document:2905a…`，点开报「打不开这个文件——可能已被移动或删除」。

## 原因

以下来自读代码，没拿用户设备上的数据核对。

**名字和桌面打不开。** Android 的文件选择器返回 `content://…/document%3A2905a`，末段不是文件名，名字就成了 `document:2905a`。这条 URI 作为路径进了 topics.json。桌面库里没有这本书时回退去读这条路径，必然失败。

**手机传不上去就永远传不上去。** 手机的 books 通道是 off，导入只调一次 `pushBook`，失败或当时没登录都不补传。topics.json 和 library.json 照常同步，桌面于是显示一行永远打不开的书。

**手机删不掉。** 同一本书（同一内容哈希）挂在两个主题里时，手机长按只给「从主题移除」。移除只删 topics.json 里的一行，不留删除记录。topics.json 按整个主题合并，两边都改过同一个主题（桌面每次打开书都写 `lastOpenedAt`）时整条主题二选一，被删的行可以回来。

**桌面丢书**，两个嫌疑最大：

1. 0.22.0 起书架读取和启动时的 `settleDeletions` 都按 `deleted-books.jsonl` 执行，而 revive 事件也是 0.22.0 才有。0.21 时代删过、后来又加回来的书，日志里只有删除，升级后被当成已删：各设备的库条目、blob、topics 行被清掉，桌面 pass 从 Drive 硬删 blob。
2. topics.json 同一个主题两边都改过时整条二选一（`chooseByContent`），输的一边新加的书从主题里掉出去，库里还在，书架上看不到。0.22 的手机频繁写主题（关书写打开时间、导入、长按删除），比以前容易撞。0.22.0 合并 Drive 上同名副本（29e03dd）时对 topics.json 也是无 base 合并，同样整条二选一。

次要的：手机按本机那份 topics.json 数引用决定删不删书，本机那份落后时会把桌面另一个主题里的同一本书连带删掉；手机删主题不勾「连书一起删」时，只在那个主题里的桌面书留在库里但不在任何主题下。

查证要看的：桌面的 `deleted-books.jsonl`（`at` 只有日期、之后没有 revive 的书），两台设备 `sync-trash.jsonl` 里 `path` 为 `topics.json` 的条目，`sync-base/topics.json`、`sync-base/library.json`，以及 Drive 上 `data/topics.json` 的历史版本。

## 当场修了的

分支 `fix/cross-device-books`：

- 桌面打开库里没有的书，原路径读不到且有 book id 时当场从账户下载；账户也没有才报「可能还没下载完成」（`reading/session/open-file.ts`）。
- 手机 books 通道改为只上不下（`upload`）：每趟 pass 补传本机有、远端没有的书，不下载、不删远端 blob（`platform/sync/engine.ts`，docs/13）。
- 路径是 `file://` 以外的 URL 时，书名取 EPUB 的 `dc:title`（`reading/session/import-book.ts`，坑 490）。已经以 `document:…` 落盘的行不自愈。

## 留给统一设计的

删除、归属和合并粒度是一个设计问题，不零散修：

- ~~「书在哪个主题」这一关系要成为能单独合并、删除留痕的单位，而不是整条主题记录的一部分。~~ 2026-10-09 做了，见 [docs/59 §11](../platform/59-同步：持有清单与裁决.md)：`topics.json` 改走 `topics` 策略，topic 的字段逐个合并、书单按 hash 逐条三方，`lastOpenedAt` 不再让书单整条二选一；从 topic 摘书在 `deleted-books.jsonl` 记 `topic-file` 事件，无 base 合并和 0.22 客户端带回来的行按日志滤掉。混版期老设备自己合并时仍整条二选一。
- ~~删除按内容哈希全局生效，和「只从这个主题拿掉」要分清；删之前按哪份视图数引用要定。~~ 2026-10-09 定一本书只在一个主题（[docs/59 §11](../platform/59-同步：持有清单与裁决.md)「一本书只在一个 topic」）：同一本书不再挂在两个主题里，从主题拿掉就是删书，只有它还被别的书列为辅助资料时才只摘行。引用仍按本机视图数。
- 0.21 时代没有 revive 的旧删除记录：定了不处理，升级不做迁移。
- 被合并丢掉的主题版本目前只在本机 `sync-trash.jsonl` 留 30 天：定了不做找回入口。
