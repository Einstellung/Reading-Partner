## 两层

一通语音电话分两层。

前台负责听、接话、附和、判轮次、闲聊，不开思考。它自己答得了的就当场答，两句以内。答不了的——要查、要算、要多步推理、拿不准的事实、超过三句话才说得清的——先说一句「我去想想」「我查一下」，调 `delegate` 交给后台，然后接着陪用户聊。

后台是 legion 的一个 run，跑在对话档的思考模型上。跑完原文落进 Red Box 和这通电话所属的那条对话。用户还在通话，前台在下一个空档说一句「刚才那个想好了，要我念还是你自己看」；已经挂断，就只落盒。

前台可换，后台可换，交接口不认供应商。后台随设置里的默认供应商和对话档走，换 Claude 还是 ChatGPT 就是换设置。前台至少容纳两种：

- 级联前台：端上 VAD 和 Smart Turn 判停，`SpeechAnalyzer` 转写，快模型不开思考，流式 TTS 出声。
- 托管前台：qwen3.8-omni-flash-realtime 这一类全双工模型，轮次在云端判，音频进、音频出。

两种前台下面共用一个音频前端，上面共用后台交接、落盒、念出来这一半。

## 音频前端（共用）

全在原生侧，两种前台都经过它。VPIO 回声消除、神经 VAD（Silero v6 和 FireRedVAD 二选一，选型见调研）、只喂判定支路的降噪（GTCRN）、声纹门（CAM++）、打断规则、播放器。打断规则照调研结论二第 4 条：播放期抬阈值，连续人声至少 0.5 s，先暂停不停止，2 s 内没出字从断点续播，转写够三四个字且不在附和词表里才算打断。

前端对上交两样：过了声纹门的音频帧，和 `speech-start` / `duck` / `stop` / `resume` / `end` 事件。声纹不像本人的那段不送 ASR、不送托管前台（送等长静音保住时间轴）、不触发打断。

本地 `SpeechAnalyzer` 两种前台下都跑：打断规则要字数，对话记录里用户那一侧的文字也取它，两种前台的记录因此同形。

播放和打断的权威在本地。托管前台能关掉云端自动打断的就关掉，打断由本地规则判定后通知前台取消；关不掉的列在待定。

判停（Smart Turn、`hangoverMs`）不在这一层，属于级联前台：托管前台的轮次在云端判。

## 前台接口

前台是 soul 装上的一个角色 `voice-front`（71：一段职责、一份工具清单、一道写入闸）。写入闸是没有写入：前台只有 `delegate`、`cancel`、`read_out`、`show` 四个工具，副作用只有派工和取消，都可撤。

```ts
interface VoiceFront {
  readonly id: string;                      // "cascade"、"hosted-omni" 这类
  readonly turnTaking: "local" | "remote";  // 谁判轮次
  readonly speech: "tts" | "native";        // 用我们的 TTS 出声，还是它自己出音频
  open(call: FrontCall): Promise<void>;
  notify(note: FrontNote): void;            // 后台回来了、失败了；前台在下一个空档说一句
  interrupt(heard: HeardUpTo): void;        // 本地前端判定的打断，带用户听到的句位
  hold(on: boolean): void;                  // 念原文期间前台闭嘴，念完或被打断后交回
  close(): Promise<void>;
}

interface FrontCall {
  prompt: string;                   // 短提示，固定前缀，走 prompt cache
  context(): FrontContext;          // 每轮现取：最近几轮、编号清单
  tools: AgentTool[];               // delegate、cancel、read_out、show
  audio: GatedAudio;                // 音频前端过了门的帧和事件
  record(line: CallLine): void;     // 写进这通电话所属的对话文件
}
```

工具定义用现有的 `AgentTool`（TypeBox 的 JSON schema）。托管前台的适配器把它翻成那家的 function 格式，工具名和参数原样，执行在本机。

托管前台的连接放 Rust 侧，和 TTS 同一处：音频帧在 Swift 和 Rust 之间走，不经 webview；转写和工具调用作为事件交给 webview 执行。

## 前台的上下文与模型

不开思考，不挂别的工具，一次调用。上下文封顶约 4k token，按固定在前的顺序排：

1. 职责（约 600 token）：用读者的语言，答得了两句内答完；答不了先说一句再派；不编事实；不转述后台的内容；附和只用一两个字。
2. 所在地方的摘要：简报页是当天各研究室的标题，书是书名和当前章节标题，约 400 token。
3. 编号清单：这通电话派出的 run（编号、任务一句、状态、`progress` 那一行、回来的就带封面）和盒里没开的项的封面，最多十行，程序生成。
4. 这通电话最近十轮，约 2k token。念过的结果全文在里面，没念过的只有封面。

用户问「好了没」，前台读清单里的 `progress` 回答，不调工具。

级联前台用前台模型槽，存模型和思考档位两样（`voiceFrontModelId`、`voiceFrontThinking`），和两档模型一起存 `device.json`。模型为 null 时跟对话档的模型；思考默认关，可选 low，供应商关不掉思考时取它的最低档。默认值由一期实测定：同一模型关思考和 low 各跑一遍，比首响和交接判断的准确率。托管前台的模型和凭据由适配器自己带，和 TTS 的 key 一样是语音设置里的一项。

前台回合不进 durable 库：一次短调用，不排在 `quiet()` 后面等这条对话上别的回合；进程被杀丢的是一句闲聊。对话照写归属文件。

级联前台的一次回复可以同时带一句话和一个 `delegate` 调用。话先出，调用执行完不再回喂模型续写，回合就此结束。回复里只有调用没有话时，程序播一句预合成的「我去想想」。

## delegate

就是 soul 现有的 `delegate`（`src/soul/delegate.ts`，68 第 3 片），前台挂同一个，多两个可选参数：

| 参数 | |
|---|---|
| `kind` | kind 目录里的一个。语音里通常是 `think` |
| `task` | 任务书，写给看不见这通电话的人：要回答什么、答到什么程度算答上 |
| `follows` | 可选，清单里的编号。接着某个任务往下想时用，工具把那次的任务书和已回的产出挂进新任务书；那个任务照跑 |
| `replaces` | 可选，清单里的编号。只在用户改口时用：那个任务还在跑就取消 |

返回编号或拒绝原因。`deliverTo` 由程序按电话所在的地方填，模型不给：今天是简报页（`{ place: "briefing", date }`），将来书里开电话就是那本书那条线程。

kind `think` 由 soul 登记：agent worker、`local` 档、`delegable`。身体是坐在 `deliverTo` 那张桌前的 soul，带那张桌的只读工具加 `web_search`、`read_page`，没有写入工具（27「语音里没有确认卡」）。模型是对话档，思考档读 `chatThinking`：派的时候用户在电话里等着。产出为朗读写：第一句是结论，150 到 600 字，不用表格和代码块，列表最多一层。现有的 `research-literature`、`tasking` 照样能派。

交接之后前台说的那一句不承诺时间、不复述问题、不报进度，然后回到用户身上。等待期间前台不主动找话说。

## 并行、取消、改口

一通电话可以同时有几个 run，每个是独立的 run，没有 `idempotencyKey`。在飞的上限三个，第四个前台直接说先等一个回来。

用户说「算了」，前台调 `cancel(编号)`，走 runner 的取消，run 进 `cancelled`，不进盒、不落对话。

新问题一律另派，不顶替在飞的。改口按 55「任务书发出即冻结」：派新的，带 `replaces` 指向旧编号，程序取消旧的；新任务书写全，不写「同上」。只有 `replaces` 会取消任务。

追问一个已回的结果：念过的全文在前台上下文里，答得了就当场答；要再想就派新 run，带 `follows`。

挂断不取消任何 run。结果照落对话和盒，等用户回来看。

## 回来

`think` 的 `run-done` 不起答铃回合。答铃时程序把产出原文作为 soul 的一条回复追加进 `deliverTo` 那条对话，再往盒里放一项；`think` 登记时声明这种投递法，其余 kind 照旧起回合。`run-failed` 照 55 放一项标「要你定」。

通话还开着，程序给前台一条 note（编号、任务一句、封面或失败原因）。前台在下一个空档说一句：自己没在说、用户没在说、上一轮结束超过 2 s。用户一直在说就一直等。这句的请求被用户开口掐掉，留到下一个空档再说。两个结果同时到，一句话说完。没挂断就不再提第二遍。

Lumen 照 66：前台空闲而有 run 在飞时演「查」那一段，盒子到了往盒子瞟一眼。

## 落盒

通话里派出去的 run，结果一律放盒，通话不算「正看着」：在电话里听见一句通知不等于读到了原文。项的字段照 68：`source` 取 `run`，`body` 是产出原文，`origin` 是电话所在的地方。

用户说「念」，前台调 `read_out(编号)`；说「我自己看」，调 `show(编号)`，屏幕上打开那张卡跳到原地，电话不断。念完或打开记 `told`（60 的 `told` 本来就是「讲过了」）。念到一半被打断不记，项留在盒里，「接着念」从被打断那句开始。挂断时没念没看的，留 `in box`。

前台自己答的话只进对话，不进盒。

## 文本检查点

后台的原文存三处，是同一份：`legion/outputs/<runId>.md`、盒项的 `body`、对话里 soul 那条回复。

念的是原文：`read_out` 绕过前台模型，原文经 `normalizeForSpeech` 和切句器直接进我们自己的 TTS，两种前台都一样。念的期间前台 `hold`，托管前台不收音频；本地判定打断后把从起声起缓存的那段音频补送给前台，由它接话。用户要短的，念第一段。

前台不转述后台的内容。级联前台的话是文本先于音频；托管前台的文字是它音频的转写，只当记录。前台说的话不承载后台内容，这个差别不影响检查点。

被打断的那句照 33「打断留下什么」按句存原文。

## 附和

托管前台自带的附和照用。级联前台在用户长段落里停顿、Smart Turn 判未完、停顿超过 1.5 s 时，播一个预合成的「嗯」「对」。片段和开场句一样预合成在本地，不经模型。

## 分期

每期都在 iPad 上验，iPhone 顺带。

一期，后台一半加级联前台换快档。`think` 登记和原文投递、通话里的落盒规则、`voice-front` 角色和短上下文、四个工具、前台回合出 durable、前台模型槽、TTS 首帧开播。iPad 上验：闲聊两轮的首响（`turn-log.jsonl` 的 `first-byte` 和原生 `RP-CALL` 对上时钟），问一个难题一秒半内听到「我去想想」并且还能接着聊，结果落盒、前台告知、念和看都通，挂断后再回来只在盒里，「算了」取消得掉。顺带答 33 欠的两条：iPad 上 `SpeechTranscriber.isAvailable`，iPad 外放的回声泄漏窗。

二期，音频前端。神经 VAD 选型、Smart Turn、判定支路降噪、声纹门、打断规则、耳机路由切策略、附和片段。iPad 上用调研那套录音脚本（安静 / 背景人声 / 街噪 × 中文 / 英文 / 中英混，每格 20 回合）量首响 p50/p90、误打断率、该停不停率。

三期，托管前台。qwen3.8-omni-flash-realtime 的适配器，后台一半不动。同一套脚本和二期的级联前台比三个数，再看托管前台调 `delegate` 前那句话自不自然、关不关得掉云端打断。两个数都不比级联好就只留级联。

## 待定

- `think` 走对话档还是日常档。本文按「派的时候用户在等」定对话档，挂断之后仍按对话档跑完。
- 托管前台的云端自动打断能不能关，qwen3.8-omni-flash-realtime 要实测。
- 托管前台的计费和 key 放在哪个设置面。
- 在飞上限三个、空档 2 s、附和停顿 1.5 s 都是起步值，二期按录音调。
- 书里开电话：今天只有简报页有语音，书里开时 `deliverTo` 是那条线程，68 对书的「正看着」规则要不要一并按本文改。
- 33 的岔路口（锁屏后电话继不继续）不变，定成继续时挂断的判据要改成「会话结束」而不是「app 离开前台」。
