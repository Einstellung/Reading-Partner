# 桌宠的名字与自我介绍

> 2026-10-21 定。产品改名 Reading Partner → Lumen，角落里的桌宠让出这个名字，改成用户可设的名字，默认 Kris。本文是四步里的第一步，只做加法：目录、标识符、i18n key、产品名和界面上现有的「Lumen」字样都不动，后面的步骤再换。上游：[66](./66-Lumen.md) 的边界，[71](../soul/71-soul.md) 的 places 与角色，[136](./136-混合语音架构.md) 的前台。

## 名字

`settings.json` 里的 `companionName`，跟账号走、随同步（同 `meals`），不进 `device.json`。空串或全是空白就是默认名 Kris（`DEFAULT_COMPANION_NAME`）。读它一律经 `companionNameOf(settings)`：空白折成一个空格、去头尾、按字符截到 24 个、不是字符串的当没设。同步按 `fields` 策略单键合并，不需要字段组。设置界面上的输入框这一步没做。

## 自我介绍块

`src/soul/intro.ts` 的 `introBlock`，由 `soul/turn.ts` 拼在每个回合 system prompt 的最前面，在角色职责之前，所以门口、书、简报、复述、排练的对话都带它。内容是：名字；它是 Lumen app 里的那个伙伴，住在每一屏的角落；边界；被问「你是谁、你会什么」时报自己的名字，只说下面列出来的，没列的就说这个 app 没有。

「会什么」不手写，从两处现成的东西生成：外壳登记的 places（`desk/places.ts`，每个地方一行 `id: about`），和这一回合伙伴自己的工具（角色的、soul 的、门口那种 surface 带的，每个一行 `名字: 描述第一句`）。桌上那样东西带来的工具由它自己的 prompt 讲，不进这里。外壳加一个屏、soul 多挂一个工具，介绍自动跟着变。

同样的名字、外壳和工具清单产出同样的字节，介绍块在 prompt 开头，缓存前缀因此在一次对话里不动（见坑 663）。代价是锚定阅读桌的 prompt 不再从书的那段开始：现在是介绍块加一个空行，后面才是 docs/09 钉住的那段，那段本身仍逐字不变。

## 边界

照 [66](./66-Lumen.md)：不演想念、孤独、亲密，不提「多久没来」；它是读书、分析和处理用户材料的工具，不是人。这几句写在介绍块和语音前台里。

## 语音前台

前台走另一条 prompt 链（`soul/voice/front/context.ts`）。`frontIdentity(name)` 是口语版的身份：名字、是什么、边界、被问时一句话报名，「会什么」只说下面职责允许的，不列清单。它和 `FRONT_DUTY` 一起组成固定前缀（`frontFixedPrompt`），排在 place 和清单之前；名字在开通话时从设置读一次，改名下一通生效。

## 其他人设句

和名字冲突的「你是……」改掉了：阅读 prompt 的「You are a reading companion embedded in a PDF reader」改成「Here you sit beside the user inside a PDF reader」；秘书职责改成「Here you are going through the user's daily briefing with them」；每日简报开场白（`info/issue/opening-record.ts`）的「You are Lumen」改成由调用方传入名字；加源引导里「介绍自己是阅读伙伴」改成「报自己的名字」。不面对用户的备课、讲义、蒸馏提示词里的「reading companion」不动。

## 没做的

设置界面的输入框；界面文案里的 Lumen/卢明换成名字；本地 TTS 对自定义名字的读音（Kokoro 前端的中文走 jieba+pypinyin，多音字可能读错；英文名夹在中文里走英文词表，不在词表里的专名按字母拼读，非 ASCII 的拉丁字母会被丢掉）。`plugins/voice` 里「我是卢明」那句只是 G2P 的金标语料，没改。
