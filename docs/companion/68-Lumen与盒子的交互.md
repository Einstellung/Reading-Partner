## 不推送与回原地

run 完成不打断用户，不弹窗、不红点、不进任何系统通知。60 的推论 4 照旧。

回复写回提问的地方。run 带 `deliverTo`，记的是它从哪儿派出来的：某本书的某条线程（划线线程带 annotationId，也可能是书的总线程），或门口。铃响时 soul 的答铃回合按那个地方装配——是书就按阅读桌装配，桌上有那本书；是门口就按门口装配——然后把回复追加进那条对话。用户下次翻回那页、点开那条划线，答案就在那里。

答完之后由程序层（60 的 Staff Secretary，不用模型）往 Red Box 里放一项，指回那条对话。失败或拿不准的 run 放进去时标「要你定」，这一类 soul 可以在门口主动说一句；其余沉默。回复落地时用户正看着那条线程（在那本书里、开着那条线程的通话）就不放，成功失败都不放——理由和下一段同一条：人已经读到了。门口和简报没有「正看着」这回事，照放。

用户自己问的那一轮同理。turn 发出去之后只有停止按钮和删除线程能掐断它，关掉聊天、点书页、合上书、退出阅读器都不打断（docs/03）。回答落地时那条线程不在屏幕上——视图关了、开着别的线程、或者人已经离开这本书——就放一项：`source` 取 `turn`，`boxId` 取线程 id 加时间戳，封面是回答第一句（和铃那边同一个 `coverOf`），`origin` 指回书和线程，摁一下跳回去。落地时人正看着这条线程就不放。这一轮失败了又没人看见，放一项标「要你定」，封面是错误本身——线程里什么都没留下，这项是它唯一的痕迹。

## 盒

盒泛化，不再是 info 私有。一个盒是一个 batch，一项是一条 cable 或一个 run 的产出。研究 run 就是一盒一项；`local` 档的 run 不带 `batchId`，`boxId` 取 run 的 id。

文件形态沿用 60：一项一个文件，生在 palace 里，随账户同步；封面写一次不改；状态在项自己那份文件上，没有第二个可变文件。状态表也沿用 60 那张：`in box` / `told` / `asked` / `dismissed` / `saved` / `promoted` / `folded` / `aggregated`。跳转到原地就是 `told`，摁掉就是 `dismissed`。`told` 之后对秘书仍算 open。徽标数的是本机能显示的 open 项（`lumen/box-cards.ts` 的 `cardsHere`），也就是对话窗里会出现的那些卡，不另记「看过」（2026-10-15 实现时定）。

## Lumen 作为入口

卢明身上会承载越来越多的东西，角落只当一个入口：各种内容都放进卢明的对话窗，靠聊天卡片（卡片注册表）扩展，角上不另长控件（2026-10-15 改）。

Lumen 全局常驻：每个外壳每个地方的右下角都有，72 px，就是今天 info 简报角上的那个位置。门那一层放大的不变。全窗聊天里输入条占着下边缘，角就抬到输入条上面——按输入条量出来的盒子抬（含安全区），不是估一个高度。只有按住说话的那一下让开：落点面板铺满输入条宽度，右边那个「Edit」正压在角下面。

盒子是角上独立的一层，不在 Lumen 手里：一个竖放的红色公文盒（英国大臣的 dispatch box 那种，红色哑光皮面、盒盖在上、正中一个铜扣，没有花押也没有文字；柔光 2.5D 和 Lumen 一致，但它自己不发光），站在 Lumen 左边、同一个光池里，和身体一起生成再抠出来（`docs/assets/lumen/lumen-with-case.png`），比例照那张图量：72 px 的角上盒子约 24×25 px，是圆身子（约 45×44 px）的六成高，右边缘压在身体左侧轮廓里，两个底边齐平，盒子左边探出身体方框约 5 px。第一项到了，Lumen 从身后把盒子取出来放在身边；盒子空了它把盒子放回身后，角上只剩 Lumen。手机宽度上 72 加 40 加间距不到 130 px。Lumen 的身体位图和 SVG 眼嘴不为盒子改动。

点左上角的 Reading Partner logo 切换它出现或消失，按设备记住。阅读器里没有 logo，开关是顶栏 More 菜单里的一行 `Lumen`，右侧 On/Off。关掉时盒子一起关，项照攒。设置 → 功能 → 阅读里也有一张「Show Lumen」卡片（手机、iPad、电脑都有），手机阅读器 Display 面板的 More 标签里也是这个开关（2026-09-29）。所有开关读写同一个值，`lumen/use-lumen-shown.ts`，一处改了其他处立刻跟着变。卢明会挡内容，所以能藏；隐藏就是隐藏，工具栏里不补卢明的图标。当天的简报从 info 首页或书架打开，打开时对话窗照样出来，卢明隐藏时只出对话窗，不出角上的卢明和盒子（2026-10-15，随简报书阅读器那一片做完，`lumen/issue-context.ts`）。

看书时它静止：不呼吸不摇。取盒子和放盒子这两下例外，看书时也走。

盒子的路线：起点是身体正中，整个矩形都盖在圆身子轮廓里，什么都不露；往左下走，走在身体后面，到不再和身体重叠的那一点换到身前（在不重叠处换层，才不会看见一下跳层），再往右下落进原位，最后这段从 0.92 放大到 1，像是朝人递过来。取出 550 ms，放回 450 ms，进度是匀速时钟，缓动在路径里：中途盒子空了或又来一项，只改目标，盒子从当前位置掉头，不跳。这两下里眼睛盯着盒子、身体朝盒子那边倾几度，落定或收回后都回正。已经出来了再多一项，只改徽标数字。开 app 时盒里本来就有项的，盒子直接在原位，不演取出。prefers-reduced-motion 下没有路径也没有倾斜，盒子直接出现或消失。盒子只有落定后能点，路上不接指针也不进 tab 序。

数字徽标 16 px，盒子落定后才出现，不跟着路径走，骑在盒子左上角（外侧那个角），用现有的墨绿徽标样式，数的是本机能显示的 open 项。不放右上角：盒子压在身体左下，顶边齐到眼睛，右上角的徽标正好盖住 Lumen 的左眼。

点 Lumen 或点盒子，效果一样：打开卢明的对话窗（2026-10-15 改，取代「点 Lumen 什么都不做」和从角上展开的那列卡片）。

语音聊天（2026-10-20 改，取代 10-15 的长按开语音）：身体上不再有长按、充能和桌面右键，按住身体只是拖或点。入口在对话窗：输入条右边、输入框外面常驻一个蓝色圆形波形按钮（白色竖条），发送键仍在输入框里。点它开语音会话（ChatGPT 语音模式那种免手持通话，麦克风常开、自己判轮次，通话本身不变），同时收起对话窗，用户对着角上的 Lumen 说；他的眉毛、眼睛方向和三种嘴形跟着通话走，不另加光圈或状态字，放在打开的书旁边也照样动。通话中身体上靠离盒子那一侧的上角挂一个小圆 X（贴左边时随镜像换边，和盒子、角标不重叠，触摸目标 44 px 向外长），点一下挂断，结束震两下轻的。通话中点 Lumen 或盒子打开对话窗、不挂断：输入条换成一根显示「在听 / 在想 / 在说」的条，波形按钮的位置换成深色圆形结束键，通话中不能打字；用对话窗自己的关闭键收起，通话继续。通话里说的每一句随说随写进当天门口的对话，对话窗打开就看得到（`soul/voice/live/call-transcript.ts`）。2026-10-20 起每个屏都能从门口开语音，通话挂在哪里看开始时的屏（`lumen/voice-call-mode.ts`）：在简报页照旧挂在当天简报上，用当天的 info 线程和简报锚点，每句同时抄进门口的对话，挂断后蒸馏 info 线程；别的屏挂在当天门口的对话上，每句只写这一条，派出去的活答在门口（`{ place: "door", date }`，think 拿门口对话的只读工具），挂断不另起蒸馏，和关掉门口的文字对话一样（`soul/voice/live/door-call.ts`）。阅读器里开着简报时，门口通话把这期摆上桌：前台每轮知道是哪期、第几页、划了什么、各条标题在哪页，think 拿到这本书的读工具和简报的提示词，开场不再概括这期，见 [88](../info/88-主题搜索.md)「简报的对话」。门口的日期在开通话时定下，跨过午夜的通话继续写进开始那天。开了以后切屏，通话不断。卢明做成一条连续的对话、各屏只递附件、语音完全不再要屏的上下文、检索和回忆卡片，这些更长远的形态不在这次改动里，以后和其余部分一起重新设计。通话中来了要用户点的卡（盒里新到的项、对话里新出的卡片，比如收链接的选主题卡、简报的提问卡），对话窗自动打开，通话继续；Lumen 不另外开口提醒，语音那边没有现成的干净口子。能不能通话只看宿主能不能出声；不能时按钮变灰，点一下给一行原因。点一下以松手为准：没拖过 8 px 的那一下，松手就开对话窗，随后那个 click 吞掉（iOS 上按久了的一下可能不给 click）；没有按下在先的 click 是键盘回车，也开对话窗；鼠标右键不算按。判定在 `lumen/lumen-press.ts`，按钮和条的判定在 `lumen/door-voice.ts`。不支持把链接拖到 Lumen 上。

## 卢明的对话窗

2026-10-15 改。对话窗就是当天门口的对话（docs/61，`soul/door.ts`）。渲染用和其他对话同一套聊天（卡片注册表照用），回合挂 soul 的常规工具和归档主题提议，门口专用工具在 `ui/components/lumen/door-tools.ts` 一行一个；问后台的活回来没有、在不在跑，卢明先调 `background_status`（[55](../soul/55-legion.md)「门口查进度」）。收链接卡、主题搜索的起草卡、run 的结果、简报卡（[88](../info/88-主题搜索.md)）都在这个对话窗里。打开某期简报时卢明先开口，那几句话和问题卡也在这里，每期只说一次（88「简报书的实现」）。

形态：

- iPad 和桌面：立在 Lumen 上方的小面板（现有门口面板，`door-panel.ts`），跟着 Lumen 停靠的那条边，Lumen 照常露着。面板标题栏关闭键左边一个放大按钮：点一下铺满外壳（安全区以内，有键盘时铺到键盘上沿），详细聊，Lumen 让位；再点缩回小窗，简略聊。小窗直接盖在书页上，书页不挪；不聊就关。关掉再开回到小窗。
- 手机：整屏，从底部滑上来（300 ms，reduced motion 下直接出现），Lumen 让位。顶栏带一条把手，按住顶栏往下拉，拉过 120 px 或松手时往下甩（≥ 0.5 px/ms 且已走过 24 px）就收起，否则弹回；对话区本身不接这个手势，免得和滚动抢。不做半屏档。算术在 `door-sheet.ts`。

盒里的项以卡片形式出现在对话的时间线里。卡片是程序放的，不是卢明说的话，样子和卢明的消息分开，也不进模型上下文（见「soul 知道盒里有什么」）。每张一行小标题（「盒子里的」，要你定的写「需要你定」并用墨绿），一句封面，一行来源（哪本书哪页，或 info 哪个研究室）。卡片走卡片注册表（kind `box-item`，payload 类型在 `box/card.ts`，组件 `lumen/BoxCard.tsx`），行只在渲染时并进去，不进 `use-door-chat` 的消息列表。点一张跳到原地——是书就开那本书、翻到那页、开那条线程，跨书先开书；是简报就打开那一期——并记 `told`；跳到书、简报这些别处时对话窗先收起，跳到某天门口对话的卡在对话窗里换成那一天。横划摁掉记 `dismissed`，鼠标设备用悬停出现的叉。状态表不变。

不推送照旧：项进盒时卡片放进对话，不弹窗，用户点卢明才看到。用户打开简报时对话窗跟着出来，不算推送。

卡片不写进任何一天的线程文件。当天的对话窗显示所有仍在盒里的项，前几天留下的也在，按项的 `createdAt` 插在对话行之间（同一毫秒排在那句前面），早于当天第一句的排在最上；正在写的回复和排队的那句永远在最下，卡不插到它们下面。从卡片跳去前几天的对话时，那一天不显示盒里的项。代码 `lumen/box-timeline.ts`（2026-10-15 实现时定）。

## 收链接

门口对话里贴链接，或让 Lumen 收一个，模型调 `take_link`（`reading/ingest/take-link-tool.ts`）。链接由程序从读者最近一条带链接的消息里抽出来编号，模型只给编号或 `all`，可选给一个主题编号；编号和主题列表作为 app note 附在那条消息上发给模型，不进线程文件，工具定义每轮不变。工具起一个 topic intake（`topic-intake.ts`），立刻在对话里立一张收链接卡就结束，不等抓取。工具结果告诉模型抓取在后台、什么都还没存，只回一句短的收到，不谈内容、存没存、归哪个主题，用读者的语言回；调用是 quiet 的，卡就代表这次调用，回复下面不再挂回执和工具行。

卡的状态只读 intake 记录（`watchIntake`），payload 只有 intakeId 和 Lumen 建议的主题 id，重开对话也对。没选主题是「放进哪个主题？」：主题列表标出建议（只在有依据时标：模型按编号给的那个；模型没给时链接里出现了名字的主题；都没有就不标），末行「新建主题」就地输名字，建好即选；底下一行写正在读哪个站。选了没读完是「放进「X」，读完就收」。读完没选是「读完了，选个主题就收」，列表照旧能点。选了且读完变回执：「收进了「X」」，每篇标题加节数或页数，每条没收的一行「没收：…」，「打开阅读」在当前外壳的阅读器里打开。失败只写原因。后端原因是英文程序句子，认得的几类按界面语言说，认不出的说「没能读到这个链接的内容」，程序原话作小字附在下面。别的设备打开这天的对话，卡只说链接是在另一台设备上收的。

抓取结束后 Lumen 不再补话（2026-10-09 定）：intake 的 run 由 program 派（`link-intake`，带 `tellFailure`），成功的 bell 只确认，不起回合、不进盒；失败才起一个回合，只用对话的语言说一句读者能做什么（如「链接地址可能写错了，发我正确的再收一次」），不复述卡上的原因，run 的失败卡照旧进盒。一篇都没收成也算失败（worker 抛 `GiveUpError`）；书内对话的 `ingest_url` 不变。

红盒规则（2026-10-09 定）：没选主题时文档挂在哪儿都没有，书架上找不到，所以 intake 一开始就往盒里放一项（`reading/ingest/intake-box.ts`）：box id 是这次 run 的，kind `link-intake`，body 是 intakeId，标要你定。这一项在收链接那天的时间线里就是那张收链接卡本身，不另放一张卡（2026-10-15 改）；从别处跳过来时打开那一天的门口对话并滚到那张卡（门口对话按天，可以不是今天），不记 `told`；不能横划摁掉，桌面上没有 ×。隔天还没选主题时，它在当天对话里是一张普通的盒卡（同样不能摁掉），点开打开收链接那天的门口对话并滚到收链接卡（2026-10-15 实现时定）。选了主题就记 `saved` 出盒，没读完也一样，读完时文档自己挂上；同一次投递里 run 自己的那张卡一起记 `folded`。intake 失败记 `dismissed` 出盒，run 的失败卡留着说原因。不自动归进 Brief，不过期。

同步：盒项同步，intake 记录（`link-intakes/`）只在本机。没有这条记录的设备不在时间线里放、也不数这一项（`lumen/box-cards.ts` 的 `cardsHere`，徽标和时间线读的是同一份结果），主题只能在收链接的那台设备上选；那边选完出盒，同步过来这边也没了。有记录的设备上，同一投递的其他卡收在它下面不另放。

## 拖动

2026-09-21 加。上面的「右下角」从此是默认位置，不是唯一位置：拖 Lumen 的身体能把它挪走。起因是手机上贴底的 Display 面板右下角的色板被它压住。

按下后指针走过 8 px 算拖，拖过的那一下松手什么都不开。没走过 8 px 的按是点，开对话窗（2026-10-20 改：长按已去掉）。手指和鼠标同一套 pointer 事件，按下就 `setPointerCapture`；`touch-action: none` 只在身体上，页面滚动不受影响。

抬手吸附到近的那条侧边（比的是身体中心和窗口中线），纵向停在抬手的高度。吸附 180 ms，`prefers-reduced-motion` 下直接落位。拖动全程夹在可见范围内：上到安全区顶部再留 64 px 顶栏，下不低于默认那格，左右就是 `pl-safe-4` / `pr-safe-4` 的那两点。

在左边时整个角落是镜像——身体所在的那个盒子上一个 `scaleX(-1)`：盒子从身体右侧取出，徽标还在盒子外侧的上角，对话面板立在左边这一侧。跟着镜像走的东西都对：盯盒子的眼神、朝盒子的倾斜。只有跟随指针的眼神在镜像里会指反，那一份在 `Lumen.tsx` 里翻回来。

composer 抬升照旧，实际高度取用户拖出来的和 composer 量出来的里大的那个：停在底部那一带仍按输入条抬，拖到高处就不抬。按住说话仍然整个让开。

位置按设备记在 localStorage，键 `shell.lumenCornerSpot`，和开关的 `shell.lumenCorner` 并列，值是 `{"side":"left","lift":0.43}`——边，加上离默认那格的高度占窗口高的比例。存比例是因为转屏换了高度，像素会落到屏幕外面；读出来按上面那条夹回可见范围，坏值回右下角。

算术全在 `corner-drag.ts`（吸附、夹取、序列化），指针和那一个 transform 在 `use-corner-drag.ts`，`LumenCorner.tsx` 只绑事件。拖动期间不 re-render：偏移直接写成外层盒子的 transform，落位才有一次渲染。`lumen-case-spike.html?mirror` 是镜像后那一版的对照表。

## 顺序

1. 盒生在 palace：`src/box/` 的项与盒、palace 登记行、状态迁移。验收：两台设备各写一项，合并后两项都在，状态按项自己那份文件收敛。
2. Lumen 全局化：每个外壳右下角常驻，logo 开关按设备记住，看书时静止，徽标数没开的项，点开是那一列卡片，点一张跳回原地。验收：在书里派一个 run，回来后角上出现红盒和徽标 1，点进去点那张卡回到原页原线程，项变 `told`。
3. research run：kind `research-literature` 登记、`deliverTo` 投回线程、soul 的 `delegate` 工具加 kind 目录。验收：阅读回合里派一个文献研究，回合立刻结束，结果回来追加进那条划线线程，同时盒里多一项。

三片 2026-09-15 都已进 main。实现时定的几条：

- `delegate` 每个 soul 回合都挂，不看本机有没有登记 kind；kind 清单写在参数说明里，错的 kind 调用时拒绝（坑 303）。
- `local` 档的 run 在 runner 之外读不到，所以 `run-done` / `run-failed` 铃的 payload 自带 `deliverTo`，答铃先读 payload，再退到 run 文件。
- 任务书写在 `legion/briefs/<uuid>.md`，产出写在 `legion/outputs/<runId>.md`，都是本地文件，palace 行 `run-brief` / `run-output`。
