# 思维导图调研

> 「读完之后梳理 → 大纲 → deck」这条路（[31](./31-读完之后的梳理与讲.md)）上要不要顺带出一份思维导图。外部事实的查证日期是 2026-08-06。

---

## 结论

不做成一个功能。

这场讲的大纲是一棵深度 2 的有序树：一层章、一层要点（`src/reading/talks/types.ts:27` 的 `TalkDecision`，`points: string[]`，没有更深的嵌套也没有跨条的连线）。这样的树画成思维导图，和 `OutlinePane` 现在的列表是同一份信息换个方向排，还丢掉了顺序——大纲的价值一半在"第几条"，放射状的图读不出先后。[16](./16-知识图谱.md) 已经就同一件事下过判断：用户真理解了，结构图就在他脑子里，把已经懂的画成图给他看是冗余。

唯一值得做的一点点是 deck 里的一张全景页：讲之前给听众看整场的形状。这补的是一个真缺口——现在 `SlideKind` 只有 `title | section | content | closing`（`src/reading/slides/types.ts:15`），deck 没有议程页。它从 `buildTalkOutline` 的 `included` 直接算，不调 AI、不引库、手写 SVG。这张图是 deck 的一页，不是一个新对象、不是新的存储、不进聊天、不进阅读器。

四种形态里：它不是共同工作面（改大纲走对话和 OutlinePane 的两个按钮，再加一块可编辑画布是第三个编辑器）；不是和 PPT 并列的另一份产物（多一个要维护的产物，没有听众要过）；不是读的时候的东西（[16](./16-知识图谱.md) 的判定）。它就是大纲的另一种视图，而这个视图只在"一屏看完整场"这一个场合比列表强，那个场合就是 deck 的一页。

## ReadAny

[codedogQBY/ReadAny](https://github.com/codedogQBY/ReadAny)，AI 电子书阅读器，Tauri 2 + React 19 + foliate-js + LangChain.js，桌面和移动。许可证 GPL-3.0-or-later（`package.json` 的 `license` 字段）——只能看，代码不能抄进来。

它有思维导图，做法是：

- 一个 AI 工具 `mindmap`（`packages/core/src/ai/tools/mindmap-tools.ts`），模型产出标准 Markdown 标题层级（`#`/`##`/`###`/`-`），工具本身不画图，只回一个 `{ type: "mindmap", title, markdown }`。
- 渲染在 `packages/app/src/components/common/MindmapView.tsx`：`markmap-lib` 的 `Transformer` 把 Markdown 转成树，`markmap-view` 的 `Markmap.create` 画进一个 `<svg>`。固定高 400，带全屏 portal、复原、下载三个按钮。
- 导出是 SVG：克隆节点、用 `getBBox` 定 viewBox、把 CSS 变量替换成固定色再序列化。
- 图在聊天里是一个 part（`case "mindmap"` in `packages/app/src/components/chat/PartRenderer.tsx`），组件 `lazy` 加载，markmap 不进主包。
- 另有一个侧栏面板「思维导图 — 章节结构可视化」（`website/src/content/docs/zh/support/reading/basics.md`），即读的时候看这本书的章节结构。

两条值得记下来。一是它的工具产出直接变成聊天里的一个 part，和我们的 card part 是同一个形状，说明这条路在工程上不需要新机制。二是 `mindmap-tools.ts` 里那个 `convertMermaidMindmapToMarkdown`：提示词已经三处写了"NOT mermaid syntax"，仍要写一个兜底把 mermaid mindmap 语法转回 Markdown 标题——让模型自由产出图的语法就要准备接住它写错的那一种。

不值得借鉴的是主路径本身：markmap 存在的理由是把任意 Markdown 转成树，而我们的树不是 Markdown，是盘上已经结构化的 `decisions`。让模型再写一遍 Markdown 是把已有的结构降解成文本再解析回来。

## 候选库

许可证和体积查自 npm registry，2026-08-06。体积一列，标「打包后」的是在临时目录里 `bun build --minify` 单入口实测的字节数，标「npm 解包」的是 registry 的 `unpackedSize`。

| 库 | 版本 | 许可证 | 体积 | 联网 |
|---|---|---|---|---|
| markmap-view | 0.18.12 | MIT | 78 KB 打包后（含 d3 子集），gzip 26 KB | 不需要 |
| markmap-lib（Markdown 转树） | 0.18.12 | MIT | 625 KB 打包后，gzip 211 KB | 见下 |
| markmap-common / markmap-cli / markmap-render | 0.18.x | MIT | — | 见下 |
| mermaid（含 mindmap 图种） | 11.16.1 | MIT | 3.57 MB（`dist/mermaid.min.js`） | 不需要 |
| jsmind | 0.9.1 | BSD-3-Clause | 51 KB（`es6/jsmind.js`，未压缩），零依赖 | 不需要 |
| mind-elixir | 5.15.1 | MIT | 505 KB npm 解包 | 未查证 |
| simple-mind-map | 0.14.0 | MIT | 26 MB npm 解包，依赖含 quill、yjs、pdf-lib | 未查证 |
| @antv/g6 | 5.1.1 | MIT | 7.6 MB npm 解包 | 未查证 |
| 自己画 SVG | — | — | 0 | 不需要 |

许可证都不挡路，AGPL 那类问题这里没有。真正的判据变成体积和自包含。

markmap 有两处会联网，都能绕开。`markmap-lib` 的 `Transformer` 会为 katex / prism 声明外部资源，`markmap-common` 的 `loadJS`/`loadCSS` 用注入 `<script src>` 的方式取，会被我们的 CSP `default-src 'self'`（`src-tauri/tauri.conf.json`）挡掉。markmap 官方的自包含模板（`markmap-render` 的 `baseJsPaths`）默认从 CDN 取 d3 和 markmap-view，要自己换掉 `baseJs`。绕开的办法是不走 Markdown：`Markmap.create(svg, opts, root)` 收的是 `IPureNode`（`{ content: HTML 字符串, children: [] }`，`markmap-common/dist/types/common.d.ts`），自己造这棵树就只需要那 78 KB 的 `markmap-view`，`markmap-lib` 那 625 KB 一起省掉。

mermaid 的 mindmap 出局：为一张图带 3.57 MB 进 deck，而 deck 的定位是零外部依赖的单文件。jsmind 和 mind-elixir 是可编辑思维导图的核心，我们不需要编辑。

WKWebView（iPad）和 WebKitGTK（Linux）上跑不跑得动：markmap 只用 SVG、`foreignObject`（`markmap-view` 里 4 处）和 d3 的指针事件，不碰 canvas、WASM、worker，按面上看没有障碍，但没在真机验证过。自己画 SVG 只用 SVG，同样没验证过，但表面积小得多。

自包含产物：markmap 可以——一份 root JSON 加内联的 78 KB IIFE，我们的 deck 模板（`src/reading/slides/template.ts`）本来就是全内联，形状对得上。代价是每个 deck 多 78 KB 第三方 JS，换来的是我们用不上的无限缩放和折叠。自己画 SVG 的产物就是那段 SVG 本身，没有运行时。

聊天里内联显示：card part 机制现成，不用改协议也不用 iframe。加一个 `ReadingCard` 的 union 成员（`src/reading/rehearsal/cards.ts`）、一个组件登记进 `READING_CARD_REGISTRY`、在 `isPersistableCardKind`（`src/ui/components/chat/chatParts.ts:203`）里决定存不存，就够了。payload 要能 JSON 序列化，所以存的是树不是 DOM。真要引 markmap 的话它渲染进一个 `<svg>` 元素，不需要 iframe。但按上面的结论，这条不做。

## 接法

如果做那张全景页：`src/reading/slides/` 加一个 `map` 的 `SlideKind`，一个纯函数把 `buildTalkOutline` 的 `included`（`src/reading/slides/outline.ts`）画成 SVG，assemble 时插在 title 之后。plan 阶段不参与，模型不知道有这一页，也就不会去编它的内容。被 Cut 的条目不出现，和 deck 其余部分同一条规则。

`src/reading/talks/` 和 `src/ui/components/talk/` 不动。
