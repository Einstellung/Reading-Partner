# 思维导图调研

> "梳理完出 PPT 之外，顺带出一份思维导图"值不值得做。上游是 [31](./31-读完之后的梳理与讲.md)（梳理决定 → 大纲 → deck 这条管线）、[16](./16-信息陪读与分诊.md)（可视化图谱按产品理由关掉）和 [29](./29-读到slides这条路的现状.md)。参考项目是 ReadAny。外部事实查证日期 2026-08-06，查不到的写"未查证"。

## 结论

不做成功能。想画的那张图，数据是"章 → 要点"两层，顺序有意义；`OutlinePane` 已经把这份数据按顺序列出来并且可编辑，换成放射状的画法信息量不增，还丢掉顺序。[16](./16-信息陪读与分诊.md) 的判断在这里同样成立：读者已经懂的东西画给他看是冗余。

有正回报的窄用法有两个，都不引库、都不新增对象，也都不急：真要拖一个库进来，mermaid 的 mindmap 语法最贴合但整个包 83 MB 未压缩，划不来；markmap 体量小且是 MIT 许可证，产物能序列化成 SVG，但两个用法都不需要它，直接手写序列化。

一是第二段开头那一步——[31](./31-读完之后的梳理与讲.md) 的"AI 给出它读到的骨架，用户确认、纠正"。那时读者要一次看清一本还没外化过的书的形状，图不是复述他懂的东西，是摊开待审的东西。做法是聊天里一张只读卡。

二是 deck 里的一张全景页：讲之前给听众看整场的形状。现在 `SlideKind` 只有 `title | section | content | closing`，deck 没有议程页，这是个真缺口。做法见末节。

## ReadAny

local-first 的 AI 电子书阅读器（EPUB/PDF/MOBI 等），卖点是对书提问、语义检索、本地向量库、标注、TTS、WebDAV 同步。桌面 Tauri 2，移动 Expo/React Native，React 19 + Vite + Tailwind v4 + Radix，SQLite，嵌入用 Transformers.js，阅读引擎是 vendored 的 foliate-js。模型走用户自己配的 provider，仓库里唯一的服务端产物是反馈 worker。2149 star，最近提交 2026-08-02。许可证 GPL-3.0-or-later（LICENSE 是标准 GPLv3 全文，无附加条款；GitHub API 报 `NOASSERTION`，以文件为准）。代码不能借，做法可以看。

有思维导图，形态和我们这套 card part 几乎一样：LLM 工具调用 → 聊天里的一个 part → 组件渲染。

- 工具 `mindmap`（`packages/core/src/ai/tools/mindmap-tools.ts`），入参 title + markdown，提示词明写要标准 Markdown 标题层级、不要 mermaid mindmap 语法，并带一段 mermaid → Markdown 的兜底转换。返回 `{type:"mindmap", title, markdown, stats}`。
- 桌面 `MindmapView.tsx` 用 `markmap-lib` 的 Transformer 把 Markdown 转成节点树，`markmap-view` 的 `Markmap.create` 渲染进一个 `<svg>`。交互是点节点折叠、拖动、全屏。导出只有 SVG：克隆 svg、算 `getBBox` 定 viewBox、塞一段白底深字的 `<style>`、把 CSS 变量替换成字面色值、序列化下载。
- 移动端是另一套：`react-native-webview` 里塞一段 HTML，`<script src="https://cdn.jsdelivr.net/npm/markmap-autoloader@0.18.12/dist/index.js">`。移动端的导图需要联网。
- mermaid 是独立的一条线（`beautiful-mermaid`，MIT），只渲染 Markdown 正文里的图表块，而且以 `mindmap` 开头的 mermaid 块它不渲染，当代码显示。

值得借鉴的是三点：AI 产出的是文本大纲不是图形；渲染是纯前端一次性的；导出走序列化 SVG。移动端那条 CDN 路我们走不了。

## 四种形态

- 大纲的另一种视图：不做。`Talk.decisions` 是一维数组，一条决定带 `points: string[]`，画出来是一棵两层的梳子，没有跨章的边。而数组顺序是"要讲的顺序"（`reading/talks/outline.ts`），放射状布局没有正典读序，画成图是丢信息。真做还要处理图上编辑写回决定，否则第二个界面和第一个漂开。
- 梳理时的共同工作面：已经有了，就是 `OutlinePane`——聊完一章多一条，能上下移、Cut、Remove，写回同一份 `decisions`。换成图不改变这件事，只是把两个按钮换成拖拽，而拖拽在触摸和 Pencil 上要单独定契约（`OutlinePane` 开头已经写明为什么没做）。
- 和 PPT 并列的交付物：可以做，但没人要。它面向的是听众不是读者，是一页发下去的纸；现在的判据是"能不能讲给别人听"，deck 已经是那个出口。等真有人要一张图再说。
- 读的时候的东西：不做。[16](./16-信息陪读与分诊.md) 直接管这条。而且读的这一侧根本没有树——只有划线和章节笔记，要先跑一遍抽取才有节点，成本最高、理由最弱。

真要落一步，就是开头说的那张骨架确认卡：`reading/rehearsal/skeleton.ts` 那份 skeleton 本来就在手上，一层树，只读，不引库，只在梳理的第一步出现一次。
