## 硬规则

1. 程序算得出的事实不经模型转手。URL、作者、时间、计数、标题、引用由程序取、程序写；模型只按程序编的号选。X 帖子的时间由 status id 解出（snowflake），永久链接由 id 加 handle 重建。
2. 只读：不发、不赞、不转、不关注、不回复（57）。开搜索页、永久链接页和外链都是导航，不点页面上的按钮。
3. 碰到登录失效、验证、限流，当次停手，不重试，不自动重登。
4. 每晚、每次 run 都有硬上限（条数、开页数、模型调用数、时长），到了就收尾。
5. 碰 X 的活只在桌面采集端跑（Linux、macOS，有 webview 取材的那台），同一台同一时间只有一个。iOS 只看结果、发请求。

## 简报

### 章程里的 X 搜索配置

简报的主题就是现有研究室。章程（`info/labs/types.ts` 的 `Charter`）加一段可选的 `x`：

```ts
interface XSearchConfig {
  accounts: { handle: string; role: "first-party" | "related" | "commentary"; weight: number }[];
  anchors: string[];            // 锚词：消歧，也判「提没提到主实体」，命中任一个算提到
  subqueries: { id: string; search: string; ranking: string; weight: number }[];
  revision: number;
  confirmedAt: number | null;   // 用户点头的时间；null 是草稿，不跑
}
```

- `accounts`：第一方是这个领域的当事人（公司、项目、创始人）；关联和评论号权重低。初值第一方 1.0，其余 0.3。
- `subqueries`：1 到 4 条。`search` 是按平台上标题的写法写的关键词，`ranking` 是一句自然语言问题，给重排用。权重主 1.0，次 0.6 到 0.8，外围 0.3 到 0.5。
- 不进 `search` 的：时间词、「news」「updates」这类元词；数字除非就是话题本身（GPT-4）。同名风险高的，每条子查询都带锚词。

谁起草：用户说「这个室也在 X 上搜」或起新研究室时，招募员起草。它用 `web_search`（24）和 X 搜索页找候选账号，候选由程序编号；程序在桌面 webview 里开每个候选的主页，读出是否存在、简介、粉丝数、最近发帖时间，模型按号选并标角色，排除粉丝号和恶搞号。招募员的提示词带 last30days 的关键词陷阱五类（人群购物、数字撞车、教程措辞、单个泛名词、非拉丁文字），单个泛名词这类在对话里问用户一句再起草。解析要开 X 页，所以起草 run 和详细资料一样排给桌面。

谁确认：草稿照给用户看，用户在对话里改，点头才写 `confirmedAt` 生效，`revision` 加一。用户以后在对话里改，同样点头生效。

### 夜里取材

什么时候：`info/program/daily.ts` 加第二个锚点 01:00，判据同 05:00 那个：最近过去的 01:00 这台还没派过。派的条件：`amICollecting()`、本机有 webview 取材、X 会话有效、至少一个研究室的 `x` 已确认。只在能干活的机器上派，worker 再拒一次（坑 380）。开始在锚点后随机 0 到 40 分钟；结束取最早的：04:40、所有线读到上次位置、碰到每晚上限、停手。机器睡过 01:00，醒来还在 04:40 之前就补跑，过了当晚不读。

防电脑睡眠：开始时拿一把别睡锁，收尾时放。Linux 走 logind 的 `Inhibit("sleep:idle")`，macOS 走 `IOPMAssertionCreateWithName`（`PreventUserIdleSystemSleep`）。宿主能力 `platform/app/keep-awake.ts`，Rust 侧 `src-tauri/src/keep_awake.rs`。合盖或手动睡眠不拦。

三条线，都开 `x.com/search?q=…&f=live`（按时间倒序）：

| 线 | 查询 | 给谁 |
|---|---|---|
| topic | `<search> -filter:retweets` | 每条子查询 |
| from | `from:<handle> -filter:retweets` | 第一方和关联账号 |
| about | `@<handle> -from:<handle> -filter:retweets` | 第一方账号 |

运算符在第一期实测核对。一个研究室的线按权重排，每晚至少跑主子查询的 topic 线；线多于每室份额的，按上次读的时间轮到下一晚。研究室之间轮流取线，不让一个室吃完全晚。

节奏（初值，跑一周后按夜读文件调）：

| 项 | 值 |
|---|---|
| 每晚上限 | 读入 400 条帖子、开搜索页 30 次、开永久链接页 40 次、有效阅读 150 分钟；每室最多 8 条线 |
| 分段 | 2 到 3 段，每段 30 到 60 分钟，段间歇 10 到 30 分钟 |
| 每屏停留 | 屏上新文字按每秒 12 到 20 字算，再加 2 到 6 秒随机 |
| 长停 | 每 5 到 10 屏一次，30 到 120 秒 |
| 滚动 | 每次 0.6 到 0.9 屏，拆成几次小步 |
| 线的顺序 | 每晚打乱 |

读到上次位置就停：每条线（研究室、线、查询）记上次读到的最上面一条的 status id 和 30 天内见过的 id。往下读时连续 8 条见过、或比那条早，这条线就停。第一次读的线往回读到 24 小时前，时间由 id 解出。

每一步先由程序走缺省策略：往下滚；截断的帖子过了本地相关度地板（见「打分」）才开永久链接页补全文，有上限；夜里不开外链，外链正文留给早上的取材相位。每一步落一条进夜读文件：步号、屏上帖子 id、动作和结果。以后由判断模型接手这一步（见「判断模型」）。

停手（坑 494：页面自己的后台请求 403 不算）：

- 登录失效：落地 URL 变成登录页，或搜索页出现登录墙。
- 验证：落地到挑战页（`/account/access` 一类），或页面出现验证提示。
- 限流：页面出现限流或「稍后再试」提示。
- 结构变了：连续 3 屏解析出 0 条帖子而页面字数正常。

当晚立刻收尾，已读的照常往下走，原因写进夜读文件的 `halt` 和采集端状态文件（36 的 `halt`、`sites`）。登录失效等用户在 PC 上重新登录才再派；验证和限流跳过下一晚，再下一晚试一次，再碰到就停到用户在对话里说恢复；结构变了只停当晚，等改页内脚本。

读法：app 自己的隐藏 webview，和彭博全文共用 `webview_fetch` 的 profile 和 cookie 罐（坑 385）。登录走现有站点登录：X 搜索源的 descriptor 写上 X 的登录页，`site-session.ts` 把它折成一个站，源页面那一行就能开窗登录、查会话、退出（17、36）。登录是全程唯一的可见窗口，用户自己点。`webview_fetch` 只会给一个 URL 取一篇，取材要一个长命的页：Rust 侧加 `webview_fetch/browse.rs`，开一个隐藏 webview，前端能让它导航、跑页内脚本、按像素滚、后退、关；前端门面 `workshop/extract/webview-browse.ts`（capability，不认识 X）。搜索页脚本和解析放 `info/x/search-page.ts`，和 `permalink.ts` 并列。判稳定看脚本读没读到帖子，不等 load 事件（坑 496）。滚动用页内 `scrollBy`。

### 可续跑

一晚的取材是一个 legion run 里跑一个 pi-durable 任务。run 的 kind 是 `x-night`，程序 worker，`local` tier，只在采集端跑。idempotencyKey 是 `x-night:<锚点日期>`，闸在被调用的一侧（坑 210）。任务 `rp.xnight` 用 `defineTask`，四个相位：`open`（拿别睡锁、验会话、开页）、`read`（逐线逐屏）、`rank`（关页后打分，见下）、`wrap`（放锁、写夜读文件和状态）。定义在 `info/x/night/`，打开 Harness 时经注入登记，`legion/durable` 不 import info。停顿一律走 `runtime.sleep` 或 `awaitWithContext`（87「换代」）。

| 借的做法 | 落在这里 |
|---|---|
| requestId 由计划 id 加次数推出 | 每一步的键是 `<计划 id>:<步号>`，重排调用的键是 `<计划 id>:rank:<labId>`，结果 memo，恢复后不重问 |
| revision 作废旧任务 | 计划由已确认的各室 `x` 生成，记下各室 `revision`。每一步前比对，用户改了章程或说今晚不读，就收尾 |
| 恢复后先验目标还在 | 恢复时查：revision 没变、当前研究室和线还在计划里、还在窗口内、会话有效。任一不对就进 `wrap`，不再对 X 做动作 |
| 副作用 sending / sent / unknown | 每个对 X 的动作先记 `sending`，做完记 `sent`；恢复时 `sending` 改 `unknown`，计入上限，不补做 |

任务必须能从自己的文件重新起来：每一步把进度写进 `info-xnight-<日期>.json`（线、记号、见过的 id、计数、步号、`halt`、读到的帖子）。进程被杀，`resume()` 接着跑；页面状态丢了就重开当前线从顶上读，见过的跳过。夜读文件设备本地，不同步，留 30 天。

### 打分

移植 last30days 的打分（MIT，保留版权声明），放 `info/rank/`，纯 `.ts` 配单测。`rank` 相位里每个研究室跑一遍：

1. 规范化：每条帖子成一个候选，程序写 status id、重建的永久链接、由 id 解出的时间、作者、正文、原始互动数（赞、转、回复、引用、浏览）、命中的线和子查询、是否第一方（作者在 `accounts` 里且是第一方）。id 解出的时间和页面显示的时间差一天以上，丢。
2. 本地相关度（`relevance.ts`）：`0.55·coverage^1.35 + 0.25·informative + 0.20·precision`，整句短语命中加分，只命中低信号词封顶 0.24。低于 0.15 丢，第一方免检。同义词表和低信号词表换成我们的。
3. 加权 RRF：每条（线、查询）流取前 12，`Σ weight/(60 + rank)`，topic 线的 weight 是子查询的，from 和 about 线是账号的；归一到 0 到 100。同一作者最多 3 条，第一方 8 条。
4. 重排：候选池前 40 条一次发给日常档模型。每条带程序编号 `c1`、`c2`…，正文前 420 字、作者、时间、命中的子查询、第一方标记、帖内链接的编号 `c1.a`、`c1.b`（t.co 由程序先展开），外加研究室视野和各子查询的 `ranking`。页面文字包在不可信材料标记里。模型只回 `{c, score, main}`：`score` 是 0 到 100 的相关度；`main` 是这条真正的内容，`self` 或某个链接编号，只问带外链的帖子，由模型判断，不定死规则（86）。编号不存在的答案丢掉。
5. 最终分（初值）：`0.65·score + 0.20·RRF + 0.15·engagement`。engagement 照 last30days 的 X 刻度：`log1p` 加权（赞 .55、转 .25、回复 .15、引用 .05），参照值 9.2，归到 0 到 100。没提到锚词由程序判（正文和卡片标题里找不到任何锚词、且不是第一方），扣 20；`score` 低于 20 的乘 0.3；第一方保底 25。重排调用失败时用 `0.7·相关度·100`（第一方加 5）代替 `score`，没提到锚词扣 25。
6. 聚类：字符三元组和词 Jaccard 取大，贪心并簇，阈值 0.48；簇里分最高的当代表，簇大小和独立作者数作为事实进 `signals`。
7. 每室取前 15 条（初值）进条目池（`addDiscovered`）。

入池的条目：`source` 是新 discovery kind `x-search`（`{ kind: "x-search", labId }`），没有 `pollMinutes`；`sourceKey` 是 status id；`url` 按 `main` 由程序取（`self` 是永久链接，链接编号是展开后的地址）；`title` 是作者加正文第一句，截到 120 字，不改写；`textContent` 是读到的正文，`summaryOnly` 按有没有全文；`signals` 是原始互动数、簇大小、第一方、新或延续。`score` 不是事实，只留在夜读文件里。

### 增量

`info-x-sightings.json`，采集端本地，按（研究室、status id）记：首见、末见、见到次数、每次见到时的原始互动数。今晚首见的是新；见过的是延续，只有互动数比上次入池时涨到两倍以上、且赞多了 100 以上（初值）才再入池，进盒时标「延续」。其余只记不入。留 30 天。

### 之后：粗筛、分析员、盒、秘书

05:00 的日更照常从池子里取，X 的条目和别的源一起过粗筛（按可观测项命中）、取材（正主是外链的在这里取正文）、出 cable、分析员、进盒，秘书讲。cable 的来源行是「X · @handle」，引子帖显示正主的标题。用户在盒里存下一条 X 条目，走 86 的链接摄入。

分析员改两处（`info/analysis/analyst.ts`）：

- 读昨天：输入加上这个研究室上一盒的封面和昨天 cable 的标题（程序编号）。延续的事不从头讲，只说变了什么；没有新东西就写一句没有，不凑。
- 写作规矩（follow-builders 的跳过规则）：跳过推广、活动吹捧、刷互动的帖；线程当一篇讲；引用帖连被引用的内容一起讲（程序给出被引用帖的正文）。每句按编号引 cable，链接由程序渲染。封面里的数字和日期必须出现在它引的 cable 正文里，程序抽数字核对，对不上重写一次，再不对用兜底封面。

### 跨日去重

移植 ARA 的三段去重（`dedupe_headline_alerts.py` 的核心，MIT），放 `info/collect/dedupe.ts`，在出 cable 时对 14 天内所有研究室的 cable 跑：

1. 完全相同：同一事件键、同一标题键；同 URL 且标题相似度（包含度和 Jaccard 取大）≥ 0.62。
2. 重播：同一 status id 或同一规范化 URL 进过盒。
3. 跨源：不同 URL，共享词 ≥ 4 且 Jaccard ≥ 0.5。

Jaccard 在 [0.35, 0.5)、共享词 ≥ 3 的争议带交给日常档模型，每条附最近 5 条已进盒的标题，都由程序编号；模型只回 `{id, verdict, confidence, matched}`，只有 duplicate 且 high 才压掉，判官失败一律照发。中文按二元组分词。压掉的条目和理由按 35 的 `cappedOut` 规矩出现在日志和简报文件里。

### 兜底封面与源健康

分析员或综合失败，程序出兜底封面：研究室名、一句「今天的封面没写成」、命中的 cable 标题列表，标明是兜底版。盒照常落，不静默缺盒。

X 搜索的健康按线记，写进采集端状态文件，源页面显示：上次取到的时间、读到条数、新条数、过地板条数，「没取到」（停手、解析失败）和「没新内容」分开。登录失效、连续两晚停手、结构变了，盒里来一项，说是哪种、点开到源页处理。

### 每周复查

招募员每周在桌面复查一次（周日夜里取材收尾后），先由程序从夜读文件和 sightings 算指标：

- 每个账号 from 线的切题率（过地板的条数 / 读到的条数）。
- 每条子查询的产出（过地板的条数、进盒的条数）和连续零产出的天数。
- 锚词未命中率。
- 候选账号：不在 `accounts` 里、一周内有 3 晚以上切题命中 ≥ 2 次且切题比例 ≥ 0.5 的作者。

模型读这些数字起草改动，每周最多加 5 删 2，每条带指标做证据，进这个研究室的盒；用户在对话里点头才改章程。

## 详细资料

### 秘书的两档

用户听简报时：

- 「展开讲讲」「多说点」：秘书用手里已有的正文当场讲（cable 正文、读到的帖子全文），不派 run。
- 「这方面给我详细资料」「多找点材料」：派详细资料 run，当场说多久能到（见下），然后接着讲。

秘书按用户的话判：要的是听，还是要材料读。拿不准时先按第一档讲，讲完一句话问要不要详细资料。正文里答不上的追问照旧走现有的 tasking（63），不变。

### run 与排队

kind `dossier`，agent worker，`synced` tier，`requires: [WEBVIEW_FETCH]`，只有桌面采集端认领。idempotencyKey 是 `dossier:<cableId>`：同一条还在排队或在跑时再要，秘书说已经在做；做完后再要是新的一次（`dossier:<cableId>:<n>`）。

排队：桌面上碰 X 的活一次一个，按请求先后。白天桌面开着就认领就做，几十分钟出；关着就等桌面下次开，夜里在简报取材收尾后接着跑，早上前到。秘书报时看桌面的 claim 心跳（`legion/claim`，每小时一次）：两小时内有就说「桌面开着，几十分钟」，没有就说「电脑开着时做，最晚今晚」。

X 的动作按设备每天一份总额度，简报取材和详细资料共用（初值：搜索页 60 次、永久链接页 80 次）。

### 深挖

一个 agent 多轮调工具（`legion/subagent` 的 `runSubagent`），日常档。种子是那条 cable：是帖子的话，帖子只证明作者说了什么，要顺着它的链接和点到的实体到 X 以外找原始材料（文章、论文、仓库、官方页）。

开始前程序先查本 topic 已有的文档（移植 ARA 的 `prior_context.py`，MIT）：按标题 2 分、小标题 1 分对种子标题和正文首段打分，中文按二元组，阈值 2 取前 5，编号 `P1`…，每条给标题和开头 400 字；另把 topic 里所有文档的来源 URL 规范化后建表。

工具，参数都只有编号和短文字：

| 工具 | 做什么 |
|---|---|
| `plan` | 开头调一次：4 到 8 个可回答的问题，每题写明什么算一手；2 到 3 个证伪问题（什么会推翻这条的说法）。程序编号 `Q1`…、`F1`… |
| `x_search` | 线（topic、from、about）和查询词或 handle。程序在桌面 webview 按简报的节奏读一屏到几屏，回编号帖子，同简报的候选格式 |
| `web_search` | 24 的工具，返回的来源由程序编成候选 |
| `open` | 读候选 #n，86 的 `open`：读法登记表、站点适配器（arXiv、GitHub、Drive）、通用网页和 PDF；X 帖子给出自身全文候选和全部外链候选。是引子还是正文，由模型判断 |
| `pick` | 选一份材料：编号、角色（一手、二手、评论、反方）、回答了哪些问题号 |
| `ask` | 在某个问题下加追问，程序编号挂在它下面（深挖树，每题最多 3 个追问、最多两层） |
| `finish` | 一句说明，结束 |

每轮模型看到的进度由程序写：每个问题挂了哪些材料、还缺哪些。

够了的判据由程序数：每个 `Q` 至少一份一手材料；每个 `F` 至少一份反方材料，或用 `x_search` 和 `web_search` 各查过一次没找到（程序记下查过什么）；选中的材料 3 到 20 份。不满足时 `finish` 被拒，回缺的问题号。上限（初值）：工具调用 60 次、`x_search` 10 次、`open` 30 次、模型轮数 30、时长 60 分钟。到上限就按已选的交出去，缺的问题号写进交接。

已经在本 topic 里的材料（规范化 URL 命中）不能 `pick`；模型要提它，就在指南草稿里写 `P` 编号。

### 材料登记

每次 `open` 读到东西，程序登记一份材料，`info/dossier/registry.ts`：

| 字段 | 内容 |
|---|---|
| `id` | `M<n>`，同一规范化 URL 只登记一次 |
| `url`、`canonicalUrl` | 规范化移植 ARA `source_cache.py` 的 `canonicalize_url`：去 `utm_*`、`fbclid` 等追踪参数，query 排序 |
| `title`、`author`、`publishedAt` | 读法和适配器读出来的 |
| `reader` | x、web、arxiv、github、drive、pdf |
| `hash` | 正文内容哈希 |
| `sections` | 按标题边界切的节 `M<n>.§k`：小标题、字数。整份 PDF 没有节 |
| 正文 | 可读稿（`Manuscript`）或整份文档的字节，缓存在 run 目录 |

模型在任何地方提到材料，只写 `M3`、`M3.§2`、`P2`；程序校验编号存在。

### 交给装订器

深挖结束，`info/dossier` 写一份交接放在 run 目录，交给装订器：

```ts
interface DossierHandoff {
  runId: string;
  topicId: string;
  seed: { cableId: string; material: string };      // 种子材料的 M 编号
  plan: { id: string; text: string; kind: "question" | "falsify"; parent?: string }[];
  materials: RegisteredMaterial[];                   // 程序登记的全部材料，含没选的
  picks: { material: string; role: "primary" | "secondary" | "commentary" | "opposing"; answers: string[] }[];
  prior: { id: string; documentHash: string; title: string }[];
  guideDraft: string | null;                         // 指南草稿，见装订另议
  gaps: string[];                                    // 没答上的问题号
}
```

装订器接收交接、出 EPUB 的入口和合订本内部规则（选节、指南、排序、翻译、附录）见装订另议。topic 取研究室章程的 `topicId`，没有就按 63 同名新建并写回章程。

### 到了

装订出的文档入库挂到那个 topic，入库由 reading 注入（同 86），文档经同步到手机。盒里来一项，`kind: "dossier"`，origin 指那天的简报和种子 cable，标题由程序写「详细资料：<种子标题>」，点开进阅读器。简报线程里追加一行。一份材料都没选中，run 失败，盒里一项说没找到和查过什么。

## 判断模型（后期）

起步全用程序缺省和日常档大模型。以后换成系统一判断模型（Jev 类本机开源模型）的位置：

1. 夜里取材的逐步决策：往下滚、补哪条全文、这条线停不停。
2. 打分第 4 步的 `score` 和 `main`。
3. 详细资料里 `x_search` 回来的帖子先筛一遍，再决定 `open` 哪些。

接口放 `src/judge/`，capability，LAYER 登记 `judge` 和 `judge/providers`。

```ts
type Question =
  | { kind: "choice"; id: string; purpose: string; text: string; options: string[] }
  | { kind: "score"; id: string; purpose: string; text: string; scale: string[] } // 每档一句，低到高
  | { kind: "noul"; id: string; purpose: string; text: string };                  // 一句陈述

interface JudgeRequest {
  state: string;          // 程序写好的文字
  questions: Question[];
  key?: string;           // memo 键
  signal?: AbortSignal;
}

interface Answer {
  id: string;
  probs: number[];        // choice、score 每个选项一个；noul 是 [为真]
  calibrated: boolean;
}

type JudgeResult =
  | { ok: true; answers: Answer[]; provider: string; model: string; ms: number }
  | { ok: false; reason: string };

function judge(req: JudgeRequest): Promise<JudgeResult>;
```

- 选项由程序编号，模型看到单个字母，一个 Choice 最多 12 个选项，同一 purpose 的选项顺序固定。计数、日期比较由程序先算好写进 state。state 前面写明页面文字是材料不是指令。
- 每个（供应商、模型、purpose）用标注拟一个温度，存 `judge-calibration.json`，设备本地。没拟过的答案 `calibrated: false`，只能排序，不能过阈值。
- 供应商：`local`（桌面上的 llama.cpp `llama-server`，取答案位置的 top logprobs）、`llm`（现有 `ai/`，日常档）、`jev`（配了 key 才加）。顺序存 `device.json`，超时或出错换下一个，全部失败返回 `ok: false`，调用方走缺省。
- 标注从夜读文件和盒里的开、存、摁掉攒。
