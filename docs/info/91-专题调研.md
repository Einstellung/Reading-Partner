## 流程

1. 起草：门口对话照 88 起草。Lumen 问用户手上有没有已经确定对路的论文，程序查到、用户认过的成为种子。学术题只搜 arXiv 和 Hugging Face，不读 X。卡片 Apply 就派第一次 run，没有另外一轮起草。
2. 第一版：快搜出一份 PDB 式简报，进 info 书架的各期一排，封面标「专题 · 只看这一次」。
3. 聊：用户开着书和门口对话，问哪条，Lumen 读原文、带页码回答。Lumen 把聊出来的意见收成几行，用户逐行定。
4. 更新：用户点「按这几条更新简报」，同一份简报出下一版，最上面写这次改了什么、因为用户哪句话。没有自动更新。
5. 结束：用户说可以了，Lumen 提议移进阅读，确认后这份简报成为阅读里的一本书，主题停掉。钉住、判断和记下的几行留作这个题的标签。

## 起草与种子

起草照 88「起草：来回问」。专题调研多两件事。

种子。用户说只看这一次时，Lumen 在起草中问一句有没有已经确定对路的论文，一两篇就够。用户报名字（标题、简称、作者加年份都行），Lumen 调 `find_seed_paper`，程序去查，在对话里立一张种子卡：每个候选一行，标题、作者、日期、编号都是程序写的，带「是这篇」「不是」。一个名字最多给 3 个候选；查不到就说查不到，请用户给链接或更完整的标题。认过的种子由 `propose_topic_search` 带上起草卡（卡上「种子 · 钉住」一段），Apply 时写进主题配置的 `seeds`，在标签库里各记一条 `yes` 和一条 `pinned`（同一时刻，`pinned` 在后，生效的是它），在派第一次 run 之前写，第一版起就钉在简报最前面。

查法（`seed-lookup.ts`）：`find_seed_paper` 两个参数，`name` 是照论文本身的写法去查的名字（标题、简称、作者加年份、arXiv 编号或链接），`said` 是用户原话。名字里有 arXiv 编号就按编号查一次；否则 arXiv 搜索和 Hugging Face 论文搜索各问一次，两边都没有对得上的才问一次 Semantic Scholar（期刊论文靠它，带设置里用户自己的 Semantic Scholar key，同别处调 S2 的地方）。只有对得上的才上卡（`plausiblePaper`）：标题相等或一方含另一方（短名至少 6 个字符），或者名字去掉虚词后至少 3 个词、论文的标题加作者加年份里含其中至少 80%（`COVERAGE_THRESHOLD`，记错一个词还认得出，「Vaswani 2017 attention」也认得出）。库对它没有的论文给出的最近邻是别的论文，一篇都不上卡；全都对不上就是没找到，不立卡，回给 Lumen 让它问用户要链接或全名。标题相等的排前面，其余按相关度。没有 arXiv 编号也没有 DOI 的候选不上卡，钉不住。请求都走 run 用的主机闸（`infoFetch`），在冷却的库当场拒绝，回给 Lumen 说在冷却，不等。

认法（`seeds.ts`）：卡上点「是这篇」「不是」记在卡上，同时在对话里留一行（「是这篇：……」），下一轮 Lumen 看得到。用户在话里认的，Lumen 把候选的键（`arxiv:<id>`、`doi:<doi>`）传给 `propose_topic_search` 的 `seeds`；卡上点过「是这篇」的不传也算，点过「不是」的传了也不算。只有带 `once` 的起草卡收种子。

来源。见下一节。起草卡上写一行「来源：arXiv, Hugging Face。不翻：X，学术题。」，再一行「只看这一次：不每晚跟。出一份简报，聊着改，你说可以了就移进阅读。」X 不读的主题，卡上不写「X 慢慢翻、另出一期」那句。

## 来源开关

主题配置加 `sources`：这个主题读哪些源（`pace.ts` 的 `RunSource`）。起草时 Lumen 判这个题是不是学术题，学术题默认不含 `x`，写在卡上让用户纠正；不是学术题照旧全读。旧配置没有这个字段，按全读算。对所有主题都有效，不只专题调研。`propose_topic_search` 带 `academic`（Lumen 判的学术题，卡上说明 X 为什么不翻）和 `sources`；学术题没给 `sources` 时读 arXiv 和 Hugging Face；选了全部源时不写这个字段，以后加的源照样读。

不含 `x` 的主题：第一次 run 不分两段（88「第一次分两段」），只有快段，一段读完，结果文件不写 `awaiting`；不拿防休眠锁、不查 X 登录、不进 X 的排队；`planRetry` 不列 X；源健康不写 X 那几行（`build-result.ts` 写源健康时按 `sources` 滤）；开场、确认回执、`background_status` 和卡片不说「X 还在读」。读源一律经 `pace.ts` 的 `topicSources`、`sourcesOf(part, topic)`、`splitsFirstLook(kind, topic)`。

## 一份简报

一个专题调研只有一份简报，各版是它的不同版本。第一版就是第一次 run 的那一期（键照旧 `first:<searchId>`），在 info 书架的各期一排，不在专题册一排。封面版头写「专题 · 只看这一次」，和每日简报的「每日简报」分开，边框用苔绿；书架卡下写「调研中 · 第 n 版 · m 条」。

书的结构照 88「简报书」，几处不同：

- 封面后第一页：题名、「第 n 版 · 日期」，一句「这份简报回答一件事：<主题配置的 scope>」（程序照抄 scope，结果文件里没有模型写的这段），一行来源和回看窗口（程序写，窗口取第一次 run 的 `window`：「来源：arXiv、Hugging Face，回看 2 年。X 没有翻。」；主题配置不存「学术题」，只按 `sources` 里有没有 X 写），条数（正文几条、札记几条、钉住几篇），一句「哪条有想法就在 Lumen 对话里说，你确认的意见会让这份简报原地更新」。
- 第二版起，「这次更新」放在最前面，目录之前（见「更新」）。
- 目录先列钉住的，再列正文，最后札记（Notes 在专题调研里叫札记）。
- 每条的版头标签：钉住的写「钉住 · 你给的种子」或「钉住 · 你钉的」，没钉的写子题；读深按 `confidence.read.depth`（旧条目按 `facts.depth`）写「读了原文」「读了正文开头」「只读了摘要」；本版变动写「新增」「改写」「降到札记」「新钉」。
- 每一条的原文都挂成这本书的辅助资料（88 每期最多 12 份的上限对专题调研放开到全部条目）。每版是一本新书，辅助资料跟着每版重新取一遍（每份一次请求），更新几次就多取几次。

## 条目格式

每条按这个顺序写，括号里是条目 `parts` 的字段（`result-types.ts` 的 `EntryParts`），用不懂这个领域的人也读得懂的中文（书的语言照 88 跟界面语言；下面说的是中文版）：

1. 背景（`background`）：这件事为什么要做。
2. 之前的工作（`prior`）：以前怎么做，点名代表工作。
3. 不足（`gap`）：以前的做法缺什么，用论文自己的说法，原话放进 `quote`。
4. 这篇做了什么（`method`，分段）：讲成一个能读的故事，每一步写明是谁（大模型、算法工具、人）做什么。
5. 成果（`results`）：精确数字，带比较对象（「75%，PySR 40%」），一个比较一句。
6. 和你的目标的关系（`relevance.helps`、`relevance.cannot`）：分「帮得上」和「碰不到」两段，对着主题的 scope、want、judgments 说。
7. 把握（`confidence`）：读到多深（`read`，程序写：`depth` 取自 `facts.depth`，读了全文 / 读了正文开头 / 只读了摘要；全文读到封顶时 `cut` 为真，`through` 是读到的最后一节的标题）；「论文自己承认」的局限（`admitted`，带原话）；「我们看到」的问题（`ours`，比如准确率由同一个模型判、对照的数字没有重跑）。

术语第一次出现时在句子里用一个分句解释（「符号回归，也就是直接从数据里找显式的数学式子」），解不解释由「读者懂什么」定。

每段是一串句子 `{text, cites, quote?}`，`method` 是几段这样的句子。`cites` 是这句站得住的节，用 88「材料登记」的节号 `M3.§2`：那一节的正文在 run 目录的 `materials/M3.json`，标题在结果文件的 `materials` 里，程序能核对，H 片据此翻到那一节。书里画成小章节号（「§3.3」，取那节标题开头的编号，认数字、`A.1`、罗马数字；PDF 读的节标题是「PDF part n」，画成「第 n 部分」；标题没有编号的画标题前 24 字；不知道标题的画「§k」；整份材料 `M3` 画「原文」）。除了「帮得上」「碰不到」「我们看到」三段，每句至少引一节，只能引这一条自己的材料；只有一节的材料写 `M3` 按 `M3.§1` 收。

核对在 `entry-parts.ts`。每句的数字必须出现在它引的那几节里（另认条目标题和事实行），88 的数字核对对专题调研收紧到逐句；没引节的句子照旧对整条的材料核。`quote` 必须出现在所引的某一节里（大小写、引号、破折号、空白不计，省略号隔开的几段各自要在）。引了不存在的节、别条的材料、该引没引，都算错。这些错和全景、结论的错一起退回改一次：重试带上模型上一次的整份回答和错处，只要改正的部分（全景有错才回全景；条目只回被点名的，每条只回要改的段，整段重写），程序按段盖回上一次的回答再核（`compose.ts` 的 `mergeCorrection`），上一次回答不是 JSON 才整份重写；第二次还错，那句不印，记进 `confidence.dropped`（哪一段，因为数字、原话还是出处），书里在那段写一句没核对上，成果段因数字掉的写「成果的数字没核对上」。全景和结论第二次还错照旧走兜底版；一条连「这篇做了什么」都没写的算没写成。作者、日期、编号、链接照 88 硬规则 1 由程序写，提示词明说不写。

只读了摘要的条目照样分七段，摘要没给的段回空，书里写「摘要里没写」；成果段没有数字就写「具体数字摘要里没给」（G 片按 `read.depth` 和成果句里有没有数字判），不许从别处补。读了正文的条目空着的段写「读到的部分没写」。

条目的 `body` 同时存这些句子去掉出处后的段落，给认不得 `parts` 的出书路径用；`unknown` 不写。

篇幅（初值，`entry-parts.ts` 的 `STUDY_ENTRY_CHARS`，只写进提示词，程序不卡）：读了原文的条目在手机上半页到一页，正文不超过 1200 字；只读了摘要的不超过 400 字；英文等按 2.6 字一词折算。

读深。专题调研不等模型开口：第一次 run 写稿前，程序把还没读全的论文按「种子的先、再按分数」读全文（`compose.ts` 的 `studyReadOrder`），篇数沿用 88 的 `DEEP_READS.first`（5 篇），写稿不再给 `deeper`（没到上限说明都试过了）。读法照 88：整篇 arXiv HTML 去掉摘要、参考文献和致谢，没有 HTML 用 PDF 文字层到参考文献前；按小标题切节登记；按节的先后取到 4.8 万字封顶（`PAPER_FULL_CHARS`），长论文截掉的是后面的节和附录。每件最多 2 份原文（`ORIGINALS_PER_ITEM`）不变，全文那份替掉开头那份。每次更新给新加的条目另 3 篇（初值，E 片）。

花费（估算，没量过；日常档 Sonnet 5.5：输入每百万 token 2 美元，输出 10 美元，缓存读 0.2，缓存写 2.5）：普通第一次 run 不读深时，写稿输入约 1.2 万 token、输出约 7 千，按两次写稿算约 0.17 美元。专题调研 5 篇全文进提示词，输入约 7 万 token；七段的输出约 1.5 万 token（读深 5 条各约 1.6 千，只读摘要 10 条各约 6 百）；第二次写稿读缓存，但输出整份重写，合计约 0.5 美元，每份调研多约 0.3 美元，大头是输出。网络：arXiv HTML 30 分钟内存过（`fetch-memo.ts`），读全文不再发请求；没有 HTML 的每篇多下一次 PDF。

## 读者懂什么

写条目那一步除了主题和候选材料，还拿到读者懂什么的 statement，逐个术语决定解释不解释；拿不准就在句子里短短解释一句。

D 片之前：statement 只有 `profile` 和 `concern` 两种 kind（`memory/statements/types.ts`）；48 把「懂了什么、卡在什么上」算在 profile 里，dream 只写 profile（`memory/dream/proposals.ts`）；写稿已经拿到全部 profile 的文字（`build-live.ts` 的 `profile`，`compose.ts` 的 `ComposeInput.profile`）。D 片加的（已进 main）：

- `STATEMENT_KINDS` 加 `known`：读者懂或不懂某个东西，一条一句（「熟悉强化学习和 AlphaZero」「不熟悉符号回归」）。profile 只留讲法。
- dream 的提议可以写 `known`，证据是 `understood-concept` 和 `stuck-point` 观察（`memory/observations/types.ts`）。
- `statement_write` 的 kind 说明加 `known`，回执「Noted about you」和 profile 一样。
- 写稿的 `ComposeInput` 加 `known`（没被取代的 known 文字），提示词写明按它决定解释，拿不准就解释。
- dream 的 known 只能挂这两种观察，程序校验；dream 自己写的 profile 里讲懂不懂的，可以 supersede 时带 `kind: known` 挪过去。
- 读者自己说的排在 dream 的前面：`build-live.ts` 按这个顺序交给写稿，提示词写明两条冲突时前面的算数；dream 照旧不许 supersede 读者写的。
- 阅读对话的记忆段（`memory/live/memory-section.ts`）和 info 侧的读者段（`memory/statements/section.ts`）也印 known：前者接在同一作者的 profile 后面，后者单独一块。

对话里写回：用户问「符号回归是什么」，Lumen 答完调 `statement_write` 写一条 reader 的 known（「不熟悉符号回归」，evidence 是那条问话）；用户说「这个我清楚」，写「清楚 X」。statement 是猜测，对话里的纠正用同一个工具带目标下标取代旧条（48「读者自己写」）。

## 对话里改

用户读简报时对话窗在旁边：手机是整屏 sheet（68「卢明的对话窗」），iPad 和桌面是书旁的小面板。问法照 88「简报的对话」：选中一句 Ask，或直接说。Lumen 用简报的读工具（`read_pages`、`search_topic`、`read_supplement`，`reading/issue-desk.ts`）读原文回答，带 `[p.N "原话"]` 和原文的节号。

聊出来的意见不当场生效。Lumen 觉得说到了可以记的地方，先用一句话复述自己的理解，再调 `propose_study_lines` 立一张确认卡，每行一条：

| 种类 | 例子 | 记到哪 |
|---|---|---|
| 不要 | 只从现成数据拟合方程、不回头设计下一轮实验的符号回归 | 主题配置的 `avoid` |
| 我的理解 | 先验怎样进入归纳和实验设计是重点，排序时优先 | 主题配置的 `judgments` |
| 钉住 | LLM-IDEA | 只动这份简报，标签库记 `pinned` |
| 降级 | The AI Scientist 降到札记 | 只动这份简报，标签库记 `borderline` |
| 改写 | KeplerAgent「和你的目标的关系」写重了，它不设计下一轮实验 | 只动这份简报 |

每行下面一行小字「你说：『……』」是用户原话（程序按 propose 的 `readerLines` 找到那条消息做锚），一行写记到哪。每行三个按钮：对 / 改一下 / 别记。「改一下」就地改那句，改完算对。全部定完，卡片底部的「按这几条更新简报」才可点；点了才写配置、写标签、派更新。用户在对话里说「对，更新吧」时 Lumen 调 `update_study_brief`，对本对话最新那张确认卡做和按钮同一个动作（做法同 `confirm_topic_search`）。别记的行什么都不写。

钉住可以点当前版里没有的论文（简报里出现过的都行），降级和改写只能点当前版里的条目。一张卡只写一次：按下后先写配置、调研记录和标签，再派更新（`study-lines.ts` 的 `sendStudyLines`）。派不出去（上一次还在做，或被拒）时卡停在「已记下」，再按一次只重新派，不再写。调研已结束的卡按了什么都不做。

写配置走 `update_topic_search` 同一条路（`changeTopicSearch`，`revision` 加一，原话进 `answers`）；只有钉住、降级、改写的卡不动配置。钉住、降级、改写只进这一次的更新请求和标签库，不进主题配置。所有确认的行都进调研记录（`L<n>`），钉住和降级再各记一条标签（`pinned`、`borderline`，`source: "line"`，带当前版里的位置和分数）。

## 更新

更新是一种新的 run，kind 照旧 `topic-search`，brief kind `update`，idempotencyKey `topic-search:<id>:update:<n>`。n 数的是请求次数，不是版本号：失败的更新也占掉一个 n（`run-worker.ts` 的 `nextUpdateNumber` 取已有键里最大的加一），版本号在构建时定，是文件里最大的版号加一。同一调研的第一次 run、重试或更新还在 pending/running 时不派（`askUpdateRun` 回 `busy`），Lumen 说还在改。和别的 run 一样在桌面采集端跑，`background_status` 能查。

给 F 片的接缝是 `runs-live.ts` 的 `askStudyUpdate(searchId, { lines?, queries? })`。F 先写确认行、主题配置（补搜查询追加进 `queries`）和标签，再调它。`lines` 是这次用的确认行 id，不给就用所有确认过、还没被哪一版用过的行；`queries` 是补搜查询的 id，最多 3 条（`UPDATE_QUERIES_MAX`，初值）。

一次更新做三件事：

1. 补搜（`read` 相位）。只跑主题 `sources` 里的 arXiv 和 Hugging Face，不读 X，不拿防休眠锁。上一版没跑完的查询（`StudyVersion.skipped`）排前面，再接这次带的，只留主题里还有的（`update.ts` 的 `planUpdate`）。
2. 重判候选池（`build-update.ts`）。池子是这个调研所有 run 读到的东西：第一次 run、`retries` 和 `judged` 里每个 run 的目录里的 `arxiv-read.json`、`hf-read.json`、`x-read.json`，加这次补搜读到的。上一版的条目、钉住的和降级的不受相关度门槛和融合截断，一定进池；钉住的论文在读到的和文件里都没有时按键补查，同「起草与种子」的种子。重排的提示带上主题配置、这次的确认行（用行自己的 id `L1`、`L2`…）、标签库里每条目当前生效的标签，yes（钉住的算 yes，种子的 yes 和钉住同一时刻写下、生效的是钉住）、borderline、no 各最多 6 条（标题加理由，当示例）。模型每个候选多回一个可选的 `because`，只认这次给的行 id。
3. 选件和重写。钉住的排最前，不占条数也不受分数下限；降级的进札记；其余照分数，45 分（`LABEL_BOUNDARY`）以下进札记。上一版有的条目原样搬，不调模型。有改写行的条目用它的原材料重写，换新编号、键不变，旧版留旧文字。新加的条目照「条目格式」写，写之前先读全文，最多 3 篇（`UPDATE_DEEP_READS`，初值）。全景每版重写。

钉住和降级按读者最后一句话定（`update.ts` 的 `studyMarks`）：每个条目最新的标签和所有确认过的钉住、降级行按时间排，后来的说了算。`pinned` 标签钉住；确认行写的 `borderline` 标签降级；问答里的「说不准」和别的标签把钉住、降级撤掉。钉住、降级跨版本有效，直到读者另说；改写行只管它那一次更新。

每处改动挂一行（`diffVersion`）：钉住、降级、改写取那条确认行，新加和去掉取重排的 `because`，都没有是 null，书里就不写原因行。版本记进 `study.versions`；`retries` 记一条 `part: "update"`、`version: n`；用过的确认行在调研记录里写上 `usedIn`（`putStudyLines`）。更新不调 `ran`，主题的 `lastRunAt` 和 `revision` 不动。

判不了和写不成都不出新版，当前版不变。重排失败或一个候选都没判：文件里只记一条不带版号的 `retries` 和 `unjudged`，不列条目，确认行不标用过，下一次更新再用。写稿失败：构建抛错，run 失败，文件不动，没有兜底版。

冷却。补搜碰到 arXiv 或 Hugging Face 冷却（主机闸 `hostGate`），进度行写还要等几分钟，run 在 `read` 相位里用 `deps.sleep` 等到冷却结束，把被挡的查询从读取文件里拿掉再搜，最多读 3 轮（`UPDATE_READ_ROUNDS`）。冷却剩下超过 60 分钟（`UPDATE_COOLDOWN_WAIT_MS`，初值）就不等，用已有的候选出新版。被挡和没跑到的查询记在这一版的 `skipped` 上（`skippedQueries`），「这次更新」末尾写一行，下次更新先跑它们。

专题的慢段和重试。要读 X 的专题，第一次 run 照 88 分两段，快段出第 1 版（键 `first:<searchId>`）。慢段（X）和以后的重试读到的东西不出普通的一期，而是做成下一版（`update.ts` 的 `addedVersion`）：当前版的条目原样，新条目按分数并进来（种子钉住），每条记一处 `add`，不挂行，全景用并好的文件的；`retries` 那条带版号。什么都没加就不出版本。

出书。run 关时 `closed` 带 kind `update` 和版号（专题的慢段和重试做出新版时也这样报），`runs-live.ts` 原样交给 `info/issue/live.ts` 的 `issueRunClosed`，即 `runClosed(deps, { searchId, kind: "update", night: null, resultFile, version: n })`，按 `study:<searchId>:v<n>` 组装。没做出版本的不带 `version`，不组装。

更新期间书照常能读。阅读器顶上一条状态「正在更新到第 2 版，几分钟。现在看的是第 1 版，可以接着看」；门口对话里没有单独的 run 卡，确认卡底部一行跟着 run 走：等开着的电脑、正在更新、冷却约 n 分钟后接着搜、做完了、没做成（`study-lines.ts` 的 `studyRunStatus`；冷却分钟数从 `run.ts` 的进度行读；桌面跑的 run 靠同步过来，卡每 20 秒再看一次，`use-study-run.ts`）。新版出来，盒里放一项（kind `brief-issue`，body 是新版的书，封面程序写「<题名> · 第 2 版：加 3 · 去 2 · 降 1 · 改 1」），Lumen 在当天门口对话里说一句新版好了、哪一两条值得先看。开着的那本如果是刚才的当前版，换成新版，停在同一条上（那条还在的话）。

## 这次更新

第二版起，书的最前面一块「这次更新」，程序写，不经模型：

- 标题行：「这次更新 · 10月21日 15:41 · 从第 1 版」。
- 分组：加 n 条、去 n 条、降 n 条进札记、改 n 条、新钉 n 篇。每组下面每条一行：条目标题（链接到那条的页，降到札记的链接到札记里那一条；去掉的画删除线、不能点）、「因为你说：『……』」。EPUB 没有固定页码，不印页码。原因取自 `changes[].line` 指的那行在调研记录里的 `said`（只取 `confirmed` 的行）；没有 `line` 的不写原因行。
- 有没跑完的补搜就加一行说明。

每条的版头标签（新增、改写、降到札记、新钉）只在它变动的那一版上有，下一版就没了。

## 版本

阅读器顶栏在标题右边一个「第 n 版」按钮，点开版本列表：每版一行，版号、时间、一句改动（「加 3 · 去 2 · 降 1 · 改 1」），当前版标「当前」，正在看的标「正在看」。每行两个动作：

- 打开：在阅读器里看那一版，只是看。顶上一条「你在看第 1 版，不是当前的第 2 版」和「看当前」。
- 回到这一版：先确认一次（「这本书换回第 1 版的内容，别的版本留在列表里。你确认过的几条不撤，要撤跟 Lumen 说」），确认后当前版指回那一版。不新出版本号，版本列表不变；下一次更新从当前版改起，版号接着最大的往后。

回到旧版不撤已经写进主题配置的「不要」和判断，也不撤标签。

划线跟着版本：新版出来时，旧版上的划线按那句原文搬到新版，那句在新版里还在就搬，不在就留在旧版上。

## 结束

用户说可以了（「可以了」「就这样」），Lumen 调 `end_study`，在对话里立一张移进阅读卡：标题「移进阅读 · <题名> · 第 n 版」，reading 主题列表（建议照 68「收链接」的标法），末行新建主题，一行小字「移进去以后不再更新，主题记成结束」，按钮「移进阅读，结束调研」和「再看看」。确认后：

- 当前版的书（照回滚算）走 88「info 书架与专题册」的 Move to…：第一次移入 `addFileToTopic`；之后它是一本普通的书（课堂、划线线程）。info 书架不再显示它（书架本来就不显示已在某个 reading 主题下的书）。移不进去就什么都不做，卡上说没移成。
- 主题 `stopFollowing`：记 `stopped`，concern 标 `lapsed`。
- 旧版的书走删书联动删掉，版本记录留着。
- 标签库、种子、主题配置里的「不要」和判断都留着。卡片回执写「这次调研已结束，不再更新。你钉住的 n 篇和记下的 m 条留在这次调研里」，不许诺以后别的调研会用它们（见「待定」最后一条）。n 是标签库里最新一条是 `pinned` 的论文数，m 是确认过的「不要」和「我的理解」行数。
- 结束后 `retry_topic_search` 拒绝这个题（`retry-tool.ts`：`once` 的题停了就是结束了）。

做的地方是 `ui/components/companion/study-end.ts`：书架文件归 `info/issue`，`info/topic-search` 读不了；`ui/components/info` 又 import 了 companion，所以 `fileVolume` 那两行在这里照抄，不 import。

书架上也能结束：专题封面右下角的菜单（和专题册一样的 `CardMenu`）有「打开」和「移进阅读，结束调研…」。点后者弹出同一张移进阅读卡当确认（`study-end.ts` 的 `shelfStudyMoveCard`：当前版的书照回滚算，建议的主题是和题名同名的 reading 主题，没有就不标），卡上按「移进阅读，结束调研」走同一个 `endStudyLive`，「再看看」关掉。书架没有模型，建议只能按名字对。

专题简报不过期（`info/issue/expiry.ts` 跳过带 `study` 的行，调研中和结束后都跳过：结束后当前版在 reading 里，旧版由结束的流程删）。

## 攒着问

照 88「攒着问」：每期最多 3 个，已定的不再问。专题调研多一种问题：对某一条的标注问题（「这篇算对路吗？」），卡上印条目标题和它的一句话结论，快捷回答「对路」「不对路」「说不准」，外加「我自己说」。

挑哪条（`questions.ts` 的 `labelQuestion`，初值）：这一版的条目里，不在标签库里、以前没问过、最终分在 40 到 60 之间的，取离 45 最近的那条（45 是 `info/issue/plan.ts` 的 `NOTE_BELOW`，正文和札记的分界，分数在这附近时用户的回答最有信息），一样近取文件里靠前的。没有就不问。只有带 `once` 的主题问，每版最多 1 个，占 3 个里的一个，排在这一版其他问题后面；它不进待问队列等下一期，只以「已问」记在队列里防止同一条再问。

`ResultQuestion.template.code` 加 `label-item`，参数是条目键、标题、那句结论、分数、版号、当时主题配置的 `revision`；组装简报时（`info/issue/opening-record.ts` 的 `placedQuestion`）按书的安排补上位置（钉住 `pinned`、正文 `main`、札记 `note`、没进书 `absent`）、它在书里的编号和这本书的版号。

回答由程序写，不经模型（`info/issue/question-card.ts`，门口对话 `use-door-chat.ts`）：点「对路」「说不准」，按钮上那句当用户的一行话落进对话，不跑回合，立刻用 `addTopicLabels` 写一条 `source: "question"` 的标签，理由是那句话原样，证据是那行的消息锚点，`brief` 是上面那几个参数；卡上回执「已记进这个主题的标注：对路。」。点「不对路」照样写，然后卡上问「为什么不对路？」并给「不说了」：用户接着打的一句原样作理由再写一条 `no`（同一条目后写的盖前面的）。点「我自己说」，用户打的那句先留在卡上，卡再问算哪种，点了才写，理由是那句原话。打字的这两种照常发给模型，附一条说明：标签已由 app 写好，不要再写到别处，回一句短话。

## 标签

每个主题一个标签库 `topic-search-labels-<searchId>.json`，随账户同步，按记录合并（`palace/kinds.ts` 登记），只追加：

```ts
interface TopicLabel {
  id: string;                 // "tl-" + 8 hex
  searchId: string;
  item: string;               // 条目身份：arxiv:<id>，或 info/rank/link-identity.ts 的事件键
  title: string;              // 程序写
  label: "yes" | "no" | "borderline" | "pinned";
  reason: string;             // 用户原话
  source: "seed" | "line" | "question" | "import";  // import：用重放脚本从手写清单导入
  evidence: string;           // 那句话的消息锚点
  at: number;
  brief: { version: number; place: "pinned" | "main" | "note" | "absent"; rank: number | null; score: number | null } | null;
  criteria: number;           // 当时主题配置的 revision
}
```

同一条目后来的标签盖前面的（按 `at` 取最新），旧的留着。`brief` 记当时这条在第几版、在哪、第几位、几分，没进简报的（种子、对话里提到但不在书里的）记 `absent`。`criteria` 现在用主题配置的 `revision`，以后有判据表（调研第 1 条）换成判据版本。

这些标签是这个题的金标集。离线重放脚本 `scripts/topic-labels-replay.ts`（纯函数在 `info/topic-search/label-replay.ts`）：给主题 id 和一份结果文件，读标签库（每个条目取最新那条），不联网、不调模型，报：yes 和钉住的条目有几条在结果里（召回）；它们的名次（按最终分排）、分数、MRR、前 10 和前 20 里各几条；no 条目有几条进了结果、在第几名；borderline 只列不计。结果文件不存候选池，没进结果的 yes 条目靠结果里记的 run 目录（`runDir`、`retries` 和 `judged` 的 run）里的 `arxiv-read.json`、`hf-read.json`、`x-read.json` 分成「没检索到」和「检索到了没选上」；同目录有主题配置时按 `gatherCandidates` 重算本地相关度，再分出「没过相关度门槛」。重排要调模型，脚本不重跑，名次就是那份结果里的。比较检索和打分改动前后，用 `--against` 并排看两份结果。专题的结果文件按最新一版（或 `--version n`）的条目算。`--import-seeds` 从手写清单（每行 `yes|no|borderline|pinned <arXiv 号、链接、键或标题> [| 理由]`）写标签，`source: "import"`，写到 `--out` 指定的目录，只有带 `--appdata` 才写进 app 自己的数据目录；标题只按结果和读取里的标题精确匹配，匹配不上的不写。

它们也是 [decision-data](../north-star/decision-data.md) 说的决策数据的原料：带上下文（主题配置、当时的版次和位置）、有显式理由。只留本地和账户同步，不上传；上传要另行征得用户同意，流程归 decision-data。

## 数据

主题配置（`info/topic-search/types.ts`）加：

```ts
interface TopicSearch {
  // …88 的字段
  once?: boolean;              // 专题调研：不派夜跑，第一次送达后不停，end_study 时才 stopped
  sources?: RunSource[];       // 读哪些源；缺省全读
  seeds?: TopicSeed[];
}

interface TopicSeed {
  key: string;                 // arxiv:<id> 或 doi:<doi>，link-identity 的键
  title: string;               // 程序查到的
  said: string;                // 用户报的名字，原话
  at: number;
}
```

结果文件：专题调研只有一份，就是第一次 run 那份，每次更新照 `mergeRetry` 的接法并进去：新条目和改写后的条目接着编号（改写的是新编号、同一个键，旧的留给旧版），材料接着编号，正文进这次 run 的目录，`retries` 记一条，`ResultRetry.part` 加 `"update"` 并带版号（专题的慢段和重试做出的版本也带版号，见「更新」）。文件多一个字段：

```ts
interface TopicSearchResult {
  // …88 的字段
  study?: { versions: StudyVersion[] };
}

interface StudyVersion {
  n: number;                   // 1, 2, 3 …
  at: number;
  runId: string;
  base: number | null;         // 从哪一版改出来
  entries: { item: string; place: "pinned" | "main" | "note"; tag: "new" | "rewritten" | "demoted" | "pinned" | null }[];  // item 是文件里的条目号（E7），改写后同键换号，各版指各自的文字
  removed: { key: string; title: string; line: string | null }[];
  changes: { kind: "add" | "remove" | "demote" | "rewrite" | "pin"; item: string; line: string | null }[];  // item 是条目键
  lines: string[];             // 促成这一版的确认行
  skipped?: string[];          // 冷却没跑的补搜查询 id
  overview: TopicSearchResult["overview"];
}
```

一版是这份文件上的一张视图：`versionPart(result, n)`（`result-types.ts`，照 `firstPart`、`retryPart` 的写法）取出那一版的条目（按 `entries` 的顺序）、材料、全景和问题，出书用它；那一版的 `StudyVersion` 挂在返回值的 `studyVersion` 上（不进文件），版头标签和位置从这里读。第 1 版的问题是第一次 run 自己的，之后各版的是带 `version: n` 的那条 `retries` 记录的。条目加 `parts`（七段，见「条目格式」），旧条目没有就按 `summary` 加 `body` 印。

调研记录 `topic-study-<searchId>.json`，同步，按记录合并，任何设备都写：

```ts
interface StudyFile {
  version: 1;
  searchId: string;
  lines: StudyLine[];                                  // 按 id 合并
  rollbacks: { to: number; at: number }[];             // 只追加
}
```

`rollbacks` 在盘上是以 `rb-<at>` 为键的 map，读出来按时间排成数组：同步的按记录合并只按 id 合并 `lines`，旁边的字段按字段合并，数组两边都加了会丢一边，map 按键合并两边都留（`info/topic-search/study.ts`）。

```ts
interface StudyLine {
  id: string;                  // "L" + n
  kind: "avoid" | "judgment" | "pin" | "demote" | "rewrite";
  text: string;                // 卡上那句，用户改过就是改后的
  said: string;                // 用户原话
  evidence: string;            // 消息锚点
  item: string | null;         // 钉住、降级、改写指的条目键
  state: "confirmed" | "dropped";
  at: number;
  usedIn: number | null;       // 用在哪一版
}
```

当前版是最新的那个事件：最新一版出来的时间和最新一次回到旧版的时间里晚的那个。

书架索引（`info/issue/types.ts` 的 `IssueEntry`）加 `study?: { current: number; versions: { n: number; bookId: string; at: number; date: string; line: string; items: number; boxItemId: string }[] }`，那一行的键仍是 `first:<searchId>`，期号不随版本变；行上的 `bookId`、`items`、`opening`、`topics` 跟最新一版。`current` 是做出来的最新版号，回到旧版不改它；当前版照「版本」在读的时候用 `currentVersion(versions, rollbacks)` 算（`study.ts`，参数只要 `n`、`at`，可以直接传书架行的 `versions`）。每版的书单独入库（kind `issue`，库里名「<题名> · 第 n 版」）。第 1 版就是第一次 run 那期，键 `first:<searchId>`；第 2 版起键 `study:<searchId>:v<n>`；都记在 `info-issue-state.json` 的 done 里，组装照 88 按键幂等：那一版已在行上就只把它的盒项再放一次。盒项的 `boxId` 第 1 版 `issue:first:<searchId>`，之后 `issue:study:<searchId>:v<n>`。G 片之前出过的专题第一期没有 `study`，原样留着；它的第 2 版组装时把那一期的书补记成第 1 版。

结果文件没有 `study.versions`（C、E 片之前写的）时，出书按第一次 run 当第 1 版：种子钉住，其余照 88 的规则分正文和札记（`study-plan.ts` 的 `withStudyVersions`）。

## run 和出书的改动

`info/topic-search/run.ts`：

- `TopicSearchRunKind` 加 `update`，`encodeBrief`、`parseBrief`、`topicSearchRunKey` 跟着加 `update:<n>`（n 数请求次数），brief 带 `lines`、`queries`。

- 按 `sources` 决定读哪些源、分不分段（`pace.ts` 的 `sourcesOf` 和 `splitsFirstLook` 加主题参数）。

`info/topic-search/build-result.ts`：`makeResultBuilder` 加更新路径。`BuildTopicSearchResultArgs` 加 `update`（这次的 run、确认行 id、补搜查询 id；基准版、钉住、降级、改写和标签示例由构建从调研记录和标签库读）。`carry` 对专题调研传全部之前的 run id。重排（`rank-pool.ts`）多收确认行和标签示例，多回 `because`。选件（`select.ts`）先放钉住的，降级的直接进札记。写稿（`compose.ts`）加专题调研的条目格式、`known`、逐句出处和逐句数字核对，只写新的和改写的。最后用 `mergeRetry` 并进文件，写 `study.versions`。第一次 run 也写 `study.versions` 的第 1 版（钉住的种子作为条目）。种子不在这次读到的候选里时，程序按 arXiv 号用种子的查法补一个候选（构建依赖 `seedPaper`，接 `seed-live.ts` 的 `byArxivId`），照常看原文；种子不受相关度门槛、融合截断和短名单的限制。只有 DOI 的种子补不进来（候选池只装 arXiv 论文和帖子），查不到或在冷却的这次缺着，下一次构建再查。

`nightly.ts` 和 `info/issue/assemble.ts` 等「当晚所有 active 主题」的地方跳过 `once`（共用 `topic-searches.ts` 的 `nightlyTopicSearches`；组装等的主题列表在 `info/issue/live.ts` 的 `activeSearchIds` 里取）。`run-worker.ts` 加 `askUpdateRun`（同一调研的第一次 run、重试、更新在跑时回 `busy`），`run-status.ts` 认得更新 run（标题「第 n 版更新」，三步进度）。

`info/issue/`（G 片，已进 main）：`study-plan.ts` 排一版（钉住、正文、札记按 `StudyVersion.entries`，不走 88 的分数规则），`render-study.ts` 出书（这次更新、首页、目录、每条一页的七段、札记、全景、封面），`study-cites.ts` 定节号和条目的标记，`assemble.ts` 按版组装并改那一行的 `study`，辅助资料对专题调研不设 12 份上限，`expiry.ts` 跳过专题行。`live.ts` 给 `once` 的主题带上 `study: { scope, sources, seeds }`。主题判不出时（主题已删）看结果文件有没有 `study`。不是专题的书一个字节都不变，`tests/info/issue/issue.test.ts` 末尾按哈希钉住。

H 片可以依赖的：

- 节号：`<a class="rp-cite" id="rp-cite-E7-3" href="#rp-cite-M3-2">§3.3</a>`。`href` 只是记号，书里没有这个 id，点了要 H 拦下；`anchorOfHref(href)` 还原成 `M3.§2`（整份材料是 `M3`），连解析过的完整路径也认。`id` 是条目号加它在那一页上的序号。bindery 的清洗只留 `id`、`class`、相对 `href`，`data-*` 会被删，所以标记只用这三样。
- 条目：每条的页、札记里的每一条都包在 `<div class="rp-study-item" id="rp-item-E7">` 里，`itemOfAnchorId` 还原条目号。新版到了「停在同一条」可以按条目键（结果文件里同键换号）找到新版的条目号再找这个 id。
- 版本列表：书架行的 `study.versions`（版号、书、时间、日期、一句改动、条数），`studyOfBook(shelf, bookId)` 从书找到那一行和那一版；当前版用 `currentVersion` 加调研记录的 `rollbacks` 算。
- 节对应的原文：材料 `M3` 的辅助资料是它的 `url` 重新取的那本（`attachOriginal`），节标题在结果文件 `materials[].sections`。

H 片（已进 main）的做法：

- 判断都在 `info/issue/study-reader.ts`（纯函数）：`studyBookContext` 从书架行和调研记录的 `rollbacks` 算正在看的版和当前版；`versionRows` 出版本列表；`studyStrip` 定顶上那条（新版好了 > 在看旧版 > 正在更新）；`updatingTo` 从 legion 的 run 里找 idempotencyKey 为 `topic-search:<id>:update:<n>`、在 pending/running 的那个，有就是在出「已有最新版 + 1」那版（键里的 n 数的是请求次数，不是版号）；`landedAction` 定新版到了怎么办：开着的是当前版时，读者一分钟内没翻页（或屏幕不在前台）就直接换，否则顶上出「第 n 版好了 · 换过去」，不在读者眼皮底下换书；`itemAtPage` 加 `sameItemIn` 按条目键找到新版里同一条，换书后翻到它的页（按标题找页，`reading/issue.ts` 的 `headingPage`）。
- 界面在 `ui/components/reader/study/`：`use-study-reader.ts` 每 15 秒重读书架、调研记录和 run；`StudyChrome.tsx` 是顶栏的「第 n 版 ▾」、版本列表（打开、回到这一版，回到之前就地确认）、顶上那条和节号的原文 sheet。手机放在 `PhoneReaderBar` 标题右边、条贴在页顶；平板和桌面放在 `ReaderTopBar` 返回键后面、条在顶栏下面。换版是在同一个阅读器里换书（手机替换栈顶那一项）。
- 节号：书里点链接先交给 `reading/epub/reader-logic.ts` 的 `setBookLinkTaker`（三个 EPUB 视图跟链接之前都先问它），专题书开着时它拦下 `#rp-cite-…`。sheet 的数据 `citeSheet`：从链接的 id（`rp-cite-E7-3`）按出书时的计数顺序（`study-cites.ts` 的 `citeAt`，测试拿 G 片出的书逐个核对）找到那句话，中文那句标「要点」，句子自带的 `quote` 是英文原话；那一节的正文段落从材料缓存 `materials/M3.json` 取（有 quote 取含 quote 的段，否则取含这句数字的段，表格行在读取时就成了段落，否则取开头），按 `materialBodyPaths` 先找第一次 run 的目录再找各次更新的目录。底部「打开原文」用浏览器开材料的 url。
- 划线搬到新版：打开最新一版时（书架点开或从阅读器换过去），从它的 `base` 那版的书把划线和批注搬过来（`study-live.ts` 的 `prepareStudyBook`）。在旧版里落在哪一条（`rp-study-item` 块）就只搬进新版同键那一条的块，按原文找（`reading/replace/carry-marks.ts` 的 `carryMarksByBlock`）；条目外的（首页等）按原文全书找。新书已有划线就不搬；每台设备每本只搬一次；划线保留原 id，两台设备各搬一次写的是同一批记录。没搬过去的留在旧版，提示「n 处划线留在了第 m 版」。

和上文不一致、以代码为准的：「界面」表里「点节号开原文那一节」说的在阅读器里打开辅助资料并翻到那一节没有做：辅助资料是按 url 重新取的那本（arXiv 的往往是 PDF），节标题在里面找不准；sheet 底部用浏览器开原文。sheet 里的原文段落从书里读，见下一节。

## 节号的原文

材料正文缓存在 run 目录（`topic-search-runs/`，palace 登记为不同步），只有跑调研的那台电脑有。所以出书时把被引的各节原文写进书里（`info/issue/study-excerpts.ts`），手机和 iPad 上 sheet 一样有原文段落。

- 收哪些：这一版正文条目（钉住和正文，札记不印七段）的句子引到的节，按书里第一次引到的顺序，同一节只收一次。整份材料的引用（`M3`）收整份材料的正文。
- 每节最多 2000 字符（`SECTION_EXCERPT_CHARS`）：先收引它的句子指着的段（含 `quote` 的段、含句子里数字的段，和 sheet 找段的规则一样），再按原文顺序从开头补，补到放不下的那段为止；收进的段按原文顺序排。指着的段太长放不下时截到剩下的字数（少于 160 字符就不收），开头一段就超的也这样截。有段没收进的，这一节末尾写一行「这里截断，其余见原文」。
- 每本最多 12 万字符（`BOOK_EXCERPT_CHARS`）：按顺序收，放不下的节跳过并计数，块末写「还有 n 节引文放不下」。没有正文的节（缓存没有、文件坏了）直接跳过，不计数。
- 写法：书最后一节「引文原文」（目录里有，正文目录不列），开头一行说明每节最多约 2000 字符；每节一块 `<div class="rp-excerpt" id="rp-excerpt-M3-2">`，第一段是材料标题和节标题（PDF 读的写「第 n 部分」），原文每段是 `<p class="rp-excerpt-text">`。只用 `id`、`class`，经得起 bindery 清洗。
- 正文从哪来：组装（`assemble.ts` 的 `assembleStudy`）用 `loadStudyExcerpts` 按 `materialBodyPaths` 读缓存（第一次 run 的目录，再各次更新的目录）。组装在跑 run 的桌面上做，所以缓存都在；读不到的材料这本就不带它的原文。没有任何可收的节时书里没有这一节，和以前一样。
- 阅读器：点节号后 sheet 先从开着的这本书里按 `rp-excerpt-<锚点>` 找那一块（`study-live.ts` 的 `readBookExcerpt`，解析过的书留到换书），找不到才读 run 目录的缓存。两边的段都过同一个 `excerptFor` 挑要显示的。都没有时 sheet 写「这本书没有收这一节的正文，打开原文看」（这一功能之前出的书、放不下的节）。

体积（2026-10-22 量，`studyEpubInput` 加不加引文原文各出一次 EPUB，英文原文）：15 条（5 条读深、10 条只读摘要），材料用桌面上两次真实 run 的 23 份缓存正文（读了开头，每份约 9 千字符），引到 31 节、全收（8 节截断），收了 4.3 万字符，书从 19.7 KB 到 36.0 KB；5 篇读全文到 4.8 万字符封顶（各 15 节、每条引 10 节，正文取自同一批真实段落）加 10 篇摘要，引到 60 节、全收（53 节截断），收了 10 万字符，书从 20.6 KB 到 60.1 KB。辅助资料的原文（PDF）每份就以 MB 计，这点增量不算什么。

## 待定

- `find_seed_paper` 从一个名字怎么查准：简称（「AlphaFold 那篇」）、非 arXiv 的期刊论文、同名多篇，arXiv 标题搜索和 S2 标题匹配各自的命中率要拿真名字试。
