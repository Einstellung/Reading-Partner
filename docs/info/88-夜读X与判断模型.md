## 硬规则

1. 程序算得出的事实不经模型转手。页面由程序整理成文字，动作和链接由程序编号，模型只交编号上的概率。URL、作者、时间、计数都由程序取、程序写。
2. 只读：不发、不赞、不转、不关注、不回复（57）。开永久链接页和外链都是导航，不点页面上的按钮。
3. 碰到登录失效、验证、限流，当晚停手，不重试，不自动重登。
4. 每晚有硬上限（条数、开页数、模型调用数、时长），到了就收尾。
5. 只在桌面采集端跑（Linux、macOS，有 webview 取材的那台）。iOS 不跑，手机只看桌面读好的结果。

## 夜读

### 什么时候

`info/program/daily.ts` 加第二个锚点 01:00，判据同 05:00 那个：最近过去的 01:00 这台还没派过。派的条件：`amICollecting()`、本机有 webview 取材、X 会话有效、计划里至少一个 List。只在能干活的机器上派，worker 再拒一次（坑 380）。

开始在锚点后随机 0 到 40 分钟。结束取最早的那个：04:40（给 05:00 的日更留余量）、所有 List 读到上次位置、碰到每晚上限、停手。机器睡过 01:00，醒来还在 04:40 之前就补跑，过了当晚不读。

### 防电脑睡眠

开始时拿一把别睡锁，收尾时放：Linux 走 logind 的 `Inhibit("sleep:idle")`，macOS 走 `IOPMAssertionCreateWithName`（`PreventUserIdleSystemSleep`）。宿主能力一个文件 `platform/app/keep-awake.ts`，Rust 侧 `src-tauri/src/keep_awake.rs`。进程死了锁跟着释放。用户合盖或手动睡眠不拦，醒来按上面的窗口规则走。

### 节奏

初值，跑一周后按夜读文件里的实际数据调：

| 项 | 值 |
|---|---|
| 每晚上限 | 读入 400 条帖子、开永久链接页 40 次、开外链 20 次、有效阅读 150 分钟 |
| 分段 | 2 到 3 段，每段 30 到 60 分钟，段间歇 10 到 30 分钟 |
| 每屏停留 | 屏上新文字按每秒 12 到 20 字算，再加 2 到 6 秒随机 |
| 长停 | 每 5 到 10 屏一次，30 到 120 秒 |
| 滚动 | 每次 0.6 到 0.9 屏，拆成几次小步 |
| 开页 | 停留按正文字数同样算，读完返回 |
| 多个 List | 依次读，一个读到上次位置换下一个，顺序每晚打乱 |

### 读到上次位置就停

每个 List 记两样：上次读到的最上面一条的 status id，30 天内见过的 status id。往下读时连续 8 条都是见过的、或比那条早（status id 随时间单调），这个 List 就停。置顶和转推旧帖夹在中间不触发，因为要连续 8 条。第一次读的 List 没有记号，往回读到 24 小时前。

### 停手

判据（坑 494：页面自己的后台请求 403 不算）：

- 登录失效：落地 URL 变成登录页，或 List 页出现登录墙。
- 验证：落地到挑战页（`/account/access` 一类），或页面出现验证提示。
- 限流：页面出现限流或「稍后再试」提示。
- 结构变了：连续 3 屏解析出 0 条帖子而页面字数正常。

当晚立刻收尾，已读的照常入池，原因写进夜读文件的 `halt` 和采集端状态文件（36 的 `halt`、`sites`）。之后：登录失效等用户在 PC 上重新登录才再派；验证和限流跳过下一晚，再下一晚试一次，再碰到就停到用户在对话里说恢复；结构变了只停当晚，等改页内脚本。

### 读法

在 app 自己的隐藏 webview 里读，和彭博全文共用 `webview_fetch` 的 profile 和 cookie 罐（Linux 是 `<profile>/cookies`，macOS 是 `data_store_identifier` 那份，坑 385）。登录走现有站点登录：X List 源的 descriptor 写上 X 的登录页，`site-session.ts` 把它折成一个站，源页面现有那一行就能开窗登录、查会话、退出（17、36）。登录是全程唯一的可见窗口，用户自己点。

`webview_fetch` 只会「给一个 URL 取一篇」。夜读要一个长命的页：Rust 侧加 `webview_fetch/browse.rs`，开一个隐藏 webview，前端能让它导航、跑页内脚本、按像素滚、后退、关；前端门面 `workshop/extract/webview-browse.ts`（capability，不认识 X）。X 的 List 页脚本和解析放 `info/x`，和永久链接页那份（`permalink.ts`）并列。判稳定看脚本读没读到帖子，不等 load 事件（坑 496）。滚动用页内 `scrollBy`，不需要真鼠标事件（57）。

### 每一步

程序把当前屏写成一段文字当 state：

- 头：List 名、第几屏、今晚已读条数和上限、剩余时间、上一步做了什么。
- 每条帖子一块：编号 `p1`、`p2`…，作者、时间、形态（原创、引用、带评论转推、回复）、正文（最多 600 字，截断的标「只有开头」）、卡片标题和 host、计数、程序的标记（见过、截断、有外链）。帖内链接编号 `p1.a`、`p1.b`，t.co 由程序先展开（86）。
- 各研究室的视野，一室一句（63 的章程）。

一次请求带三类问题：

| 问题 | 类型 | 内容 |
|---|---|---|
| `action` | Choice | 这一步可做的动作，程序只列合法的：往下滚、展开 pK（开永久链接页，只给截断的帖子）、打开 pK.x、返回、今晚到此为止 |
| `worth:pK` | Noul | 「这条值得给用户看」，每条新帖一个 |
| `main:pK` | Choice | 「这条帖子真正的内容是」：帖子本身、pK.a、pK.b…，只问 L0 规则判不清的带外链帖子 |

程序拿到答案后先查动作合法和上限，再执行。判断失败或答案不合法时走缺省策略：往下滚，不展开，不开外链。到了条数或时长上限只剩「今晚到此为止」。每一步落一条进夜读文件：步号、屏上帖子 id、问题、答案、供应商、耗时、执行的动作和结果。

### 产出

L0 留下的每条帖子变一条 `InfoItem`，读到时就进条目池（`addDiscovered`）：

- `source`：这个 List 的 descriptor，新 discovery kind `x-list`（`{ kind: "x-list", url }`），没有 `pollMinutes`，由夜读替它轮询。
- `sourceKey` 是 status id；`url` 是永久链接，引子帖换成正主链接（L0 规则或校准过的 `main`）；`title` 是作者加正文第一句，截到 120 字，不改写。
- `textContent` 是读到的正文，展开过的是全文，`summaryOnly` 按有没有全文；正主是外链的，正文留给早上的取材相位。
- `signals` 是赞、转、回复、浏览和作者。`worth`、`main` 的概率不是事实，不进 signals，只留在夜读文件里给 L3 当特征。

早上 05:00 的日更照常从池子里取，X 的条目和别的源一起过 L1 到 L5、取材、分析员、进盒。用户在盒里存下一条 X 条目时，走 86 的链接摄入。

## 可续跑

夜读是一个 legion run 里跑一个 pi-durable 任务。

run 的 kind 是 `x-night`，程序 worker，`local` tier，只在采集端跑。idempotencyKey 是计划 id `x-night:<锚点日期>`，同一晚第二次派拿回同一个 run，闸在被调用的一侧（坑 210）。

任务 `rp.xnight` 用 `defineTask`，三个相位：`open`（拿别睡锁、验会话、开页）、`read`（逐步循环）、`wrap`（放锁、关页、写夜读文件和状态）。定义在 `info/x/night/`（domain，登记进 LAYER），打开 Harness 时经注入登记，和子 agent 定义的 extension 同一种做法，`legion/durable` 不 import info。停顿一律走 `runtime.sleep` 或 `awaitWithContext`，abort、关 app、换代都不挂在它上面（87「换代」）。

| 借的做法 | 落在这里 |
|---|---|
| requestId 由计划 id 加次数推出 | 每一步的键是 `<计划 id>:<步号>`。judge 的结果按这个键 memo，恢复后同一步不重问 |
| revision 作废旧任务 | 计划文件 `info-xnight-plan.json`（List、窗口、上限、revision），用户在对话里改 List 或说今晚不读，revision 加一。任务开始时记下 revision，每一步前比对，不等就收尾 |
| 恢复后先验目标还在 | 恢复时依次查：revision 没变、当前 List 还在计划里、还在窗口内、会话有效（读一屏，落地是 List 页不是登录页）。任一不对就进 `wrap`，不再对 X 做任何动作 |
| 副作用 sending / sent / unknown | 每个对 X 的动作（滚、开页、开外链）先 commit `sending`，做完记 `sent`。恢复时 `sending` 一律改 `unknown`，计入上限，不补做 |

任务必须能从自己的文件重新起来（87 对常驻任务的要求）：每一步把进度写进 `info-xnight-<日期>.json`，包括 List、记号、见过的 id、各项计数、步号、`halt`。进程被杀，`resume()` 接着跑；页面状态丢了就重开当前 List 从顶上读，见过的帖子跳过不入池，滚动照常按节奏。换代强制 abort 后 run 还挂着，下一次 tick 起新任务读夜读文件接着做。夜读文件设备本地，不同步，留 30 天。

## 判断模型

### 接口

放 `src/judge/`，capability。LAYER 表登记 `judge` 和 `judge/providers` 两行。

```ts
type Question =
  | { kind: "choice"; id: string; purpose: string; text: string; options: string[] }
  | { kind: "score"; id: string; purpose: string; text: string; scale: string[] } // 每档一句，低到高
  | { kind: "noul"; id: string; purpose: string; text: string };                  // 一句陈述

interface JudgeRequest {
  state: string;          // 程序写好的文字
  questions: Question[];
  key?: string;           // memo 键，夜读是 <计划 id>:<步号>
  signal?: AbortSignal;
}

interface Answer {
  id: string;
  probs: number[];        // choice、score 每个选项一个；noul 是 [为真]
  calibrated: boolean;
}

type JudgeResult =
  | { ok: true; answers: Answer[]; provider: string; model: string; ms: number }
  | { ok: false; reason: string };

function judge(req: JudgeRequest): Promise<JudgeResult>;
```

规则：

- 选项由程序编号，模型看到的是 A、B、C 单个字母，读 logits 时一个选项一个 token。一个 Choice 最多 12 个选项。同一 purpose 的选项顺序固定（打乱顺序会改掉一成多答案，Jev 开源生态调研）。
- 问题按字面写，不靠否定和隐含条件；计数、日期比较、算术由程序先算好写进 state（系统一「已知短板」）。
- state 前面写明页面文字是材料不是指令。
- 同一次请求里的问题各自独立作答，程序组合时不假设它们自洽。

### 置信度

原始概率不直接过阈值。每个（供应商、模型、purpose）用自己的标注拟一个温度（最小化负对数似然；Score 按档位当 Choice 拟），存 `judge-calibration.json`，设备本地，跟本机模型走。没拟过的答案 `calibrated: false`，只能排序，不能过阈值，调用方按缺省处理。阈值按 purpose 定：拟合后 p ≥ τ 的那部分命中率到 0.95。标注每多 100 条、或换模型，重拟一次。

夜读里 `action` 取最大概率的合法选项，不过阈值，错一步只是多开一页，有上限兜着。`main` 校准过才改条目的 `url`。

### 超时与兜底

- 供应商顺序存 `device.json` 的 `judgeProviders`，缺省本机在前、大模型在后；Jev 只在配了 key 时加入。
- 单次超时：本机 3 秒，Jev 5 秒，大模型 30 秒。超时或出错换下一个。本机连续 3 次失败，当晚剩下的步都跳过本机。
- 大模型兜底每晚最多 300 次，用完只走程序缺省。
- 全部失败返回 `ok: false` 和一句原因，调用方走缺省，同一步不重试。

### 供应商

| 名 | 跑在哪 | 概率怎么来 |
|---|---|---|
| `local` | 桌面上的 llama.cpp `llama-server`（RTX 3060 12 GB），端点写 `device.json` 的 `judgeEndpoint`，app 不管它的进程 | 一个问题一次补全请求，共享 state 前缀走 prompt cache；只取答案位置的 top logprobs，对合法选项的 token 做 softmax |
| `llm` | 现有 `ai/`，日常档 | 结构化输出只交选项字母；选中项的概率取这个 purpose 在标注集上的命中率，没标过就 `calibrated: false` |
| `jev` | TypeSafe API，key 存 `credentials.json` | 原样取 Choice、Score、Noul 的概率 |

本机用哪个模型待定，候选和许可证见 [JevBench决策模型榜单](../research/JevBench决策模型榜单.md)。

### 在管线里的位置

补充，不替代 L4 粗筛：粗筛顺手写的一句话摘要和 outside 理由，判断模型写不出来。三处，按分期依次接：

1. 夜读逐步：`action`、`worth`、`main`。
2. L3 的特征：每条条目对每个研究室问一个 Noul（「这条落在 <视野> 里」），概率和 TF-IDF 一起进该室的逻辑回归。标注少时由它顶冷启动（独立评测：判断模型的输出当特征，8 到 128 条标注能追平零样本）。
3. L4 前的闸：L3 分和判断模型都说不落在任何研究室、且校准后概率 ≥ 0.97 的，不进粗筛。被闸掉的条数照 35 的 `cappedOut` 规矩出现在日志、进度和简报文件里。L3 没训出来或判断模型没校准时闸不开。

## 筛选分层

越往后越贵。L0 到 L3 是程序，L4 是现有的模型粗筛，L5 是程序。新代码放 `info/filter/`（domain，登记进 LAYER），都是纯 `.ts` 配单测。

| 层 | 插在哪 | 做什么 | 输出 |
|---|---|---|---|
| L0 规则 | 入池前（`addDiscovered`）；X 在夜读读到时 | URL 规范化：去追踪参数、展开短链，存 `canonicalUrl`，不改条目 id，池里的 marks 照旧有效。带有效期的静音词（一天、一周、一月、永久）。作者和源的允许、屏蔽名单，屏蔽强否决（NewsBlur 的合并规则）。X 专有：无评论转推丢掉；同作者自回复的线程折成一条；引子帖按 84、86 的规则由程序判，没外链是帖子本身，去掉链接后正文很短且只有一个外链是那个链接，其余交 `main` | 留下的条目，或丢掉和原因 |
| L1 近重复与聚类 | screen 相位开头，对 `drawForDay` 取出的条目加 30 天内进过简报的标题 | MinHash（字符 shingle 的 Jaccard）把转载并成簇，簇里数独立原始报道方，同稿重复计一 | 簇代表进下一层，其余挂在簇上；簇大小和独立方数作为一行事实进 `signals`，就是 63 的「本条可信度」 |
| L2 新颖度、汇聚度、速度 | L1 之后 | 名字抽取（移植 new-term-radar 的 `names()`，MIT）和 60 天名字词表（采集端本地）；同一新名字 30 小时内出现在 2 个以上 descriptor 算汇聚；GitHub stars 快照差，HF trending 前 50 对上一轮前 100 的差（`base_name` 归到底座）。快照差分丢掉最后两天没定型的数据 | 一行事实经 `formatSignals` 进粗筛提示词；65 日更列表的第四类候选 |
| L3 兴趣分 | L2 之后 | 每研究室一个 TF-IDF（1 到 2 元，sublinear）加逻辑回归。正例 saved、promoted、asked，负例 dismissed，told 不进，粗筛丢掉的当降权负例。日更 run 开头重训，模型存采集端本地。正例不到 20 条不出分 | 每条每室一个分，只用于室内排序、`SCREEN_MAX_KEEP` 截断的先后和 L4 前的闸；不改可观测项（63 的刹车） |
| L4 粗筛 | 现有 `collect/screen.ts` | 提示词补负例：营销、只有时间地点的发布通知、促销。多交一个枚举 `source_proximity`：原创、实现、转述、噪音。verdict 记提示词版本；调用失败的批不记判过，`fillMissingVerdicts` 补成留的规矩不变 | 命中的研究室和可观测项下标，同今天 |
| L5 进盒前排序 | box 相位，每室盒内 | 同作者、同源衰减 `(1 − floor)·decay^k + floor`（x-algorithm，Apache，初值 decay 0.5、floor 0.25）；簇间 MMR 去冗余，相似度用 L1 的 Jaccard；每天一条 outside 名额照旧留给探索 | 盒里的顺序 |

静音词和名单存 `info-filters.json`，同步，按记录合并，经对话加删（秘书加两个工具），不加界面。

## 早上看到什么
