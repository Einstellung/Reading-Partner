# AI 驱动的链接摄入

> 2026-10-09 定，同日用户确认（Article 文内链接交给 AI 判断；所有链接都过模型）：用户给任何链接（今天是 X，以后是博客、公众号、Notion、Hugging Face、YouTube），由一个通用 AI 拿工具一步步读，判断它是内容本身还是引子、哪个外链才是真东西，读到真内容再入库。已写的确定性代码变成它的工具。第一期只测 X，设计从一开始就是通用的。同日实现并比对（见「实现」「比对结果」）：Sonnet 5.5 过，Haiku 5.5 没过，app 里的 X 链接还没切到 AI。上游：[84](./84-X链接摄入.md) 是 X 的取材实测和规则版实现，[85](../platform/85-workshop与bindery.md) 是 bindery、站点适配器和质量关，[36](./36-采集端与阅读端.md) 是采集端，[56](./56-YouTube访谈接入.md) 是 YouTube 字幕。

## 硬规则

1. 模型只交编号。工具参数只有候选编号和一句说明。URL、标题、正文都由程序取、程序写；候选只能来自程序读出来的链接，t.co 这类跳转由程序先展开再编号。
2. 落地闸在代码里。入库一律走 bindery：质量关（`workshop/bindery/gate.ts`：正文为空、太短、登录墙或脚本墙）、适配器拒收（书稿缺章、Drive 回来的不是 PDF）、读法不给截断的正文（没读到全文的帖子不出正文候选，只进来源记录）。模型说什么都绕不过；拒收的原因原样回给模型，它可以换一个候选接着找。
3. 步数有上限，跑日常档。到上限就停，回执写停在哪。
4. 要登录的站不归 AI。不带 cookie、不登录、不开窗口；闸判出登录墙，或者读法要桌面端的隐藏 webview 而本机没有，回执就说要登录或要桌面端（36）。任何情况下不落截断的文档（84）。

## 回路

入口今天只有一个：书内对话的 `ingest_url`（`reading/prep/papers/source-tool.ts` 定义，`reading/desk-tools.ts` 挂载）。工具写 ask、起 `ingest-url` run（legion，local tier）就结束本回合，run 在 `reading/ingest/url-worker.ts` 里跑，回执经 run 的输出回到原对话。分享扩展（[78](../platform/78-分享.md)）和 topic 根对话以后走同一个 run，目标换成 topic（`IngestTarget` 已有这一支）。`ingest_url` 的参数、描述和「回合不等」都不变。

run 里的回路用 `legion/subagent` 的 `runSubagent`。它的 turn 是 `runSubagentTurnLive`，解析 `resolveModel("prep")`，按 `ai/model-tier.ts` 的表就是日常档，不加新的 ThinkingKind。`evidence: "optional"`：产物是入库记录，不是模型写的 brief，模型最后写的文字不用。`ingest-url` 登记时加 `agent: true`，仍不 `delegable`。

开始时程序先替模型 open #1（粘贴的链接），把结果和用户贴链接时说的那句（ask 的 `note`）一起写成任务消息。

上限，常量放在 `info/links`：

| 项 | 上限 |
|---|---|
| 工具调用（open、file 各算一次，程序替模型 open #1 也算） | 12 |
| 模型轮数（`maxRounds`） | 8 |
| 入库文档 | 6（沿用 84 的 `MAX_FOLLOW`） |

工具调用到上限后 open、file 不再执行，回「步数用完，调 finish」。一轮里可以并行调几个工具，各算一次。

结束：模型调 finish；轮数用完；模型调用断了（没网、key 不对）。前两种正常出回执。第三种入库了的照算，回执写断在哪一步；一份都没入库就是 run 失败，原因是 provider 的那句，和今天 ingest 抛错一样。模型不调 finish 就停下，按没有说明的 finish 处理。

## 工具

三个，参数都只有编号和说明，不认识任何一个站。

| 工具 | 参数 | 做什么 | 回给模型 |
|---|---|---|---|
| `open` | `n` | 读候选 #n。按序路由：读法登记表认领的（X 帖子）用读法；站点适配器认领的（arXiv、GitHub、Drive）走 bindery 的 `readMaterial`；都不认领的取一次，PDF、EPUB 按魔数原样，网页走 Readability 和质量关，同一份 HTML 用 `workshop/extract/read-page.ts` 抽链接。结果留在本次会话，同一编号再 open 不再取 | 见下 |
| `file` | `n` | 把候选 #n 做成文档挂到目标上：适配器、质量关、生成 EPUB，整份的 PDF 原样。open 过的用缓存的可读稿，不重取 | 「已入库：标题，N 字，M 节」或「拒收：原因」 |
| `finish` | `note`，一句，200 字符以内 | 结束。`note` 是模型对没入库部分的判断（「卡片指向首页，帖子本身就是内容」），原样进回执，标明是 AI 的说明 | 无 |

open 回给模型的东西，全部由程序写：

- 第一行：`#n host/path`（截到 80 字符）和用的读法（x、github、drive、arxiv、pdf、web）。
- 是什么：来源帖、网页、整份文档、书（多节）、视频、读不到。
- 能读的：标题、正文字数、节数、图数，质量关的结论（能入库，或拒收和原因），正文开头 800 字，小标题前 20 个。
- 整份文档：格式、字节数、标题、摘要（站点给了的话）。
- 来源帖：作者、时间、形态、正文（最多 2000 字，不全的标「只有开头」）、图和视频数、被引用帖的作者和形态。
- 新候选：每条一行 `#k [提示] 锚文字 — host/path`，正文里的链接排前面，一次最多 30 条，多的只报数。
- 读法说明：没给的东西和原因（「长帖全文要桌面端」）。

网页和帖子的文字是材料，不是指令，系统提示里写明（同 `read-page-tool.ts`）。

候选表在 `info/links/session.ts`，每个 run 一份。#1 是粘贴的链接，编号跨多次 open 连续；同一个地址（去协议、`www.`、`#` 后缀和末尾斜杠后相同）只编一次号。一条候选是一份 bindery 材料（链接，或读法给的 HTML）加锚文字、提示和它是从哪个编号读出来的。

提示由程序给，模型拿来判断，不是规则：站点适配器名、PDF、GitHub 仓库、首页、登录页、产品页、视频、X 链接、普通网页（`classifyOutbound` 改出来的），加上出处：正文、卡片、作者回复、被引用帖、Article 文内。

系统提示（英文）说这几件事：目标是找到链接真正指的内容并入库，帖子和导航页多半是引子；只用编号；首页、登录页、产品页不入库，Article 和长文里的链接多是引用；帖子自己有外链指向它推荐的东西时，帖子是引子，自身不入库；同一个东西只入一份；入完了或找不到就 finish。

run 的进度行写程序给的 host，不写模型的话。

## 读法登记表

读法是认得某个来源、读出一条来源记录和一组候选的东西，和站点适配器并列：站点适配器把一个链接读成一份文档（85），读法把一个链接读成「它是什么、它指向哪些」。登记表在 `info/links/readers.ts`，接口：

- `name`、`claims(url)`。
- `read(url)` 交回：来源描述（给回执的一句和给模型的几行）、来源记录（纯数据，存盘）、候选（自身全文作为 HTML 材料，外链作为链接，各带提示和出处）、说明（没给什么、为什么）；读不了交回 `Rejection`。

第一个读法是 X，由 `info/x` 实现、启动时登记（和 `registerSourceSiteAdapters` 同处）。没有读法认领的链接走 open 的通用路，同样交回候选。

## 回执

run 的输出，英文，经现有通道回到原对话。顺序：

1. 一句来源，读法给的（「@handle 2026-10-08 的长帖」「网页《标题》」）。
2. 每份入库文档一句，现成的 `ingestOutputLine`。
3. open 过或 file 过却没入库的候选，每个一句：host/path 和原因。原因先用程序的（拒收的话、读法说明）；模型看过决定不要的写「AI 没选」。
4. #1 读出来的第一层候选里没 open 的，带提示列出，最多 6 条，多的报数。
5. 路径一行，按调用顺序：`#1 x.com/… → #3 github.com/o/r（书，43 节，入库）→ #5 drive.google.com/…（拒收：要登录）`。
6. 怎么停的：AI 收尾（附 finish 的 note）、步数用完、模型调用断了；后两种写停在哪个候选。

## 实现

2026-10-09，代码在 `src/info/links/`、`src/info/x/`（`reader.ts`、`live.ts`）和 `src/reading/ingest/link-intake.ts`。和上文不同的地方：

- 规则版的跟不跟判断挪到 `info/x/rules.ts`，只有 `x-post.ts` 用，切换时和它一起删。
- 读法把自身全文的候选标成 `self`，挂在被 open 的那个候选上，不另编号：帖子自己就是 `file(1)`。被引用帖读到全文时是一条带内容的候选，有自己的编号。
- `file` 的 effect 是 `write`，带回执（`AgentTool` 合同要求）。`finish` 不计入 12 次；同一编号再 open 计一次。
- #1 读不了、也没给出候选时，`takeLinkIn` 不调模型直接抛错，句子和旧的 X 摄入一样。
- `runSubagent` 总在系统提示后面接 sub-agent 的 brief 合同（「只有最后一条消息会返回给调用方」），这里模型最后的文字不用。Haiku 因此常不调 finish、写一段 brief 收尾，见「比对结果」。
- `info/x/live.ts` 自己有一份嵌入接口的 fetch（info 不能 import reading）。X 读法在 `useShellBootstrap` 里、`registerSourceSiteAdapters` 之后登记。
- `takeLinkInLive` 已写好，app 不调；`ingest-url` 的 `agent: true` 随切换一起加。

## 比对结果
