# 引文扩展与第二轮查询

> 2026-10-22 起草，待项目发起人看。专题调研（[91](./91-专题调研.md)）在字面查询之外，从种子和用户认过的论文顺引文图和推荐找候选，判完第一轮再按缺口补一轮查询。起因：「AI 自主机制发现」真跑一次出 15 条，对路 4、擦边 4、噪声 7，符号回归占四成，「领域先验」那条线几乎空手。arXiv 和 Hugging Face 的搜索只在标题和摘要上按字面匹配，换了说法的论文搜不到。不接 Google Scholar。上游：[88](./88-主题搜索.md) 是管道，[91](./91-专题调研.md) 是种子、标签和更新，[开源主题情报与研究代理项目调研](../research/开源主题情报与研究代理项目调研.md) 第 4、5、8 条（PaSa 去掉引文扩展召回掉 23 到 32 个点）。坑：[73](../pitfall/network/73-s2-citation-edges-null-and-ignored-year.md)、[502](../pitfall/network/502-every-arxiv-caller-kept-its-own-clock.md)、[659](../pitfall/network/659-hugging-face-paper-search-has-its-own-rate-limit.md)。

## 结论

- 只给专题调研（`once`）。常态主题和 X 不动。
- 第一次 run：read 段在字面查询旁边多一路「图扩展」，从正例出发取 S2 推荐、被引、引用；build 段判完第一轮后找缺口，补一轮查询，最多一轮。
- 更新：只对上一版之后新增的正例走图扩展，不自动补查；空着的线在书里直说，卢明可以提议补搜。
- 扩展来的论文作为新的 RRF 流进候选池，源记 `graph`，按 arXiv id 和字面结果去重。条目数、精读数、判分池大小都不变。
- 每次第一次 run 多出：S2 最多 21 次请求，S2 不通时 OpenAlex 最多 18 次，模型 2 次。
- 上线前在项目发起人的题上做两折留出实验：图扩展找不到一篇字面漏掉的已知 yes，就不上。

## 正例和反例

正例按这个顺序排：种子（`topic.seeds`），最新标签是 `pinned` 的，最新标签是 `yes` 的（新标的在前）。`borderline` 两边都不算。反例是最新标签为 `no` 的论文，新标的在前，取 10 条。

- 推荐用前 20 个正例和 10 个反例。
- 顺引文走（被引、引用）只走前 6 个正例（`MAX_WALKED`）。
- 第一次 run 时还没有标签，正例就是种子。

一个种子都没有时用「暂定正例」：第一轮判分 ≥80 的论文取前 3 篇，只在第二轮用（见下），它们的流权重减半。

正例先用一次 S2 `POST /graph/v1/paper/batch`（`ARXIV:<id>` / `DOI:<doi>`）换成 S2 paperId，顺便拿 `citationCount`、`externalIds`。S2 查不到的再去 OpenAlex 找。

## 哪个库做什么

| 动作 | 首选 | S2 冷却、429、404 或 `data: null` 时 |
| --- | --- | --- |
| 推荐 | S2 `POST /recommendations/v1/papers/`，正反例一起给，`limit=100` | OpenAlex 每个正例的 `related_works` 合起来，按命中几个正例排序；没有反例 |
| 被引 | S2 `/paper/{id}/citations`，`limit=1000`；正例 `citationCount > 300` 不走，记 `hub` | OpenAlex `filter=cites:<W>,from_publication_date=<窗口起点>`，`sort=cited_by_count:desc`，`per_page=100` |
| 引用 | S2 `/paper/{id}/references`，`limit=500` | OpenAlex `referenced_works`，再按 id 批量取（每次 ≤50 个，`|` 分隔） |

- 时间窗用这次 run 论文的窗（第一次看 365 天，`FIRST_LOOK_BACK_DAYS`），按 arXiv id 的年月判（同 `paperDay`），一律在本地筛，不给 S2 传年份参数。
- 只收有 arXiv id 的：S2 的 `externalIds.ArXiv`，或 DOI 形如 `10.48550/arXiv.<id>`，或 OpenAlex 的 locations（现成的 `extractArxivId`），一律落成 `arxiv:<id>`。只有 DOI 的不进池（候选池只装 arXiv 论文和 X 帖），只记个数和前 5 个标题。
- 摘要：S2 给的优先；缺的用 OpenAlex 的 `abstract_inverted_index` 还原；还缺的走 arXiv export API `id_list` 批量补，每次 ≤50 个，最多 2 次；再缺就只有标题。
- 正例自己和标了 `no` 的论文从所有扩展流里去掉。

### 接口事实

2026-10-22 查文档核过的：

- S2 推荐：`POST /recommendations/v1/papers/`，body `{positivePaperIds, negativePaperIds}`，query 有 `limit`（默认 100，最多 500）和 `fields`，没有 `from`。`GET /recommendations/v1/papers/forpaper/{id}` 有 `from=recent|all-cs`，`recent` 是什么范围文档没写。id 可以写 `ArXiv:1805.02262`。查不到回 404「Input papers not found」。
- S2 图：`/citations`、`/references` 有 `offset`、`limit`（默认 100，最多 1000）、`fields`，边上有 `contexts`、`intents`、`isInfluential`。`POST /paper/batch` 一次最多 500 个 id。`/paper/{id}` 认 `CorpusId:`、`DOI:`、`ARXIV:` 等前缀。
- S2 限额：不带 key 是所有匿名用户共用的池，可能被限；带 key 起步是所有接口合计每秒 1 次。
- OpenAlex（帮助页 2026-10-15 更新）：不带 key 能查，每秒 10 次；免费 key 每秒 30 次、每日额度 ×10、激活后每天 1 美元；key 走 `?api_key=` 或 `Authorization: Bearer`。超每日额度或每秒上限回 429。按 2026-02-24 的价目：按 id 取单条免费，列表和过滤每次 0.0001 美元，搜索 0.001 美元。帮助页不再提 mailto 的 polite pool。
- OpenAlex work 的 `ids` 里没有 arxiv。文档说 `related_works` 是「共有主题最多的近期论文」，实测不是近期的（见下）。

2026-10-22 实测（共 11 次请求；设置里没有 S2 key，S2 走匿名池）：

- S2 匿名池第一次请求（`/citations`）就回 429，不带 `Retry-After`；几分钟后匿名的推荐请求回 200。
- S2 推荐的 `positivePaperIds` 收 `DOI:` 前缀：只给 AlphaFold 的 Nature DOI，回 100 条。POST 推荐只出近期论文：100 条里 2026-09 和 2026-10 共 77 条，最早 2025-12-23，6 条没日期。其中有 arXiv id 的 21 条，只有 DOI 的 75 条（生物题，计算机题的比例要在实验里看）。
- OpenAlex 不带 key 照常回答，「所有请求都要 key」不成立。不带 key 是同一 IP 上所有人共用每天 0.1 美元（回答头 `X-RateLimit-Limit-USD: 0.1`，`meta.notice` 原话），mailto 不加额度。按 id 取单条 `X-RateLimit-Cost-USD: 0`，列表和过滤 0.0001，即每天约 1000 次列表请求。notice 里 key 写成 `api_key=` 参数。
- OpenAlex 按 `/works/doi:10.48550/arXiv.<id>` 和 `filter=doi:10.48550/arxiv.<a>|10.48550/arxiv.<b>` 都查得到，但回来的 work 的 `doi`、`publication_date` 可能是别的版本的，甚至是合并错的另一篇论文（坑 [668](../pitfall/network/668-openalex-arxiv-doi-lookup-returns-another-version-or-paper.md)）。
- `cites:` 能用（服务端改写成 `referenced_works:`），`from_publication_date:<日>` 生效。`related_to:` 还在。`related_works` 是 1964 到 2024 年的老论文，过一年的窗基本是空的（坑 [669](../pitfall/network/669-openalex-related-works-are-not-recent.md)）。
- `openalex_id:` 用 `|` 连 51 个 id 不报错（服务端改写成 `ids.openalex`）。客户端仍按 50 个一批发。

没核的：

- `/citations` 的 `publicationDateOrYear` 能不能真筛（坑 73 里 `year=` 被静默忽略；这次匿名池 429 没测到）。照旧在本地筛。
- `POST /paper/batch` 的回答形状按文档写：和请求同序的数组，不认识的 id 是 null。
- OpenAlex 认不认 `Authorization: Bearer`（没有 key）。不认就改走 `api_key=`，但要从日志里滤掉。

## 进候选池

- `Candidate.source` 加 `graph`。流的 key 是 `rec|graph`、`cites:<正例 key>|graph`、`refs:<正例 key>|graph`，写进 `foundIn`。同一篇被几个正例的被引或引用流找到，RRF 自然叠加，这就是共引。
- `gatherCandidates` 现在丢掉查询 id 不在 `topic.queries` 里的流，改成源为 `graph` 的流另认。
- 权重：推荐 0.8，被引 0.6，引用 0.5；推荐换成 OpenAlex 顶的时 0.5；暂定正例的流再 ×0.5。每路取前几名（`STREAM_TAKE`）：推荐 20，每条被引、引用流 8。落盘时推荐存 50 条、每条走流存 30 条。
- `POOL_RESERVE` 加 `graph: 12`，判分池总数不变（第一次 60）。
- 只从图上来的候选不过字面相关度下限 0.15；它们的 `relevance` 照样按全部查询算最大值，只用来排序和记录。
- 锚词：打分里没有锚词扣分（2026-10-22 起，88「打分」），图上来的候选和字面候选一样只看重排分。
- 模型漏答时的兜底分（`0.7·relevance·100`）对只从图上来的候选改成 0。
- 判分提示里每个候选多一行来路（「推荐」「引用了种子 X」「被种子 X 引用」），规则里加一句：怎么找到的不说明对不对路，只按正文判。
- 结果条目加 `via`，记它从哪些流来；书里先不显示（见待定）。
- `RESULT_ITEMS`（15）、`DEEP_READS`（5）、`RERANK_POOL`、`MAX_MODEL_CALLS`（24）不变。

## 第二轮查询

1. 第一轮判完，把模型的回答存进 run 目录的 `judge-1.json`，续跑不重判。
2. 找缺口：每个 `picked` 的子题（没有子题就是整个题），第一轮最终分 ≥45（`LABEL_BOUNDARY`）、模型答的 `subtopic` 是它的候选不到 2 个，就是缺口。没有缺口就不做第二轮。
3. 一次模型调用写查询：给它缺口子题、已经发过的查询、≤8 篇对路论文的标题加摘要前 600 字（种子和正例在前，再按第一轮分）。每个缺口最多 2 条，合计最多 4 条，每条标明属于哪个子题。
4. 程序检查每条：至少 2 个能搜的词；至少 1 个词出现在那几篇对路论文的文字里；和每条已发查询的词集 Jaccard < 0.5。不过的扔掉，不重写。
5. 过了的查询编号 `w1`…`w4`，权重 0.7，`ranking` 抄这个子题已有查询的，X 留空。只在这次 run 里用，不写回主题配置。在 arXiv 和 Hugging Face 上搜；有暂定正例时同时走它们的图扩展。
6. 源在冷却就不等，那条记 `not_searched`。
7. 新候选（第一轮池里没有的）不到 3 个，跳过第二次判分。否则只判新的，最多 30 个，编号接着第一轮，附第一轮最高和最低各 3 条作对照。
8. 全部流（两轮）一起做 RRF、算最终分，后面挑选、看原文、成书照旧。
9. 第二轮之后还是缺口的子题写进结果的 `widen.lines`：`empty`（两轮都搜了，没有过 45 的）或 `not_searched`（第二轮没搜成）。书的第一页照实说，比如「领域先验：搜了两轮，没找到对路的论文」「领域先验：第二轮没搜成，arXiv 在冷却」。卢明看得到，可以提议用 `update_study_brief` 补搜。

第二轮在 build 段里做，每一步落自己的文件：`widen.json`（缺口、模型写的和过检查的查询、每条的结果）、`arxiv-read-2.json`、`hf-read-2.json`、`graph-read-2.json`。续跑读文件跳过做完的步。

## 预算、闸、缓存和 key

一次第一次 run：

| | 第一轮 | 第二轮 |
| --- | --- | --- |
| S2 | batch 1 + 推荐 1 + 被引 ≤6 + 引用 ≤6 = ≤14 | 仅暂定正例：≤7 |
| OpenAlex（兜底） | ≤18 次列表请求，约 0.002 美元 | 同左，共用 |
| arXiv | 补摘要 ≤2 | ≤4 条查询，每条照现有阶梯 ≤3 次 |
| Hugging Face | 0 | ≤4 |
| 模型 | 0 | 写查询 1 + 第二次判分 1，约 0.04 美元（估） |

一次更新：S2 batch 1 + 推荐 1 + 新正例的被引和引用（最多 6 个正例）。

闸（`platform/http/host-gate.ts`）：

- S2 的 key 是所有接口合计每秒 1 次，所以 S2 主机和它所有车道共用一个间隔组 `semanticscholar`，1500 ms。冷却按车道分开记：新增 `S2_GRAPH_LANE`（`/paper/batch`、`/citations`、`/references`）和 `S2_REC_LANE`（`/recommendations/`），和现有 `S2_DOI_LANE` 一样遇 429 冷却、冷却中直接跳过。现在冷却开关挂在组上（`GROUP_POLICY.cooldown`），要改成按车道定，间隔仍按组。
- OpenAlex 新增 `OPENALEX_GRAPH_LANE`（`cites:`、`openalex_id:` 过滤和 `/works/{id}`），遇 429 冷却，间隔和主机同组 500 ms。
- 车道按 URL 认，阅读端的 `walk_citations`（`src/reading/papers/citations.ts`）在冷却期间也会直接跳过。
- 专题 run 不等冷却：流记 `cooling_down`，`planRetry`（`retry.ts`）把 `cooling_down`、`rate_limited`、`failed` 的图扩展流和失败的查询一样列进重试。

缓存：本机文件 `topic-search-graph-cache.json`（palace 本地 kind，不同步）。引用和 id 换算存 30 天；被引存 3 天；推荐按正例集合和反例集合的哈希存 3 天。写入时顺手删过期的。

key：S2 用设置里现有的 `semanticScholarApiKey`，走 `x-api-key`。新加同步设置 `openAlexApiKey`，走 `Authorization: Bearer`，不进 URL 和日志；没填就不带 key 查。URL 里的 mailto 留着，不指望它。

## 怎么评

- 标签重放（`src/info/topic-search/label-replay.ts`、`scripts/topic-labels-replay.ts`）给每个 yes 和 pinned 记它最早从哪条路进池：第一轮查询、第一轮图扩展、第二轮查询、第二轮图扩展、没进池。按路报 yes 和 no 的条数，`--json` 也带上。
- 新脚本 `scripts/topic-expand-probe.ts`：读 run 目录和标签，`--holdout` 把 yes 分两半，轮流拿一半（加种子）当正例走图扩展，看另一半找回几篇、其中几篇字面读里没有；报图扩展前 20 名里 no 的占比、推荐结果的日期分布、只有 DOI 的条数。`--round2` 按结果条目的分数近似找缺口，打出程序会放行的查询；默认不调模型，`--model` 才调。只写 `--out`，不碰 app 数据目录。走同一套客户端和缓存。

实验（主会话做，用项目发起人的 S2 key）：题是「AI 自主机制发现」。导入他对那 15 条的判断，再请他报 10 到 20 篇他知道对路的论文（标题或 arXiv id），用 `--import-seeds` 进标签。两折留出，看三件事：留出的 yes 里字面漏掉、图扩展找回的有几篇；图扩展前 20 名里 no 的占比；推荐结果是不是都挤在最近几个月。两折都找回 0 篇就不上，先查正例换算和接口。权重 0.8 / 0.6 / 0.5 是起点，按实验调完再合。

## 数据

`graph-read.json`（run 目录，本机，不同步；第二轮是 `graph-read-2.json`）：

```ts
interface GraphRead {
  version: 1;
  positives: { key: string; title: string; why: "seed" | "pinned" | "yes" | "provisional";
               s2: string | null; openAlex: string | null; citationCount: number | null; walked: boolean }[];
  negatives: string[];                       // keys
  streams: {
    id: string;                              // "rec" | "cites:<key>" | "refs:<key>"
    kind: "rec" | "cites" | "refs";
    from: string[];                          // positive keys
    library: "s2" | "openalex" | null;
    outcome: "ok" | "empty" | "hub" | "not_found" | "rate_limited" | "cooling_down" | "failed";
    total: number;                           // before window and arXiv filtering
    papers: { arxivId: string; title: string; abstract: string; authors: string[];
              publishedAt: string; citationCount: number | null }[];
    at: string;
  }[];
  doiOnly: { count: number; titles: string[] };
}
```
