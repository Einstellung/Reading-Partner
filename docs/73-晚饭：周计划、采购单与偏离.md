# 晚饭：周计划、采购单与偏离

> 2026-09-20 定案。上游：[north-star/diet.md](./north-star/diet.md)、[63](./63-情报局：研究室、专项组与态势.md)、[69](./69-源模型：索引、叙事源、用户带来的与快照.md)。

饭这条线的第一片：一周的晚饭计划、一张从计划推出来的采购单、偏离时说一句话。

## 形态

内部它是一个研究室（63），视野是用户本人。但它不落 `Lab` 记录：`sources: []` 的 lab 会被 `labsForSource` 派到每个无人认领的源上，饭不认领任何源，也不该进采集管线。它自己一份 store 在 `src/info/dinner/`，和 labs 平级。界面上不出现研究室、情报局、lab 这些词。

`settings.json` 里一个布尔 `dinner`，默认关，跟着账号同步。关掉只是不显示入口，数据留着。开着时 info 侧多一个 Dinner 入口，进去是一屏：这周七天（今天和明天占大头）、采购单、Ask。

排计划的单位是一周七天，一天一顿晚饭，每天一个模式：`cook`（做）、`reheat`（热昨天的底再加一把新鲜的）、`out`（出去吃）、`delivery`（点外卖）。四种平等，外卖不是次等选项。

做一次吃两顿写进菜的形态：每道菜分耐放的底（`base`）和吃的时候现加的那部分（`fresh`，绿叶、沙拉、面），带 `keepsADay`。一个 `cook` 日可以配第二天一个 `reheat` 日，`reheatOf` 指向底是哪天做的。省事的约束是硬的：一口锅、动手时间 ≤15 分钟、要洗的东西不比做一顿多。

健康只是过滤器：蔬菜多、全谷物、瘦蛋白，少油少盐少精制碳水。不数卡路里、不报克数、这一片里任何地方不出现营养数字。

## 三张卡

每一次 AI 写盘都走卡片加 Apply，照 `info/briefer/lab-tool.ts` 那套：工具只起草卡片，一个字节都不写；Apply 执行写入；写完补一条合成的用户回合告诉模型落了什么。

- `dinner-charter`：章程。人数、常去的店、厨房、忌口、一周做几顿/出去几顿/外卖几顿，外加 `text`——用户自己话说的那一段。没有表单，第一次「排这周」时在对话里问两三句就够，之后靠说话改。
- `dinner-plan`（整周）：七天的模式、菜、底和现加的那部分。
- `dinner-plan`（调整）：同一种卡，`adjustment: true`，带 `changedDates[]`，界面据此高亮改了哪几天。

## 采购单

采购单不由模型写，由程序从周计划推（`shopping.ts` 的 `deriveShoppingList(plan, today)`，纯函数）：

- 只有带 `dishId` 的 `cook` 日贡献配料。`reheat` 日吃的是前一天的底，它那把现加的绿叶算在 `cook` 那道菜的配料里——一道菜的配料按它覆盖的所有顿写。`out` 和 `delivery` 不贡献。
- 同名同类的配料跨菜合并成一条，份量文本用 ` + ` 接起来，保质期取两者里短的，`freezeOnArrival` 取或。
- `neededBy` 是最早用到它的那天。
- 分组按品类走一遍店（produce、protein、dairy、frozen、grains、pantry、other），组内按保质期档从短到长排，再按 `neededBy`、名字。保质期档照 diet.md 的 FoodKeeper 表：`d1-2` / `d3-5` / `w1` / `w2plus` / `pantry`。
- `freezeOnArrival`：`d1-2` 的 protein，`neededBy` 距采购当天两天以上（第三天及以后）的，标「一到家就冻」。
- 条目可勾。勾掉的就是冰箱里有的。计划调整后重新推导时，按名字加品类把勾的状态接过来（`reconcileShoppingList`）。

## 偏离

计划就是记录。默认照计划吃了，零输入。只有偏离才在对话里说一句「今晚点了外卖」。

程序拿到的是一条 `Deviation`：哪天、原话、实际成了哪个模式。`applyDeviation` 只动眼前一两天：把那天的模式改成实际发生的，清掉它的菜；如果第二天正靠这天的底热，那天的 `reheatOf` 和 `dishId` 一起清掉。返回需要模型接着管的日期，最多两个。别的天一概不动，整周不重排。

腻了、太麻烦这类反馈不当场改计划，留到下次「排这周」用。

## 事实不经模型

日期、今天是哪天、采购单、「一到家就冻」的标记、偏离之后哪几天要重排，全由程序算。模型只交菜、配料（`category` 和 `keeps` 从固定枚举里选）、模式和文字。

## 数据模型

一份 JSON：`info-dinner.json`，`src/info/dinner/store.ts`，io 照 `labs/store.ts`（`readGuardedJson` + 原子写 + 版本号）。文件内容是一个整体——章程、当前这周、采购单、偏离清单——字段之间互相依赖，拆开按字段合并会拼出没存在过的状态，所以 palace 里登记成 `sync: "data"` + `merge: "opaque"`：整文件最后写者胜，对方那份停在旁边，不做 lattice。两台设备同一周各排一次是罕见情况，代价是丢掉其中一份的编辑，不是丢掉半份。

类型在 `types.ts`：`DinnerCharter`、`Dish`（`base` / `fresh` / `keepsADay` / `handsOnMinutes` / `ingredients`）、`Ingredient`（`name` / `qty` / `category` / `keeps`）、`DayPlan`（`date` / `mode` / `dishId?` / `reheatOf?` / `freshAdd?` / `place?`）、`WeekPlan`（七天、菜、`revision`）、`ShoppingItem`、`Deviation`、`DinnerState`。
