# TTS 选型：一次把价格口径钉死之后的结论

先钉住基准价，因为三份调研在这一条上互相矛盾，而整张表都挂在它上面。硅基流动定价页的原始数据是 `{"price":"50","specification":"utf8_bytes","unitOfGood":"/ M UTF-8 bytes"}`，页面显示为「¥ 0.05 / 千字符 UTF-8」——50/百万 = 0.05/千，两个数只有在单位是**字节**时才自洽，且 API 文档写明「按照输入文本长度对应的 UTF-8 字节数进行计费」。所以正确口径是 **¥0.05 / 1000 UTF-8 字节**（[siliconflow.cn/pricing](https://siliconflow.cn/pricing)，[docs.siliconflow.cn](https://docs.siliconflow.cn/cn/userguide/capabilities/text-to-speech)）。「per 1000 characters」和「per million bytes」两个修正都是错的：后者把 ¥50 看成了 ¥0.05。199 汉字 × 3 字节 = 597 字节 → **¥0.0299/min**，你自己记的 ¥0.039/min 是把中文标点（同样 3 字节）算进去后的实际账单，两个都对。

下表统一按 199 汉字/分钟、不含标点计算，年费按每天 5 分钟 × 365 = 1825 分钟。所有厂商都收标点的钱，真实账单一律再加约 25–30%。

### 未进表的，及其失分项

- **小米 mimo-v2.5-tts** — 标准 3（首包 1100–1900 ms）。基准 .275 佐证，念错 350 条多于念对 273 条。
- **MiniMax speech-2.8-hd / turbo** — 不是硬标准失分，是两头都输：基准 .548 对火山 .879，而「1 汉字 = 2 字符」的口径把 hd 抬到 ¥0.139/min（¥254/年），是现状的 4.7 倍。turbo ¥0.0796/min 仍贵于火山且质量只会更低。没有需要实测才能翻案的余地。
- **AWS Polly (Zhiyu)** — 质量：基准倒数第一 .244，correct 242 / wrong 323，念错比念对多。中国区还要企业 ICP 账户。
- **Google Chirp 3 HD / OpenAI TTS** — 境内可达性。Google 基准 .604、255 个错读，也不值得为它翻墙。
- **ElevenLabs / Cartesia / Fish Audio / DeepInfra / Novita / Replicate / fal.ai** — 标准 3。这台机器上**带隧道**测到的 TLS 握手：DeepInfra 0.605–0.629 s、Novita 0.805 s、Fish 0.592 s、Replicate 0.538–0.554 s。一次握手就吃光 500 ms 预算，而这还是下界。ElevenLabs 的「75 ms」明文刨掉了网络，而网络正是从中国用它最贵的那段。
- **Deepgram / Rime / Hume** — 根本不支持普通话。
- **Kokoro-82M / Chatterbox / F5-TTS / Spark-TTS / MegaTTS3 / IndexTTS-2.5 / ZipVoice / 端侧** — 标准 1：整句一次性生成，没有流式，按句接力就失去意义。端侧另有一条：每天 3 分钟一年才 18.25 小时音频、¥43–55 的账单，任何移植工作都赚不回来；要做只能是为了离线，不能是为了省钱。
- **Higgs Audio V3** — 标准 3：厂商自己在 H100 上量到 1079 ms 平均延迟。
- **百度智能云大模型 TTS / 华为云 SIS** — 价格取不到（前端渲染 / EdgeOne 人机校验挡住），且不在任何中文基准里。两项都不可核实。
- **硅基流动 fnlp/MOSS-TTSD-v0.5** — 形态不对：双人对话/播客模型，`[S1][S2]` 切换说话人，不是单人朗读。
- **火山 bigtts 1.0（¥5/万字符）/ 豆包音频生成 1.0（¥1/分钟、不流式）/ 腾讯超自然档（¥0.129/min）/ 腾讯精品档（上一代小模型）** — 分别失价格、失流式、失价格、失质量。

## 2. 诚实的推荐：留在硅基流动，但去做一次读音实测

没有任何候选在**质价比**上打赢现状。逐条说清楚：

- 比现状便宜的只有腾讯大模型音色档（¥44 对 ¥55，一年省 ¥11），它的中文质量证据是**零**，而且采样率在官方同一页里自相矛盾。为每年 11 块钱换一个没有任何基准数据、可能只有 16 kHz 的音色档，是明显的坏交易。
- 比现状**质量有据地好**的只有火山 seed-tts-2.0（.879）和 Azure（.756）。火山贵一倍，绝对差额是每年 ¥54；Azure 在 F0 免费层下反而是 ¥0。价格在这个用量下根本不是决策变量——你一年的 TTS 账单是一顿饭钱，¥55 和 ¥109 之间的选择不该由钱来定。
- 挡在火山前面的是延迟，不是钱。火山自己的产品简介写「流式调用首包耗时在 600ms 左右」，那会直接违反 p90 < 500 ms。但那张表描述的是上一代 bigtts，且表里的采样率信息已经和 2.0 接口文档打架（表说单向流只有 24K/16K/8K，接口文档给到 48000），说明它至少部分过期。这是唯一一个研究解决不了、只能实测的问题。
- 挡在 Azure 前面的是两件事：世纪互联中国区个人开发者能不能开户（azure.cn 的 purchase-options / subscription-agreement 页面 2026-08-27 全部 404，条款只给 PDF，历史惯例要企业执照），以及 F0 免费层写死的 **20 次请求 / 60 秒**不可调。按句接力时 5 分钟简报约 100 句，稳态就是每分钟 20 次请求，正好顶在天花板上。免费额度按字符算只用掉 12%，卡死你的是请求频率不是字符数。

所以：**不要换。** 换厂商的成本是一条新的 Rust 路径加一整套新的失败模式，换来的是每年几十块钱的价差和一个未经你自己验证的质量分。现状在三条硬标准上的余量是全场唯一被真实测量过的：首帧 0.9%（标准是 < 40%）、RTF 0.118（标准是 < 0.7）、p90 350.9 ms（标准是 500 ms）。没有第二家拿得出这样一组数。

真正该动的地方也不在厂商侧。基准的失分集中在 Sports .233 / Unit .342 / Brand .422 / Military .440 / Generation .509，而科技简报密集命中 Unit / Brand / Abbreviation / Range。基准之所以禁止 LLM 改写和 SSML，是因为它在考产品的裸输入行为——**但你的管线上游本来就有一个 LLM 在生成简报文本**。让它直接吐「九十六比九十一」「六百二十牛·米」「百分之三十」而不是「96-91」「620N·m」「30%」，整条失分轴就绕开了，成本为零，对任何厂商都生效，而且比任何一次换厂商的收益都大。先做这个。

## 3. 质量单独说

CN-NewsTTS Bench v0.1（[arXiv:2606.24714](https://arxiv.org/abs/2606.24714)，网易云音乐 Shijun Luo，采样 2026-06-20~06-23，仓库 [github.com/Jayden-X-L/cn-news-tts-bench](https://github.com/Jayden-X-L/cn-news-tts-bench)）：

| Azure zh-CN-XiaoxiaoNeural | .756 | [.728, .782] | .756 | **1.000** | 750 / **0** / 242 |
| Google cmn-CN-Chirp3-HD | .604 | — | .861 | .701 | 599 / 255 / 138 |
| MiniMax speech-2.8-hd | .548 | [.517, .579] | .850 | — | — |
| 阿里 cosyvoice-v3-plus | .472 | [.441, .503] | .533 | — | — |
| 小米 mimo-v2.5-tts | .275 | — | .628 | .438 | 273 / 350 / 369 |
| AWS Polly Zhiyu | .244 | [.218, .272] | .570 | .428 | 242 / 323 / 427 |

分类里：火山体育比分 .996、军事 .865，弱在单位符号 .573 和中外混合品牌名 .391。cosyvoice-v3-plus 单位符号 **.021**（几乎全错）、体育比分 .134、军事 .198、品牌 .281。MiniMax 体育比分 .000（把 96-91 读成「九十六到九十一」）。

这份证据能信到什么程度，说清楚：它是**唯一**一份对口的中文 TTS 基准，测的正是「裸文本进去，数字/比分/型号/单位/缩写/年份区间念对没有」，和每日科技简报是同一件事。但它是单作者 2026-06 的 v0.1 预印本，全自动 ASR 评分，四天采样窗口，论文里没有厂商配置确认环节，它自己的 Limitations 写明「should not replace human listening tests. ASR text can hide pronunciation errors, especially same-character tones」。当方向性证据用，别当判决书。

三条限制必须点名：

1. **现役方案根本没被测过。** 表里的 .472 是阿里托管的 cosyvoice-v3-plus（longanyang 音色），和硅基流动托管的 CosyVoice2-0.5B 开放权重是同族不同物。把 .472 安到你头上是推断不是测量。0.5B 更小更老，没有理由假设它更好，但这终究是推断。
2. **没有任何基准量「好不好听」。** TTS Arena V2 明文 English-only；Artificial Analysis 的 Elo 不发布语种分解，证据是同一家厂商内部劈成 Qwen3 TTS Flash 940.4 对 Qwen-Audio-3.0-TTS-Plus 1237.3。2026 年在普通话自然度上没有任何可引用的公开证据。Cartesia 那个全场最高的 Elo 1285 对「念中文科技新闻」信息量为零。
3. **没有任何第三方量首包时间。** Artificial Analysis 的 Speed 指标是「生成整段音频的中位时间，含下载」。所以火山的 600 ms、ElevenLabs 的 75 ms、CosyVoice 的 150 ms、Breeze 的 40 ms，一个都没有被第三方复现过。你那 40 句的测试台是唯一能量到你这套架构真正依赖的那个数的仪器。

最好的质量不是最好的质价比：火山比现状每年多花 **¥54**（5 分钟/天，¥109 对 ¥55；含标点约 ¥137 对 ¥71）。差距是可听的不是仅可测的——.879 对（推断的）.472 意味着在型号、单位、百分号、英文缩写密集的文本上，大约是「八个里错一个」和「两个里错一个」的分别，你会直接听到 620N·m 被念成字母、96-91 被念成区间。这不是韵律偏好上的细微差异。但 CosyVoice2 具体是不是按 v3-plus 的比率在错，没人测过。

## 4. 接下来该测什么

两个，都是一小时量级，回答的是研究回答不了的问题。（顺带：`docs/assets/tts-probe/tts_bench.py` 不在主 checkout 也不在 git 索引里，应该还在 ttsbench 那个 worktree，落地前记得合过来。）

**第一个：火山 seed-tts-2.0-standard，走 HTTP Chunked 单向流式。** 适配器约一小时——`POST /api/v3/tts/unidirectional`，三个明文请求头，没有 HMAC，没有 access token 交换，reqwest 流式读 chunk + serde_json + base64 就完了（[volcengine.com/docs/6561/1359370](https://www.volcengine.com/docs/6561/1359370)）。控制台点【试用】领 20000 字符免费额度，够跑两轮还有大量富余。它回答两个研究解决不了的问题：一是首包到底是不是 600 ms——厂商自己那句话描述的是上一代，可能过期也可能没过期，只有同隧道同 session 跑那 40 句才知道；二是首帧携带多少音频，两条流式路的 chunk 粒度厂商一个字都没写。**如果 p90 真落在 600 ms，照标准 3 判死，不要因为 .879 而放宽标准。** 如果 HTTP 路首帧粒度太粗但延迟过关，再上 WebSocket 单向流式（raw PCM 二进制帧，一两百行）复测。

同一轮里顺手把读音也测了：从基准公开的 800 条里挑几十条含型号、单位、百分比、英文缩写的科技类，用现在的 CosyVoice2 和火山各合一遍，评分器可离线跑。这把「CosyVoice2 到底多差」从推断变成数字——这是整份研究里最大的空洞，而且它决定了要不要换。

**第二个：Gitee AI 模力方舟的 CosyVoice3，但先花十分钟而不是一小时。** 注册（要大陆手机号），打开模型页把价格和免费额度抄出来，然后 `POST /v1/audio/speech` 带 `response_format=pcm` 发一句。**这一步就能判生死**：如果只出 mp3 或者攒整句才 flush，整条路当场塌掉，别再往下投时间。过了这关再改 base URL 和 model id 跑那 40 句——代码已经是 OpenAI 兼容的，不需要新适配器。它回答的问题是：有没有一个同族、同参数量、CER 减半（0.71–0.81 对 1.45）、境内托管、按句接力的 relay 经济学原封不动的升级。这是全场唯一一个「换过去几乎零工程成本」的质量升级路径，缺的只有价格那一个数（[ai.gitee.com/v1/models](https://ai.gitee.com/v1/models)，[huggingface.co/FunAudioLLM/Fun-CosyVoice3-0.5B-2512](https://huggingface.co/FunAudioLLM/Fun-CosyVoice3-0.5B-2512)）。

不值得花那一小时的：Azure（先得知道个人能不能开 21Vianet 的户，再得解决 F0 的 20 次/60 秒和按句接力撞车；问蓝云 contactus@oe.21vianet.com / 400-089-0365 是十分钟的事，测试台是一小时的事，顺序别反）、腾讯（零质量证据，省 ¥11/年）、讯飞（超拟人没有公开价）、阿里（你已经测过 qwen3-tts-flash，三项全输，qwen-audio-3.0-tts 连单价都没公开）、所有境外厂商（RTT 结构性出局）。

最后一条前提要先说清楚，否则上面所有可达性结论都悬空：你现有的 317.7 / 350.9 是「same tunnel」下测的。如果开发机常态走隧道，那这是隧道下的数字，而 TestFlight 上架后终端用户走裸网。对境内厂商这只会更快不会更慢，现状的余量只是被低估了；但这也意味着这台机器上测到的任何境外厂商数字都只是下界，不能当结论用。真要判境外，只能在 iPad 真机的真实网络上测。
