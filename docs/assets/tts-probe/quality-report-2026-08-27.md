所有音频 24 kHz / 16-bit / 单声道。脚本 `ttsq.py`（合成 + ASR）、`retake.py`（二次取样复核）、`metrics.py`、`match.py`。

## 二、判读

### 三家共同的硬伤：连字符

`苏-27` 三家全部念成「苏**负**二十七」，两次取样、六个音色，无一例外。第三方评测点名小米的那个错法，实际上三家都有。
`RISC-V`、`5G-A` 里硅基流动和阿里把连字符念成「**减**」，只有小米念对。小米则在 `GPT-5` 上把连字符念成「**杠**」。
没有一家的连字符处理是对的，只是错的位置不同。这一类必须在送进 TTS 之前做文本预处理，三家都一样。

### 小米 mimo-v2.5：四个确定的前端 bug，但都可预测

- `LLM` → 念成「一千」。两个音色都复现。这个词这个项目每天都要念。
- `18A 制程` → 念成「十八**安培**制程」。两个音色都复现。
- `GPT-5` → 「GPT **杠** 5」。
- `620N·m` → 「620 N 米」（字母 N 加「米」，正确应为「牛米」）。

另一面：`4.8TB/s` 三家里只有小米展开成「**四点八太字节每秒**」，另两家在拼字母。`RISC-V`、`5G-A` 也只有小米对。
百分比、小数、`2026 年`、`1024 比特`、`第十二次`、长数字、五句多音字（量产/参数/涨幅/着陆/重新）全对。

这些错误的共同点是**确定性**：同一段文本每次都错在同一处，用一张替换表（LLM→大模型、18A→18A、GPT-5→GPT5）就能全部消掉。

我没有复现第三方评测里「小米 0.275 排第 6、阿里 0.472」的差距。在我这批句子上小米和阿里各有胜负，量级相当。
（口径不同：那份评测按整句严格准确率，我这里按逐项判读；但相对排序应该是可比的，而相对排序没有复现。）

### 阿里 qwen3-tts-flash：错得最少，也最没有惊喜

真错只有连字符那一类（`苏-27`、`RISC-V`、`5G-A`）和把单位拼成字母（`4.8TBS`、`620 2M`）。
`18A`、`GPT-5`、`LLM`、`API`、`SDK`、所有百分比和数字全对。三十一句里没有一句出现解码器抖动。
弱点是单位一律拼字母不展开，听感偏"机器读稿"，但不产生歧义。

### 硅基流动 CosyVoice2：不是读音问题，是稳定性问题

前端错误和阿里同级（同样的连字符坑），但另外有 **11/31 句出现内容级损坏**，其中 6 句整词被毁：

- `RTX 5090 首发售价公布` → 「RTX 509**式**首发**手加工部**」
- `传回首批地表图像` → 「**船回手 PD 表**图像」
- `月产能规划 5 万片晶圆` → 「**天越**产能规划 5 万**聘精元**」
- `OpenAI 宣布` → 「**欧克美艾**宣布」
- `服务器芯片` → 「**微负器**芯片」
- `新款电机峰值扭矩` → 「新款**舰机风式**扭矩」，并且把 `·m` 整个吞掉

外加几处声调错：`推理`→`退理`、`该`→`改`、`开源`→`开人`。

重取四句，全部变干净——所以这不是可以靠文本预处理修掉的前端 bug，是**随机的**。
对每天自动播报的场景，随机比确定性糟得多：你无法预防，也不知道今天哪一句会崩。

### 对「每天念科技简报」这个用途的结论

排序：**阿里 ≈ 小米（预处理后）> 小米（裸用）>> 硅基流动**。

- 硅基流动 CosyVoice2 出局。三成句子随机损坏，加上 8 kHz 带宽（见下），两条都是不能接受的。
- 阿里裸用最稳，代价是单位拼字母、听感平。
- 小米裸用会在 `LLM` 上翻车（每天必踩），但四个 bug 全部可预测、可用替换表消掉；消掉之后它在单位展开和 RISC-V/5G-A 上反而比阿里好，音频指标也最好。
- 不管选谁，连字符都要在送进 TTS 前处理掉。

## 五、一个必须记下来的接口坑

**阿里 qwen3-tts-flash 的 SSE 首帧不是裸 PCM，是一整个 WAV 文件**：44 字节 RIFF 头（data size 填的是占位符 0x7FFFFFFF），后面才是采样点。
按裸 PCM 拼起来，那 44 字节会解码成每一条音频开头一个满刻度的咔哒声——31/31 句的全段峰值都落在前 5 ms，`|x[0]|` 高达 0.57。

我第一版就是这么写的，差点把它当成阿里的音频缺陷写进报告。修掉之后阿里的峰值中位数从 -0.0 dBFS 回到 -7.3 dBFS，"削波 62 个样本"这个数字归零。
本报告第三节的所有阿里数字都是修正后的。补丁在 `ttsq.py` 的 `synth_dashscope()` 末尾。

另两家给的是真裸 PCM，没有头。

## 六、没测到的东西

- **自动 MOS 打分**：没做。要下 torch 加一个音质打分模型，成本高，而且这类模型在中文上的可靠性存疑——一个不可信的分数比没有分数更糟。音质判断交给第四节的试听样本。
- **主观自然度、情感、停顿合理性**：机器测不了，只能靠人听。
- **句间接力的实际听感**：只合成了整段，没有做「逐句合成再拼接」的音频。头尾静音数据（第三节）能预估，但拼接处的音高和语速是否连得上，要真拼一遍才知道。
- **长文本一致性**：样本只有 375 字约 70 秒。更长的稿子里音色是否漂移没有验证。
- **ASR 天花板**：SenseVoiceSmall 自己会错（`该`/`改`、`自给`/`次给`、`晶圆`/`金圆` 这类同音字分不开），所以本报告只用它做三家横向对照，没有拿它算绝对准确率。
- **音色选择**：每家只测了一到两个音色。读音错误来自文本前端，换音色不该变（第二节的复核也印证了），但音质和听感会变。
