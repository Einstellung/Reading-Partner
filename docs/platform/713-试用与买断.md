# 试用与买断

2026-11-27 定。C 端定价：3 个月免费试用，功能完整；试用期满一次性买断 9.99 美元，永久解锁。用户继续用自己的 AI API key，我们不代理也不垫付模型调用费。

## 规则

试用期满未买断，整个 app 锁住，不只是 AI。锁屏只有四项：购买、恢复购买、删除账号、退出登录。不提供数据导出，书和对话本来就在用户自己的 Google Drive（docs/platform/13）。

使用 app 必须登录，试用时钟因此跑在服务端。登录方式是 Google 和 Sign in with Apple，都走原生：app 拿到服务商的 id_token，调用 Supabase Auth 的 `signInWithIdToken` 换会话。Google 的 id_token 在 Drive 同步登录里已经在取（docs/platform/18）；Apple 在 iOS 上走原生 ASAuthorization。

强制登录写进审核备注的理由：授权跨设备生效，同步按账号进行。另备一个审核测试账号。

已有用户（发起人和一两个在用的人）在管理后台直接标为已购买。

## Sign in with Apple

代码已进 main，处于关闭状态。原生插件 `plugins/apple-sign-in`：iOS 上用 `ASAuthorizationAppleIDProvider` 发请求，scope 只要 email（不收姓名，同 665），`ASAuthorizationController` 挂在 app 的 key window 上；其他平台答 unavailable。前端 `src/platform/app/apple-sign-in.ts` 生成随机原始 nonce，把它的 SHA-256 十六进制交给 Swift 放进 `request.nonce`，自己留着原始值；`signInWithApple()` 返回 `{ ok, idToken?, nonce?, cancelled?, error? }`，用户取消是 `cancelled: true`。拿到后调 `exchangeIdToken(backend, idToken, fetch, now, { provider: "apple", nonce })` 换 Supabase 会话（请求体 `{ provider: "apple", id_token, nonce }`）。`APPLE_SIGN_IN_ENABLED` 为 false 时 `signInWithApple()` 直接答 unavailable、`appleSignInAvailable()` 答 false，都不调插件。没有 entitlement 时 Swift 照样编得过，模拟器冒烟不受影响。

打开步骤：

1. 开发者门户 Identifiers 里给 `com.xinyuan.readingpartner` 勾 Sign In with Apple（Enable as a primary App ID），`.dev` 包名（ios-linux-loop 用）也勾一次；或用 API `POST /v1/bundleIdCapabilities`，`capabilityType` 为 `APPLE_ID_AUTH`。云签名不会替 App ID 开 capability（坑 401）。
2. 加 entitlement `com.apple.developer.applesignin = ["Default"]`。文件是 `src-tauri/gen/apple/reading-partner_iOS/reading-partner_iOS.entitlements`，由 `tauri ios init` 每次现生成、不进 git，所以在 `ios-testflight.yml` 和 `ios-linux-loop.yml` 的 `tauri ios init` 之后加一步写入，例如 `/usr/libexec/PlistBuddy -c "Add :com.apple.developer.applesignin array" -c "Add :com.apple.developer.applesignin:0 string Default" <该文件>`。不要放进插件的 build.rs：命中 rust-cache 时 build script 不跑（坑 157）。
3. 不用重做 profile：TestFlight 走 App Store Connect API key 云签名（`-allowProvisioningUpdates`），export 时按 App ID 现建 profile，第 1 步做完新 profile 自然带上这个 capability。仓库里没有手工 profile。
4. Supabase 控制台 Authentication → Providers → Apple 打开，Client IDs 填 `com.xinyuan.readingpartner`（测 dev 包再加 `com.xinyuan.readingpartner.dev`）。只走原生不需要 Secret Key。nonce 检查保持开启。
5. 把 `APPLE_SIGN_IN_ENABLED` 改成 true，登录界面接 `appleSignInAvailable()` 和 `signInWithApple()`。

## 支付

RevenueCat，月跟踪收入 2500 美元以内免费，超出收 1%。RevenueCat 的 app_user_id 取 Supabase 的 user id，这样在 iPad 上买了，手机和桌面也解锁。RevenueCat webhook 调 Edge Function 写 purchased_at。

iOS：9.99 美元的非消耗型内购，加入小型企业计划，抽成 15%。苹果对非订阅 app 的限时试用要求做成一个 0 元的非消耗型项目，名字如「3-Month Trial」，照做；但试用是否到期以服务端时钟为准。Android：Google Play 一次性商品，经 RevenueCat。桌面和 GitHub 版安卓：Stripe 网页结账，直接由服务端接 Stripe 的通知，见下文「网页结账」。

app 侧是插件 `plugins/purchases`，iOS 经 SPM 引入 RevenueCat `purchases-ios` 5.x，Android 经 Gradle 引入 `purchases-android` 11.x。两端共用 `configure`（用 Supabase user id，换账号走 `logIn`）、`buy_lifetime`（取消返回 `cancelled: true`）和 `restore`（返回 `lifetime` entitlement 是否生效）。前端 `src/platform/app/purchases.ts` 按平台取 `REVENUECAT_IOS_API_KEY` 或 `REVENUECAT_ANDROID_API_KEY`，对应 key 为空时返回 `not configured`。桌面原生插件返回 `unavailable`。两端的商品 ID 都是 `lumen.lifetime`，都挂到 `lifetime`。StoreKit 内购不需要 entitlement 文件条目。

启用 Android 内购时，在 Google Play Console 开通商家收款账号，创建 9.99 美元的一次性商品 `lumen.lifetime` 并启用购买选项。用服务账号凭据把 Play 应用接入 RevenueCat，将商品设为非消耗型，接通 Play 实时开发者通知以同步退款，再把 Android 公开 SDK key 填进 `REVENUECAT_ANDROID_API_KEY`。

## 状态检查

app 启动时带 Supabase 会话问 Edge Function，答案是 trial、purchased、expired、banned 之一，附试用截止日期。答案带签名，缓存在本地。离线宽限 7 天：连不上服务器时，只要上次成功检查在 7 天内就沿用缓存的答案，超过 7 天锁住。

## 管理后台

起步不做自定义面板。用户、登录和设备看 Supabase 控制台，购买看 RevenueCat 控制台，再建一个 Postgres 视图做总览：今日登录数、即将到期的试用、购买数。需要手工操作（延长试用、封禁、退款）时再上自定义面板，Refine 或 Retool。

## 实施顺序

第一步只动后端，app 界面不变：建 Supabase 项目和 accounts、devices 两张表（`supabase/migrations/`），app 现有的 Google 登录上报改为拿 id_token 换 Supabase 会话再报设备，默认打开（docs/platform/665）。不加 `profile` scope，不收姓名。Vercel 后端 `server/` 删除，隐私政策和条款移到 `site/`。上架前苹果隐私标签照隐私政策列出收集的字段：邮箱、用户 ID、设备信息。

后续依次：Sign in with Apple、启动强制登录、锁屏、内购与 RevenueCat、升 Pro。

## 实现

代码已写完、默认关闭（2026-11-27）。两道开关都关着时，app 的启动和今天完全一样：不发状态请求、不出界面、不写文件。

客户端开关是 `src/platform/license/config.ts` 的 `LICENSING_ENABLED`，出厂为 false，测试盯着。同一文件里的 `LICENSE_PUBLIC_KEY` 为空、后端地址为空、或这个构建没有可用的登录方式时，检查也直接放行。服务端开关是 `public.app_config` 表的 `licensing_enforced`，默认 false；没开时 `license-status` 对所有人答 `open`，旧客户端打开开关也锁不住任何人。

状态值五个：`open`（服务端开关没开）、`trial`、`purchased`、`expired`、`banned`。服务端判定顺序：封禁优先，其次已购买，再看试用；试用截止 = `trial_started_at` + 3 个月，按 Postgres 加 interval 的方式（月底截到当月最后一天）。客户端把 `open`、`purchased` 和未到期的 `trial` 视为放行；`trial` 过了截止日期即使来自缓存也按 `expired` 处理。

答案是 `{ payload, signature }`：payload 是 `{ v, userId, status, trialEndsAt, issuedAt }` 的 JSON 原文，signature 是对这段原文的 ECDSA P-256 / SHA-256 签名（WebCrypto 的 r||s 64 字节，base64url）。客户端只验签收到的原文，不做规范化。不用 Ed25519，WKWebView 和 WebView2 的 WebCrypto 都稳定支持 P-256。

缓存是 AppData 下的 `license.json`，存签过名的原样答案，和 `account.json` 一样不在任何 palace kind 里，因此不同步；每次读都重新验签，改文件没用。离线宽限从服务端签发时间 `issuedAt` 算 7 天，不信本机记的检查时间；`issuedAt` 比本机时钟晚一天以上也不认（防把时钟往回调）。缓存只对签发给的那个账号有效。

会话：沿用 `account.json` 里的 Supabase 会话，access token 剩不到一分钟就刷新，刷新被拒再用 Google id_token 换，不看上报的同意标记。完全拿不到会话（没登录 Google）出登录页；连不上（没网、服务端出错、超时 10 秒、签名不对）走缓存。状态请求返回 401 时强制刷新一次再问。

检查时机：启动一次；回前台时，距上次检查超过 6 小时、或当前不是放行状态就再查；Google 登录状态变化时再查。

界面：`src/ui/components/license/`，两个外壳各挂一个 `<LicenseGate />`，放行时什么都不画。登录页只有 Google 按钮（复用设置里同一个登录流程），Apple 按钮受 `APPLE_SIGN_IN_AVAILABLE` 控制，现为 false。锁屏是盖住整个 app 的全屏页（`OVERLAY_Z.lock`，在所有浮层之上，确认框在 `lockDialog`）。试用到期：购买、恢复购买、删除账号、退出登录四个按钮；封禁：只有删除账号和退出登录，买了也解不开；离线超过宽限：重试和退出登录。删除账号先确认，调 `delete-account`，成功后本机退出 Google 登录并删 `license.json`。

购买和恢复由 `src/platform/license/store-handlers.ts` 调用内购插件，app_user_id 传 Supabase user id。授权开启后，购买成功会立刻重查，服务端还没收到 webhook 时提示稍等。

服务端代码在 `supabase/functions/`，未部署：`license-status`、`revenuecat-webhook`、`delete-account`，共用的判定和 webhook 映射是 `_shared/license.ts`、`_shared/revenuecat.ts`，不依赖 Deno，app 的 `bun test` 直接测（`tests/supabase/`）。webhook 只认 `LIFETIME_PRODUCT_ID` 的 INITIAL_PURCHASE、NON_RENEWING_PURCHASE（写 purchased_at 和 purchase_source，已有则不动）和 REFUND、CANCELLATION（清空），app_user_id 不是 UUID 的忽略；重放无害。沙盒购买的 purchase_source 带 `(sandbox)`。

打开的步骤：

1. `bun scripts/license-keygen.ts` 生成密钥对，私钥 JWK 不进仓库。
2. 在 SQL Editor 跑 `supabase/migrations/20261127010000_app_config.sql`。
3. 设密钥：`supabase secrets set LICENSE_SIGNING_KEY='<私钥 JWK>' REVENUECAT_WEBHOOK_AUTH='<随机串>' LIFETIME_PRODUCT_ID='<商品 id>'`。
4. 部署：`supabase functions deploy license-status`、`supabase functions deploy delete-account`、`supabase functions deploy revenuecat-webhook --no-verify-jwt`。RevenueCat 后台的 webhook 填 `https://<ref>.supabase.co/functions/v1/revenuecat-webhook`，Authorization 填同一个随机串。
5. 把公钥 JWK 填进 `LICENSE_PUBLIC_KEY`，`LICENSING_ENABLED` 改 true，发版。此时服务端仍答 `open`，客户端只验证链路。
6. 已有用户在控制台标 purchased_at，然后 `update public.app_config set value = 'true' where key = 'licensing_enforced';` 打开强制。

## 网页结账

代码已写完、默认关闭（2026-11-27）。给没有应用商店内购的设备用：macOS、Windows 桌面和 GitHub 上发的 Android APK。

设备走哪条路由 `src/platform/license/purchase-path.ts` 的 `choosePurchasePath` 定：iOS 和 Google Play 构建只走商店内购，商店不可用时不给买；桌面和 APK 在 `WEB_CHECKOUT_URL` 非空时走网页结账，为空时也不给买。Android 构建默认算 GitHub APK（`VITE_ANDROID_DISTRIBUTION` 不设），以后出 Play 构建时设成 `play`。不给买的锁屏把购买和恢复购买换成一行「在 iPhone、iPad 或 Android 上的 Lumen 里用同一个账号购买，然后刷新」和一个刷新按钮。

网页结账用 Stripe Payment Link，不由服务端建 session。点购买时在系统浏览器里打开 `WEB_CHECKOUT_URL?client_reference_id=<Supabase user id>&prefilled_email=<Google 邮箱>`，锁屏随后出现刷新按钮，刷新就是重新问 `license-status`，由服务端决定。这类设备没有恢复购买，刷新顶替它。支付方式（银行卡、Apple Pay、Google Pay、微信支付，不开支付宝）在 Stripe 后台配，代码不依赖。

服务端是 Edge Function `stripe-webhook`，用 `STRIPE_WEBHOOK_SECRET` 验 `Stripe-Signature`（对 `${t}.${原始请求体}` 做 HMAC-SHA256，常量时间比较，签名时间超过 5 分钟拒收），逻辑在 `_shared/stripe.ts`，不用 Stripe SDK。`checkout.session.completed` 且 `payment_status` 为 paid、`client_reference_id` 是 UUID 时，写 purchased_at（已有则不动）、purchase_source 为 `stripe`（测试模式为 `stripe (test)`）、purchase_ref 为 payment intent id。`charge.refunded` 且全额退款时按 purchase_ref 找到账号清空购买。重放无害，其他事件答 200 不处理。purchase_ref 列由迁移 `20261127020000_purchase_ref.sql` 加，客户端权限不变。

销售税：Stripe 不是记录商户（merchant of record），税由发起人自己负责。只在某个州的销售额或单数超过该州的经济关联（economic nexus）门槛后才需要在那个州登记和缴税；Stripe Tax 可以监控各州是否接近门槛。

打开步骤：

1. 以美国个人身份开 Stripe 账号。申请微信支付：Stripe 要求有一个能访问的网站，上面有产品、价格和结账入口。
2. 在 Stripe 后台建 9.99 美元的一次性商品和它的 Payment Link，打开需要的支付方式。
3. 在 SQL Editor 跑 `supabase/migrations/20261127020000_purchase_ref.sql`。
4. Stripe 后台 Webhooks 建 endpoint：`https://<ref>.supabase.co/functions/v1/stripe-webhook`，payload 选 Snapshot（函数读 `data.object`），事件只勾 `checkout.session.completed` 和 `charge.refunded`。把 `whsec_` 开头的签名密钥设进去：`supabase secrets set STRIPE_WEBHOOK_SECRET='whsec_...'`。
5. 部署：`supabase functions deploy stripe-webhook --no-verify-jwt`。
6. 把 Payment Link 填进 `src/platform/license/config.ts` 的 `WEB_CHECKOUT_URL`，发版。
