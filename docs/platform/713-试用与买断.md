# 试用与买断

2026-11-27 定。C 端定价：3 个月免费试用，功能完整；试用期满一次性买断 4.99 美元，永久解锁。用户继续用自己的 AI API key，我们不代理也不垫付模型调用费。

## 规则

试用期满未买断，整个 app 锁住，不只是 AI。锁屏只有四项：购买、恢复购买、删除账号、退出登录。不提供数据导出，书和对话本来就在用户自己的 Google Drive（docs/platform/13）。

使用 app 必须登录，试用时钟因此跑在服务端。登录方式是 Google 和 Sign in with Apple，都走原生：app 拿到服务商的 id_token，调用 Supabase Auth 的 `signInWithIdToken` 换会话。Google 的 id_token 在 Drive 同步登录里已经在取（docs/platform/18）；Apple 在 iOS 上走原生 ASAuthorization。

强制登录写进审核备注的理由：授权跨设备生效，同步按账号进行。另备一个审核测试账号。

已有用户（发起人和一两个在用的人）在管理后台直接标为已购买。

## Sign in with Apple

代码已进 main，处于关闭状态。原生插件 `plugins/apple-sign-in`：iOS 上用 `ASAuthorizationAppleIDProvider` 发请求，scope 只要 email（不收姓名，同 665），`ASAuthorizationController` 挂在 app 的 key window 上；其他平台答 unavailable。前端 `src/platform/app/apple-sign-in.ts` 生成随机原始 nonce，把它的 SHA-256 十六进制交给 Swift 放进 `request.nonce`，自己留着原始值；`signInWithApple()` 返回 `{ ok, idToken?, nonce?, cancelled?, error? }`，用户取消是 `cancelled: true`。拿到后调 `exchangeIdToken(backend, idToken, fetch, now, { provider: "apple", nonce })` 换 Supabase 会话（请求体 `{ provider: "apple", id_token, nonce }`）。`APPLE_SIGN_IN_ENABLED` 为 false 时 `signInWithApple()` 直接答 unavailable、`appleSignInAvailable()` 答 false，都不调插件。没有 entitlement 时 Swift 照样编得过，模拟器冒烟不受影响。

打开步骤：

1. 开发者门户 Identifiers 里给 `com.xinyuan.readingpartner` 勾 Sign In with Apple（Enable as a primary App ID），`.dev` 包名（ios-linux-loop 用）也勾一次；或用 API `POST /v1/bundleIdCapabilities`，`capabilityType` 为 `APPLE_ID_AUTH`。云签名不会替 App ID 开 capability（坑 401）。
2. 加 entitlement `com.apple.developer.applesignin = ["Default"]`。文件是 `src-tauri/gen/apple/reading-partner_iOS/reading-partner_iOS.entitlements`，由 `tauri ios init` 每次现生成、不进 git，所以在 `ios-testflight.yml` 和 `ios-linux-loop.yml` 的 `tauri ios init` 之后加一步写入，例如 `/usr/libexec/PlistBuddy -c "Add :com.apple.developer.applesignin array" -c "Add :com.apple.developer.applesignin:0 string Default" <该文件>`。不要放进插件的 build.rs：命中 rust-cache 时 build script 不跑（坑 157）。
3. 不用重做 profile：TestFlight 走 App Store Connect API key 云签名（`-allowProvisioningUpdates`），export 时按 App ID 现建 profile，第 1 步做完新 profile 自然带上这个 capability。仓库里没有手工 profile。
4. Supabase 控制台 Authentication → Providers → Apple 打开，Client IDs 填 `com.xinyuan.readingpartner`（测 dev 包再加 `com.xinyuan.readingpartner.dev`）。只走原生不需要 Secret Key。nonce 检查保持开启。
5. 把 `APPLE_SIGN_IN_ENABLED` 改成 true，登录界面接 `appleSignInAvailable()` 和 `signInWithApple()`。

## 后端

Supabase：Auth、Postgres、Edge Functions。先用免费档，收钱之前升 Pro（25 美元/月）：免费项目一周没有任何请求会被暂停，数据保留、90 天内可恢复，暂停期间登录和状态检查都失败。不用 Vercel，它的 Hobby 档只许非商业用途。授权接口放在 Supabase Edge Function。

665 的 users 表迁过来，增加 trial_started_at（用户首次登录时由服务端写入）、purchased_at、purchase_source、banned。devices 表原样迁过来。防一份购买被很多人共用：把 Drive 同步用的 Google 账号和登录账号对照，并盯每个账号下的设备数。

## 支付

RevenueCat，月跟踪收入 2500 美元以内免费，超出收 1%。RevenueCat 的 app_user_id 取 Supabase 的 user id，这样在 iPad 上买了，手机和桌面也解锁。RevenueCat webhook 调 Edge Function 写 purchased_at。

iOS：4.99 美元的非消耗型内购，加入小型企业计划，抽成 15%。苹果对非订阅 app 的限时试用要求做成一个 0 元的非消耗型项目，名字如「3-Month Trial」，照做；但试用是否到期以服务端时钟为准。Android：Google Play 一次性商品，经 RevenueCat。桌面：以后用 Stripe 或 Paddle，同样记入 RevenueCat。

## 状态检查

app 启动时带 Supabase 会话问 Edge Function，答案是 trial、purchased、expired、banned 之一，附试用截止日期。答案带签名，缓存在本地。离线宽限 7 天：连不上服务器时，只要上次成功检查在 7 天内就沿用缓存的答案，超过 7 天锁住。

## 管理后台

起步不做自定义面板。用户、登录和设备看 Supabase 控制台，购买看 RevenueCat 控制台，再建一个 Postgres 视图做总览：今日登录数、即将到期的试用、购买数。需要手工操作（延长试用、封禁、退款）时再上自定义面板，Refine 或 Retool。

## 实施顺序

第一步只动后端，app 界面不变：建 Supabase 项目和 accounts、devices 两张表（`supabase/migrations/`），app 现有的 Google 登录上报改为拿 id_token 换 Supabase 会话再报设备，默认打开（docs/platform/665）。不加 `profile` scope，不收姓名。Vercel 后端 `server/` 删除，隐私政策和条款移到 `site/`。上架前苹果隐私标签照隐私政策列出收集的字段：邮箱、用户 ID、设备信息。
