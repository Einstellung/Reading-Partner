# 删除一本书

> 2026-09-05 定案。同步引擎的删除模型在 [13](./13-账户同步.md)，文件级删除过不了同步的实测在坑 [208](../pitfall/storage/208-file-deletion-does-not-survive-sync.md)，两个记忆仓在 [48](../soul/48-记忆：观察与statement.md)。

---

## 删什么留什么

划分标准是数据关于书还是关于人。

关于书的随书删：PDF 本体和 library 条目、阅读位置、批注、聊天线程、章节备课材料 `prep-<bookId>/`、全文和图表缓存、复述与排练。

关于人的留下：statement 一律不动。

观察介于两者之间。按 bookId 挑出这本书的观察写观察墓碑，被任何 statement 的 `evidence` 或 `contradictedBy` 引用的观察跳过不删——它们是 statement 的证据链，dream 靠它核对和 supersede。留下来的那些观察的消息锚点会悬空，接受：锚点只是"点回去"，dream 和检索用的是正文和日期。

topic 不等于书。一个 topic 装几本书，一本书可以在多个 topic 里。观察全部在一个 `observations/` 目录里，每条带 bookId 和 topic。"删一本书"对观察是按 bookId 挑，topic 不参与。

## 载体

`deleted-books.jsonl`（名字是历史遗留，装的是所有会同步的删除），AppData 根目录，在同步范围内，走 `records` 策略的 lines 形状取并集，只追加不改写。一行是一个事件，不是一个状态：

- 书的删除 `{"bookId":"<内容 hash>","at":"<ISO 时刻>"}`，保留第一版的形状，老客户端还能读到书的删除。
- 其余 `{"kind":"book|retell|outline|rehearsal|topic","id":"…","op":"delete|revive","at":"<ISO 时刻>"}`。

一个东西现在的状态 = 它最新那条事件；`at` 按字串比，第一版写的日期排在当天任何时刻之前；同刻删除赢。两台设备各自从同一个并集算，结论相同，所以收敛。写入方 `platform/app/deleted-books.ts`（`recordDeletion` / `recordRevival`，同状态不写第二行，读-改-写串行）；读方一律 `effectiveDeletions`。日志在但读不出来时抛错、绝不改写：改写成一行等于向合并宣布其余每行都删了。

重新导入删过的书就是复活：`importBook` 看到 hash 在日志里是死的，先追加 revive 再落盘。复活只对已知道删除的设备生效——另一台还没收到删除就重导，导入是空操作，删除到达后书被清掉，再导一次就活。

## 引擎

pass 列完远端、扫完本地，先单独把日志拉到最新（download 或 merge），重扫，再算 dead（坑 404）。dead 路径由 palace 表折出来（`platform/sync/dead-paths.ts`）：一条日志事件 `(kind, id)` 命中的是「文件名里的 id 就是这个 id、且 `deleteWith` 不是 never」的所有行——书是 `annotations-`、`supplements-`、`threads-`、`pagination-`、`prep-<hash>/`；复述是 `retell-`、`threads-retell-`；讲稿是 `outline-`、`threads-talk-`；排练是 `rehearsal-`、`runs-rehearsal-`、`runs/<id>/`；topic 不命中任何文件。命中的路径不下载、不上传、不合并，删远端也删本地，本地删之前记进 `sync-trash.jsonl`（只在本机，留 30 天）。

Drive 上的 PDF blob 由 mirror 设备删；手机的 `fetchBook` 拒绝日志里死的书。

purge 队列（`requestRemotePurge`）只删远端，管不了别的设备的本地副本，删除一律不再走它。

## 领域侧顺序

`deleteBook(bookId)`：

1. 写日志。
2. 删 `library.json` 和 `reading-state.json` 里的条目。
3. 从每个 topic 的 `files` 里摘掉引用。
4. 观察按 bookId 写观察墓碑，跳过被 statement 引用的。一遍读完整个目录，不按 topic 循环。
5. 只含这本书的复述：走 `deleteRetellWithTalk`（下文）。
6. supplement 递归按书删。
7. 删本地派生文件和 `library/<hash>.*`（列表从 palace 折出：blob、covers、fulltext、figures、prep 目录）。

`deleteRetellWithTalk(retellId)`（`reading/delete/delete-retell.ts`，复述菜单、删书、删 topic 三处都走它）：先讲稿——讲稿的排练、`outline-` 和 `threads-talk-`；再复述——`retell-`、`threads-retell-`、按 retellId 挂的排练。每个 store 的 delete 自己写日志、删自己的本地文件。

`deleteTopic(topicId)`：先写 topic 的日志（Brief 除外，它该回来），再级联，最后删 `topics.json` 的行。选日志而不是把 `lastOpenedAt` 搬出 topic 记录：对端在删除前后打开过 topic 里的书就算改了这条记录，合并里改赢删，行会回来；topic store 读盘时按日志滤掉死 topic 和死书的 FileRef，行在不在文件里不再重要。

## 收尾

`settleDeletions()`（`reading/delete/settle.ts`）启动时跑一次、书架 pull 路由每次收到日志也跑：日志里死的书还有 library 条目或 blob 的，补删条目、阅读位置和本地文件；`topics.json` 里被合并带回来的死 topic 行和死书 FileRef 重写掉。删书中途崩、日志从别的设备到达、合并复活记录，都靠它收敛。

## 引用计数与翻译替换

同一个 hash 可以被多处列着：topic 的 FileRef、任何一本书的 `supplements-<id>.json`。从 topic 摘书、删 supplement、删书时递归删它的 supplement，都先数这两处引用，还有别处列着就只摘这一处引用，不动数据。正在同一趟删的书的 supplement 列表不算引用。引用列表读不出来就不删。入口 `deleteIfUnreferenced` / `removeFromTopic`（`reading/delete/delete-book.ts`），判定在 `pick.ts: hasOtherReference`。

删书顺带删这本书各线程的 `images/threads/<threadId>/`，和 prep 下载论文的 `fulltext-*`/`figures-*`（key 是 `prep://<id>/<slug>` 的 hashPath，从 prep state 的 slug 算）。单删一个线程也删它的图。书的观察一次批量写墓碑、重建一次索引。

翻译替换原文不走 deleteBook，走 `retireReplacedBook`（`reading/delete/retire-book.ts`）。批注和线程由 replace.ts 先搬；然后搬到新 hash 的有：阅读位置、supplement 列表、所有列着原文的 topic 和书的 supplement 引用、复述的 materials 和 decisions、观察的 bookId 和按书的批注游标（按 threadId 的游标因线程 id 不变自然对齐）、`prep-<old>/` 整个目录连同 state 里的 id 和论文缓存。全部搬完才写墓碑；搬的任何一步失败就抛，两份文档都留着。之后删的只有原文自己的字节层：blob、封面、全文和图表缓存、pagination、旧的批注和线程文件。线程图片跟着线程 id 走，不删。

## 删 topic 带走文件，手机上的删除入口

删 topic 的确认框列出只在这个 topic 里的书和文章（`pick.ts: filesOnlyInTopic`，按上面的引用计数、把这个 topic 去掉后数；同一趟一起走的书的 supplement 列表不算引用，`orphanedTogether`），给一个默认不勾的「Also delete these N books and M articles」。勾了就在 topic 行删掉之后把这些 hash 逐个再走 `deleteIfUnreferenced`，删时重新数，期间被归进别的 topic 的留下。文案在 `ui/components/shelf/topic-delete.ts`，两端共用。手机上的删除：topic、topic 里的书（`removeFromTopic`，最后一处引用才删书）、Saved 里的文章（`removeSavedArticle`）、PDF 的课（即书级线程连同 aside，删后下一课从头开始）、EPUB 的书级对话、课里的一条 aside（连同它在课里留的那行回执）、阅读器里带对话的划线（对话一起走）。对话类都在 `reading/delete/delete-thread.ts`：删线程树、删线程图片、记 `thread-delete` 事件、删以这些线程为门的页面划线。

## 冲突与老客户端

离线一周的设备回来把批注以更高 rev 推上去，别的设备这一趟判 dead 再 purge 一次，它自己同一趟拉到日志也删本地，一个来回收敛。那一周的编辑没了，这就是删除的含义，`sync-trash.jsonl` 是唯一的回头路。

老版本客户端只读 `bookId` 行，看不见 revive：复活的书在它眼里仍是死的，它会把新批注再 purge 一遍；也看不见复述、讲稿、排练、topic 的删除，会继续持有并推回。全部设备升级之前不要重导删过的书。观察墓碑当初也一样，接受。

## 不做的

- 日志压缩和过期。只增不减，一行不到一百字节，条数被删过和复活过的次数限住。真要做，判据是"比最老那台设备的 lastSyncAt 还老"，需要各设备的心跳文件，今天没有。
- ~~删 topic~~。已实现（`src/reading/delete/delete-topic.ts`）：按 palace kinds 表遍历每种声明了 topicId 引用的记录，删这个 topic 的 retell/outline/rehearsal，解除归档在它下面的对话，收藏文章挪回 Brief，清蒸馏游标，删事件日志，最后删 `topics.json` 条目。不是按书逐条写删除记录——观察目录已经拍平，删 topic 记录本就不会让任何观察消失。
- 给读者一个"连这本书留下的印象一起删"的选项，把只以这本书为证据的 statement 一并标掉。statement 是关于人的，默认不做；将来要做也是显式的第二档。
