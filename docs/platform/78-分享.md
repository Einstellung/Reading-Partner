# 分享

> 2026-09-26 定案。上游：[77](../info/77-办公室与红盒子.md) 是 Lumen 坐在桌角、点它开对话，以及线与批注；[68](../companion/68-Lumen与盒子的交互.md) 是 Lumen；[11](./11-iOS-TestFlight发布.md) 是 iOS 签名和 CI。坑：[426](../pitfall/ios-build/426-a-no-sign-simulator-build-has-no-entitlements.md)、[427](../pitfall/ios-build/427-a-copied-cargo-target-breaks-swift-rs-module-cache.md)。

iOS 上两个方向：别的 app 经系统分享面板把东西交给 Reading Partner，Reading Partner 把东西交给别的 app。Android 不做。

## 往里分享

用户在 X、微信、Safari 里点分享面板里的 Reading Partner，弹一个很薄的表单：上面是链接预览，下面一个可以空着的文本框（占位 "Say something (optional)"），左上 Cancel，右上 Send。UI 文案英文。

链接和文字连同那句话进 Lumen 的对话，作为用户发的一条消息。用户在这句话里说「这是 A 类」，AI 据此把材料分到 77 的某条线；没说就由 AI 猜，回执里标明是猜的。分类工具和线怎么处理不在本文，本文只写到消息落进对话、发起一轮为止。Lumen 是队列的第一个消费方。

PDF、EPUB 等文件进书库导入，和 `watchSharedBooks`（`src/reading/session/shared-file.ts`）用同一个 `fileSharedBook`，落 Brief topic。`CFBundleDocumentTypes` 那条路（Files 的「打开方式」、Safari 下载）保留不动。

## 往外分享

扩展现有的 `plugins/openin`。它在 iOS 上弹 `UIActivityViewController`，现在只交文件，iPad 的弹出锚点已处理。加两个命令：`share_text(text)` 和 `share_url(url)`，URL 以 `URL` 对象放进 activityItems，接收方才当链接处理。改动面：`plugins/openin/src/`（commands、models、ios、fallback、lib 的注册）、`ios/Sources/OpenInPlugin.swift`、`permissions/`。前端 `src/platform/app/open-in.ts` 加 `shareText`、`shareUrl`，可用性沿用 `openInAvailable`。

合订本 EPUB 直接用现有的 `openIn(path, name)`。不引第三方插件，不用 `navigator.share`。

## 开工前

App Group 标识符的注册和分配只能在 developer.apple.com 手动做。ASC API key 做不到：ASC API 没有 appGroups 端点；2026-09-26 用手上的 key 给成员开 provisioningAllowed 也被拒（`The API key in use does not allow this request`）。

步骤，Certificates, Identifiers & Profiles → Identifiers：

1. 注册 App Groups：`group.com.xinyuan.readingpartner`、`group.com.xinyuan.readingpartner.dev`。
2. 注册 App IDs：`com.xinyuan.readingpartner.share`、`com.xinyuan.readingpartner.dev.share`，勾 App Groups。
3. 四个 App ID（两个 app、两个扩展）逐个 Configure，选对应的 group：正式的两个配 `group.com.xinyuan.readingpartner`，`.dev` 的两个配 `.dev` 那个。

做完后先在 Mac 上用 `.dev` 包名跑一次云签名（`--export-method debugging`，配方同 `scripts/ios-dictation/bench-run.sh`），验 app 和扩展两份 `embedded.mobileprovision` 里都带 `com.apple.security.application-groups`，再接 CI。

## 扩展

源码在 `src-tauri/ios-share/`：`ShareViewController.swift`（表单和取 item）、`ShareInbox.swift`（队列）。扩展不含 Rust，设 `APPLICATION_EXTENSION_API_ONLY`。

`src-tauri/gen/apple` 每次 CI 都重新生成，所以扩展靠脚本注入：`scripts/ios-share-extension.ts`，两个子命令，形状同 `ios-deep-link-plist.ts`。

- `inject`，在 `tauri ios init` 之后跑：往 `project.yml` 加 `ShareExtension` 这个 app-extension target；主 target 加 `dependencies: - target: ShareExtension, embed: true`；两边 Info.plist 写 `RPAppGroup`；拷 Swift 源码；重跑 xcodegen；之后再把 group 补进主 app 的 entitlements（xcodegen 重跑会清空它，init 写出的是空 dict）。
- `verify <.app|.ipa>`：扩展在 `PlugIns/ShareExtension.appex`，id、`RPAppGroup`、版本号和 app 对得上。

扩展 bundle id 和 group 从 app 的 bundle id 派生：`<app>.share`、`group.<app>`。正式包和 `.dev` 包各一套，互不串数据。`inject` 从 `project.yml` 读 app id，所以 init 和 build 要用同一个 identifier（`.dev` 包两步都带同一个 `--config`）。扩展的版本号在构建时从 app 的 Info.plist 拷（target 的 postBuildScript），因为 Tauri 在 spec 生成之后才写 app 的版本。激活规则：网页 URL 1 个、网页 1 个、文字、图片 5 张、文件 5 个。

表单是自写 SwiftUI，挂在 `UIHostingController` 里，不用 `SLComposeServiceViewController`。取 item：

- Safari 只给 `public.url`，页面标题在 `NSExtensionItem.attributedContentText`。拿不到标题用 LinkPresentation（`LPMetadataProvider`）取，超时 4 秒。
- X、微信预期给带链接的纯文本：用 `NSDataDetector` 抽出链接成 url item，去掉链接后剩下的文字非空就另成一条 text item。真机未验。
- 图片和文件用 `loadFileRepresentation` 流式拷进队列目录，回调返回后源文件就被删，所以在回调里拷。扩展内存上限约 120MB，不把文件读进内存。

## 队列

扩展写 App Group 容器里的 `ShareInbox/`，一条分享一个 `<id>.json`，`id` 是 `<毫秒时间戳>-<uuid>`，按名字排序就是时间序。先写点开头的临时名再 rename，读的一方只认不以点开头的 `.json`。附件拷进 `ShareInbox/<id>/`，JSON 里用相对路径指它。

格式 v1：

```
{ "v": 1, "id": "<ms>-<uuid>", "createdAt": "<ISO 8601>", "note": "…" | null,
  "items": [
    { "kind": "url",   "url": "https://…", "title": "…" | null },
    { "kind": "text",  "text": "…" },
    { "kind": "image", "file": "<id>/a.jpg", "uti": "public.jpeg", "name": "a.jpg" },
    { "kind": "file",  "file": "<id>/b.pdf", "uti": "com.adobe.pdf", "name": "b.pdf" }
  ] }
```

探针的 `probe` 字段正式版去掉。app 遇到 `v` 大于它认识的版本就不动这条。

## app 侧

Rust 新模块 `src-tauri/src/share_inbox.rs`，只在 iOS 编译和注册。经 objc2（`objc2`、`objc2-foundation`，只加在 iOS target 的依赖里）调 `NSFileManager.containerURLForSecurityApplicationGroupIdentifier`，group 名从主 app Info.plist 的 `RPAppGroup` 读。两个命令：

- `share_inbox_list`：所有完整条目，旧的在前。App Group 容器不在 fs 插件的读范围里，所以 image、file 两种 item 的附件拷到 `$APPDATA/share-inbox/<id>/`（已在就不再拷），返回时每个带 `path`（绝对路径）。这个目录是暂存，不登记进 palace 目录。
- `share_inbox_claim(id)`：删 `ShareInbox/<id>.json`、`ShareInbox/<id>/` 和 `$APPDATA/share-inbox/<id>/`。

前端 `src/platform/app/share-inbox.ts` 包这两个命令，一件宿主能力一个文件；桌面、Android 和浏览器 dev server 上不 invoke，直接返回空。

新开 headless 目录 `src/intake/`，登记进 `tests/layering.test.ts` 的 LAYER 表，capability 层。它只 import `platform`，不 import 任何领域。领域往里注册处理函数：一个名字、它收哪几种 kind、一个 `(entry) => Promise<void>`，抛错就是没处理成。一轮分发：取队列，每条按 item 的 kind 找处理函数，同一个处理函数拿到的 item 合成一次调用，带上 note；这条的每个 item 都有处理函数接、所有调用都成功，才 claim。没人接的留在队列，下一轮再来。处理函数必须对同一条幂等，因为部分成功的条目下一轮会整条重发。同一时刻只跑一轮，跑着时再触发就跳过。分发逻辑放 `.ts`，io 注入，配单测（`tests/intake/`）。

外壳在处理函数注册之后跑一轮，之后每次回前台（`src/platform/app/lifecycle.ts` 的 `observeAppLifecycle`，`onForeground`）跑一轮。Lumen 消费方两个外壳（`App.tsx`、`PhoneApp.tsx`）都注册；文件消费方和 `watchSharedBooks` 注册在同一处（`App.tsx`，理由见 [22](../ui/22-手机形态.md)），所以手机上分享进来的文件留在队列里。

## Lumen 消费方

收 url 和 text，放 info 领域。每条分享一条用户消息、一轮回合，按 id 顺序一条一条来。

消息正文：note 在前，空一行，然后每个 url item 是标题一行、URL 一行，text item 原样，item 之间空一行。没有 note 就只有 item。

写进门口对话：`appendMessage(bookId, threadId, { role: "user", text, ts })`（`src/platform/app/threads.ts`），线程 key 是 `doorKey(doorDate())`，即 `door-<消费当天>`（`src/soul/door.ts`）；`ts` 取消费时刻。`ThreadMessage.origin` 标来源：`MessageOrigin` 从 `{ runId }` 扩成 `{ runId } | { shareId }`。幂等靠它：门口对话里已有同一 `shareId` 的消息就跳过写入和回合。

写盘成功后发起一轮，照 `src/ui/components/info/use-info-call.ts` 的 `send()`：`appendMessage` 之后按历史跑回合（`assembleInfoTurn` 拼，`runAgentTurn` 跑）。这段目前在 hook 里，消费方不能 import ui，把不依赖 React 的部分抽成 info 下的 `.ts`，hook 和消费方共用。界面正开着这条对话时要看得到新消息（`threads.ts` 的 `onThreadMessage`）。

以上名字写代码前先核对还在不在、签名变了没有。

## 书库消费方

收 kind 为 file 且扩展名是 pdf、epub 的 item（`isBookFileName`），调 `fileSharedBook` 导进 Brief topic，导入成功后照 `App.tsx` 里 `watchSharedBooks` 那段打开它。`fileSharedBook` 收 file URL，inbox 给的是绝对路径，转一下或把收路径的那层拆出来。书库按内容哈希存，同一本重导不会多一份，写代码时核对 `fileBook` 对已有内容的返回。别的文件和图片第一版没有消费方，留在队列。
