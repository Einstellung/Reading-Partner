# 560 iOS 开发验收环境

iOS 的构建、模拟器和真机验收有两套环境：租来的 Mac mini（2026-08 起用，2026-10 归还），和不需要自己的 Mac 的 Linux + GitHub Actions + USB 真机。本文写两套各自怎么搭、怎么用、能验什么，以及将来租云 Mac 时照着重建。

## 两套共用的

**包名。** 开发包一律 `com.xinyuan.readingpartner.dev`（ASC 资源 id `VW3G7LG4MS`）。正式包名 `com.xinyuan.readingpartner` 装上去会顶掉设备上的 TestFlight 版。包名只能经 CLI 的 `--config` 改，装机前从 ipa 的 `Info.plist` 读回 `CFBundleIdentifier` 校验；下面所有脚本都带这道闸。

**签名。** 付费团队 `HF6369DDYP`，用 App Store Connect API key 云签名（坑 47、197），profile 一年有效，Xcode 里不需要登任何 Apple ID。新设备要先 `POST /v1/devices` 注册，占每年 100 个名额之一、不可删。已注册：iPhone 16 `00008140-000C31641EEB001C`、iPad `00008120-001E78AC2EE00032`。新 entitlement 要先给 App ID 开 capability（坑 401）。

**密钥放在哪。** 不进仓库。Linux：仓库 `.env` 的 `ASC_KEY_ID` / `ASC_ISSUER_ID` / `ASC_PRIVATE_KEY_PATH`，`.p8` 在 `~/.appstoreconnect/private_keys/`。GitHub secrets：`APPLE_API_KEY_ID`、`APPLE_API_ISSUER`、`APPLE_API_KEY_P8_BASE64`、`APPLE_TEAM_ID`。Mac：`~/.asc-env`（600，导出 `APPLE_API_KEY`、`APPLE_API_ISSUER`、`APPLE_API_KEY_PATH`、`APPLE_DEVELOPMENT_TEAM`），`.p8` 在 `~/.appstoreconnect/private_keys/`。重建时从 Linux 拷过去。

**设备。** iPhone 16（iOS 26.5.2）、iPad15,7（iPadOS 26.7.1）。前提：开发者模式开、信任这台电脑、解锁、自动锁屏设永不；换了签名身份要在「设置 → 通用 → VPN 与设备管理」信任一次；国行 iPhone 每次重装 .dev 都要重新给「无线数据」权限（坑 217）。iPad 上的 Shadowrocket 不许关。

**验收顺序。** Linux 上 xvfb 跑真 WebKitGTK → 模拟器 → 真机，不跳步。xvfb 那一步在用户的 Linux 上做，不开可见窗口；Mac 上开模拟器窗口不受这条限制。模拟器只有 Mac 版有。

## Mac mini 版

### 拓扑

Mac mini M4 / 16 GB / macOS 26.5 / Xcode 26.6（`/Applications/Xcode.app`）/ iOS 26.5 模拟器 runtime，用户 `mima1234`（uid 501）。Mac 在 192.168.110.x 的 NAT 后面，Linux（192.168.0.107）到不了它，所以由 Mac 上的 LaunchAgent `com.readingpartner.tunnel` 常驻一条 SSH 隧道连到 Linux（模板在 `scripts/macos/com.readingpartner.tunnel.plist`）：

- Linux `127.0.0.1:2222` → Mac sshd；Linux 的 `~/.ssh/config` 里 `Host macmini` 指 `127.0.0.1:2222`、`User mima1234`，免密。
- Linux `127.0.0.1:5900` → Mac 屏幕共享。
- Mac `17890`/`17891` → Linux 的 Mihomo 代理（HTTP/SOCKS）。

隧道里写死了 Linux 的地址，Linux 换 IP 就断（坑 202），日志在 Mac 的 `/tmp/rp-tunnel.log`。

代码：`~/Reading-Partner` 是独立 clone，remote `linux` 指 `ssh://xinyuan@192.168.0.107/<主 checkout>`，只 fetch（push URL 设成了 `DISABLED_no_push_to_users_workspace`）；`origin` 是 GitHub，Mac 到 github.com 走 HTTP/2 会断（坑 204）。每件活一个 `git worktree add --detach ~/rp-<活名> FETCH_HEAD`；`~/rp-flow` 是来回切版本用的那个；`~/rp-swiftcheck` 归 `scripts/ios-swiftcheck.sh` 用，它从 Linux 用 git bundle 经 scp 送代码。同步代码只 `git checkout FETCH_HEAD -- src tests`，整树 reset 会让 tauri 重启整条构建（坑 381、205）。

### 装机

1. 系统设置开「远程登录」和「屏幕共享」，并保持一个图形登录会话：codesign 和模拟器窗口都要它（坑 179、566）。
2. Xcode 26.6，然后 `sudo xcodebuild -runFirstLaunch`，装 iOS 模拟器 runtime。用 `mas get 497799835` 装 Xcode 时 App Store 的 `storedownloadd` 会在自己的安装步骤失败后删掉下好的 `.pkg`；办法是盯住 `$(getconf DARWIN_USER_CACHE_DIR)com.apple.AppStore/497799835/`，`.pkg` 一出现就硬链接到别处，下满后 `sudo installer -pkg <它> -target /`。
3. 无 tty 的 SSH 里 `sudo` 要 askpass：`~/.askpass.sh`（700，两行，echo 登录密码），`~/.zshenv` 写：

   ```
   export PATH="$HOME/.cargo/bin:$HOME/.bun/bin:/opt/homebrew/bin:/opt/homebrew/sbin:$PATH"
   export BUN_INSTALL="$HOME/.bun"
   export SUDO_ASKPASS="$HOME/.askpass.sh"
   ```

   不要在这里写 `http_proxy`：代理是隧道，隧道一断每条命令都挂。自己拼的 `ssh macmini '...'` 覆盖了环境时要再导一次 `SUDO_ASKPASS`。
4. 工具链（下载走隧道代理 `http_proxy=http://127.0.0.1:17890`）：
   - rustup stable，`rustup target add aarch64-apple-ios aarch64-apple-ios-sim`；bun。
   - Homebrew：`xcodegen cocoapods ios-deploy libimobiledevice ios-webkit-debug-proxy mas`，`brew tap facebook/fb && brew install idb-companion`。
   - `python3 -m venv ~/idbvenv && no_proxy='*' ~/idbvenv/bin/pip install fb-idb`（不要建在 `/tmp`，坑 374）。
   - `python3 -m venv ~/pmd3venv && no_proxy='*' ~/pmd3venv/bin/pip install pymobiledevice3 websocket-client`。
   - macOS 系统代理指着本机 7890（Clash Party，平时不跑），Python 系的网络命令都要加 `NO_PROXY='*' no_proxy='*'`；curl 不读系统代理，拿它判断通不通会误判。
5. 签名：放好 `~/.asc-env` 和 `.p8`。不往 Xcode 里加 Apple ID。
6. 隧道：Mac 的 `~/.ssh/id_ed25519.pub` 加进 Linux 的 `authorized_keys`，Linux 的公钥加进 Mac 的 `authorized_keys`；plist 改好用户名和 IP 后放进 `~/Library/LaunchAgents/`，`launchctl load`。
7. `git clone`，`git remote add linux ...`，`bun install`，`bun run wasm`。

2026-10 时的版本：Homebrew 7.0.9、bun 1.3.14、rustc 1.97.1、xcodegen 2.46.0、cocoapods 1.17.0、idb-companion 1.1.8、fb-idb 1.1.7、pymobiledevice3 11.26.1、ios-webkit-debug-proxy 1.9.2、libimobiledevice 1.4.0。

### 日常循环

Swift 类型检查，写完 `plugins/*/ios` 的 Swift 就跑，热跑 4 秒：

```
scripts/ios-swiftcheck.sh --dirty [--pkg plugins/openin/ios]
```

模拟器（在 Mac 上、各自的 worktree 里，每个会话用自己的端口，坑 382、432）：

```
xcrun simctl boot <udid>
sudo -A launchctl asuser 501 sudo -u mima1234 open -a Simulator --args -CurrentDeviceUDID <udid>
export IOS_SIM_PORT=1430
nohup bun run tauri ios dev "<模拟器名>" --no-dev-server-wait \
  --config '{"build":{"devUrl":"http://localhost:1430","beforeDevCommand":"bunx vite --port 1430 --strictPort"}}' > /tmp/<活名>-dev.log 2>&1 &
# 轮询到 tauri://localhost
IOS_SIM_UDID=<udid> IDB=~/idbvenv/bin/idb scripts/ios-sim.sh eval 'location.href'
scripts/ios-sim.sh shot out.png | tap x y | gesture <名> | reader
scripts/macos/sim-tap-text.sh "按钮上的字"
```

`scripts/ios-sim.sh up` 在 SSH 里会卡在 `bootstatus`（坑 566），按上面手动起。idb 打的是真触摸，能产生什么不能产生什么见坑 118；原生浮层对 `eval` 不可见，用 `idb ui describe-all` 读。书用 `simctl openurl` 投 `file://` 会被「预览」截走（坑 294），分享进 app 用 `scripts/ios-sim/ShareDriver`。常用 udid：iPad Pro 11-inch (M5) `C1F7689F-18AA-4AD3-A13B-DEA225FEF152`、iPhone 17 Pro `18CF1932-8E96-4B70-AA76-4E9998D65225`；`xcrun simctl create` 可另建。

真机 iPhone（Xcode 认得的系统）：`scripts/ios-dictation/ios-dev.sh`，构建、devicectl 装机一条龙；配对过的手机走 Wi-Fi 也能装，锁屏时报 `kAMDMobileImageMounterDeviceLocked`，等解锁重试。原先放在 Mac `/tmp/ios-dev.sh` 的就是它，已随 `/tmp` 清掉。

真机 iPad（比 Xcode 新，devicectl 看不到，坑 521）：

```
REPO=~/rp-ipad scripts/macos/build-dev-ipa.sh            # 只构建，出 /tmp/rp-dev.ipa
~/pmd3venv/bin/pymobiledevice3 apps install --udid <udid> /tmp/rp-dev.ipa
UDID=<udid> scripts/macos/device.sh launch | shot <名> | seed | ls | pull | iwdp | js '<expr>' | ajs '<body>'
```

`js`/`ajs` 经 ios_webkit_debug_proxy 在真 WKWebView 里跑 JS（`scripts/macos/webview-eval.py`），要 inspectable 构建、app 在前台。给 .dev 包铺书：先杀 app，往 `Library/Application Support/com.xinyuan.readingpartner.dev/` 写 `library.json`、`topics.json`、`library/<sha256 前 32 hex>.epub`，再启动。

从 TestFlight 版取数据不需要开发签名：`pymobiledevice3 apps afc com.xinyuan.readingpartner`，或 Mac 上 `xcrun devicectl device copy from --domain-type appDataContainer --domain-identifier <bundle id> --user mobile ...`。

### 能验 / 不能验

能：Swift 类型（4 秒）；模拟器里真 WKWebView、真 PDFium、idb 真触摸、webview 内取值、截图、分享面板、文件选择器；真机上装 .dev、启动、截图、读写容器、WKWebView 里跑 JS。

不能：模拟器没有 Pencil、接触面积，一次一根手指（捏合走 GestureDriver）；真机手势这套没接 WDA，点按靠人；Swift 检查不管运行时、链接、plist 和签名。

### 一轮耗时

Swift 检查 4.2 秒（冷 8.6 秒）。模拟器里改前端是一次页面重载；改 Rust/Swift 要重跑 `tauri ios dev`，分钟级。真机出包加装机一轮十几分钟。

## Linux + CI + USB 真机版

### 拓扑

- GitHub Actions（`macos-26`，Xcode 26.5）出要 Xcode 的两样东西：workflow `.github/workflows/ios-linux-loop.yml`，现在只在 `exp/linux-ios-loop` 分支上。三个 job：`devices`（只读查 ASC 已注册设备，`scripts/ios-linux/asc-devices.py`）、`wda`（WebDriverAgent v16.14.2 `build-for-testing`，包名 `com.xinyuan.wda`，runner 是 `com.xinyuan.wda.xctrunner`，通配 profile 到 2027-10-12）、`devbuild`（.dev 的 dev 模式包，devUrl 写死 `http://192.168.0.107:1437`，做法见坑 561）。产物是 artifact `wda-runner-ipa` 和 `rp-dev-ipa`。
- Linux：设备插 USB；`usbmuxd`；pymobiledevice3 10.3.0 在 `~/.local/share/pmd3-venv`，`--userspace` 隧道，不要 root、不跑 tunneld；`scripts/ios-linux/device.sh` 包住装包、挂盘、起 WDA、截图、点按；`scripts/ios-linux/dev-server.sh` + `vite.lan.config.ts` 在 `192.168.0.107:1437` 起 Vite（HMR 1438）；`~/.local/bin/ios_webkit_debug_proxy`（源码编）和 `ipad-shot`。
- WDA 转发到 `127.0.0.1:18100`，iPhone-use MCP（zhongerxin/iPhone-use 0.3.10）不改代码直接连它，起的时候关统计（坑 565）。

### 装机

1. apt：`usbmuxd libimobiledevice-utils ideviceinstaller`（用户自己 sudo），`sudo systemctl start usbmuxd`。`ios_webkit_debug_proxy` Ubuntu 没打包，从源码编进 `~/.local/bin`，依赖 `libimobiledevice-dev libplist-dev libusbmuxd-dev`。
2. `python3 -m venv ~/.local/share/pmd3-venv && ~/.local/share/pmd3-venv/bin/pip install pymobiledevice3`。
3. `gh auth login`（`device.sh fetch` 用它下 artifact）。
4. GitHub secrets 四项见上。
5. ufw 默认丢弃入站，给设备放行 Vite：`sudo ufw allow proto tcp from <设备的地址或网段> to any port 1437:1438`。
6. 设备 iOS 比 pymobiledevice3 认识的新时 `mount` 会警告 DDI 版本未知，照样能挂。

### 日常循环

```
scripts/ios-linux/device.sh check
scripts/ios-linux/device.sh fetch [run-id]       # 最新一次成功 run 的两个 ipa，19 秒
scripts/ios-linux/device.sh install ~/.cache/rp-ios-linux/ipa/wda-runner-ipa/WebDriverAgentRunner.ipa
scripts/ios-linux/device.sh install ~/.cache/rp-ios-linux/ipa/rp-dev-ipa/reading-partner-dev.ipa
scripts/ios-linux/device.sh mount                # 17 秒
scripts/ios-linux/device.sh wda-start            # 首次可能 60 秒失败，再起一次（坑 562）
scripts/ios-linux/device.sh smoke | launch | shot out.png
scripts/ios-linux/dev-server.sh                  # 给 .dev 包供前端
scripts/ios-linux/device.sh wda-stop             # 连设备上的 runner 一起停（坑 563）
```

Rust、Swift、plist 改动：推到分支触发 workflow，等 devbuild，再 `fetch` + `install`。`dev-server.sh` 让局域网上任何人都能读它供出的文件（坑 123），只在可信网络上开，用完就停。

### 实测状态（2026-10-12）

已通：USB 控制 iPad——装包（WDA 6.1 秒、.dev 6.9 秒）、挂盘、起 WDA（第二次 10 秒内，之后 2.4 秒）、WDA 截图和点按、iPhone-use MCP（就绪 0.8 秒、点一下 2.8 秒）、DVT 截图约 1.1 秒；CI 出 WDA（1 分 46 秒）和 .dev 包（冷 Rust 缓存 6 分 40 秒），包名、devUrl、profile 里的设备都校验过。

未通：前端热更新。.dev 包启动报 `Failed to request http://192.168.0.107:1437/ ... local network permissions?`，iPad 上 Safari 开同一地址报连接丢失。当时 iPad 在 Wi-Fi「hongchun」上，地址 192.168.110.72，开着 Shadowrocket；Linux 是 192.168.0.107/23，ufw 已对 192.168.1.200 放行 1437:1438。Linux 上每 0.1 秒采样 12 秒，1437/1438 上一条连接都没有，请求没到达 Linux，原因未定。下一步等 iPad 换到和 Linux 同网段再验，然后量热更新延迟。热更新通之前这个 .dev 包打开只有那句报错，真机看前端改动只能走 ios-testflight workflow 出包。

### 能验 / 不能验

能：真机装包、启动、截图、真触摸点按和手势（WDA 的 W3C actions，坑 118 说的那些模拟器限制在这里不存在）、读写容器（`apps afc`）、MCP 驱动。WKWebView 里跑 JS 走 ios_webkit_debug_proxy，要 inspectable 构建；dev 模式包是否默认可检查未验。

不能：没有模拟器，验收顺序里那一步整段缺；Swift 没有 4 秒检查，只能等 CI 编（devbuild 一轮约 7 分钟，失败日志在 job 里）；热更新未通（见上）；devUrl 写死 Linux 的 IP，Linux 换地址要改 `DEV_HOST` 重跑 devbuild。

### 一轮耗时

改 Rust/Swift：CI 约 7 分钟 + 下载 19 秒 + 装包 7 秒。改前端：热更新通了应是秒级，未量。真机上一次截图 1 秒、一次点按 3 秒以内。

## 将来租云 Mac 时怎么重建

云 Mac 只承担 Swift 检查、模拟器和需要 Xcode 的构建；真机仍插在 Linux 上走 USB 那套。

1. 选机：Apple silicon，能拿到图形登录会话（VNC 或自动登录），系统和 Xcode 至少和设备的 iOS 一样新（坑 521）。
2. 连法：云 Mac 一般 Linux 能直连，`~/.ssh/config` 里把 `Host macmini` 指过去即可，`scripts/ios-swiftcheck.sh` 认 `RP_MAC`。只有 Mac 在 NAT 后面才装隧道 plist。云 Mac 到不了 Linux 时，代码从 GitHub 拉，或像 `ios-swiftcheck.sh` 那样用 git bundle 送。
3. 照「Mac mini 版 → 装机」第 1–7 步做；有直连外网就跳过隧道代理和 `NO_PROXY` 那几条。
4. 从 Linux 拷 `.p8`，写 `~/.asc-env`。不注册新设备，不加 Apple ID。
5. 验收这台机器：`scripts/ios-swiftcheck.sh` 绿；按「日常循环」起一个 iPad 模拟器，`scripts/ios-sim.sh reader` 跑一遍对照 `scripts/ios-sim/baseline.md`；`scripts/macos/build-dev-ipa.sh` 出包，包名校验通过，ipa 拿回 Linux 用 `device.sh install` 装上真机。
