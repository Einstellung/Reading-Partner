# 账号登记

Google 登录后把账号和设备登记到我们自己的后端。这是商业化账号体系（docs/north-star/commercialization.md）的第一步，只登记，不存用户数据；同步数据仍在用户自己的 Drive（docs/platform/13）。

## 后端

仓库 `server/`，Vercel 项目（Root Directory 设为 `server`）。Vercel Functions（Node 运行时）加 Neon Postgres，连接串从 `DATABASE_URL` 读，由 Vercel 的 Neon 集成注入。部署步骤在 `server/README.md`。

`POST /api/register`，body 是 Google id_token 加设备信息（设备 ID、平台、系统版本、机型、软件版本）。服务端用 Google 的 JWKS 验签名、iss、exp，aud 必须是我们的 OAuth client ID 之一：iOS、Android 两个写在 `server/lib/config.ts`，桌面那个从 Vercel 环境变量 `GOOGLE_DESKTOP_CLIENT_ID` 读。验不过 401，body 不对 400。处理逻辑 `server/lib/register.ts` 注入验签器和库，单测在 `server/tests/`。

服务端不存 IP，不打印请求 body。

## 两张表

建表 SQL 在 `server/schema.sql`，都按主键 upsert。

- users：Google `sub` 主键、email、name、first_seen、last_seen。name 可空。
- devices：设备 ID 主键、user_sub、platform、os_version、model、app_version、first_seen、last_seen。同一台设备换了账号，user_sub 跟着改。

## 客户端

`src/platform/account/`。设备 ID 用 device.json 里已有的 `deviceId`（首次启动生成的随机 UUID，不同步）。平台和系统版本来自 plugin-os，软件版本来自 Tauri，机型由 Rust 命令 `device_model` 给：iOS 读 sysctl `hw.machine`（如 iPad14,1），macOS 读 `hw.model`，Android 读 `ro.product.model`，Linux 和 Windows 为空。

上报时机：Google 登录成功后一次；已登录时每天第一次启动一次（`initSync` 里触发，按本地日期，记在 `account.json` 的 `lastReportDay`）。每天那次要现取 id_token，靠 `freshIdToken()` 做一次 token 刷新。日期在发请求前就记下，失败静默、当天不再试，不影响同步。

同意标记：`account.json` 的 `consent`，只存本机，不同步。没同意不上报。`setAccountConsent()` 供同意界面调用，界面另做。

地址常量：`src/platform/account/endpoint.ts` 的 `ACCOUNT_ENDPOINT`，现在是空字符串，空时整个上报跳过。部署后填 vercel.app 地址，换域名只改这里。

id_token 里的 name 解析后和 email 一起存在 `sync-auth.json`。现在的 scope 还是 `drive.file openid email`，token 里没有 name，存的是 null。功能打开时再给 `GOOGLE_SCOPES` 加 `profile`；老用户的 token 没有 name 时照样是 null，不强制重新登录。

## 隐私政策

`server/public/privacy.html` 和 `server/public/terms.html`，部署后在 `/privacy` 和 `/terms`。写明收哪些字段、为什么收、目前不向第三方提供（以后要提供会另行征得同意）、删除请求发到哪个邮箱。
