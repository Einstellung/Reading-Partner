# 账号登记

Google 登录后把账号和设备登记到我们自己的后端。这是商业化账号体系（docs/north-star/commercialization.md）的第一步，也是 [713](./713-试用与买断.md) 试用时钟的地基。只登记，不存用户数据；同步数据仍在用户自己的 Drive（docs/platform/13）。

## 后端

Supabase 项目，建表 SQL 在 `supabase/migrations/`，应用方法在 `supabase/README.md`。app 只用 publishable key 直接发 HTTP，不引 SDK。Google provider 填三个 OAuth client ID（桌面、iOS、Android），开「Skip nonce checks」，因为我们的 Google 授权码流程不带 nonce。

- `accounts`：Supabase user id 主键、trial_started_at、purchased_at、purchase_source、banned。`auth.users` 插入时由触发器建行，试用从首次登录算起。用户只能读自己那行，客户端不能写。
- `devices`：设备 ID 主键、user_id、platform、os_version、model、app_version、first_seen、last_seen。客户端只能经 `report_device` 函数写，函数按设备 ID upsert，user_id 取调用者，所以同一台设备换了账号就跟着改。
- `admin_overview`：控制台看的总览视图（总用户、今日登录、今日活跃设备、14 天内到期的试用、购买数），API 读不到。

邮箱和登录时间在 Supabase 的 `auth.users` 里。

## 客户端

`src/platform/account/`。Google 登录拿到的 id_token 发给 `/auth/v1/token?grant_type=id_token` 换 Supabase 会话（首次即建用户），再带会话调 `/rest/v1/rpc/report_device` 报设备。会话（access/refresh token、过期时间、user id）存在 `account.json`，只在本机，不同步；退出 Google 登录时清掉。

设备 ID 用 device.json 里已有的 `deviceId`（首次启动生成的随机 UUID，不同步）。平台和系统版本来自 plugin-os，软件版本来自 Tauri，机型由 Rust 命令 `device_model` 给：iOS 读 sysctl `hw.machine`（如 iPad14,1），macOS 读 `hw.model`，Android 读 `ro.product.model`，Linux 和 Windows 为空。

上报时机：Google 登录成功后一次；已登录时每天第一次启动一次（`initSync` 里触发，按本地日期，记在 `account.json` 的 `lastReportDay`）。每天那次先用存着的 refresh token 刷新会话（refresh token 每次轮换，新的立刻存下）；没有会话或刷新失败，就用 `freshIdToken()` 现取 Google id_token 重新换。日期在发请求前就记下，失败静默、当天不再试，不影响同步。

同意标记：`account.json` 的 `consent`，只存本机，不同步。默认开，只有显式写成 false 才不上报。`setAccountConsent()` 留给以后的同意界面。

地址和 key：`src/platform/account/endpoint.ts` 的 `ACCOUNT_BACKEND`，url 为空时整个上报跳过。

scope 仍是 `drive.file openid email`，不收姓名。

## 隐私政策

`site/privacy.html` 和 `site/terms.html`，静态页，托管位置另定。写明收哪些字段（Google 邮箱、Supabase user id、设备 ID、平台、系统版本、机型、软件版本、登录和最近活跃时间）、为什么收、存在 Supabase、目前不向第三方提供（以后要提供会另行征得同意）、删除请求发到哪个邮箱。
