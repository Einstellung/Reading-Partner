## 两个仓

情景仓存"某天发生了什么"，知识仓存"这个读者是什么样"。

| 概念 | 是什么 | 谁写 | 谁读 |
|---|---|---|---|
| 划线、消息 | 原始证据 | 读者、AI 对话 | 观察通过锚点引用 |
| 观察（情景仓） | 某天发生了什么，带日期和锚点。从不改写，更正是新记录 | 白天的蒸馏器 | dream；聊天按需追溯 |
| statement（知识仓） | 这个读者是什么样，不带日期，指回观察。不改写，新的取代旧的 | dream，以及读者自己 | 聊天、拷问、info 分拣、写入时的 relation 判定 |
| 使用日志 | 哪条记录被谁在什么时候取出来用过，append-only | 检索代码 | dream 选回放、排序 |

statement 两种 kind：

- `profile`：讲法（要完整推导不要图、术语第一次出现要展开）、懂了什么、卡在什么上。
- `concern`：他现在盯着的一件事，多带新鲜度和 lapse。

字段：`kind`、`text`、`evidence[]`、`contradictedBy[]`、`established`、`lastSupported`、`supersededBy`、`author`；concern 另加预期复现间隔和 `lapsed`。除 `text` 外全部由代码从锚点和日期算，不经模型。

目录 `src/memory/statements/`，合并策略 `records`。"profile"这个词的旧用法（`loadProfile`、`readerProfileSection`、`user-profile.md`）按下文的作废清单删函数、留文件，名字空出来给新的。

## 边

四种，全是盘上的事实，没有一种是相似度：

- 观察 → 划线 / 消息：锚点，已有。
- 观察 → 观察：正文里提到 id，已有 285 处提及、278 个不同的源-目标对，全部可解析，今天没有代码读它。
- statement → 观察：`evidence` 和 `contradictedBy`，新增。
- statement → statement：`supersededBy`，新增。

"边的类型不做枚举"只对观察→观察的正文提及成立——45% 的提及抗单标签分类，因为它们本来就不是边。statement 上这三种边有类型，各有各的消费者。

"前台"不存，算出来：一条观察被活着的 statement 引用为 evidence，就退出默认上下文，盘上不动。

## 写入侧

观察正文不可变。要改一条观察的意思是写一条新的，旧的留着。锚点只追加，不重写。

蒸馏器写观察的工具上加一个必填参数 relation，四选一。目标一律用索引行的整数下标，代码校验，解析不了就拒绝写入交回重写。

| relation | 效果 |
|---|---|
| `new` | 新建观察 |
| `same-as <观察>` | 同一件事又发生一次。往那条观察追加锚点，`updated` 刷新为新证据的日期，正文不动，不新建 |
| `predicted-by <statement>` | 照常新建观察，并立刻作为 evidence 挂到那条 statement 上，刷新它的 `lastSupported`。这条观察生下来就是退出前台的，因为已被引用 |
| `contradicts <statement>` | 新建观察，并在那条 statement 上追加 `contradictedBy`。statement 文本不改 |

下一节的三档（一致 / 无关 / 冲突）对应 `predicted-by` / `new` / `contradicts`；`same-as` 是对观察而不是对 statement 的。

判断和起草在蒸馏器同一次调用里，不加第二次调用。判在写入时而不是攒到夜里：不管改动是否必要都写，是干扰更多、容量更低的那种写法，而"合并同类项"这一类夜间整理任务根本不该产生。白天只做一跳能确定的，需要跨多条归纳的留给 dream。

落盘前一道 id 校验闸：正文里提到的 id 逐个解析，解析不了就拒绝这次写入并把错误交回模型重写。没有这道闸，一个不存在的 id 写进正文就永远悬空。

闸有两个前提。一是锚点渲染的 bug 修好之后才能开——诊断过的 74 条悬空消息锚点里 71 条是程序打印了父线程 id，只有 4% 是模型抄错和编造，闸提前上线会成批拒绝合法蒸馏。二是只校验本次调用交上来的锚点，不校验整条记录的锚点全集：`store.update` 在 patch 不带 anchors 时保留旧的，校验全集会让改写历史观察的模型无过被拒。

## 惊奇是一条边

惊奇不是一种记录，是观察 —contradicts→ statement。它只能相对预期存在，而预期就是 statement。

三档是硬要求，不能压成两档。两档下"反驳这条 statement"和"与它无关"在相似度上不可分，跨主题 recall@3 的 0.125 就是这个不可分的样子。文献同向：与预期一致的和与预期冲突的都比无关的记得牢，是 U 形不是单调，所有两档设计得出的是相反的单调结论。

一次冲突不改 statement，只多一条 `contradictedBy`。第二次冲突把"不一致"这件事本身写成新 statement，原来那句降权或被取代。

带 contradicts 边的观察免于"没挂上就退出"。

读者自己的惊奇（同一个问题连问三遍）只能当观察内容，进不了边——那是他对材料意外，不是材料对 statement 意外。

## concern

一条 concern 是"现在要替我盯着的一件事"，不是"你是谁"。作者是读者，时态是当下。

判据是跨渠道跨时间的反复：同一件事在划线里出现一次、在读过的文章里出现一次、在对话里被追问一次，才算一条。单次出现的留在观察里。

三档证据决定怎么成立：他亲口说的当场成立；跨渠道复现的先记暂定、只弱影响排序，写下来之后新到的行为里再复现一次才转正；只出现过一次的不写。确认走行为不走弹窗，读者一个问题都不用回答。

衰减的对象是证据不是记录：新鲜度 = 距最近一次支撑证据多久，每来一条新证据就刷新。衰减和转正因此是同一个机制，不需要单独的确认步骤。

不用统一半衰期。每条 concern 带自己的预期复现间隔，从它实际复现过的历史推出来。一个月里每周复现的静默两周有意义，本来一月一次的静默两周不说明什么。

过期只标 `lapsed` 不删除。复发本身是信号，而且 lapsed 是一次编辑不是一次移除，同步不用墓碑。

读者亲口说的不自动下场：有死线按死线，没死线一直留着，只是排序权重随时间衰减，靠他自己撤。蒸出来的靠复现续命。

`author` 决定谁能改：dream 可以往读者写的 concern 上挂新证据、刷新新鲜度，不许改措辞、不许提前判它下场。

## 读者自己写

聊天里挂一个写 statement 的工具，是 `update_profile` 的归处。读者说了关于自己的话（"以后别画图"、"我懂了"、"我最近在盯 X"）模型就调它：写一条 statement，`author` 记读者，`kind` 由模型在 profile 和 concern 之间选，evidence 是那条消息的 id。推翻旧的用同一个工具带目标下标，新条 supersede 旧条，旧条不删。

挂阅读侧——一个人怎么读只在阅读对话里看得见。info 侧这次不管。

`ObservationPanel` 里加一份只读的 statement 列表，读者能看到 AI 认为他是什么样、每条指回哪些证据。改和删走对话，不加按钮。

首次启动的引导改成收集第一批 concern（今天那条是让 AI 起草第一份画像）。

迁移就是一屏：列出现有的 19 行 declared 和 4 条 guess，他勾还成立的，勾中的直接变成 statement，作者记成他。没勾中的直接丢，不写成观察——"看了一眼没勾"信号太弱又没有日期。磁盘上一个字节都不删，`user-profile.md`、guess 的时间戳文件、遗留的 `info-profile.md` 原样躺着，代码停止读它们。

## 消费侧

聊天提示词里记忆那一段固定三块，顺序固定：

1. profile 整组，讲法类在最前。
2. 这本书悬着的事。
3. 检索来的观察，摘要行带 id，正文留在 `observation_read` 后面。

常驻的只有讲法类：它由"正在讲解"这个动作触发，和内容没有词面联系，检索不出来，只能常驻；天然少，长了由 dream 合并。懂了 / 卡着那部分靠检索进来，会话开头以书名、章节、reading-position 做一次线索检索取第一批，之后按轮续，不够模型自己再要。

concern 不进聊天段，消费者是 info 分拣和 dream。

悬项是程序判的，不等 dream：一条 stuck-point 观察，没有被任何更晚的 understood-concept 观察在正文里提及，就算悬着。拷问的出题池就是这个集合。答对了白天写一条 understood-concept 观察提及那条 stuck-point，当天它就从悬项里消失，dream 夜里再把它升成 profile。

收口只认后续证据——答对、复述对、亲口说懂了——不认"AI 又讲了一遍"。resolved 的卡点还读作开着，AI 会把他已经懂的再讲一遍，这是最容易被读者看见的失败。

## dream

夜间机制统一叫 dream，包含主动检索、记忆更新和 statement。每晚 3:00 在采集端跑，挂在 `amICollecting()` 后面复用 [36](./36-采集端与阅读端.md) 的选举，5:00 的简报 pipeline 读它的产出。

顺序有依赖：修复整理 → 蒸馏欠账 → 主动检索与连接 → statement 更新 → 简报备料。

3 点的理由只有 CPU 空着、一天结束是自然分界，不给它加睡眠的理由——隔夜整理的好处来自没有新的干扰上下文，而批处理本来就没有竞争者。也不加全局夜间衰减：突触缩小是按比例的，乘性缩放保序，对 top-k 毫无影响。

每晚三问：

- 回放哪些。候选 = 上次之后新写或改过的 + 白天被取用过的（使用日志）+ 悬着的。correction 优先，reading-position 不算。优先级是 gain × need：gain 是预测误差幅度，correction 天生是有符号的预测误差；need 是近期被用到的概率，使用日志给。出现次数不是重要性。
- 写什么。读者亲口说的当场成立；蒸出来的至少两条独立证据；单次不写。
- 谁退出。被引用为证据的观察退出前台。规则漏洞是单次且从未被引用的永远退不出，补一条"考虑过 K 晚都没挂上 → unattached 退出，检索仍然可达"，K 待数据。

pass 只做追加和刷新，不做整组替换。哪条下场由有效期决定，不由这一轮没被重新提起决定。140 条 / 10 万字全量重读在这个量级不贵，不设窗口——照抄先例的窗口常数，结果就是"每主题 12 行导致 74% 的记录不可见"。

dream 只能读同步范围内的东西：它跑在 PC 上而阅读发生在 iPad 上，本地状态它看不见。concern 落后阅读最多一趟同步，这个延迟要认。

迁移未完成不跑：观察目录里还有 8 位 id 的文件，整晚停手（`waiting-migration`，不推进日期也不推进 hash），否则写出的证据指着马上要被改名的文件（坑 210）。

supersede 一次可以指多条：两条 statement 说同一件事就合成一条，证据取并集，每条目标各自受 `author` 规则约束。

第一版只做"观察出 statement、观察退出前台"。检索不动。

## 使用回路

一条观察从写下到现在只有日期在变；被取出来用过没有、用了有没有帮上忙，盘上一个字都没有。

补的是 append-only 使用日志（id、时间、查询、读者事后有没有否掉），不是记录上的计数器。两个理由：被需要的几率对使用频率是 log-log 线性、对距上次使用是幂律，朴素计数会把词面检索本来就打得中的那批记录复利地推到前台；每次读都写回记录文件必然制造三方冲突。

第一版只记不用。

## 多设备

- statement 存成带 id 的 JSON 数组不是 JSONL：JSONL 的身份是整行，而 statement 会被刷新，改一行会被当成两条留下。进同步范围，合并策略 `records`，加进 `RECORD_FILES` 一行。
- dream 只在 PC 上写。iPad 那一侧只写读者自己说的。
- 使用日志按设备分文件，各写各的，读取取并集。
- 删一本书不碰 statement。观察按 bookId 挑着删，被引用为证据的那些跳过，见 [50](./50-删除.md)。

## 检索：待数据，先不做

274 道锚点题量过一次：整体 recall@3 0.777、消息档 0.924、划线档 0.729、跨主题 0.125。八个调参变体全部落在噪声里或倒退，词面打分器已在局部最优附近。先修数据缺陷（补回被工具 XML 困住的锚点，基线 0.777 → 0.788，比所有变体的差都大），再谈换检索器。

statement 层的检索用同一套方法在 statement 上重新量，量出不行再走 [28](./28-记忆与画像调研.md) 那条语义路线。索引 statement 时把它的证据观察里的词并进索引（代码做），覆盖读者自己会怎么说。

作用域撤掉。topic 会改，它只是归档便利，不是检索键。今天的 `observationScope` 判据是"不是这本书"而不是"是另一本书"，印出来的标签 45% 的时候是假的，而且印在 prompt 里。

三个入口，都不需要 topic：当下工作记忆的内容（最近几轮、光标下的文字、书名章节）、稳定锚点走边、使用日志给的激活度。相似度只在入口出现一次。

管线六步：

1. 造线索。程序做：词（从消息、划线段、章节标题抽）+ 结构（bookId、页码、threadId、日期）。
2. 三个入口并行出候选。词面走 BM25，跑在 statement 上（索引含证据观察的词）和观察上，带绝对分数阈值，低于阈值就是"没有"。锚点取本书当前页前后若干页锚定的观察、本线程锚定的观察、日期邻近的观察。悬项是过滤不是搜索。
3. 沿边扩一到两跳。观察 → 它支撑的 statement → 同一条 statement 的其他证据观察；正文提及只走一跳。限跳数和边的类型，不限条数。
4. 排序。入口分 + 激活度（使用日志，ACT-R 基线激活）+ statement 的 `lastSupported` + 悬项和带 contradicts 边的加成。不设 k。
5. 装进上下文。statement 整行；观察给摘要行加 id，正文留在工具后面；每条带一句程序算出来的"为什么在这"（页码命中 / 词面命中 / 悬项）。装多少由预算阶梯定，不够模型再要。
6. 记日志。展示了哪些、模型引用了哪些 id、读者随后有没有顶回来。

三个时刻走同一条管线：会话开始（线索是书、reading-position、章节标题、悬项）、每轮消息之前（线索是消息、划线段、页码、线程）、模型主动带查询对象来要。

开放问题三个：

- 词面不匹配。跨语言那档 recall 0.125。三条路按代价排：索引侧并入证据观察的词、模型改写查询、本地小 embedding；先量第一条。
- BM25 的绝对阈值要在锚点题集上标定，statement 有了之后再标一次。
- 多跳的噪声界。跳数和边类型现在是猜的，看日志里扩出来的哪些从来没被用过。

## 三层的结论

- 事件线不变。还在 `platform/app`，不搬进 memory。
- 区间不做。存区间的唯一论据是"锚点需要一个比事件耐久的目标"，消息有了自己的 id 之后这个前提没了。会话是一个函数：要"这次坐下来发生了什么"就拿事件时间戳现算窗口，要"上周这本书上聊过什么"就按时间范围过滤。现算的永远解析得出来，存下来的会随事件被改被删而悬空。
- 观察图不变，它就是情景仓。其上新加 statement 层，只往下指。

每一层只往下指、下面那层不需要知道上面有谁——这条性质是能继续加层的唯一前提。破坏它的是某层往上指或两层互指。

有效期不落在观察上。观察是事实、从不改写（更正是新记录），没有 `valid_from` / `valid_until`；判断的有效期全在 statement：`established`、`lastSupported`、`supersededBy`、concern 的 `lapsed`。

## 已否掉的

- 按天分文件。两台设备各写各的当天文件，每天必冲突且整份停副本。一条一个文件才能每条独立三向合并、冲突只停那一条。
- 边单独存。正文是耐久的那份拷贝，索引是它上面的投影；单独的 edges 文件未注册就是 opaque，一侧的边会停进没有代码看得见的副本。
- 换存储引擎。实测的缺陷没有一条出在引擎上。
- 作用域当检索键。
- 向量库。判据是能举出一个"读者确实想要、但 id、引用边、全文三路都召不回"的真实 query，举不出来就不上。跨主题那 0.125 是词面打分器的上限，先修数据和换靶子。
- 全局夜间衰减。
- 破坏性更新。脑改写记忆是因为没有便宜的第二份存储，三方合并的 markdown 有。更新要同时留住旧的、新的、和"不一致"这件事本身，mismatch 是 correction 的一等内容，不只是一条指向旧记录的边。
- guess / declared 两段式画像。guess 在阅读侧没有消费者，每轮花预算塞进去再叫模型别当回事；declared 是 blob 不是记录集，整份同意一千字不等于逐条作者身份，带不了日期、没法过期、没法被单条推翻。

有数据之前先做这四件，检索入口等量过再定。
