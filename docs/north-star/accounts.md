# 账户

## 愿景

app 要让用户登录的东西会越来越多，需要一个统一的"账户"位置：用户在那里集中登录、看状态、处理失效。登录入口不再散放在信息源页的各个源下面。

账户分两类。

浏览器会话：X、Bloomberg 这类。用户在站点自己的登录窗口里输入，关窗口算完成，cookie 留在本机，再加载首页确认。现状在 `src/info/sources/site-session.ts`（站点会话，由订阅的 webview 源和主题搜索派生出一行行站点）。

API 凭据：GitHub 令牌、Semantic Scholar 的 key 等。GitHub 未认证每小时 60 次，认证后 5000 次；这个限额是 API 的，网页 cookie 不起作用，要令牌。做法倾向 OAuth 设备流：app 显示一个码，用户在浏览器授权，令牌存本机不出本机，不让用户复制粘贴令牌。

统一位置里每行写明这个账户给哪些源带来什么好处（例如"GitHub：每小时 60 次提到 5000 次"），失效在同一处提示。具体放在哪个交互位置，发起人以后定，现在不定。

## 将来做时已知的事实

- 2026-10-16 主题搜索第一次 run，X 一条没读到：桌面没登录 X，停手记录 `signed-out`，每个 X 查询都是 `signed out of X`。用户在信息源页登录后可继续。
- 登录规矩沿用 [57](../info/57-登录态浏览器取材与computer-use.md)：登录由用户自己完成，cookie 不出本机，会话失效不自动重登，等用户处理。
- 站点只能从用户订阅的源（及 X 主题搜索）里选，模型给的 URL 不能变成登录页（见 `site-session.ts` 里 `resolveSignInSite` 的注释）；统一账户位置要保住这条。
- 登录失效提示现在落在采集端状态文件的 `sites` 字段（见 [36](../info/36-采集端与阅读端.md)）。
