# 饮食规划

## 愿景

给忙碌的都市白领——在意吃得健康，但没时间也没心力天天想吃什么的人——每天一句「今晚吃什么」。

这是伙伴为用户做的第一件和读书无关、而且天天发生的事。读书是天天打开的习惯，伙伴长在上面；吃饭是把用户真正用起 info 的入口；PDB 是同一个行为往外扩到世界。内部它是一个 info 研究室（[63](../63-情报局：研究室、专项组与态势.md)），视野是用户本人；界面上不出现研究室、情报局这类词，用户只是在和伙伴说话。

它不是一个独立的饮食 app。独立的饮食 app 死在录入摩擦上，两周之内数据就断了。这条线能活的唯一原因是录入只是对一个已经记得你别的事的伙伴说一句话。它同时是 info 反馈环的练兵场：一个用户每天都会验一次的题材，命中没命中当天就知道。

需求是决策疲劳，不是信息匮乏。输出是一句话，不是列表：今晚吃 X，一句理由，一个备选。决策分两层：先定形态（做饭 / 出去吃 / 点外卖），依据是到家时间、累不累、有没有备好的、这周外卖几次；再定具体吃什么，依据是口味和最近吃过什么，换着来不重样。

批量做饭把单位从一顿变成一周。周日两锅、一张购物清单、哪几天吃备好的、哪几天出去吃或者点。工作日六点那句话于是变成「热周日那锅鹰嘴豆炖菜」或者「备的菜放三天了，今晚出去吃」。周末给一份这周的计划加清单。每周回看一句话就够——外卖几次、蔬菜够不够，不做仪表盘。

健康指的是模式，不是记卡路里：蔬菜多、全谷物、瘦蛋白，少油少盐少精制碳水。哈佛健康饮食餐盘、地中海饮食、DGA 2020-2025、NHS Eatwell 说的是同一件事。它们是规则，写成给模型的一页约束，不是一个数据库。生成菜式的约束：动手时间 ≤30 分钟、食材 ≤8 样、符合模式、可批量（做一次吃三顿）。主方向是西式和地中海做法，它更简单也更贴这个模式；中式家常（HowToCook）降为可选参考，不做主力菜库。

语音只在灶台前是前提。六点那个决策发生在回家路上，打字或者一句语音就够，第一片不需要做饭那种长会话语音。

读书在 iPad 和桌面，吃饭在手机。今天缺三样：从手机把一句话或一张照片送进这个研究室、六点前把「今晚」那句话按时段推到手机、对话之外的反馈通道。手机交、PC 蒸、六点推回手机，这条线也是手机与 PC 联动的练习。

不做：菜谱数据库、餐厅搜索、卡路里记账、营养优化器、代下单。

## 源分三类

按 [69](../69-源模型：索引、叙事源、用户带来的与快照.md) 的源模型分，没有一类要商务合作，也没有一类要爬。

世界数据，能吃什么：

- 菜谱不内置库。两条路：用户贴一个菜谱链接（Budget Bytes、Serious Eats、BBC Good Food、NYT Cooking 这类），走现有的网页摄入管子抽里面的 schema.org Recipe JSON-LD——几乎每个英文菜谱站都埋了，含配料、时间、份数、每份营养；或者模型按上面那组约束直接生成简单菜。批量做饭是方法，不是数据。配料表是事实不受版权保护，存用户自己收的菜谱正是 Paprika 在做的事。
- 营养用 USDA FoodData Central（CC0），西式食材覆盖完整。[47](../47-饮食规划调研.md) 里「中式菜品和国内预包装食品无源」那个缺口因此基本消失，何况这条线本来就不数克。
- 出去吃和外卖没有菜单数据，美团、饿了么、大众点评都是封闭的，也不爬。唯一的外部源是地图 POI：高德和 Apple MapKit 的周边搜索对个人开发者开放，给店名、品类、距离、评分。到店级，不到菜级。

用户数据，他会吃什么：吃过什么、常去的那几家（说过一次「楼下那家米线」就记住）、忌口、这周外卖几次，以及他实际买得到什么——常去的店（山姆、盒马、Ole'）定义了可行的食材集合，山姆的烤鸡和沙拉包是很多人批量做饭的起点。没有外部源，全靠用户吃完一句话或者一张照片带进来。这是主源，推荐质量由它决定。

当日数据：天气、日历、位置。已经有了。

## 现在的位置

已经排上了，不再是搁置。第一步是项目发起人自己用一周：用对话开这个研究室，吃完一句话记下来，六点问它。

要验的前提换了。旧的是「用户会不会维护冰箱库存」，新的是「用户吃完会不会说一句话」。库存只是做饭这个形态的一个输入，没有就推另外两个形态。第一指标是录入摩擦，推荐质量第二。命中率（今晚那句话用户照做没有）和落空记录（改吃了什么、为什么）是第一批能量化的反馈数据。

都市白领在国内和美国怎么买菜（线下为主、线上补齐），单独一份调研写在 [71](../71-都市白领买菜渠道调研.md)。

## 已知的事实

底账在 [47](../47-饮食规划调研.md)，2026-08-28。形态结论按本文修订，下面这些事实仍然成立。

- 代下单不通。十二家生鲜和外卖平台没有一家有消费者侧接口，开放面全朝商家、服务商、供应商，都要企业资质。逆向不做：最高检 2025-06 的口径里「绕过官方客户端让对方系统执行指令」是刑事定性，且 App Store 5.2.2 要求随时出示第三方授权。
- 唯一对个人身份开放的正规下单口子是京东联盟 CPS，次日达，配不上「今晚吃什么」。
- 跳转到对方 app 的收益很小：已知 scheme 只有小象超市和多点两家，2022 年的社区数据，只能到首页不带搜索词。清单的价值靠清单本身做好。
- license 雷已经点名：GitHub 上那份中国食物成分表 JSON、聚合数据那份、Open Food Facts（ODbL share-alike 污染闭源）、Edamam（缓存条款等于不能建本地库）、下厨房豆果美食杰的逆向接口、CC-BY-NC 的中文菜谱数据集。
- 一旦承诺数字精确，App Store 1.4.1 会按健康数据准确性更严格地审，要披露数据和方法并给就医提示。这是不数克的第二个理由。
- UI 自动化替用户在 app 里点按钮：iOS 非越狱做不到，Android 真机加 ADB 可行，但那是个人自动化不是产品能力，且卡在支付确认那一步。
- HealthKit 的 39 个膳食营养标识符加身体指标现在就能读写，做不做另说。
