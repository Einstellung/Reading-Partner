# 饮食规划

## 愿景

info 侧的一条线。AI 知道你的口味、身体数据和这周的安排，替你决定吃什么，并且一路管到你站在灶台前。

分三层，各自的粒度不一样：

- **做什么**：菜谱。有现成的中式家常菜库可以整个内置。
- **吃多少**：结构性营养建议——今天蔬菜够不够、蛋白够不够、油盐重不重——不追克级精确。精确到毫克的营养素记账是减脂 app 的活，这条线要的是「今晚吃什么」这个决策，不是事后记账。
- **买什么**：一周菜单合并同类项算出食材总量，生成一份带数量的清单。到此为止，不代下单。代下单这条路查过，不通，理由和证据在 [47](../47-饮食规划调研.md)。

语音是这条线成立的前提，不是锦上添花。做饭本身是免手免眼的场景——站在灶台前手上全是油，念下一步、问「刚才说小火几分钟」、顺手起个计时器，只有语音能做。这和陪读时的语音不是一回事：陪读你在看屏幕，语音是补充；做饭你根本不看屏幕，语音是全部。

更要紧的是录入。这个功能的死穴是 AI 不知道你家里有什么、上周吃了什么、你不吃香菜；这些状态打字维护没人会坚持，三天就荒废。语音是唯一有可能把录入成本压到能接受的输入方式——「我买了两斤排骨」「香菜别放」随口一说就进画像。库存和口味这两份状态能不能活下来，直接决定它是真能用还是又一个菜谱列表。

分工是语音管规划和做，不管买：真到下单那一步屏幕更好使，超市里也不方便开口。

## 为什么现在不做

前提没验证过。整条线押在「用户会维护冰箱库存」上，而这件事没有任何体感证据。先把清单那版做出来自己用一段时间，看状态维护得下去维护不下去，再谈别的。

它是 info 侧的功能，排在 info 线本身之后（[17](../17-信息源系统.md)）。语音那半也还在做：按住说话已经落地（[15](../15-语音输入.md)），边说边聊的会话形态和 TTS 见 [33](../33-语音简报.md) 和 [45](../45-陪伴的形态.md)，做饭这种长会话（一顿饭四十分钟、要能被打断、油烟机噪音下要能听清）不在现有覆盖范围里。

## 将来做时已知的事实

调研底账在 [47](../47-饮食规划调研.md)，2026-08-28。

- 代下单不通。十二家生鲜和外卖平台没有一家有消费者侧接口，开放面全朝商家、服务商、供应商，都要企业资质。逆向不做：最高检 2025-06 的口径里「绕过官方客户端让对方系统执行指令」是刑事定性，且 App Store 5.2.2 要求随时出示第三方授权。
- 唯一对个人身份开放的正规下单口子是京东联盟 CPS，但它是次日达，只配得上「按周备货」的场景，配不上「今晚吃什么」。要用先验证它的商品库覆不覆盖生鲜和秒送。
- 跳转到对方 app 的收益很小：已知 scheme 只有小象超市和多点两家，还是 2022 年的社区数据，而且只能到首页，不带搜索词。清单的价值要靠清单本身做好——按一次搜一个词排好、勾掉已买、单条复制。
- 数据侧现在就能用的：HowToCook（Unlicense，400+ 道中式家常菜）、USDA FoodData Central（CC0，可整库内置，缺中餐）、HealthKit 的 39 个膳食营养标识符加身体指标、膳食指南 2022 与 DRIs 的数值。
- 唯一的数据缺口是中式菜品和国内预包装食品的营养，只有薄荷健康的 API 覆盖，要商务谈价。绕不过去的原因是菜谱配料是自然语言、中文食材在 USDA 里对不上。
- license 雷已经点名：GitHub 上那份中国食物成分表 JSON、聚合数据那份、Open Food Facts（ODbL share-alike 污染闭源）、Edamam（缓存条款等于不能建本地库）、下厨房豆果美食杰的逆向接口、CC-BY-NC 的中文菜谱数据集。
- 一旦承诺数字精确，App Store 1.4.1 会按健康数据准确性更严格地审，要披露数据和方法并给就医提示。这是「不追克级精确」的第二个理由。
- UI 自动化替用户在 app 里点按钮：iOS 非越狱做不到，Android 真机加 ADB 可行，但那是个人自动化不是产品能力（用户手机旁边没有常驻 Mac），且卡在支付确认那一步。现在不做，要做的验证顺序在 [47](../47-饮食规划调研.md) 第八节。
