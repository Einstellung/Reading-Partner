# 交互式讲解图

## 愿景

读到文字讲不清的地方，用户点一下"给我做个演示"，AI 为这个概念生成一个可以动手拨弄的小模型（交互网页），Lumen 在旁边讲：这是什么零件、现在发生了什么、为什么。结果作为盒子卡片送回，不在对话里让用户干等。

单有动画不够：不懂原理的人对着精致的动画还是懵，要有讲解跟着画面走。我们已有对话和语音，补的是画面这半边。

## 为什么现在不做

交互形态还有很多迭代和打磨要做，别的在推进的事更重要。2026-10-16 用户定：先记下，将来再做。

## 将来做时已知的事实

- 参考实现：[wheresryan22/anatomy](https://github.com/wheresryan22/anatomy)，MIT。Claude Code skill，输出等距视角的 SVG/HTML/React 组件，自带一套轻量 3D 投影（不用 Three.js），只重算活动部件，交互标 beta，手机约 13 到 15 fps。核心做法是把概念做成一台会动的机器，物体本身就是解释。
- 评说文章（卡兹克、tashi，微信公众号）的实测：5 分钟视频要约 1.5 小时（Opus 5.5 Ultra），约占 Max 周额度 1%；Sonnet 5.5 高强度够自学用。零基础的人只看动画会懵，加讲解和配音的版本明显更好。作者提醒：参数和机制不保证正确，要核对。
- 形态阶梯（Karpathy）：文字，图表，交互网页，讲解视频；各有用处，不是互相替代。我们先做交互网页加 Lumen 讲解词，视频太慢。
- 慢且贵，所以只能走后台，用户点了之后不等；结果放盒子卡片，回合不因关掉对话而停（见 closing-chat 的既定做法）。
- 生成的是可执行代码：必须沙盒里跑，不许联网、不许训练模型（文章作者让它讲 Transformer，它自己去训小模型，会话被判敏感行为封了）。按"起草自由、落地设闸"处理。我们之前定过聊天卡片不上 iframe，这条要重新看。
- 图里的参数和机制要能回溯到书里的原文，至少标出依据。
- 开工前先做小实验：挑 2 到 3 段用户没看懂的内容，用 Sonnet 档各生成一张交互网页，配上讲解词，在手机上看是否真有帮助，再决定做进卡片。
