# 访谈视频

## 愿景

独立的一条线，是 info 线和读书线的交集。入口像 info：外部内容流进来，先要分诊值不值得花时间。体验像读书：长内容、共读、批注。核心动作是蒸馏——两小时的访谈取字幕后，AI 告诉你值不值得看、讲了什么、哪几分钟值得跳看，并能就内容对话。

只做长访谈、演讲这类没有文字替代、信息密度高的内容。新闻类视频不做：文字媒体已经全覆盖，不值得为它维护脆弱的依赖。

只接 YouTube，播客不做：访谈类播客几乎都同时发 YouTube，只有音频的源不覆盖。接法见 [56](../56-YouTube访谈接入.md)：频道 RSS 当发现层，yt-dlp 取字幕当正文层，取材之后多跑一次蒸馏压成摘要，之后漏斗不知道它是访谈。

## 为什么现在不做

56 写在今天的 descriptor / engine 结构上，而 [17](../17-信息源系统.md) 那套信息源系统要整体推翻重做，重做时按 56 的事实和决定重新落。

## 将来做时已知的事实

实测数据（2026-09-07）在 56 的「实测事实」。要点：

- yt-dlp 官方 standalone zipapp 3 MB，取字幕不用登录、不用 PO token；字幕必须在 yt-dlp 进程里取，自己拿签名 URL 去 fetch 会被 429。
- 频道 RSS 仍然活，一页 15 条，不带时长；Shorts 靠 `<link>` 里的 `/shorts/` 区分，缺省过滤掉，否则粗筛会被同一集的切片刷屏。
- 一小时英文访谈约 1.4 万 token。
- B 站要养号，放弃。
