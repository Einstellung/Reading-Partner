# 商业化

## 愿景

盈利主要靠用户数据，以及在这些数据之上建一个基于 agent 的社交网络，向 B 端收费。C 端入口免费，用户越多网络越值钱；托管 AI（登录即用，自带 key 的照旧免费）带来用户和网络需要的账号体系。C 端付费以后再探索。

网络的形态：每个用户的 Lumen 代表本人，agent 之间先交流，只在值得时把人拉进来。数据是读了什么、卡在哪、问了什么、划了什么，比社交帖子更能说明一个人真正关心什么、懂到什么程度。Lumen 已经在攒 profile、concern、observation（见 [48](../soul/48-记忆：观察与statement.md)）。用法举例：

- 找到读过同一本书且真读懂某章的人。
- 我的 agent 问你的 agent，对方根据你的笔记回答，不打扰本人。
- 同主题的人自动成小组。

B 端收入：

1. 找人：招聘方、研究组、投资人付费在网络里搜某领域真有深度的人。被找的人自愿开放，开放的拿报酬。付费意愿最高的一方。
2. 聚合趋势：某领域在读什么、问什么、卡在哪，匿名聚合后卖给出版社、作者、做课程的人。
3. 赞助位：出版社推新书这类，明确标注。agent 的回答和推荐不能被买，标注过的赞助位可以有。

C 端以后探索的：

- 问答市场：用户的 agent 替本人回答别人的问题，按次收费，平台抽成。
- 托管 AI 的重度档：免费档有额度，超出的付费。iOS 上卖额度要走内购，小型企业计划抽 15%。

已定的做法：

- 仓库将来转私有。
- 做注册体系，第三方登录（Google 等），注册时同意使用协议，不同意不能用。
- 用户数据集中存到服务端。

## 为什么现在不做

2026-09-25 定过商业化搁置，继续开发到自己用得非常好。真在用的只有一两个人，社交网络的价值看密度，现在没有密度可言。

## 将来做时已知的事实

### 账号和上架

- 这里的「账号」是 app 自己的注册账号，和设置里列站点登录的 Accounts 页（[accounts](./accounts.md)）不是一回事。
- App Store 审核指南 4.8：提供 Google 等第三方登录，就必须同时提供 Sign in with Apple。
- 审核指南 5.1.1(v)：能注册账号就必须能在 app 内删除账号。
- 不登录也能用核心功能时（自带 key 读本地书），强制登录可能被拒。所以托管 AI 和网络放在登录之后，本地读书和自带 key 不要求登录。隐私标签要跟着改。
- 国内用户用不了 Google 登录，要另有 Apple 登录或邮箱、手机号。

### 同意分两层

法规约束：

- 个人信息保护法第十六条：不得以用户不同意处理非必要的个人信息为由拒绝提供服务；工信部通报 app 最常见的就是「强制捆绑授权」。
- 第二十三条：向第三方提供个人信息要单独同意。数据出境另有要求。
- GDPR 第 9 条：读的书和提的问题可能透露宗教、政治、健康倾向，属特殊类别数据，同意门槛更高。

所以分两层：

- 必需层：账号、同步、AI 处理、匿名聚合分析，是提供服务所必需的，写进使用协议，作为注册门槛。
- 单独开关层：按人对第三方提供（找人、问答）。不勾也照常能用，产品上包装成用户主动开启的「被找到」。

匿名聚合先做，按人提供等网络起来再做。决策数据的上传与同意（[decision-data](./decision-data.md) 里说「上架前设计」）归到这里的分层里。匿名使用统计的口径见 [telemetry](./telemetry.md)。

### 上传必须公开地做

转私有之前源码是公开的，上传了什么谁都看得到。用户愿意交数据的前提是换到东西：云端同步备份、换设备不丢记忆、网络里的找人和问答。

### 仓库转私有

迁移的事（更新端点、产物托管、macOS runner 按 10 倍计费）见 [release-hosting](./release-hosting.md)，不重复。补一句：xtool（github.com/xtool-org/xtool）只能在 Linux 上构建 iOS 的 SwiftPM 包，不出 macOS 桌面包，也替代不了 Tauri 的 xcodebuild 流水线，苹果 SDK 许可又只允许在苹果硬件上用，所以解决不了私有仓库的 macOS 计费。出路是租一台 Mac 当自托管 runner。

### C 端免费的成本

红果短剧、番茄小说那种免费加广告成立，是因为多服务一个用户几乎不花钱。我们每个活跃用户都要付模型费。粗估（未实测）：每天陪读一小时、整页正文进上下文，便宜模型也要一天一两块，一个月几十块；国内免费阅读类 app 的广告收入每用户每月一两块的量级，差十倍以上。所以 C 端免费要把成本压下来：免费档用最便宜的模型加每日额度；能放端侧的推理放端侧（TTS 已在本地，[system-one](./system-one.md) 本来就是端侧模型）；收钱放在网络上，不放在阅读上。

每个活跃用户每天实际用多少 token 现在不知道。[telemetry](./telemetry.md) 的匿名统计加上每日 token 用量后，这笔账才算得清。

### 顺序

1. 账号、服务端、托管 AI 作为一个阶段一起设计。
2. 装上即用的免费试用额度。
3. 从读同一本书、追同一主题的小圈子冷启动，十个人就有用。
4. 找人和问答。
5. 对第三方提供。

### 现在能先留的位置

- profile 分对外可见和私有两层。
- agent 的身份和可被别的 agent 调用的协议，在设计上留好位置，现在不实现。
