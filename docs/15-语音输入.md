# 语音输入（M-voice-1）

## 设计

两条路并存：桌面录 WAV 送 STT 主机，iOS 在设备上听写（见「手机上的本机听写」）。这一节到「润色 pass」讲的是桌面那条。

按住说话，做出 Wispr Flow 的两段式效果：录音 → STT 转写 → LLM 润色 → 成稿落进聊天输入框，用户看一眼再发。不自动发送。

聊天输入框旁加一个麦克风按钮。pointerdown 开始录，松手结束并触发转写+润色；录音中显示红点和秒数，转写中显示 spinner。指针按住后移出按钮再松手＝取消，Esc 也取消。没配 STT key 时点麦克风给一行提示指向设置。

录音在 Rust 侧（cpal + hound）。WebKitGTK 的 getUserMedia/MediaRecorder 在 Linux 上历史性地不可靠，而本项目主力桌面是 Linux。Rust 采集设备原生采样率，混成单声道、线性重采样到 16k、写 16-bit PCM WAV（SenseVoice/whisper 类模型要 16k 单声道）。cpal 的 Stream 不是 Send，所以用独立线程持有 stream，AtomicBool 通知停止，回调把采样推进共享 buffer；start/stop/cancel 三个命令驱动这个线程。录音上限 90s 兜底。

STT 请求走 Tauri http 插件（cleanTauriFetch），绕过 webview 的 CORS 和 CSP（connect-src 拦直连跨源，插件走 IPC）；任意 https STT 主机都能用。

## STT 可插拔层

OpenAI 兼容的转写客户端：POST `{base}/v1/audio/transcriptions`，multipart 带 file(audio.wav) + model，Bearer key，响应容忍 `{text}` 和纯字符串。默认硅基流动 `https://api.siliconflow.cn` + `FunAudioLLM/SenseVoiceSmall`（免费、中文最强、OpenAI 兼容）。base/model 存 settings.json（跟随同步），key 存 credentials.json（不同步，和图片中继 key 一个路子）。设置里可换任意 OpenAI 兼容供应商。

调研结论：小米 ASR 不免费；Groq 的 whisper 中文弱；本地离线（sherpa-onnx 等）后置。

## 润色 pass

一次调用用户现有的聊天供应商，低思考。系统提示：清理口语转写成可直接输入的文本——去填充词、自我更正只留改后版本、加标点断句、保持原语言（中文保持中文、英文保持英文、混合保持混合、不翻译）、按术语表纠正明显听错的专名，不加内容、不作答、只输出清理后的文本。术语表＝当前书标题 + 大纲/章节标题（取自 fulltext 缓存），约 300 字封顶。润色调用失败就回退原始转写——语音输入只降级不报废。

## 手机上的本机听写

iOS 走另一条路：`SpeechAnalyzer` + `SpeechTranscriber`，完全在设备上，不上传、没有 key、没有配额。iOS 26 起才有，硬件下限 iPhone 14（docs/33，那是全 app 的下限）。原生部分封在 `plugins/voice` 这个 Tauri iOS 插件里，Swift 采集（`AVAudioEngine` + VPIO）加识别，Rust 只做桥，非 iOS 平台注册同样的命令但一句话拒掉。命令是 `start_dictation` / `stop_dictation` / `cancel_dictation`，一个 `dictation` 事件推 volatile / final / level 三种。契约在 `plugins/voice/README.md`，`SpeechAnalyzer` 的接法和实测在 [33](./33-语音简报.md)。

界面不是麦克风按钮，是按住说话条。输入框旁的按钮在键盘和语音之间切，切到语音后整条输入框换成一根条，按住说、松手出结果。松手前不显示实时文字——识别器一直在改写自己的尾巴，看着它改等于把说话变成校对——只有电平表和一行「松手会怎样」。手指滑到浮在条上方的两个落点再松手是取消或放进输入框编辑，不滑就直接发送，不经复核。手势的状态机在 `src/ai/voice/hold-machine.ts`。

开闸是 `hasOnDeviceDictation()`，按 `platform() === "ios"` 判。它和桌面的 `hasNativeRecorder()` 是两条独立的路，不是互为兜底：那条录 WAV 送出去，这条一个字节都不出手机。

语种自己选，不跟随设备：`settings.dictationLocale`，默认 `zh-CN`，设置里单独一张卡。送错语种的模型不是识别得差一点，是按音节猜出一串语法通顺的目标语言词（坑 164）。书名和大纲当 `contextualStrings` 送进去做热词，中文专名有效，英文的靠不上（docs/33）。

这条路不跑润色 pass，转写直接进输入框或直接发。

## 已知限制

- 2026-07-29 定的「语音输入是桌面功能，手机上不做」已推翻（2026-08-21，见 docs/22）：设备端识别免费、不上传、无配额，而系统键盘的听写给不了按住说话这个手势。桌面那条走 cpal（`mod voice` 是 `#[cfg(desktop)]`，手机上没注册），麦克风按钮由 `hasNativeRecorder` 决定；手机那条走 `plugins/voice`。Android 两条都没有。
- 桌面无流式预览：转写是录完整段一次性出结果，录音中不显示实时文字。手机上有 volatile，是故意不显示的。
- 桌面的 WAV 字节经 IPC 以数字数组回传，长录音偏重；典型几秒可忽略，90s 上限兜底。
- 手机上按下到麦克风交出第一个音频 buffer 约一秒，短句会丢开头一两个字。实测分段和还没验的两条候选解法在[坑 166](./pitfall/166-the-microphone-opens-after-the-user-has-started-talking.md)。已知并接受，先这样发。
