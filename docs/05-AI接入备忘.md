# AI 接入备忘

AI 能力用 pi 提供的 `@earendil-works/pi-ai`。认证范围:Anthropic 走订阅 OAuth(Claude Pro/Max),OpenAI 走订阅 OAuth(ChatGPT Plus/Pro),另外 26 个 provider 走 API key。本文是实测出来的对接手册:怎么打进 webview、请求怎么走 Tauri、OAuth 怎么落地、流式接口长什么样。

## 版本与导入

`@earendil-works/pi-ai@0.82.1`。子路径导出:`.`(主入口)、`./providers/*`、`./api/*`、`./oauth`、`./compat`、`./bedrock-provider`、`./bun-oauth`。注意 `anthropicProvider` 不在主入口,在 `@earendil-works/pi-ai/providers/anthropic`。

0.82 把 OAuth 实现挪进不导出的 `dist/auth/oauth/*`,`./oauth` 只剩几个类型;`refreshAnthropicToken`、`refreshOpenAICodexToken`、`loginOpenAICodexDeviceCode` 都没了公开入口。三个流程现在全部由 `src/ai/` 自己实现(见下),pi 只负责 provider、模型表和流式接口。provider 上仍挂着 `auth.oauth`,但它的 `login`/`refresh` 会动态 import node-only 模块,webview 用不了。

## webview 打包

能打进浏览器 bundle。主 `index.js` 没有任何静态 node-only 依赖(aws-sdk/smithy/proxy-agent/`node:` 全部无静态 import),bundle 里出现的 `node:crypto/http/fs/os/stream` 都在 dynamic import 或环境守卫后的懒路径里,不影响加载。实测:headless Chrome 加载无报错,`anthropicProvider()` 实例化成功,`getModels()` 返回模型列表,`streamSimple()` 正常出流。底层是 `@anthropic-ai/sdk`,pi 已给它设 `dangerouslyAllowBrowser`。

## fetch 桥

pi 的所有请求走全局 `fetch`(实测拦截到 `POST https://api.anthropic.com/v1/messages`,带 `x-api-key` 和 `anthropic-beta` 头)。Tauri 里启动时装的不是无条件顶替,是按 host 过滤的桥(`src/ai/fetch-bridge.ts` 的 `installFetchBridge`):只有名单里的 AI 域名走 `@tauri-apps/plugin-http` 的 fetch(绕过 CORS,凭据不进 JS),其余一律交回原生 fetch——全局顶替会打断 vite dev 请求、reader iframe 的资源等本地流量。

名单是推导出来的,不是手抄的:`providers.ts` 的 `bridgedHosts()` 遍历 provider 表,取每个 provider 的 `baseUrl` 和它每个 model 的 `baseUrl`(OpenCode 两个 provider 自身没有 `baseUrl`,端点写在 model 上),解不出 hostname 的跳过;`fetch-bridge.ts` 再并进两条 OAuth 流程用到的域名(`api.anthropic.com`、`platform.claude.com`、`claude.ai`、`api.openai.com`、`auth.openai.com`、`chatgpt.com`),其中 `platform.claude.com`、`claude.ai`、`api.openai.com`、`auth.openai.com` 不是任何 provider 的 `baseUrl`。加 provider 只改 provider 表。webview 的 CSP 只放 `'self' ipc:`,不在这个集合里的 host 会走原生 fetch 然后被 CSP 打掉。走桥的请求还会改头:删掉 SDK 自动加的 `anthropic-dangerous-direct-browser-access`(订阅态组织会因为这个头把请求当 CORS 拒掉),并把 `Origin` 置空(插件的 unsafe-headers 特性下空 Origin 等于不发这个头,否则插件会强行补上 webview 的 origin,Anthropic 又把带 Origin 的请求当 CORS),见 [docs/pitfall/15](./pitfall/15-plugin-http-forced-origin.md)。

权限集 `http:default`(含 allow-fetch / -send / -read-body / -cancel / -cancel-body)现已放开到任意 https host,只挡明文 http——`src-tauri/capabilities/default.json` 的 description 明说这是为了让用户粘贴的链接(link ingestion,docs/09)能从任何来源抓取:

```json
{
  "identifier": "http:default",
  "allow": [
    { "url": "https://api.anthropic.com/*" },
    { "url": "https://platform.claude.com/*" },
    { "url": "https://claude.ai/*" },
    { "url": "https://api.openai.com/*" },
    { "url": "https://auth.openai.com/*" },
    { "url": "https://chatgpt.com/*" },
    { "url": "https://api.deepseek.com/*" },
    { "url": "https://export.arxiv.org/*" },
    { "url": "https://arxiv.org/*" },
    { "url": "https://api.openalex.org/*" },
    { "url": "https://api.semanticscholar.org/*" },
    { "url": "https://*" }
  ]
}
```

列出来的具名条目是文档性质的,真正放行的是最后那条 `https://*`;AI 域名由 `bridgedHosts()` 推导,加 provider 不用动这个文件。

pi 的 `StreamOptions` 还有 `onPayload` 钩子和响应前回调,需要拦截或改包时用。

## Anthropic 订阅 OAuth

授权码 + PKCE 流程。常量来自 pi-ai `dist/auth/oauth/anthropic.js`:

- client_id: `9d1c250a-e61b-44d9-88ed-5944d1962f5e`(公共 client)
- 授权页: `https://claude.ai/oauth/authorize`
- token 端点: `https://platform.claude.com/v1/oauth/token`
- redirect_uri: `http://localhost:53692/callback`(注册值,精确匹配)
- scope: `org:create_api_key user:profile user:inference user:sessions:claude_code user:mcp_servers user:file_upload`
- PKCE S256,用 Web Crypto(`crypto.subtle` + `getRandomValues`),浏览器可跑;pi 把 PKCE verifier 直接当 `state` 传

授权 URL 构造:

```
https://claude.ai/oauth/authorize?client_id=<CLIENT_ID>&response_type=code
  &redirect_uri=http%3A%2F%2Flocalhost%3A53692%2Fcallback&scope=<SCOPES>
  &code_challenge=<challenge>&code_challenge_method=S256&state=<verifier>
```

(loopback redirect 不显示 code——`code=true` 也不管用,真机实测;手动粘贴走的是另一个 redirect,见下面「落地」一节的兜底。)

token 交换:`POST` token 端点,JSON body `{ grant_type: "authorization_code", client_id, code, state, redirect_uri, code_verifier }`,返回 `{ access_token, refresh_token, expires_in }`。刷新:同一端点,body 换成 `{ grant_type: "refresh_token", client_id, refresh_token }`,响应同形。两者都在 `anthropic-oauth.ts` 的 `postToken` 里,存的 `expires` 统一扣 5 分钟 skew。

token 端点响应不带 CORS 头(实测 bogus code 换 token 返回 HTTP 400 `invalid_grant`,无 `access-control-allow-origin`)。所以 token 交换必须走上面的 Tauri http 桥,webview 直接 fetch 会被 CORS 挡。

### 落地:loopback 自动捕获(定稿,2026-07-13 用户拍板,免手工粘贴)

pi 的 Anthropic 登录无条件起 node:http 回调服务器,webview 里必抛,0.82 起连 code 交换和刷新原语也不导出了。所以整条流程自己实现:

1. webview 生成 PKCE + 拼授权 URL(约 15 行)。
2. 通知 Rust 侧起一次性 `localhost:53692/callback` HTTP 监听(约 50-80 行:一次性监听 + 完成后自动关闭 + 超时,拿到 code 后经 Tauri event 发回前端,并给浏览器返回一个"可以关掉此页"的成功页)。
3. `@tauri-apps/plugin-opener` 的 `openUrl(authUrl)` 开系统浏览器,用户登录授权,浏览器自动重定向到 loopback,code 被捕获,全程无手工输入。
4. webview 收到 code,经 Tauri http 桥 POST token 端点换 token。
5. 刷新走同一个 `postToken`,由 `token-refresh.ts` 保证每个 provider 同时只有一次在飞(refresh token 用一次就轮换)。

兜底:loopback 端口被占或超时,回退手动粘贴。loopback 的 redirect(`http://localhost:53692/callback`)不会显示 code,加 `code=true` 也不管用(真机实测)——手动流程必须换用另一个注册 redirect `https://console.anthropic.com/oauth/code/callback`,授权页在这个 redirect 下会显示 code(code#state)供拷贝,粘贴进设置页换 token 时重复同一个 redirect_uri。

## OpenAI 订阅 OAuth(ChatGPT Plus/Pro)

和 Anthropic 同一姿态:用官方 Codex CLI 的公共 client 走授权码 + PKCE,没有面向第三方的独立正式通道。常量来自 pi-ai `dist/auth/oauth/openai-codex.js`:

- client_id: `app_EMoamEEZ73f0CkXaXp7hrann`
- 授权页: `https://auth.openai.com/oauth/authorize`(额外参数 `id_token_add_organizations=true`、`codex_cli_simplified_flow=true`、`originator=pi`)
- token / refresh 端点: `https://auth.openai.com/oauth/token`(form-urlencoded;token 交换不回传 `state`,与 Anthropic 不同)
- redirect_uri: `http://localhost:1455/auth/callback`(注册值,精确匹配;端口和路径都跟 Anthropic 的 53692/callback 不同,所以 Rust 回调监听器参数化了 port + path,三个 OAuth 调用方共用)
- scope: `openid profile email offline_access`
- access token 是 JWT,内含 `chatgpt_account_id`;pi 的 codex 推理 api 自己从 token 解出来设 `chatgpt-account-id` 头,所以只需把 access token 当 `apiKey` 注入,和 Anthropic 同路。
- 刷新和 code 交换共用 `openai-oauth.ts` 的 `postToken`(form-urlencoded),存的 `expires` 扣 5 分钟 skew。
- 设备码登录(iOS 路径)也在 `openai-oauth.ts`:`POST /api/accounts/deviceauth/usercode` 拿 user code(404 = 该账号没开这条路,回退粘贴),轮询 `POST /api/accounts/deviceauth/token`(403/404 和 `deviceauth_authorization_pending` 都算 pending,`slow_down` 退避),拿到 `authorization_code` + `code_verifier` 后按 `redirect_uri = https://auth.openai.com/deviceauth/callback` 换 token。RFC 8628 的轮询节奏在 `device-code.ts` 的 `pollDeviceCode`,纯逻辑、有单测。

provider 用 `openaiCodexProvider()`(不是 `openaiProvider()`),`baseUrl` 是 `https://chatgpt.com/backend-api`,Responses API 形态(`/codex/responses`)。订阅态可用模型限定为 codex 模型集(`gpt-5.4`、`gpt-5.4-mini`、`gpt-5.5`、`gpt-5.6-*` 等),provider 模型列表跟着来,不再是通用 OpenAI 模型。

约束:codex provider 默认走 WebSocket transport,但 webview 的 WebSocket API 带不了 `Authorization` / `chatgpt-account-id` 头,CSP 也禁 wss。所以对 OpenAI 强制 `transport: "sse"`,经同一个 Tauri http 桥出流。落地流程(loopback 自动捕获 + 手动粘贴兜底)与 Anthropic 完全一致,只是端口/路径/token 端点换成上面这套。

存量 OpenAI API key 凭据直接弃用:读到旧格式忽略,不迁移(用户拍板只支持订阅)。

## API key 类 provider(26 个)

设置页第一个 tab 的 "API key" 卡:一个 provider 下拉 + key 输入框 + Save。模型不在这张卡里选,选完 provider 存完 key 之后走 "Default conversation" 的 Model 下拉,它列的是该 provider 的目录。key 存本地(见 CLAUDE.md,绝不入库),请求走 fetch 桥。

清单和 authKind 在 `src/ai/provider-ids.ts`(不 import 任何模块,否则 `providers.ts` ↔ `credentials.ts` 成环),工厂在 `src/ai/providers.ts`,两边由 `Record<ProviderId, Provider>` 逼着对齐:

deepseek、opencode、opencode-go、openrouter、vercel-ai-gateway、huggingface、nvidia、together、qwen-token-plan、qwen-token-plan-cn、moonshotai、moonshotai-cn、zai、zai-coding-cn、groq、ant-ling、xiaomi、xiaomi-token-plan-ams、xiaomi-token-plan-cn、xiaomi-token-plan-sgp、cerebras、fireworks、kimi-coding、minimax、minimax-cn、xai。

`providers/*` 逐个文件 import,**不要 `providers/all`**:那个 barrel 静态 import aws-sdk 等 node-only 依赖,会打进 bundle。单个 provider 文件很轻,api 实现是懒的。

排除的 provider 和原因:

| provider | 原因 |
|---|---|
| amazon-bedrock | AWS 凭据 + node-only SDK |
| google-vertex | ADC 凭据,`baseUrl` 里有 `{location}` |
| azure-openai-responses | `baseUrl` 空,要 resource 名 |
| cloudflare-ai-gateway、cloudflare-workers-ai | `baseUrl` 里有 `{CLOUDFLARE_ACCOUNT_ID}` 占位 |
| github-copilot | OAuth 流程 |
| radius | 动态 provider,目录为空 |
| google、mistral | `@google/genai` / `@mistralai` 在 webview 没验过 |
| pi 的 `openaiProvider` | id 也叫 "openai",和 codex 那个冲突 |

单凭据:credentials.json 同时只存一个 provider(`withActiveCredential` 遍历删掉其余),`imageGen` / `voiceStt` 是设备 key,不参与。老的多凭据文件按 `ACTIVE_PRIORITY` 消歧(anthropic、openai 在前,其余按清单顺序)。

## 流式接口

```ts
import { anthropicProvider } from "@earendil-works/pi-ai/providers/anthropic";
const p = anthropicProvider();          // 或通用 createProvider({ id, name, auth, models, api })
const models = p.getModels();           // Model[]
const stream = p.streamSimple(model, context, options);  // 或 p.stream(...)
for await (const ev of stream) { /* 增量事件 */ }
const final = await stream.result();    // 最终 AssistantMessage
```

- `context`: `{ systemPrompt?, messages: Message[], tools?: Tool[] }`
- `options`(StreamOptions): `{ apiKey?, temperature?, maxTokens?, signal?, transport?, cacheRetention?, sessionId?, onPayload? }`
- provider 的 `auth`: `{ apiKey?: ApiKeyAuth, oauth?: OAuthAuth }`;OAuth 走 `auth.oauth`,`Models.getAuth()` 内部自动刷新
- 返回的 `AssistantMessageEventStream` 是 `AsyncIterable`,`for await` 消费增量,`result()` 拿终值

事件类型(`AssistantMessageEvent`,每个都带 `partial: AssistantMessage`):

| type | 含义 |
|---|---|
| `start` | 消息开始 |
| `text_start` / `text_delta` / `text_end` | 正文分块 |
| `thinking_start` / `thinking_delta` / `thinking_end` | 思考过程分块 |
| `toolcall_start` / `toolcall_delta` / … | 工具调用分块 |
| `done` | 成功终止,携带最终 AssistantMessage |
| `error` | 失败终止,stopReason 为 error/aborted，带 errorMessage |
