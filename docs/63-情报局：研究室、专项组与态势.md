## 根问题

info 侧要做的是一个赛博中情局：为一个人监察他感兴趣的领域。三块工作：获取（高质量公开源）、加工（背景挖掘与趋势分析）、呈现（讲与稿）。三块不是流水线，是一个环：分析端反过来给采集端下任务，用户的动作回流到选题。

环上必须有一个持久的状态，叫态势：一个研究室到今天为止对它那块地盘的认识。今天的 info 是一条每晚从零跑的管线，跑完状态就扔，所以粗筛只能猜用户在乎什么，深挖回来没人判答上没有，稿每次重写。所有开源 research agent 都是这个形状，所以都做不了持续监察。

| synthesis | 研究室级：合并各分析员的增量成态势更新和盒封面 | 用 | 各分析员产出、态势 | 态势、领域变化 cable |
| 编辑部 | 两阶段选题、验证、写稿、过督查、进书架 | 用 | 态势、cable | 稿 |

| 督查 | 引用逐条核对；标题不强于正文；同一判断跨期漂移；Admiralty 双轴 | 核引用用模型，其余程序 | 稿、判断记录 | 校验结果 |

分析员的粒度是 concern，不是领域。一条 concern 冷了它的分析员就不派，活跃 concern 多就多派，这就是动态增减。

## 三个仓

- palace：登记的数据。书、cable、稿、序列文件、归档的态势。61 已定。
- 态势：关于世界的状态，研究室各持一份，作为数据登记进 palace，随账户同步。
- memory：关于用户的状态。观察和 statement。48 已定。

研究室读 memory 不写 memory：run 开始时载入这个领域下的 concern（含版本变迁）、用户在这个研究室盒里的动作、画像里的猜测。用户动作由 dream 折进观察，58 已定。concern 只说用户，可观测项只说世界；前者影响排序权重，后者驱动采集和分析。

## 研究室的边界

一个研究室 = 一套常态模型能覆盖的最大范围。判据三条：

1. 判「算不算异常」的分母是同一套。具身智能和 AI agent 都读 arXiv 和 GitHub，但分母不同，是两个研究室。
2. 可观测项互相解释。利率、信用利差、专项债发行前公告在一个研究室里才看得见联系。
3. 一个 synthesis 装得下。态势摘要要能放进一次 run 的上下文；装不下就沿第二条拆。

研究室与 topic 松耦合：章程写稿落到哪个 topic，默认同名新建；一个 topic 可收几个研究室的稿。topic 是用户读书的分组，研究室是 AI 干活的编制。

层级两级：研究室下面可观测项按簇分组，簇是程序上的分组，不配 agent。哪个簇长出自己的常态模型就拆成新研究室。

## 三档渐变

| 档 | 状态 | 装备 | 起 | 终 |
|---|---|---|---|---|
| tasking | 无 | 一次深挖 | 追问、缺口、序列 event | 回盒 |
| 专项组 | 薄态势：可观测项、待答问题 | 无常态模型，不出稿 | 只从对话里起：用户说「下月去京都」，AI 提议起一个京都专项组，点头才起 | 到期或连续 N 天零命中零交互，解散。态势归档进 palace，不删 |
| 研究室 | 全套态势 | 常态模型、判断记录、编辑部、漂移检测 | 用户明确声明 | 用户明确解散，态势归档 |

升降级由证据触发、AI 提名、用户点头：tasking 的答案几天内被反复追问，提名升专项组；专项组活跃过几周或撞上某条常设 concern，提名升研究室；研究室或专项组长期零命中零交互，提名解散。

## 章程

用户只说关注点。AI 起草章程照给用户看，对话改，不填表。可观测项冷启动分两步：招募员先跑出第一批 cable，分析员读完再起草，不让模型凭空写。章程是态势的一部分，随态势同步。

## 源

源归情报局的注册表，研究室认领；一份 cable 可被多个研究室引用。用户不再管源。保留的动作只有两个：对话里说「把某某加进来」，和「这个源单独关掉」。源列表变成一页只读：有哪些源、各被谁用、健康如何。

两档源。A 档是一手约束源：财政部、统计局、EDGAR、央行、交易所这类，是研究室的地基，不因用户不看而降级。叙事源（媒体、博客、newsletter）按反馈升降。Admiralty 的源可靠性轴承担分档。A 档源今天一个都没有，怎么接另场调研，本文只立原则。

招募员七步：拆词（学术词、工程词、机构名、事件词）、五通道枚举（arXiv 按术语统计作者机构与项目域名、GitHub 按 topic、HN Algolia 按分数统计域名、机构名转域名试 feed 路径、已入选源的外链）、探测、试抓、算指标、分层（核心、外围、事件驱动）、周期复检。必须人定的：视野边界、付费与登录、关源、权威度里的价值判断、add 那道闸。付费源的提名是缺口分析的产物：几条可观测项长期没命中、能覆盖它们的源要订阅，AI 带证据提名。

迁移：现有源进注册表，带上已有描述和彭博的登录态。机器之心被具身智能和 agent 两个研究室认领，彭博的 economics 和 markets 被宏观研究室认领。

## 采集

35 的四相位保留，两处改：发现层先跑规则过滤（公司白名单、公告类型、关键词），再进粗筛；粗筛的输出从二元「值不值得抓」改成「命中了哪几条可观测项」的下标，命不中的不抓。

数值序列不进漏斗，另起三步短管：取（按日历或间隔请求，追加进本地序列文件）、判（纯程序跑规则：Z 分、变化幅度、区间突破、用户声明的水平跨越、停更；概率类指标在 logit 尺度上算）、投（每条 event 变一条 cable 进所属研究室的盒）。前两步零模型调用。序列文件一指标一个，append-only，按年切。

夜间 PC 是大预算窗口。36 已定 PC 是采集端；夜里采集经理做三件白天不做的事：跑登录态浏览器和 computer-use（57）处理没有干净管子的源；给活跃研究室的分析员放开轮次上限；跑招募员的周期复检。白天 iPad 只读盒、追问、改章程，追问变 tasking 排进夜间队列，用户明说现在要的除外。

## 一天

对照睡前消息的三层：每日新闻列表、参考信息、主线。

夜里各机构跑 run 出 cable，程序筛掉九成九。每个有命中的研究室跑分析员和 synthesis：出一条领域变化 cable 投进该研究室的盒，更新态势，缺口写进 tasking 队列，非时敏的挂着等下一轮常规采集顺路带上。早上用户看到几个盒，封面是「今天这个领域变了什么」，下面是依据的原料。白天追问变 tasking，回来是新盒，用户三态判答上了没有。编辑部周级跑选题会。dream 把用户动作折进观察，gc 回收原料时跳过被稿引用过的 cable。

## 反馈

信号来自 cable 状态（dismissed、told、asked、saved、promoted）。程序按三个维度聚合，各指向不同的病：

- 按源聚：同一研究室里某个叙事源的命中率明显低于研究室均值，是源的问题，采集经理降频或淘汰。A 档豁免。
- 按研究室聚：整个研究室的交互率低于其它研究室，是关注点的问题，提名降为周级或解散，用户点头。
- 按产物版本聚：原料 cable 有交互但领域变化 cable 没人看，是分析员的问题；标题被点开正文立刻摁掉，是 brief 的问题。分析员和 brief 的提示词带版本号，cable 记下产出它的版本。
- 全局沉默：用户几天没开任何盒，什么都不调。生产者分不清用户读没读时不能动。

刹车：反馈只调源权重和研究室预算，不改可观测项。可观测项由分析员按证据提、用户对话改。`told` 在排序权重里按零算。

## 质量规则

程序查的：

- 每条 cable 两个独立的分：源可靠性（A 到 F，存在源上，按历史更新）和本条可信度（1 到 6，由独立源数算出）。不合成一个数。
- 转载不加分。独立源看原始报道方，同稿重复计数为一。
- likelihood 七档、confidence 三档，模型只交枚举值，百分比文案由程序渲染；两个字段不在同一句里渲染。
- 判断依赖某源也挂尾注，不只直接引用。「依据」和「延伸」分开列。
- 标题不强于正文：封面和 brief 标题里的判断强度不得超过正文的档位。
- 漂移检测：判断记录里同一判断连续加强报警。
- 引用独立校验步：稿进书架前，每条引用在本地 cable 里逐字验证存在，验不过不出稿。
- 被稿引用过的 cable 正文不进 gc。

提示词查的：

- 关键假设检查：写下结论，列出全部前提，逐条问必须为真吗，只留必须为真的。
- 竞争性假设：证据只与一个假设一致才有诊断价值，数不一致而不是数一致。
- 每条判断配「什么出现会推翻它」，写回可观测项，成为下一轮采集的靶子。
- 和上次的判断一样还是变了，变了因为什么。不用套话。
- 不为少犯错而回避该下的判断。60 的「宁漏平庸」漏的是平庸，不是难。
- 稿末一段源基评估：强弱在哪、哪些源对关键判断最重要、哪些互相印证或冲突。

## 加工

细则见 [65](./65-加工手册：常态模型、日更列表、滚雪球与稿.md)。

分析员的产出是增量，不是报告：读态势和当日命中，写「和已知比变了什么」，更新可观测项的 baseline 与命中时间，提出新可观测项和缺口。更多 cable 不会让判断更准，只会让它更确定，所以态势给摘要版，分析员按需下钻。

挖掘用关键词滚雪球：从一个可命名的异常物起步，每个来源吐出新专有名词，组合成下一次查询，滚到撞上带数字的文件为止。要不要投入深挖，看能不能预见数字闭合的路径，不看热度。

## 编辑部

选题两阶段带冷却：从态势里挑候选（同一模式第 N 次复现、一条判断被新证据推翻、用户追问密集），派 tasking 验证事实和逻辑，下一次选题会没过时、没发现严重缺陷才立项。立项不问用户，写完过督查，进书架前确认一次。

稿的骨架：事件（时间线、具体个案、精确数字）、常态对照（主流解释拿常态去测）、机制、历史对照（引原文）、判断。事实、机制、主张三段显式分开，主张那段可关。稿末源基评估。

盒的模板照参考信息：固定 4 到 8 条，每条事实加官方原话加一句判断，封面一句话把全部条目各说一遍，收尾带下次投递时间。

## 呈现

盒按研究室切。封面是当日变化，下面是依据的原料 cable，机构只是每条上的标签。tasking 回盒和稿送达盒不变。数值 event 归所属研究室，不另切。

tasking 回盒带三态：这是对你那个问题的回答吗。用户不表态默认未判定，未判定的 tasking 不释放它的 idempotencyKey。

简报员读态势，才能说「和上次比」。60 的三个待定按本文定：主讲被打断算 `asked`；不要 `later`，盒级的「没开」已经覆盖；过期按同研究室的新盒取代，不按天数。60 其余不动。

## 与 legion 的对应

| 角色 | run kind | 触发 |
|---|---|---|
| 各机构 | collect（发现、粗筛、取材、分拣四相位各一） | schedule 定时、日历窗口 |
| 数值源 | series-poll、series-detect | 日历或间隔 |
| 招募员 | recruit | 起研究室、周期复检、缺口 |
| 分析员 | analyze | collect 之后，有命中的 concern |
| synthesis | synthesize | 同研究室分析员 join（batchId） |
| 编辑部 | editorial-select、editorial-write | 周级、立项 |
| 督查 | inspect | 稿写完 |
| tasking | tasking | 追问、缺口、序列 event、选题验证 |
| 采集经理 | 不是 run，是 schedule 之上的程序层 | |

调度与执行分离：schedule 只找到期的 run，每个 run 独立执行、资源上限独立。

tasking 生命周期：登记（idempotencyKey 去重，同一次异动一天只开一次）→ 先查已有 cable 和稿，查得到直接给 → 采集 → 回盒 → 用户判定（答上了 / 没答上 / 未判定）→ 判满足才释放 key；没满足的三条出路：取消、改派下一轮、提级。非时敏的 tasking 按低优先级登记，等常规采集顺路满足，一直没满足才提级。信息在公开源上不存在时，明确回「查不出来」。

## 给 docs/17 重做的规格

十份调研撞到的同一组缺口，17 重做时逐条处理：

1. POST 与请求体（表单、JSON）。
2. JSONP 剥壳、嵌套 JSON 字符串二次 parse、数组路径与行内数组展开、等值过滤。
3. URL 模板不止 `{id}`：多字段拼接、字符串变换、`{today}` 类日期占位。
4. PDF 正文模式，带 `maxBytes` 与 `maxPages`，支持 Range 只取前几页；reading 侧已有那条路，是搬不是造。
5. 查询串提成字段：同一根管子换查询串就是另一个源。
6. 发现层规则过滤。
7. 发布日历字段（iCal、表格页、推导三种取法），只调节奏和预告，不产生条目。
8. UA 策略三向：自报身份、引擎自带、非空即可。探测器三种都试。
9. 密钥不进描述：`secretRef` 加不同步的本地密钥表。
10. 每源运行时状态与描述分离：ETag、最近成功、最近出稿时间、每周出稿数、可靠性档。存活按最新条目时间对源的正常节奏判，不按 HTTP 通不通。
11. 一个机构多条 feed 归组。
12. 快照型列表声明身份字段，靠 diff 判新。
13. 条目级截止日期。
14. 序列源并列一个 `SeriesDescriptor`：指标 id、频率、单位、小数位、取值路径、回填方式、许可（open / attribution / personal-only）。
15. 发现层 webview 分支，排队的站点已经有一串。
16. 两层不同协议的发现与全文（tags.atom 发现、releases API 全文）。
17. 一次灌两三千条的快照源（会议 proceedings）。
18. 自适应轮询：按重复率伸缩周期，人工实测值只当初值。
19. 探测器的判据：content-type 加条目计数而不是状态码；识别 JS 跳转壳；单引号 href 与相对路径；Cloudflare 站串行重试；feed 读完整再数条目。
20. 能力位：requiresWebview、antiCrawler、paywalled、summaryOnly、requiresLogin。
