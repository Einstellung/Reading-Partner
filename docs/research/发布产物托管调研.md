# 发布产物托管调研

2026-10-20。源码仓库要改私有，`releases/latest/download/latest.json` 对匿名请求会 404，已装客户端的更新就断了。本文找一个免费的地方放更新产物（latest.json、各平台安装包和 .sig、Android APK），并和之后的产品网站放一起。数字都取自各家官方文档页，来源和查阅日期在每节末尾，日期统一 2026-10-20；"未查到"表示没找到官方说法，没有猜。大陆访问几乎都没有官方数据，只有社区经验，已单独标出。

## 估算口径

- 上传：每周 3 次发版、每次全平台约 600 MB，一个月约 8 GB。保留最近 5 版，常驻约 3 GB。
- 下载：一个用户只下自己平台的包，按 150 MB 算（任务书给的范围是几十到两百多 MB，这是取值假设）。100 个活跃用户每次发版都更新，一个月 13 次，最坏约 200 GB；一半用户跟每次发版约 100 GB。
- 当前现状（GitHub Releases）：单文件须小于 2 GiB，一个 release 最多 1000 个资产，总大小和下载流量页面上都没有设限。

## 公开产物仓库的 Releases

新建一个只放产物的公开仓库（例如 `Einstellung/lumen-releases`），release.yml 仍用 tauri-action，把它的 `owner`、`repo` 输入指向新仓库，`GITHUB_TOKEN` 换成对新仓库有 contents 写权限的 PAT（内置 token 只覆盖当前仓库，这是 GitHub 通行行为，本次没有逐页核对）。android-apk.yml 的 `gh release upload` 加 `--repo` 即可。latest.json 地址变成 `https://github.com/<owner>/<新仓库>/releases/latest/download/latest.json`，格式和现在一样，updater 侧零改动。

条款：GitHub 条款里禁止的是把 Actions 当 CDN，没看到针对 Releases 发行二进制的限制。Pages 不得用于经营商业站点或商业 SaaS，产品网站如果主要是卖东西要注意。产品网站可以放同一个仓库的 Pages（公开仓库免费），站点上限 1 GB。

大陆：搜到的都是个人博客和论坛帖，说 github.io 和 release 资产域名在大陆慢且不稳，有 DNS 问题，没有官方或近期测速数据。

来源：docs.github.com about-releases、github-pages-limits、github-terms-for-additional-products-and-features、creating-a-github-pages-site；github.com/tauri-apps/tauri-action；juejin.cn/post/6963424908269322247、dev.to/21yunbox（大陆部分）。

## Cloudflare R2 + Pages

R2 免费档每月 10 GB 标准存储、100 万次 Class A、1000 万次 Class B，经 Workers、S3 API、r2.dev 的出站流量不收费。保留 5 版约 3 GB，下载 200 GB/月的最坏情况也不产生流量费，是唯一在估算里没有任何一项超额的候选。单文件 5 GiB（单次上传），同一个 key 每秒最多一次并发写。

CI：R2 提供 S3 兼容接口，端点 `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`，region 填 `auto`。在 R2 的 API Tokens 页创建 Object Read & Write 令牌并限定到这个桶，得到 Access Key ID 和 Secret，放进仓库 secrets，workflow 里用 `aws s3 cp` 上传。wrangler 的 `r2 object put` 也可以（`--remote`、`--content-type`、`--cache-control` 都有），但文档页没写单文件上限，大包建议走 S3。

对 updater：公开访问要绑自定义域名，域名必须在你的 Cloudflare 账号里；r2.dev 子域有限速，官方明说只用于开发。自定义域名下可以走 Cloudflare 缓存，默认只缓存部分扩展名，latest.json 是否被缓存、缓存多久要自己设规则，不设就会遇到发版后一段时间读到旧文件，需要实测。latest.json 里 `url` 填 R2 域名下的路径即可，格式要求见 Tauri 文档，URL 本身没有限制，TLS 强制 https。

需要做的改动：tauri-action 生成的 latest.json 假定产物在 GitHub Release（文档原话），所以 CI 要变成"在私有仓库先出一个 release，再由一个 job 把资产传到 R2，用 jq 把 latest.json 里的 url 改成 R2 域名"。这一步比方案一多，但 tauri-action 本身不用动。

网站：Cloudflare Pages 免费档每月 500 次构建，单个资产 25 MiB，每站 20000 文件，自定义域名每项目 100 个，页面没列流量上限。网站放 Pages，安装包放 R2，同一个域名下用不同子域。

条款：R2 和 Pages 的条款里没有禁止分发二进制或限制大文件的条目；CDN 服务条款里有"成比例使用非 HTML 大文件"的限制，但该条属于 CDN 产品，开发者平台条款没有这条，R2 是否算在内未查到明确说法。超额后是否自动扣费、是否必须绑信用卡开通 R2：未查到。

大陆：Cloudflare 官方的大陆方案（China Network）要 ICP 备案和企业版，不适用。第三方资料说 Cloudflare 在大陆没有被封，但高峰期国际出口拥堵、不同运营商表现不一，没有 R2 专门的测速。大陆可访问性算"未知，需要实测"。

来源：developers.cloudflare.com/r2/pricing、r2/platform/limits、r2/buckets/public-buckets、r2/api/tokens、r2/examples/aws/aws-cli、workers/wrangler/commands/r2、pages/platform/limits、china-network；cloudflare.com/service-specific-terms-developer-platform、service-specific-terms-application-services；docs.apiyi.com/faq/cdn-download-slow。

## GitHub Pages 单独用

站点上限 1 GB，软带宽 100 GB/月，软构建 10 次/小时（自定义 Actions 部署不受此限）。一个版本就 600 MB，放不下多版本安装包，只适合放 latest.json 和网站。私有仓库在免费账号下不能发布 Pages，仓库转私有时已发布的站点会被自动取消发布。所以它只能和公开产物仓库配对，不单独成方案。

## Gitee

发行版附件单个不得超过 100 MB（GVP 项目 200 MB），每个仓库附件总量 1 GB（推荐项目 5 GB，GVP 20 GB），普通仓库单文件 50 MB。安装包和 APK 超单文件上限，放不下。帮助中心的 Pages 标签页标注"功能已下线"，Pages 的实名认证也有用户反馈审核麻烦。上传 API 的情况页面没写。不选。

来源：help.gitee.com/repository/release/create、help.gitee.com/account/usage-quota、gitee.com/help/labels/17。

## Backblaze B2

免费 10 GB 存储，Class A/B/C 事务对按量付费用户免费，免费出站为平均月存储量的 3 倍，超出 $0.01/GB；经 Cloudflare、Fastly 等合作 CDN 下载不收出站费。5 版 3 GB 的存储只给 9 GB 免费出站，要靠前面加一层 Cloudflare 才够，那么不如直接用 R2。S3 兼容接口存在，端点格式、单文件上限、公开桶 URL 官方页面没找到。不选。

来源：backblaze.com/cloud-storage/pricing、backblaze.com/docs/cloud-storage-s3-compatible-api。

## Netlify 和 Vercel

Netlify 免费档为信用点制，每月 300 点，带宽 20 点/GB，约 15 GB，硬上限不可续充，每次生产部署 15 点；超出后的处理（是否暂停站点）页面没写。流量远不够放安装包。

Vercel Hobby 含 100 GB 快速数据传输，但条款限定"仅非商业个人用途"，CLI 上传的源文件上限 100 MB。两者都适合放网站，不适合放安装包。产品网站如果有付费入口，Hobby 就违规。

来源：netlify.com/pricing、docs.netlify.com 积分制说明页；vercel.com/docs/plans/hobby、vercel.com/docs/limits、vercel.com/docs/limits/fair-use-guidelines。

## 国内对象存储

三家都要走"实名 + 备案域名 + 自定义域名"这条线，大陆用户体验好是推断，没找到测速数据。

- 腾讯云 COS：新用户个人 50 GB 免费容量包，有效期 180 天，流量和请求次数不在抵扣范围。2024-01-01 之后创建的存储桶用默认域名下载 apk 和 ipa 会返回 403 DownloadForbidden，必须绑自定义域名；绑定自定义域名要求域名已备案。
- 阿里云 OSS：免费额度没查到（官网页只写了"免费试用"入口和付费资源包）。默认域名下 html 和图片会被强制下载，官方建议绑已备案的自定义域名。
- 七牛 Kodo：实名用户每月免费 10 GB 存储、10 GB CDN 回源流量、10 万次写、100 万次读。新建空间的测试域名只有 30 天有效期，每日回源流量限 10 GB，只能测试；正式使用要绑已 ICP 备案的域名。

网站可以放这些厂商的静态托管，但同样要备案。备案要有境内主体，周期和费用本文没查。

来源：cloud.tencent.com/document/product/436/6240、cloud.tencent.com/document/faq/436/102489、cloud.tencent.com/document/product/436/36638；help.aliyun.com 的 0048-00000114、0048-00000100 和 document_detail/142631；www.qiniu.com/prices/kodo、developer.qiniu.com/kodo/8527、developer.qiniu.com/fusion/kb/1319。

## Tauri updater 的约束

- 端点是静态 JSON 即可，文件名不限，必须 https，除非显式打开 `dangerousInsecureTransportProtocol`。
- 整个 latest.json 在比较版本前就会被完整校验，所有平台条目都必须完整有效。`signature` 填 .sig 的内容，不能填路径或 URL。
- `endpoints` 是数组，前一个返回非 2xx 才会试下一个。文档没写重定向怎么处理，所以端点别依赖 302，直接给最终地址。
- 来源：v2.tauri.app/plugin/updater。

## 推荐

首选 Cloudflare R2（自定义域名）加 Pages：免费额度对估算的最坏情况都够，出站不收费，产物和网站同一个账号，CI 走 S3 兼容接口，和 GitHub 的私有化没有耦合。前提是要有一个放进 Cloudflare 的域名，大陆访问需要自己拿目标网络实测一次。

备选公开产物仓库的 Releases 加 Pages：不开新账号，CI 只改 tauri-action 的 `repo` 和令牌，updater 地址格式不变，随时可用；代价是大陆用户仍受 GitHub 访问质量影响。

大陆用户若实测 R2 不理想，再加一个国内镜像作为 `endpoints` 的第二项；这一步需要备案域名，本文不展开。

## 从 GitHub Releases 迁移时旧版本的过渡

已装旧包里的更新地址是 `github.com/Einstellung/Reading-Partner/releases/latest/download/latest.json`，改不了，只能让这个地址继续公开可达。做法：

1. 先发一个新版本，tauri.conf.json 的 `endpoints` 改成新地址，照常签名，产物传到新托管。
2. 把现在的源码仓库改名（例如 `reading-partner-src`），再改私有。改名后 GitHub 文档只说了网页流量会重定向，没说 release 下载链接怎么处理，所以不要依赖重定向。
3. 用 `Einstellung/Reading-Partner` 这个名字新建一个公开仓库，只放 README 和一个 release。GitHub 文档写明在原名下建新仓库会让指向改名仓库的重定向失效，所以旧地址由新仓库接管（这条是按文档推出来的，改名前先拿一个测试仓库走一遍）。
4. 这个 release 里放一份 latest.json：版本号高于所有已发布版本，`platforms.*.url` 指向新托管上第 1 步那个新版本的安装包，`signature` 填对应 .sig 内容。旧客户端读到后按正常流程下载、验签、安装，装上后以后读新端点。
5. 旧公开仓库保留到活跃用户基本都升过级为止，期间不要删这个 release。大陆用户如果原本就连不上 GitHub，旧客户端更新不了，要在网站下载页放新版安装包，让他们手动装一次。
6. 过渡 latest.json 的所有平台条目都要完整有效（校验整个文件），哪个平台暂时没有新包也要填已有的有效条目。
