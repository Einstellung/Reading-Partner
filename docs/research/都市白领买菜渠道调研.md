# 都市白领买菜渠道调研

调研日期 2026-09-17。问题：饮食规划的产出是「一周计划 + 购物清单」，那清单要落到哪里买。中美的都市白领实际在哪买菜、线上线下各占多少，以及哪些零售商留了第三方能合法用的公开数据面。代下单不在范围内，那条路见 [饮食规划调研](./饮食规划调研.md)。

本文区分一手和二手：一手指本次亲自抓到正文或亲自发请求实测的页面，二手指媒体、博客、第三方库 README 的转述。

## 结论

先做离线，两国都是。美国线下仍是主渠道（2025 年约 94% 的人线上线下都买，54% 在主力店「总是到店买」），中国线下更是（2026 年调研里线下菜市场 47.48%、线下超市 40.02% 排前两位）。清单按通用品类分组就能用，不需要任何零售商的数据。

门店这一层用地图 POI 补，不用零售商的门店接口：高德（个人认证开发者可用）管中国，Apple Maps Server API / MapKit JS（每个开发者账号 25,000 次/天）两国都能用。这只解决「你常去哪家店」，不解决货架和商品名。

美国唯一值得接的是 Kroger Public API：自助注册、免费、按门店给价格和货架位（`aisleLocations`），能把清单直接排成「乳制品，7 号货架」。它只覆盖 Kroger 系门店，占美国杂货约 8–9%，所以是加分项不是地基。Instacart Developer Platform 是唯一「清单 → 可下单页」的正规口子，但要申请、官方写从申请到拿生产 key 平均 30–40 天，且不能指定商家、不能按 SKU 指定商品——等清单功能真被用起来再申。Walmart 的联盟 API 要审批且选择性强；Amazon 的 PA-API 5 已被 Creators API 取代，旧接口直接 403。Target、Costco、Whole Foods、Aldi、Trader Joe's 没有任何对外开发者面。

中国线下零售商一个公开数据面都没有——山姆和盒马的官网都是纯 CSR 的 SPA，首页 HTML 里既没有门店也没有商品，更没有结构化数据。所以中国侧的离线支持只能是通用品类清单加 POI 门店标注，商品名对不上门店是已知损失。线上在中国绕不开的是即时零售（2025 年约 9714 亿元，2026 年破万亿），但它没有消费者侧接口（[饮食规划调研](./饮食规划调研.md)），只能做到清单列出来、用户自己去 app 搜。

## 三、美国零售商的公开数据面

| 零售商 | 有什么 | 个人能不能拿 | 验证 |
|---|---|---|---|
| Kroger | Public API：Products（按门店价 regular/promo、`aisleLocations` 如 `Dairy Aisle 7`、fulfillment 的 curbside/delivery/inStore/shipToHome、`snapEligible`）、Locations（门店与 departments）、Cart（写用户购物车，要用户 OAuth）、Identity | 开发者门户自助注册应用，免费 | 官网是 Gatsby SPA，curl 与 WebFetch 都只拿到 `This app works best with JavaScript enabled`，`page-data.json` 也回落到壳。限额取自二手：Products 10,000 次/日、Locations 1,600 次/日/端点、Cart 5,000 次/日、Identity 5,000 次/日（[kroger-api README](https://github.com/CupOfOwls/kroger-api)） |
| Instacart | Developer Platform：`POST /idp/v1/products/products_link`（购物清单页）、`/idp/v1/products/recipe`（菜谱页）、`GET /idp/v1/retailers?postal_code=&country_code=`（按邮编列零售商，只支持 US/CA）。返回的是一个 Instacart 落地页 URL，用户在页面上选店、挑品、加车、结账；支持深链唤起 app | 要申请。官方写「从提交访问申请到 demo 通过并拿到生产 key 平均 30–40 天」 | 一手：[Get started](https://docs.instacart.com/developer_platform_api/get_started/overview)（更新 2026-07-20）、[API keys](https://docs.instacart.com/developer_platform_api/get_started/api-keys)、[Shopping list](https://docs.instacart.com/developer_platform_api/guide/concepts/shopping_list)、[FAQ](https://docs.instacart.com/developer_platform_api/faq)、[Terms](https://docs.instacart.com/developer_platform_api/guide/terms_and_policies/developer_terms)（Last Updated 2024-07-03） |
| Walmart | Walmart I/O 的 Affiliate / Content Provider API：商品标题、图、描述、价格，加带跟踪的链接 | 要审批，「approved content providers」，审批选择性强 | 二手；`walmart.io/docs/affiliate/` 实测 200 但正文是空壳 SPA |
| Amazon | PA-API 5 已不是推荐路径，调用返回 403；替代是 Creators API | 要 Associates 账号，Creators API 的准入条件该页没写 | 一手：[PA-API v5 deprecation](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/paapiv5-deprecation)（`webservices.amazon.com/paapi5/...` 302 到这里） |
| Target | 无公开开发者面。Redsky 是内部聚合平台；旧的 `v2/pdp/tcin` 返回 410，Redsky 端点对非浏览器客户端 403 | 不能 | 商品页实测 200 但整页零个 `application/ld+json`（CSR） |
| Costco | 只有网页门店定位器，无公开 API | 不能 | `costco.com/warehouse-locations` 实测 200，只有 BreadcrumbList/ListItem 两种 JSON-LD，没有门店的结构化数据 |
| Whole Foods | 无公开开发者面 | 不能 | `wholefoodsmarket.com/stores` 实测 200，零个 JSON-LD |
| Aldi | 无公开开发者面 | 不能 | `aldi.us/products/` 与 `aldi.us/stores/` 实测 200，只有 BreadcrumbList |
| Trader Joe's | 商品页直接挡爬；门店页有结构化数据 | 不能 | 商品页 curl 实测 403；`locations.traderjoes.com/ca/los-angeles/` 实测 200，12 段 JSON-LD，含 11 个 `PostalAddress` |

上表「实测」列的抓取都在 2026-09-17 当天做的，用普通桌面 UA 的 curl。

Instacart 那套有三条硬限制，直接决定产品形态（均出自官方 FAQ，一手）：不能把用户导向指定商家（原文 directing users to a specific merchant is not supported，商家由 Instacart 按位置、匹配度、用户偏好选）；不支持用 SKU 指定商品；合作方只能把商品名传过去，匹配由 Instacart 做，关键词会串（查 red tomato 可能返回小番茄）。也就是说它接的是清单，不是精确到某店某 SKU 的清单。

## 五、离线支持具体要什么

想做到「清单按门店分组、再按货架分组」，缺的东西按从易到难：

品类分组不缺数据。生鲜/冷冻/乳制品/干货/调味这一层是自己定的分类学，把菜谱配料映射进去就行，HowToCook 加 USDA FoodData Central（CC0）够用。

货架级只有 Kroger 给。`aisleLocations` 是按门店的真货架描述，这是本次查到的唯一一个第三方能免费拿到的「食材 → 具体货架」的源。别家都没有。

公开的「食材 → 部门/货架」映射数据集只有一个：Instacart Online Grocery Shopping Dataset 2017，约 5 万个商品、134 个 aisle、21 个 department，可从 `instacart.com/datasets/grocery-shopping-2017` 下载——但许可写明仅供非商业用途，不能直接进产品（二手，[Instacart 技术博客](https://tech.instacart.com/3-million-instacart-orders-open-sourced-d40d29ead6f2)）。拿它当分类学参考可以，整库内置不行。

门店专属商品名（山姆的 Member's Mark 命名、Trader Joe's 的自有品牌名）没有任何公开目录。山姆中国官网是 SPA，Trader Joe's 商品页 403。能搜到的只有知乎、什么值得买这类 UGC 的「必买清单」，做不了数据源。

西式食材在中国线下店的铺货情况（羽衣甘蓝、藜麦、鹰嘴豆、希腊酸奶、燕麦、橄榄油、三文鱼、烤鸡），本次没拿到可引用的一手目录。只能确认山姆有燕麦片、酸奶、三文鱼扒、烤鸡这类（UGC 口径），其余查不到。这条进存疑清单，别写进产品假设。

## 六、存疑清单

以下没拿到可信答案，别当成已知。

美国侧：Brick Meets Click 的 2025-12 那条 19% 只从搜索摘要拿到，原始新闻稿正文未抓；FMI 的几项（94%、54%/20%/15%、客单价、「8.9% 按件数」）全部来自 Chain Store Age 转述，FMI 原报告要付费，且 19% 的金额口径和 8.9% 的件数口径是两套统计，没核对定义；2025 年各家的绝对份额是二手摘要，Numerator 原始报告没拿到。Kroger 的限额数字、注册是否真的对个人开放、公开 API 的使用条款（能不能缓存、能不能商用）全部没有一手确认——官网是 SPA，本机没有可用的浏览器（playwright 的 firefox 未安装），要拿准就得真去注册一个账号。Instacart 的申请表是否接受个人开发者、是否收费，文档没写。Walmart Content Provider API 的现行准入条款是二手。Amazon Creators API 的准入条件和费率没查。

中国侧：都市白领单独的买菜渠道切片没有公开调研，本文用的艾媒数据是全国家庭口径；山姆、盒马的数字全部来自媒体转述，沃尔玛财报原文和阿里年报原文没核。高德的配额与计价条款是二手，尤其「POI 数据能不能缓存、能不能在自己的界面里展示」这条没找到条款原文，真要用必须先看高德开放平台服务协议。Apple 的 25,000 次/天同样是二手，且 Apple Maps 在中国大陆的 POI 覆盖质量没验。

数据侧：Instacart 2017 数据集的许可原文（`instacart.com/datasets/grocery-shopping-2017` 未亲自打开）；有没有可商用的「食材 → 货架」公开映射（本次没找到，不等于没有）；西式食材在山姆、盒马、Ole'、Costco 中国的实际铺货，除山姆几样外全部未确认。
