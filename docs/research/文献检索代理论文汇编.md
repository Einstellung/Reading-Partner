# 文献检索代理论文汇编

四篇 2026 年的 arXiv 论文，都在讲让 LLM 参与科学文献检索。作为将来合订本的材料，也给主题搜索的检索与评测设计做对照。2026-10-23。数字逐一对过 arXiv HTML 版正文。

阅读顺序：先读 PaperPilot（2607.00597），它的输入是一篇种子论文加一句话，最接近我们的做法；再读 PaSaMaster（2605.14306），看规划与执行怎么拆、基准怎么建。AutoResearchBench（2604.25256）只读构造 Wide 查询金标的那一节和它的负面结论。LongHarness（2610.13075）略读，不值得通读。

## PaperPilot：Multi-Turn Agentic Scientific Literature Search via Workflow Induction

arXiv 2607.00597，v1 2026-07-01，v2 2026-07-03，CC BY 4.0。代码 github.com/mtilyxuegao/PaperPilot。

输入是一篇锚点（种子）论文加一句用户请求。LLM 从一套有类型的工具里组装出一张可执行的 DAG：关键词检索、引文扩展、并集去重、过滤、打分、取 top-k、LLM 重排、NLI 过滤、证据抽取、建图等（附录表 5 列了 17 个算子）。取源、集合运算、打分由确定性算子做；LLM 只负责规划、定参数、生成关键词和重排。每一轮要么问一个带 3-5 个选项的澄清问题，要么执行工作流；用户的反馈改的是工作流，不只是查询。

训练：底座 Qwen3.5-9B，先在 5,540 条工作流样例上 SFT（五个方向：前驱、后继、同辈、基准、综述），再用 IPO 风格的 DPO，1,733 对偏好数据，被拒绝的一方是故意破坏过的工作流。

基准：留出式，每个案例 6-15 篇隐藏金标，来自引文图信号、人工过滤、LLM 合成和 related-work 队列。多轮模式用 Qwen3.5-397B 当用户模拟器，并做泄漏检查。

数字（多轮）：

- Qwen3.5-9B 加工具集到 PaperPilot-9B：Hit@5 58.0 到 77.0，MRR 47.5 到 59.4，nDCG@10 26.8 到 32.5，Recall@50 34.8 到 40.0；工作流执行出错率 9.5% 到 0%。
- 最强组合 GPT-5.4 + 网页搜索 + 工具集：Hit@5 84.0，MRR 71.8。
- DeepResearch：Hit@5 72.0，约 6.09 美元每案例；PaperPilot-9B 约 0.02 美元。
- 自适应工作流优于固定工作流：GPT-5.4 单轮，网页搜索加工具集 Hit@5 79.5，固定工作流 52.0。注意前者带网页搜索，不是单纯工具集对固定流程。
- 候选池质量在 K=8-10 附近最好，更大的池子引入干扰项：Hit@5 在 K=10 是 0.705，K=20 是 0.660；Recall@50 在 K=8 是 0.411，K=20 是 0.374。
- 人工实验：六名志愿者各五个会话，成功率 74.7%（PaperPilot）对 32.0%（GPT-5.4）对 8.0%（DeepResearch）。样本很小。

可用：种子论文出发的引文扩展，前驱/后继/同辈这套方向划分，LLM 规划加确定性算子执行的分工，用引文图信号造留出式金标的办法，K=8-10 的池子规模。

不能直接搬：算子库是预先定义的；训练依赖教师模型，有教师偏差；主要在计算机领域；用户是模拟的。每个案例只有一篇锚点，多种子的用法没测过。证据抽取算子存在但没有评测，综合不在范围内。论文正文说 PaperPilot-9B 在 MRR 上超过单轮 GPT-5.4 网页搜索，表里是 59.4 对 60.2，只在 Hit@5/10/15 上超过。

## PaSaMaster：Towards Recursive Self-Evolving Agentic Literature Retrieval

arXiv 2605.14306，v1 2026-05-14，v3 2026-06-27。代码 github.com/sjtu-sai-agents/PaSaMaster。

前沿 LLM 担任 Navigator，只做意图理解、核对清单（checklist）和轮间反思；轻量的 Librarian 智能体负责检索、验证和打分。三条检索通道取并集：语义检索、引文网络扩展、从网页到文献库的验证，底库约 1.6 亿篇论文。打分器是蒸馏出来的小模型，对每篇论文按清单逐项打 1-5 分，取平均后与校准过的相关概率合并，再做列表式重排。只有已进入验证过的库里的论文才能被排名，所以来源幻觉为 0（其他 LLM 智能体最高 32.66%，GPT-5.2 为 5.65%）。

PaSaMaster-Bench：244 个任务，覆盖 38 个学科。专家写意图和清单；候选来自三路（带网页的前沿 LLM、PaSaMaster 自己的检索、传统网页搜索）；专家逐条标注，满足全部标准才算相关。指标是 K=20 的 Recall、Precision、F1、NDCG，另报幻觉率和成本。

F1@20：Google Scholar 1.39，GPT-5.2 16.69，Google Scholar Labs 18.87，PaSaMaster 23.00。每次查询成本 0.05 美元，GPT-5.2 是 6.06 美元。

可用：规划与执行分离；按清单逐项打分、全部满足才算相关的标注方式；基准的格式（意图加清单加逐条标注）；幻觉率作为单独指标。

不能直接搬：种子不是输入，只用来合成训练查询。没有单独评估引文扩展，也没有正式的消融表，看不出三条通道各自的贡献。金标候选池的一路来自它自己的系统，论文的局限部分谈了标注者偏差，没有谈这一点。0.05 美元的算法正文没有说明。

## AutoResearchBench：Benchmarking AI Agents on Complex Scientific Literature Discovery

arXiv 2604.25256，v1 2026-04-28。

基准建在 300 多万篇 arXiv 论文上，工具是 DeepXiv 的检索和全文工具，共 1,000 条查询：600 条 Deep（按被模糊化的约束找出唯一一篇论文，约 10% 无解，用来测智能体会不会弃权），400 条 Wide（找出满足一组条件合取的全部论文，平均每条 9.23 个答案）。

Wide 的金标：候选来自主题实体图；正文 2.2.2 说三个 LLM 一致同意才收，人工专家再抽查终集。附录 D.2 写的是对二值“满足”判断做多数表决，抽样 50% 由领域专家复核（精度阈值 75%）。两处写法不一致，读的时候以附录流程为准再对照正文。Deep 的查询要过四关：捷径筛查、智能体压力测试、限时 10 分钟的人工检索、唯一性审计。

评测：ReAct 智能体，最多 30 轮；Deep 看精确匹配，Wide 看 IoU 并报精确率和召回率。

结果：Claude-Opus-4.6 在 Deep 上最好，9.39%；Gemini-3.1-Pro-Preview 在 Wide 上最好，IoU 9.31%。正文称多数模型低于 5%（Deep 上成立）。增加轮数不保证变好；思考模式没有稳定收益，Wide 上通常更差，运行时间更长。全文检索好于开放网页搜索：四个模型平均 5.42% 对 3.97%。

失败模式。Deep：检索漂移（落在相邻论文上，只满足约束的一部分）、证据汇总失败（没有显式跟踪哪些约束已满足，核心问题是对完整约束集验证不足）、候选排序失败、工具调用失败。Wide：过早停止、对约束过于字面而漏掉满足意图的论文、不加约束地扩展候选导致精确率极低（Claude Opus 4.5 的失败里这一类占 85.3%）、领域知识缺口、与金标语义相邻但不是同一实体。

可用：Wide 查询的金标构造（实体图出候选、多 LLM 判定、专家抽查）；让 LLM 智能体包办整个检索循环成绩很差，这是支持“规划与判断交给 LLM、检索交给程序”的反面证据。

不能直接搬：只覆盖计算机领域，只有文本；评测对象是端到端智能体，没有拆开测召回与排序。

## LongHarness：Advancing Agentic Reasoning over 100M-Token Corpora via Stateful Evidence Management

arXiv 2610.13075，v1 2026-10-09。

这是在超出上下文窗口的文档集合上回答问题的框架，不是文献发现系统。两个部件：结论与证据共同演化（结论状态含已确立的论断、有支持的假设、未解决的缺口，缺口决定下一步检索什么）；证据生命周期管理（EvidenceBank 存原子陈述，每条必须引用此前一次读取返回的段落；更正会取代旧条目，撤回会直接删除）。检索是对段落块的 BM25 式词法/正则检索，由 LLM 选查询并维护结论；没有引文图。

基准：OfficeQA Pro V1/V2、AA-LCR、LongBench v2 的 Long 子集。GLM-5.3-Flash 在 OfficeQA Pro 上的精确匹配：V1 从 15.8% 到 60.2%，V2 从 4.4% 到 61.1%；消融掉任一部件损失 3.8 到 10.0 个点。主对比每种设置只跑了一次。

没有召回或排序评测，没有代码链接。可用的只有一点：用未解决缺口驱动下一步阅读，用带来源的论断账本记录结论，对应我们的精读与综合层。通读不值得。

## 对我们的含义

(a) LLM 不该驱动检索循环；它做规划和判断，检索由程序做。2604.25256 是反面：LLM 包办整个循环，最好成绩不到 10%。2605.14306 和 2607.00597 是正面：前者的 Navigator 只做意图、清单和反思，后者的 LLM 规划 DAG、确定性算子执行，成本也比对照的大模型方案低两个数量级以上（0.05 美元对 6.06 美元；0.02 美元对 6.09 美元）。

(b) 召回与排序分开量，先建金标再动检索。2605.14306 的做法是专家写清单、逐条标注、全部满足才算相关；2607.00597 用引文图信号造留出式金标；2604.25256 用多 LLM 判定加专家抽查。三篇的金标都有各自的偏差（自家系统进池、教师模型、模拟用户），用的时候要记着。

(c) 候选池大小有拐点。2607.00597 里 K 超过 8-10 之后，更大的池子带进干扰项，Hit@5 和 Recall@50 都下降。

(d) 以缺口驱动阅读、用带来源的论断账本记录结论，可能对精读层有启发（2610.13075）。这一点在文献场景下没有被测过。
