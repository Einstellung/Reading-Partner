# 开源读论文与读资料项目调研

2026-10-18。起因：主题搜索（[docs/info/88](../info/88-主题搜索.md)）顺着 X 帖子读论文、仓库、PDF、网页原文，反复遇到同一类问题（HTML 空壳、PDF 没读、限流、同一东西多个 URL、读不到却说不清为什么），都是一个一个撞出来的。这次看成熟的开源项目怎么做，只借设计，不借代码。

读法：克隆到 scratchpad 只读（没有运行、安装、构建任何东西），读 README、设计文档和关键源文件；没克隆的用 README 原文。标注：【源码】读了源文件，【文档】读了项目自己的文档，【README】只读了 README（经 WebFetch 小模型摘要，细节可能丢），【推测】我从读到的东西推出来的，没验。许可证列只说我看到的；没打开 LICENSE 文件的标【未核】。

## 结论

我们的读原文链路缺的不是某个站点的读法，而是四件通用的事：读完后判"这到底是不是正文"、失败时给带类型的原因、拿不到正文时换一条路径、同一个东西认成同一个 key。成熟项目在这四件上的做法很一致，并且都不重。

下面十条按"能少撞多少我们现在的失败模式"排序。每条括号里是出处和我们的落点。规模：S 一天内，M 两三天，L 一周以上。

1. 读完后验正文，不信状态码。三层：已知拦截页的结构标记（任意长度）、通用词只在短页面生效、结构完整性（无 `<body>`、可见文字少于 50 字、无内容元素、脚本壳）；再加长度下限、词表式文本（几十万字几乎没有句末标点）、"文本路由里拿到了 PDF 原始字节"（`%PDF-`、`endobj`、`/FlateDecode` 命中两个）。出处：crawl4ai `antibot_detector.py`，设计取向写明"误报便宜、漏报致命"；GPT Researcher `scraper.py` 的 `_looks_like_block_page`、`_looks_like_word_list`、`_looks_like_unextracted_pdf`，命中后当作抓取失败并换 PDF 读法重取；Firecrawl `isLongEnough / isGoodStatusCode / hasNoPageError` 三因子，全部【源码】。落点：`workshop/bindery/gate.ts` 的 `WALL_PATTERNS` 只有 5 条登录墙/JS 墙，补 Cloudflare、Anubis、验证码类和结构完整性，并让 `readArxivHtml`（坑 377 就是同一类）和 `readPage` 都过同一个函数。S。

2. 失败原因做成带类型的记录，不是英文句子。每一步产出 `{step, code, retryable, detail}`，最终失败带"试过哪些步"的列表。出处：Firecrawl `NoEnginesLeftError(fallbackList)` 和 `ScrapeRetryTracker`（按原因分别计上限）【源码】；MinerU 让调用方按 `error.code` 和 `retryable` 分支，不解析消息文本【README】；GROBID 的 `NO_BLOCKS / TOO_MANY_BLOCKS / TIMEOUT / PDFALTO_CONVERSION_FAILURE` 一张表对应"怎么办"【文档】；ArchiveBox 每个提取器的状态是 queued/started/backoff/succeeded/failed/skipped/noresults【源码】；Docling 在 success/failure 之外有 `partial_success`，超过 `document_timeout` 就返回已转的部分，`ErrorItem` 记出错的组件【源码】。落点：`SourceRead`、`OpenedLink` 的 `reason: string`、`ReadOriginals.reasons`、结果文件的 `verify.reason`；第三节给词表。M（触及类型和结果文件格式，要兼容旧结果）。

3. 非 arXiv 的 PDF 也读正文，并且按内容而不是后缀路由。`readPage` 遇到 `whole`（站点直接给 PDF）只带摘要元数据，正文写"not read (whole document)"【源码】；`readPdfText` 已经注入但只有 arXiv 路径用。GPT Researcher 看路径后缀选读法，但对无后缀的机构库下载链接在读到 PDF 原始字节后改用 PDF 读法重取【源码】；Docling 有 `max_num_pages`、`max_file_size`、`document_timeout`【源码】；GROBID 对扫描件明说 `NO_BLOCKS`（没有文字层）而不是返回空【文档】。落点：`verify.ts` 的 `readPage`、`build-live.ts` 的 `readPdfText`，复用 `pdfParts` 和读全文时的"去参考文献"。规模 S。读不到文字层时给 `no_text_layer`，不做 OCR（第四节）。

4. 元数据按标识符走一条梯子：多个提供方并行查、合并字段、拿到所需字段就停；标题匹配要相似度阈值。出处：PaperQA2 `DocMetadataClient`：任务列表按序，每个任务内并行查多个提供方并 `sum` 合并，`is_hydration_needed` 为假就提前停；标题查询用 `title_similarity_threshold=0.75`；单个提供方的超时、404、5xx 都吞成 `None`，不拖垮整条【源码】。GROBID 的"consolidation"：从 PDF 抽出的头部用 Crossref 校正，Crossref 查询速率按每次响应动态遵守【文档】。落点：`readPaper` 现在只有 export API 一个元数据来源，限流时只剩 HTML 的 title 和 Abstract 节；已有 `s2-client`、`openalex-client`，HF `api/papers/<id>`（见 [HF 调研](./Hugging%20Face%20作为检索与发现源调研.md)）也能补。三者按 arXiv id 查，export API 冷却时不再丢作者和日期。M。

5. DOI 和别的学术站点链接映射成同一个标识符。我们的 `eventKeyOfUrl` 只认 arXiv、GitHub、X 三类，源码里 `rank/`、`topic-search/`、`links/` 都没有 DOI 的处理【源码】，所以 `doi.org/…`、出版社页、`huggingface.co/papers/<id>`、alphaxiv、semanticscholar 页都落成 `page`，走通用网页读法，出版社页多半是付费墙或反爬。PaperQA2 的 Unpaywall 提供方按 DOI 取开放获取地址（要 email 参数，超时默认 10 秒）【源码】；Semantic Scholar 的 `externalIds` 和 `openAccessPdf`、OpenAlex 按 `doi:` 直接取作品，我们的两个客户端已在取这些字段【源码】。Zotero translation-server 对"找不到翻译器"返回 501、对多结果返回 300 让用户选【源码】，说明"识别不出就明说"是正路。落点：`eventKeyOfUrl` 加 `doi:`，识别出 arXiv id 就并入 `arxiv:`；`targetsOf` 对 DOI 先查 OA 地址再读，读不到给 `paywalled`，带摘要。M。

6. URL 去重 key 往上收一层。ClearURLs 规则里除了去追踪参数，还有 `redirections`（从 `youtube.com/redirect?q=…` 之类包装链接里取出真实目标），`exceptions` 防误伤【源码，LGPL 数据，只借思路】。trafilatura 对抽出的正文做 simhash 指纹，用来认"同一篇文章在不同 URL"【源码】。我们的 `canonicalizeUrl` 去了追踪参数、排了参数顺序，但保留 scheme 和 `www.`，所以 `http://x.com/a` 与 `https://www.x.com/a` 是两个 key【源码，推测会造成重复件】。落点：`info/rank/canonical-url.ts`：合并 http/https 和 `www.`，加包装链接拆解，读到页面后把 `<link rel=canonical>` 和 `og:url` 当第二个 key；正文指纹放第二步，M。第一步 S。

7. 每个主机一份策略，限额从响应头学。arxiv.py 的 `Client` 内共用一个时钟，重试和失败请求也计入间隔（`_last_request_dt` 在状态检查之前设置）【源码】；Crossref 在响应头给 `X-Rate-Limit-Limit` 和 `X-Rate-Limit-Interval`，带 `mailto` 进礼貌池【文档】；GROBID 对 Crossref 分公共/礼貌/Plus 三档起始并发 1/3/50，再按 `x-concurrency-limit` 调【文档】；OpenAlex 无 key 10 次每秒、每天预算看 `X-RateLimit-Remaining`，每秒的 429 不扣预算【文档】；Semantic Scholar 无 key 共享池（我们的客户端注释已写）。我们的 `host-gate.ts` 只有 arXiv 一组有间隔加冷却，其余走默认 1 秒【源码】。落点：`HOST_GROUP` 改成"主机 → 策略"表（间隔、串行、是否冷却、礼貌身份），OpenAlex、S2、GitHub 的 429 也进冷却，并把响应头里的剩余额度回写（`github-lookup` 已有 `quotaRemaining`，可统一）。S 到 M。

8. 抽取失败时升级读法，不是只换抽取库。Firecrawl 把引擎按 `quality` 排序，每个引擎有"最长合理时间"，上一个超过 `WATERFALL_DELAY` 还没回就并行启动下一个，先成功的赢，被抢的收到 `EngineSnipedError`【源码，AGPL】；Jina Reader 的 `auto` 引擎是 curl 和无头浏览器组合，`X-Respond-Timing` 区分"HTML 即回"到"网络空闲"几档【文档】；trafilatura 先用自己的抽取，再与 Readability 比，正文短或不干净时用 justext 抢救，并且只在比原来长时采用【源码】；Mozilla Readability 内部逐步放松三个标志重试，保留最长的一次【源码】。我们有 Readability 加 defuddle（`readable.ts`）。缺的是：普通 HTTP 读到壳页或拦截页时，在桌面采集端升级到隐藏 webview 读（`workshop/extract/webview-article.ts` 已有，登录态摄入在用），topic search 的 `openLink` 没接。落点：`open-link.ts` 在第 1 条判出 `js_shell` 或 `blocked` 时转 webview。M。注意 88 的第 3 条原则（碰到验证、限流当次停手），升级只限"空壳"，遇验证码不绕。

9. 读多深由证据够不够决定，并给材料标质量档。crawl4ai 的 `AdaptiveCrawler` 用覆盖、一致、饱和三项合成置信度（`0.4·覆盖 + 0.3·一致 + 0.3·饱和`），到阈值 0.7 或增益低于 0.1 或页数到顶就停【源码】；PaperQA2 用 `evidence_k`、`evidence_relevance_score_cutoff`、`answer_max_sources` 三个旋钮，证据先摘要打分再截断【源码】；Scholar QA 不取全文，直接用 Semantic Scholar 的片段搜索，按论文聚合【源码】；MinerU 的定位符 `doc/tier/page/block`、有界分块加"继续读"命令，低档结果在引用前要用默认档重读【README】。我们现在是固定额度：每件 2 份原文，读深第一次 5 件、每天 2 件（`DEEP_READS`），不看缺什么。落点：`compose.ts` 的读深选择改成"帖子的说法里有没有原文没覆盖的"，先不引入嵌入向量，用我们已有的 `claims` 的 `absent` 比例做触发。材料的 `depth` 字段（abstract/head/full）已存在，可以并入第 2 条的状态。M，需要先定设计，见第五节。

10. 抓取前的资源上限和地址安全。Docling `max_num_pages / max_file_size / document_timeout`【源码】；GROBID 的 `TOO_MANY_BLOCKS / TOO_MANY_TOKENS` 与 pdfalto 的内存和超时上限【文档】；trafilatura 的 `ssrf_protection`，连接时校验对端 IP、状态码强制重试表 `FORCE_STATUS`、`Retry-After` 封顶 `MAX_BACKOFF`【源码】；GPT Researcher 的 `validate_url`：只许 http/https，拒绝解析到私网、回环、链路本地、元数据地址的主机，并自己写明有 DNS 重绑定窗口【源码】。帖子里的链接是不可信输入，桌面端读它们等于替陌生人发局域网请求。落点：`build-live.ts` 的 `fetchBytes` 和 `fetchText` 前加一个纯函数 `checkReadable(url)`（scheme、主机是 IP 字面量或 `.local`/`localhost`/私网段），并给 `fetchBytes` 加字节上限、`readPdfText` 加页数上限（先读 PDF 头部页数）。S。

没排进前十但值得记的：读结果落盘缓存，按规范 id 为 key，页面用 ETag 或 If-Modified-Since 复核（crawl4ai `cache_validator.py`：HEAD 带条件头得 304 即新鲜，否则比 `<head>` 指纹；Jina 的 `X-Cache-Tolerance`）。我们现在只有 30 分钟的 arXiv 内存缓存（`fetch-memo.ts`），每天的增量会重读同一批论文和仓库。GitHub README 现在串行试四个文件名（`readRepo`），`GET /repos/{owner}/{repo}/readme` 一次就回，这一条是我的判断，不出自这些项目。网页元数据用"每个字段一张有序规则表，第一个命中就停"（metascraper【README】），我们的 `readPageMeta` 可以对照：`citation_*`、JSON-LD、OpenGraph 的优先级是否明确。

## 二、对照我们的代码（读到的事实）

- `readPaper`：先 export API 取元数据（限流时没有），再读 arXiv HTML（坑 377 的判法：200、正文超过 8000 字、title 不是 "Untitled Document"），HTML 没有且没摘要时才读 PDF 文字层；`reason` 是拼出来的英文句子。
- `readPage`：经 `openOriginal` 走 86 的 `open`；站点直接给 PDF 时 `whole` 非空，正文不读。
- `targetsOf`/`readOriginals`：每件 2 份，论文和仓库排在网页前；X 帖子读全文后交出外链补读（坑 657）。
- `host-gate.ts`：只有 arXiv 三个主机有"一次一个、从回来算 3 秒、429 后冷却翻倍"；其余主机默认 1 秒间隔，没有冷却（坑 497、502）。
- `gate.ts`：拒绝原因 `empty / too-short / login-wall / no-adapter / unreachable` 五个，登录墙只匹配 1500 字以内的短页。
- `eventKeyOfUrl`：arXiv、GitHub、X 三类加规范化 URL；`canonicalizeUrl` 保留 scheme 和 `www.`。
- t.co 展开在 `info/x/outbound.ts`，读 301 的 Location，不跟随。

## 三、建议采用的失败分类

只在项目给出了依据时才列。每类要有 `code`、`retryable`、`scope`（url / host / global）和给用户看的一句话。

| code | 何时 | retryable | scope | 依据 |
|---|---|---|---|---|
| `not_found` | 404/410、DOI 不存在、仓库不存在 | 否 | url | PaperQA2 `DOINotFoundError`；Zotero 对 404 回 400 |
| `no_such_format` | arXiv 没有 HTML 版（200 空壳或 404）、没有开放获取 PDF | 否 | url | 坑 377；ar2md 的 404 才退 ar5iv |
| `blocked` | 拦截页标记命中、403/503 加 HTML | 否（当次停手） | host | crawl4ai、GPT Researcher、88 第 3 条 |
| `login_wall` | 登录墙、付费墙 | 否 | url | `gate.ts` 已有；付费墙另给 `paywalled`，带摘要 |
| `js_shell` | 脚本壳、可见文字过少 | 可升级到 webview 读一次 | url | crawl4ai 结构完整性、`gate.ts` |
| `too_short` | 低于长度下限 | 否 | url | `gate.ts`、GPT Researcher 100 字、STORM 150 字 |
| `no_text_layer` | PDF 没有文字（扫描件） | 否 | url | GROBID `NO_BLOCKS` |
| `wrong_content` | 文本路由里拿到 PDF 字节、词表、列表页、软 404 | 换读法重取一次 | url | GPT Researcher |
| `rate_limited` | 429，带 Retry-After 或已知额度耗尽 | 是，过冷却 | host | 坑 497、502；OpenAlex 每秒 429 不扣额度 |
| `cooling_down` | 主机在冷却，没发请求 | 是，过冷却 | host | `HostCoolingDownError` |
| `upstream_error` | 5xx、DNS、TLS、连接失败 | 是，退避 | host | trafilatura `FORCE_STATUS`；GROBID 的 503 |
| `timeout` | 超过该步时限 | 视步骤 | url | Docling `document_timeout`、Firecrawl 每引擎时限 |
| `too_large` | 字节、页数或 token 超上限 | 否 | url | Docling、GROBID `TOO_MANY_*` |
| `unsafe_url` | 非 http(s)、私网地址 | 否 | url | GPT Researcher、trafilatura |
| `unsupported` | 音视频、压缩包、不认识的类型 | 否 | url | Firecrawl `UnsupportedFileError` |

成功侧加一个状态 `partial`，并写明覆盖了什么：只有摘要、只有开头 8000 字、被上限截断、API 元数据缺失。Docling 的 `partial_success` 是这个意思；我们的 `depth` 和 `body` 字段已经在表达，但没有归并成统一状态。

每一步记一条：`{step, url, code | ok, ms, bytes}`，一件事的读法是这些步的列表，结果文件里存下来。读不到时，"试过 arXiv HTML、PDF、摘要，各自为什么没成"一眼可见，不用再从日志里拼（Firecrawl `fallbackList`、Scholar QA 的 `event_traces`）。

## 四、不该照搬的

- 重 ML 栈：Docling 的版面模型和 VLM、MinerU、Marker、Nougat。要 GPU 或大模型权重，跑在手机上不现实；我们的 PDF 读法是文字层，扫描件明说读不到。Nougat 权重是 CC-BY-NC，Marker 权重有商用门槛，MinerU 的许可证改过，都不能进。
- 服务端设计：GROBID 的 Java 服务、Firecrawl 的队列加代理池加 fire-engine、ArchiveBox 的 Django 加 worker、Zotero translation-server 的 Docker。我们是本地应用，没有常驻服务。
- 许可证陷阱：Firecrawl、SingleFile、Zotero translation-server 和它的翻译器库都是 AGPL；ClearURLs 规则 LGPL。只看设计，不拷代码、不拷规则数据。
- 绕反爬：Firecrawl 的 stealth 代理、crawl4ai 的代理和反检测。88 第 3 条是遇到验证当次停手，这些和它相反，也有被封号的风险。
- 把 URL 交给第三方转成正文（Jina `r.jina.ai`、Firecrawl 云服务）：帖子里的链接会被一并发出去，并且依赖外部可用性。
- 嵌入向量驱动的自适应停止（crawl4ai 的 embedding 策略）：要嵌入模型。先用统计版的思路。
- 站点翻译器库的做法（几百个站点各一份脚本）：维护成本高，我们已有"站点适配器 + 通用读法"，只对读得多的几个源加适配器。

## 五、未决问题

1. 第 9 条读深的触发条件要用户定：固定额度（现状，可预测）还是按"帖子说法没被原文覆盖"自适应（省请求，但每次读的量不固定，进度条和 ETA 要改）。
2. 第 8 条升级到 webview：topic search 的 run 在 pi-durable 里只有桌面采集端认领（88），升级是否要新增相位或放在 `build` 里同步做；以及手机端没有 webview 时 `js_shell` 怎么呈现。
3. 第 5 条付费墙：只给摘要时，是否在书里标成"只读到摘要"，还是不收这件原文。
4. 开放获取服务（Unpaywall、Crossref）是否接入：两者都要带联系邮箱，和我们"不把用户信息发给第三方"的立场冲突，用项目通用邮箱还是不接。
5. 第 6 条正文指纹去重要不要做：同一篇文章在多个 URL 的实际频率没有数据，先做 key 合并，跑几期再看重复率。
6. 我没验证的假设：HF 或 S2 的元数据在 export API 冷却时能补全到什么程度（需要对近期论文抽样）；crawl4ai 的拦截标记在我们常读的站点上的误报率（需要拿一批真实帖子外链回放）。
7. 本次没有任何项目被实际运行；所有"做法"来自读源码和文档，行为没有复现。WebFetch 摘要里读到的 README 细节（Marker、MinerU、Nougat、metascraper、SingleFile）可能有遗漏，动手前要回到原文核一遍。
