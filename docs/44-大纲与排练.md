## 排练的对象是大纲

不是 PPT。做 PPT 不在这个 app 里——在外面做，做完了讲，app 不需要看见那份文件。最终可能根本没有 PPT，就拿着这份笔记讲。

retell 产出的是章的决定（`PlanDecision`：这章讲不讲、贡献什么、哪张图）。讲的时候需要的是段。两者不是一回事，中间隔着一次编排。

判据一句话：把"正确的解释"变成"你的解释"。念别人的话在台上会露馅，排练就是防这个。

## 大纲的形状

两层。

**讲这一层**，一份，管全场：主线一句、脊梁、听众是谁、全场约定（如"不出现英文缩写"）、不碰的。听众那条不是装饰，它是老师傅的量尺。

**段这一层**，一份笔记，按块存，一块是一段 markdown。块有 id 是为了同步能按块合并、AI 能说"改这一块"；读的时候看不见块的边界，它就是连着的一篇。

段和章必须解耦：开场和收尾不属于任何章；一章可以裂成六段；两章可以并成一段。

一段上的字比幻灯片少，素材一样多。听众要读完整的句子，讲的人只要够把话勾出来的钩子，剩下现场发挥。公式和图直接写在块里，原样渲染，不缩略——技术讲里那个式子是你指着讲的东西（`$$` 块走 KaTeX，`[fig:N]` 走 FigureCard）。笔记和 retell 底下都没有阅读器，图没地方跳，点一下就地放大成浮层，关掉回原位。

一块上到底写多少、块的边界划在哪，不预先定。讲过才知道，笔记本身就是长出来的。

## retell 是笔记的前站

三段，阶段由笔记自己的状态决定，不由章的决定决定。

开场：把读者自己的来路还给他，然后让他把整条路从头到尾讲一遍，一分钟版本，不看书。AI 不许先摆脊梁——它摆好了问"是这副吗"，读者点个头，成本为零，什么也没证明。它可以说材料是哪几本、覆盖多少，不许给主线、不许点站名。

宏观：聊到读者能不靠提示按顺序点出各站、说清每站把什么变成了什么。答得薄就开书把那一段走一遍，走完读者要给回来。这一段谈成了才写 `set_talk_spine`，用读者的话。这是宏观阶段唯一的落盘。

逐站：有了 spine 之后一站一站深入，顺序看宏观暴露出来的洞，不看章号。每站读者先讲，薄了开书，读者给回来，然后才 `write_talk_segment` 落一块。AI 不许写读者没讲过的块——这条同时让笔记成为进度记录：有块就等于那一站给过了。

没有单独的编排阶段。`isArranging` 删掉，五个写笔记的工具第一轮就挂上。段与章解耦本来是编排要解决的，站本身就不是章，问题在源头没了。

章剩两件事：答得薄时知道翻哪几页，以及最后审计"你这条线没碰第 6、7 章，微调那半不讲了？"。`record_chapter_decision` 留着，由站消费到哪一章顺手记哪一章，一串不要的章（前言、附录）允许一次关掉。它不再是队列——工作记录里那句 `Next up: chapter N` 每一轮都在把对话推回章的行军，读者改道活不过一轮。

所以功能只有两个：retell 聊出笔记，rehearsal 讲穿笔记。

## 排练：一份笔记

按下去调出整份笔记，连续滚动，对着讲；关掉，回聊天界面和老师傅聊这一遍讲得怎么样。排练当中 AI 不出声。

讲的时候什么都不用按。没有翻页，没有当前段，没有跳转列表——想哪里停就哪里停，想从哪里开始就滚到哪里开始。

页面绝不自己滚。抬头看观众的时候页面动过一次，就再也找不回位置了。

停下来就是交卷。不需要判断该不该打断，也不需要流式转写。

通关和拷问不是两个模式。要练一口气就从头讲到尾不停，要抠某一段就只讲那一段讲五遍，同一套机制。

哪句话在讲哪一块不再记录。陪练手里有整份笔记和逐字稿，你说出口的话本身比滚动位置更能说明你在哪。代价是交卷的时候必须说清楚这一遍未必讲全、没讲的是故意跳的，否则它会按整场来评。

## AI 是陪练

老师傅听新手做报告，不是白纸。它读过这本书，装傻只能说"我没听懂"，老师傅能说缺了哪句、该怎么补，也会截住问"你凭什么这么说"。

风险是懂行的人会自动补全你没说的那句，然后觉得你讲清楚了。两个判据挡它：一个非技术听众听到这里会不会掉队（听众写在讲那一层里），以及这段话是你的还是背下来的正确答案。

排练之后那轮对话的产物不是评语，是对笔记的一次修改——五个写笔记的工具在 `src/reading/talk/tools.ts`，编排和陪练两侧都挂着。它不许替你把一块改写成它自己的话：那样又变回"正确的解释"了。

## 已经做完的怎么处置

段事件不再发。`build.ts` 一行不动，老的 run 文件照常读，没有段事件的一遍就是一整页逐字稿。桌面录音的切只剩 60 秒兜底（`segmented-source.ts`），原本翻页那一刀没有了。run 索引和逐字稿一遍一个文件（`runs/<rehearsalId>/<runId>.json`）全部保留，`REHEARSAL_VERSION` 和 `RUN_LOG_VERSION` 都不动。

`TALK_OUTLINE_VERSION` 也不动，磁盘上的键还是 `segments`。老字段（title / cues / material / status / act / callback）在读的时候折成 markdown，幂等，不写回——已经同步到设备上的那份不用重灌。

`Rehearsal` 上大纲必填，`deckFile` 已删；run 上那个 2026-08-26 也删了。

retell 旁边那条侧栏整个删了（2026-08-26）：章的表和挂在它底下的排练历史一起撤，retell 只剩对话。run 照常记，`REHEARSAL_VERSION`、`RUN_LOG_VERSION`、`build.ts` 和 run 的存取一个字没动，交卷仍然把这一遍交给陪练。

`src/reading/slides/` 已删（2026-08-26）：生成管线、模板、图片中转、retell 头部的 Deck 按钮、topic 里的「Open deck」和 Settings 的插图卡一起走，`slides-plan` 这个 parse site 也撤了。[14](./14-PPT.md) 和 [29](./29-读到slides这条路的现状.md) 的底账留作历史。

从外面带一份 deck 进来排练那条入口也删了（2026-08-26）：`import-deck.ts`、`RehearsalSection` 的 Bring in a deck、`readRehearsalDeck`、宿主桥（`DECK_PROTOCOL`、`readDeckSignal`、`checkDeckProtocol`、`slideEvent`、`isPageTurn`、`withSlideEvent`——入参都是 deck 报上来的那条消息），以及 run 上的 `deckFile` 和删排练时清那份 HTML 的分支（`importedDeckFile`、`REHEARSAL_DECK_DIR`、`isImportedDeck`）。图片中转的 key（`credentials.json` 的 `imageGen` 和三个存取）没人读了，一起删。盘上剩的 `slides/**` 和 `rehearsals/**` 由本人手工清。

`REHEARSAL_VERSION`、`RUN_LOG_VERSION`、`TALK_OUTLINE_VERSION` 仍然一个都不升：少一个字段不用升版本，没更新的设备读得了短一截的记录，这一版读到旧记录里的 `deckFile` 只是跳过。

只有 deck 没有讲稿的旧排练：`normalizeRehearsal` 早就按「大纲必填」把它读成 null，列表里不出现也开不了，文件留在盘上不动。从 deck 导入建出来的那种带一份空讲稿，能开，屏幕上写「这场讲还没有段落」。

## 缺口

- 笔记只能通过和 AI 说来改，app 里不能手改。
- 站和块的对应靠块的首行认（`plan.ts` 的 `blockForRib`，归一化之后做包含匹配，门槛按列宽算）。认错了工作记录会说某站没给过，模型看得见块列表，不致命。
- 陪练看不见书：`reading/retell` 已经 import `reading/rehearsal`，所以 rehearsal 不能反向拿 retell 的读书工具。要给它书得在 ui 层把材料当数据传进去。
- 交卷之后自动跑一轮陪练，没有闸。讲砸了想直接重来也会花一次调用。
- 笔记怎么交给外面做 PPT 没定。
- 桌面仍然没有流式转写（[27](./27-实时语音.md)），但不再卡这个功能。
- iOS 那条 `dictated-source.ts` 没在真机上跑过（坑 158）。
