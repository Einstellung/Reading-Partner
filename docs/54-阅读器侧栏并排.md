# 54 阅读器侧栏并排

## 断点

`lg`（≥1024px）以上，阅读器左侧那块（大纲 / 标记 / 备课）是排在页面旁边的一列，280px 宽，没有背景遮罩，页面区跟着变窄。以下仍是今天的抽屉：300px（上限 85vw）盖在页面上，压暗背后，点遮罩、按 Esc、点顶栏按钮都能收。

判据是宽度不是设备。抽屉存在的理由是没有富余宽度可分：它借走阅读区的宽度，用完还回去。一旦 280px 可以直接从页面里扣掉而页面不至于变成一竖条断词，借就是错的交易——那一列可以一直在，大纲也就不再是「打开、看一行、丢掉」的东西。

1024 取的是 Tailwind 的 `lg`，所以形态切换整个由 `Sidebar.tsx` 上的变体完成，没有 JS 参与布局。JS 只拿这个断点判两件 CSS 说不了的事，都在 `ui/components/reader/sidebar-column.ts`：跳章要不要顺手关掉这块，以及开合状态值不值得记住。

## 抽屉为什么留着

窄屏下这块面板一旦并排，页面就没有能读的宽度了。而且抽屉的遮罩是它自己的一部分：遮罩吃掉页面上的滑动，所以点大纲跳页必须同时关掉抽屉，否则落在一张手指划不动的页上。并排那一列不盖任何东西，跳页就不关，读者在列表里的位置留着——同一份 `Sidebar.tsx`，两条行为由 `closesOnNavigate()` 分开。

Esc 同理：它取消的是「盖住了什么」的东西，所以只收抽屉。

开合状态按设备记在 localStorage（`reader-sidebar-open`），和纸色开关一个路子，同步读，首帧就是上次留下的布局。只记并排那一列：抽屉记住「开着」就等于每次开书先给一张压暗的页，没人会真想要。跨断点时重新判一次——变宽采用这台设备记的，变窄一律收起。

## 交接给引擎

不用交接。并排那一列开合改的是阅读器容器元素自己的宽度，引擎的视口插件本来就拿 ResizeObserver 盯着它，缩放模式还是 FitWidth，所以重排是引擎自己做的。实测 1194 宽的窗口上，页面从 1193px 变成 914px，和一开始就并排渲染的那次一模一样。`wire-engine.ts` 里那个 `onViewportResize` 只管翻页模式，continuous 不需要它。

代价是这一列不能有宽度动画：过渡的每一帧都是一次视口变化，引擎回一次重排，缩放插件 150ms 后再回一次（坑 57），一步能到的位置会被重排十几遍。所以 `lg` 上显式关掉 transition。

## 桌面色

页与页之间那圈底色是 `--desk`（默认 `#edece5`，开纸色时 `#e8e2d3`）。引擎按 `var(--desk)` 取它，纸色开关不重新光栅就把桌面一起暖过去。纸张仍是白的，页边阴影跟着换成暖灰。细节见 docs/42。

## 页码标签：不做

顶栏想显示书自己印的页码（`p. 101 of 333 · book p. 99`），做不了，不值得为它加一条 pdf.js 通道。

PDFium 有 `FPDF_GetPageLabel`，但它只出现在 `@embedpdf/pdfium` 那份原始 cwrap 签名表里，EmbedPDF 的引擎层和 models 层都不调用、也不导出。而引擎跑在 worker 里，宿主手上只有 `PdfEngine` 接口，要拿这个值就得自己接一条 worker 通道。

现在 `ViewStats.pageLabel` 有这个字段，但 `EmbedReaderPane` 填的是 `String(pageIndex + 1)`，也就是下标本身；`convert.ts` 里的 `pageLabel` 是标注字典里存的那个，不是文档的页码树。所以顶栏保持 `101 / 333`。
