## deepseek-harness（源码 dd6322d，release/dsh-0.1.2-alpha.3）

没有记忆系统。171 个文件命中 memory，全是 `MemoryVfs` / `MemorySettings` 这类内存实现和测试替身的命名。没有 embedding，没有跨会话事实库，工具表里没有写长期知识的工具，也没有任何离线批处理——无 cron、无夜间任务，最接近的 `compactNow()` 是"两轮之间的 agent 维护"，仍在会话内。

可用的四样：

**遮蔽而非删除。** 压缩把一段历史换成摘要，用 `surfaceOp: replace`，原始事件永远留在 append-only 日志里，只是不再进模型。配套警告：合并和遮蔽是一对，只搬合并不搬遮蔽，可寻址的记录会变成一坨不可逆的正文。

**归档判据。** 在一份 skill 文件里而不在产品代码里，四个生命周期目录（proposed 52 / implemented 1264 / rejected 20 / archived 341）。第一句是"逐条语义判断，字数和年龄是发现线索，永远不是归档判据"，并用带字数的标定样例打掉"长的重要"这个直觉：归档的例子 1498 字和 920 字，保留的例子 248 字和 334 字。保留条件是一张清单——这条里还写着归属边界、负面保证、持久格式语义、安全规则，或者"什么条件下要重新考虑"吗。硬规则是"不许朝着配额归档"。`## Alternatives considered` 是强制段落，理由是"一个不记录它击败了什么的决策，等于邀请重新翻案"。归档区单向冻结，只准加一行 `Archived: YYYY-MM-DD`，由 append-only 哈希清单和一个校验脚本钉死。

**写入时做取代审计，不攒到批处理。** 新增一条时当场判断是完全取代还是部分取代，完全取代的当场归档，部分取代的保留并交叉链接。调和到我们这边：它的写入者是人、看得见全局，我们的是只看窗口的蒸馏 pass，所以白天那趟加一步——写观察前先检索一次找近重复（6ms），撞上就更新或交叉链接；需要跨多条归纳的留给 dream。白天不是不整理，是只做一跳能确定的。

**矛盾用追加一句作废，不改旧的。** 指令文件被删就追加"这个文件的指令不再适用"，改了就追加"这个文件在加载后变了，用下面的内容代替之前那份"。旧内容原封不动，靠后面一句话作废。触发不是轮询，是 agent 的 fs 工具摸到那个目录时才塞进 inbox。

工程细节照抄：压缩锁写在日志里，`compaction/start` 先落盘，摘要和替换全部落地之后才写 `compaction/end`。崩在中间留下有 start 无 end 的孤儿锁，可检测；而不是留下一个谎称完成的 end。dream 照这个做。

别抄它的检索层：SQLite FTS5，分词器是裸 `unicode61` 无 CJK 处理，排序 `match_count DESC, document_length ASC, time DESC, seq DESC`，无语义无时间衰减。含义是 FTS5 不是我们的升级路径——上一个"正经搜索引擎"对中文语料会比现在这套带双字切分的手写 BM25 更差。

其他常数，记着但不抄：compaction `thresholdRatio 0.8` / `retainRatio 0.16`，工具结果剪枝 8192/4096/1024，spill `maxInlineBytes 50000`，token 估算 `chars/4`，跨进程锁等 2000ms 退避 20→200ms，会话内提醒最小间隔 300 秒。压缩摘要故意用对话本身那个模型而不是便宜模型，因为摘要指令是重放完整对话之后的最后一条 user message，是上一次请求的严格前缀，provider 的 KV cache 能复用。

## 另外八家

按时钟跑的夜间批只有一个先例：OpenClaw memory-core 注册 `0 3 * * *`，`sessionTarget: "isolated"`。其余全挂前台事件——Codex 挂根会话启动，Letta 挂压缩事件或每 5 个前台回合，LangMem 是防抖定时器，Generative Agents 是重要度预算耗尽（每条新事件按模型打的 1–10 分扣，扣到 0 触发；空闲事件硬编码成 1 分，所以"没事可做"是算出来的不是探测的）。cognee 没有调度器。

Codex 有完整的两阶段离线记忆管线。

### 抄这些

**结局枚举决定水位线。** Letta 的整合只有三行：只有 `merged` 和 `no_changes` 推进"已处理到哪条"，`parent_dirty` / `merge_conflict` / `dirty_uncommitted` / `failed` 都不推进、下次重试。叠上 OpenClaw 的三时间戳（`lastLightAt` / `lastRemAt` / `lastRemConsideredAt`），把"考虑过没选中"和"从没考虑过"分开。几十行，投入产出比最高。

**判脏用物化后的字节比对。** Codex 第二阶段把派生输入物化成文件再 diff，字节没变就零模型调用退出。比数据库水位线更适合我们：别的设备手改过的记录跟新增走同一条通道；删一行和加一行在 diff 里一样，而这三种情况都该重新考虑。

**模型只交下标和动作，正文由代码算。** OpenClaw 在代码里算出这条候选将来的完整一行，提示词要求逐字复制，再用多重集减法校验（旧集合 − 被替换的 + 新写的 == 模型返回的），改一个字整批拒绝、降级 append-only。Letta 的 voice sleeptime 更极端：模型只交 start_index / end_index，正文由代码从 transcript 切。mem0 把 UUID 换成 0..9 的下标交给模型，注释写着 anti-hallucination。

**失效标记读侧必须真的用。** Zep 的双时间线记得最认真，但失效边仍留在向量和全文索引里、所有检索配方都不过滤 `expired_at`，整套记账在默认读路径上只是装饰。验收标准不是"字段写进去了"，是"昨天会被筛进来的一篇文章，今天因为那条 concern 失效而被筛掉"。

**读时衰减可以先接进去关掉。** cognee 的 `0.5 + (w - 0.5) * (1 - beta)^idle`，beta 默认 0.02，idle 用回合计数不用墙钟，不改任何行。中性值和零影响精确等于 no-op，先证明它什么都不改再打开。

**候选集本身持久化。** LightMem 在模型调用之前就把每条记录的 top-10 候选 `{id, score}` 写回自己的 payload，且候选只能来自更早的时间戳。队列为空 = 可见的"看过，没找到对手"。

### 明确拒绝

**全量重写产出集合、把文件交给模型自由编辑。** Codex 是最坏版本：子 agent 自由编辑，后置条件只有三条体检（记忆文件是普通文件、摘要首行是 `v1`、没有新符号链接），一个决定"清理一下"把库砍成存根的 agent 能全部通过；然后 baseline 重置删掉 `.git` 重新 init 单 commit，零回滚。

**窗口和每晚上限。** 先例常数是给 10³–10⁵ 条的库调的：Codex 每次抽 2 条 rollout、扫 5000 行、喂 256 条整合；OpenClaw 每晚 240 条消息、证据池 512 条；Letta 每次 5 个会话每会话 50 回合。我们 140 条、全扫 6ms，全读，不要窗口。"每主题 12 行导致 74% 不可见"就是照抄这类上限的结果。

**让排名表达不出"没有相关的"。** Generative Agents 把相关度归一化到 [0,1]，最佳匹配永远 1.0；A-MEM 纯 top-5 截断无相似度下限。实测后果是一天内 61% 的反思条目是既有条目的逐字重复，同一句被写 22 次，推导深度堆到 10。共享锚点那个候选池本身安全（是盘上事实不是相似度），但往 BM25 邻居走的那一步必须有绝对阈值，"一条都不够格"是合法的一晚。

**纯 append-only 不带 supersede。** mem0 OSS 花近千词教模型产出 `linked_memory_ids`，代码解析出来就丢，去重只在付费版；模型跑完只做体检就落盘。

### 先例答不上来的五件

- 跨主题的候选对怎么产生。所有先例的候选都来自向量近邻或一跳邻域；唯一为"词面不像但该在一起"设计的是 Generative Agents 的 focal point，实测结果就是那 61% 的重复。
- concern 这个对象根本没有先例。所有系统产出的都是事实、偏好或技能，没人产出"要盯的事"，lapse 判据没得抄。
- 3 点的生产者和 5 点的消费者之间的契约。没有先例的产出带下游 deadline。
- 多设备。全部先例单机，我们带三方合并的 markdown 存储走在前面。
- 140 条这个量级该省掉什么。

### 一个警示

MemoryBank 的遗忘曲线实现写成 `math.exp(-t / 5*S)`，Python 解析成 `exp(-t*S/5)`，被召回十次的记忆遗忘速度快十倍，跟论文和它上面三行注释都相反——而这个函数会不可逆地删用户数据。
