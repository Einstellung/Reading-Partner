# 81 多语言

设置里一个「语言」选项同时决定界面语言和 AI 输出语言。字段仍是 `aiLanguage`（`src/platform/app/settings.ts`），存盘的键不变，老数据照常读。支持九种：en、zh-CN、ja、ko、es、fr、de、pt、ru。

- 选「自动」：界面跟系统（`navigator.languages` 按顺序取第一个能匹配的主语言，中文不分简繁都落到 zh-CN，都不匹配落到 en）；AI 行为不变，仍跟用户书写的语言。
- 选某种语言：界面和 AI 都用它。
- `<html lang>` 保持 `zh`，只有界面是日语或韩语时改成 `ja`/`ko`。它决定书页正文和 AI 回复里汉字用哪套字形，不能跟着英文界面变成 `en`。
- pt 按巴西葡萄牙语写。

语音交互这一轮不做：听写语言仍是独立的两项设置，不跟「语言」走；STT/TTS、语音通话和按住说话的界面文案不迁。记在 [north-star/voice-i18n](../north-star/voice-i18n.md)。设置页里三张语音卡片的静态标签已经走 t()，行为没动。

## 模块

`src/i18n/`，登记为 platform 层（`tests/layering.test.ts`），所以 ui、领域、capability 和 `platform/sync` 都能 import。不用第三方库，九种语言的文案全部静态打包。

- `locale.ts`：当前 locale 的模块级 store。`applyLanguageSetting(aiLanguage)` 由 `useShellBootstrap` 在设置读入和每次改动时调用；`getLocale()`、`setLocale()`、`subscribeLocale()`；`matchLocale(tags)` 做系统语言匹配。
- `translate.ts`：`t(key, params?)` 读当前 locale，给 `.ts` 里的错误、toast 用；`translate(locale, key, params)` 是不带类型的底层；`formatNumber`、`formatDateTime` 按当前 locale 格式化。
- `react.ts`：`useT()` 返回绑定到当前 locale 的 t，组件里用它，换语言立即重绘；`useLocale()`。
- `messages/<area>/`：一个区域一个目录，`en.ts` 是源（`as const`），其余八个文件用 `Translation<typeof en>` 标类型，少键多键都过不了 typecheck。`index.ts` 把九个拼成一个 area。
- `areas.ts`：区域注册表，一个区域一行。

key 是 `<area>.<name>`，两段都受类型检查。英文里有 `{name}` 的 key 必须传 `{ name }`；复数的值写成 `{ one, other, ... }`（按 `Intl.PluralRules` 的类别），必须传 `{ count }`。缺译时回退英文，英文也没有时原样返回 key。

`tests/i18n/catalogs.test.ts` 检查：每个 locale 的键与英文一致、译文不丢也不多占位符、复数覆盖该语言整数会用到的类别、没有空串。

## 加一条文案

1. 在 `src/i18n/messages/<area>/en.ts` 加 key 和英文。
2. 其余八个文件补译文（typecheck 会指出缺哪个）。
3. 组件里 `const t = useT();` 然后 `t("<area>.<key>")`；`.ts` 里直接 import `t`。

## 加一个区域

1. 建 `src/i18n/messages/<area>/`，照 `settings/` 放 `en.ts`、八个译文和 `index.ts`。
2. `src/i18n/areas.ts` 加一行。
3. `tests/layering.test.ts` 的 LAYER 表加 `"i18n/messages/<area>": "platform"`。

译文写法：界面用语跟各平台惯例（iOS/macOS 的术语优先），短，不逐字对应英文长句。品牌名和产品名不译。语言选项里各语言用本族语名，不翻译。AI 的 prompt 保持英文，不进目录。
