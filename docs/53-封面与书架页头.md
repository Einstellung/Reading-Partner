# 封面与书架页头

## 页头

书架和主题页共用一套节奏：eyebrow（11px 大写 tracking，`text-faint-foreground`）、`font-display` 标题、一行 `text-muted-foreground` 副文案，右侧一个实心墨色按钮（40px，`Button` 默认变体）。常量在 `shelf/cardStyles.ts`（`PAGE_HEADER` 一组），两个页面都从那里取。

书架标题 30px，副文案是「N topics · M books」，书按 book id 去重，没有 id 的按路径算。主题页标题保持 22px，副文案沿用原来的 `topicHeaderLine`。

「+ New topic」和「+ Add PDF」从网格里的虚线卡片挪到页头。虚线卡片只剩 `info/Vestibule.tsx` 在用。空书架不显示页头按钮，建主题走空状态那一个按钮。「+ Add PDF」只在 Materials 分节出现。

## 封面

`reading/covers.ts`：第一页 rastered 成 JPEG，落在 AppData 的 `covers/<bookId>.jpg`。bookId 就是全文缓存那个内容哈希，`FileRef.hash` 没有时读文件算一次。

渲染走 `reading/engine/raster.ts`，用 app 自己那个 PDFium 引擎（不是 pdf.js，也不新起 reader 实例）。图片以 data: URL 交给 `<img src>`：函数签名只能回一个字符串，object URL 没地方 revoke。

同时最多两个在渲染（`cover-cache.ts` 的 `createGate`，上限 `COVER_RENDER_LIMIT = 2`）：一屏三十本书会在同一 tick 里全部发起请求，而 raster 占的是画面那条线程。排队按到达顺序，抛异常也把名额还回去。

失败落 `covers/<bookId>.failed.json`，下次冷启动照它决定要不要重试；拿不到封面的卡片退回原来的首字母块。引擎整个起不来（`no-engine`）不写标记，下次启动还会再试。

删书时三个文件一起删（`reading/delete/pick.ts`）：`.jpg`、`.json`、`.failed.json`。封面按 book id 存，不删的话同一个 PDF 再导入会看见旧图。

## 作者

作者取 PDF 自己的 Author 字段，和 raster 同一次 open 里读（`getMetadata`），写在封面旁边的 `covers/<bookId>.json`。书架每次渲染都不再开 PDF。

清洗规则在 `cleanAuthor`：压成一行、去控制字符、最长 120 字符；没有字母数字的、以及 `unknown`/`N/A` 这类占位一律当没有。空作者也要写文件——下次冷启动看的是文件在不在，不是里面有什么。图片在、记录不在，按 miss 处理，重渲染一次把记录补上。

卡片标签三行：标题（`font-display` 15px）、作者、`Read 42% · 23 marks`，底下 2px `bg-accent-line` 进度条。作者那行高度固定，空的也占位，所以有作者和没作者的卡片一样高。没有 view state 的书写「Not opened yet」，进度条画空轨。
