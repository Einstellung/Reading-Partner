# 赛博秘书与分层思考

> 本文定这个应用里的 AI 往哪走，是 [25](./25-子agent与上下文隔离.md) 的上游、[02](./02-AI核心与memory设计.md) 与 [16](./16-知识图谱.md) 的下游。秘书本身的形态另开一篇，这里不设计它。现状按 2026-07-30 的代码查证。

## 分层思考

对话跑在快模型上。真需要思考的问题不由对话本身扛，委派给一个开高 effort 的子 agent，对话继续往下走。OpenAI 2026 年 7 月的全双工语音模型就是这个形状：语音模型维持对话，难的查询交给更强的文本模型。

隔离那一半已经建好（[25](./25-子agent与上下文隔离.md)）：子 agent 有自己的 message 列表、自己的工具集、自己的轮数上限，中间产物出不来，只交回一份 brief。

缺的是 effort 还不是一等维度。今天 effort 只有两个全局设置，`chatThinking` 和 `prepThinking`，由 `resolveModel("chat" | "prep")` 解析，子 agent 一律按 `prep` 跑。`SubagentDefinition.model` 里有 `reasoning`，但它和 `providerId` / `modelId` 同在一个对象里，要抬 effort 就得同时钉死一个具体模型，`research-agent.ts` 因此干脆没设——钉一个模型会点到读者没配的 provider。`runSubagent` 的入参里没有 effort：父模型只决定要不要委派，不决定用多大力气。对话自己也是一个模型一档 thinking 从头跑到尾，某一轮特别难不会让它多想。

## 载体

一个建模某个人的助手只能长在这个人真正花时间的地方。这个应用是那个地方：它同时握着用户读的东西和用户被简报的东西。

## 别人没做出来的那件事

2026-07-30 的调研结论：没有任何产品，商业的或开源的，能让用户打断正在播的新闻简报、问一句刚播那条、再接着播下去。缺的四件能力是知道现在播到哪一条、离题之后接回原处、播放中的一个手势改掉明天的简报、知道用户已经读过什么。四件都要求一个关于人的模型，而不是一个关于今天新闻的模型：新闻产品没有阅读侧，不知道用户懂什么，阅读产品从来不用给谁做简报。这四件这里同样都没有——简报现在连语音播放都没有——有的只是同时握着两侧的位置。

## 两个模型还没接上

共用的只有一份 profile。`user-profile.md`（`src/observation/profile.ts`，早期的 `info-profile.md` 在首次读取时迁过来）是跨场景的身份文档，简报分诊和陪读对话都读它。除此之外只有一条单向信号：`assembleReadingContext` 把各 topic 的 observation index 里的 reading-position 和 stuck-point 挤成 500 字符交给分诊。

反方向没有。`src/reading/turn.ts` 只读 profile，看不到 `info-feedback.jsonl` 里打开、划掉、申诉的追加日志，也不知道今天的简报给用户看了什么。AI observations 自己按 topic 分目录（`memory-<topicId>/`，历史名），记的是材料。

所以"载体已经有了"目前只对产品形态成立，对数据不成立：同一个人有两份记录，一边看不见另一边。接起来是上面所有东西的前提，也和北极星里的跨主题联想缺的是同一层——一层关于这个读者怎么读的记忆，不归任何 topic 所有。

## 约束

- 只读的工作不设闸。闸是给有副作用的动作的（[17](./17-信息源系统.md) 的 trial 和明确同意）。委派出去的子 agent 继承这条。
- 委派出去的一次运行必须如实报告失败，放弃了不能以"什么都没找到"到达用户。六种结局和处置在 [25](./25-子agent与上下文隔离.md)。
- 子 agent 的花费和一次普通对话轮记在同一个本上：每轮的尺寸走 `src/budget`，一轮之内的总轮数走 `src/ai/subagent/ledger.ts`（`src/budget` 没有跨调用累计花费的概念）。

## 还没定的

秘书本身的形态。交互、界面、名字、时间表都留给那一篇。
